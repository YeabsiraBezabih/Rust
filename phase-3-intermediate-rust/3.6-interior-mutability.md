## Concept

Rust's compile-time borrow checker enforces the **Aliasing XOR Mutability Rule**:
> You can have any number of immutable references (`&T`), **OR** exactly one mutable reference (`&mut T`), but never both simultaneously.

However, in real systems (such as graph algorithms, mock objects in testing, and UI event trees), an object may be shared immutably (`Rc<T>` or `&T`), yet certain internal fields must be modified.

**Interior Mutability** is a design pattern that allows you to mutate data even when you only possess an immutable reference (`&self` or `&T`) to the outer container.

```
       External View (Immutable Reference):
       &outer_struct ──► ┌────────────────────────────────────┐
                         │ id: 101                            │
                         │ counter: Cell<u32> (Mutated!)      │ ◄── Interior Mutability
                         │ cache: RefCell<Vec<String>>        │
                         └────────────────────────────────────┘
```

---

### 1. `Cell<T>`: Interior Mutability for `Copy` Types

`Cell<T>` provides zero-overhead interior mutability for small values that implement `Copy`:
- It does **not** give out direct references (`&T`) to the inner data.
- Instead, values are copied or moved in and out using `.get()`, `.set()`, and `.replace()`.
- **Performance**: Zero runtime overhead. It compiles directly into raw machine instructions.

```rust
use std::cell::Cell;

struct MetricCounter {
    request_count: Cell<u64>,
}

let counter = MetricCounter { request_count: Cell::new(0) };
// Mutates internal value through an immutable reference `&counter`!
counter.request_count.set(counter.request_count.get() + 1);
assert_eq!(counter.request_count.get(), 1);
```

---

### 2. `RefCell<T>`: Dynamic Borrow Checking at Runtime

For non-`Copy` types (e.g., `Vec<T>`, `String`, structs), you use **`RefCell<T>`**.

`RefCell<T>` shifts the borrow checker's rules from **compile time to runtime**:
- Maintains an internal borrow counter.
- **`.borrow()`**: Returns a `Ref<T>` (smart pointer acting like `&T`). Increments reader count.
- **`.borrow_mut()`**: Returns a `RefMut<T>` (smart pointer acting like `&mut T`). Asserts zero active readers and zero active writers.

> [!CAUTION]
> If you violate borrow rules at runtime (e.g., calling `.borrow_mut()` while an active `.borrow()` or another `.borrow_mut()` is alive), **the thread panics immediately** (`already borrowed: BorrowMutError`).

```rust
use std::cell::RefCell;

let cell = RefCell::new(vec![1, 2, 3]);

{
    let mut write_guard = cell.borrow_mut(); // Exclusively borrowed
    write_guard.push(4);
} // write_guard dropped here, freeing the lock

let read_guard = cell.borrow(); // Shared borrow
assert_eq!(read_guard.len(), 4);
```

---

### 3. The Power Combo: `Rc<RefCell<T>>`

To have **multiple owners** that can all **mutate** a shared object in single-threaded code, combine `Rc` with `RefCell`:

```
Stack:
┌──────────────┐
│ handle_a: Rc │ ──┐
└──────────────┘   │   Heap:
┌──────────────┐   │   ┌──────────────────────────────────────────────┐
│ handle_b: Rc │ ──┼─► │ Rc metadata { strong: 2, weak: 0 }           │
└──────────────┘   │   │ RefCell { borrow_count: 0, data: Vec<i32> }  │
                   │   └──────────────────────────────────────────────┘
```

---

### 4. Comparison Summary

| Smart Pointer | Target Types | Borrow Checked At | Thread Safe? | Runtime Cost |
| :--- | :--- | :--- | :--- | :--- |
| **`Cell<T>`** | `Copy` / Move types | Compile Time (No `&T` given) | ❌ No (`!Sync`) | Zero |
| **`RefCell<T>`** | Any type `T` | **Runtime** (Panics on collision) | ❌ No (`!Sync`) | Minor (Borrow counter check) |
| **`Mutex<T>`** | Any type `T` | **Runtime** (Blocks/Sleeps) | ✅ Yes (`Send + Sync`) | OS Mutex / Atomic lock |

## Why it matters

- **Test Mocking**: Testing frameworks use `RefCell` to implement mock interfaces where trait definitions require `&self`, but mock structs must record function call counts and payloads.
- **Graph Node Mutation**: Adding edges between graph nodes held by multiple shared references without needing to restructure entire ownership trees.

---

## Analogy

- **`Cell`**: A mailbox drop-slot. You can drop a new letter in (`.set()`) or take a photocopy out (`.get()`), but you cannot hold a magnifying glass inside the box while someone replaces the letter.
- **`RefCell`**: A conference room with a digital occupancy sign. Multiple readers can enter with green badges. If someone requests a red badge (writer), the door locks. If someone tries to force entry with two conflicting badges, the alarm sounds (**panic**).

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::cell::{Cell, RefCell};
use std::rc::Rc;

// 1. Trait requiring immutable &self interface
pub trait Logger {
    fn log(&self, message: &str);
}

// 2. Mock Implementation using Interior Mutability for Unit Testing
pub struct MockLogger {
    call_count: Cell<usize>,
    log_history: RefCell<Vec<String>>,
}

impl MockLogger {
    pub fn new() -> Self {
        MockLogger {
            call_count: Cell::new(0),
            log_history: RefCell::new(Vec::new()),
        }
    }

    pub fn call_count(&self) -> usize {
        self.call_count.get()
    }

    pub fn history(&self) -> Vec<String> {
        self.log_history.borrow().clone()
    }
}

impl Logger for MockLogger {
    fn log(&self, message: &str) {
        // Mutate Cell counter
        self.call_count.set(self.call_count.get() + 1);

        // Mutate RefCell vector
        self.log_history.borrow_mut().push(message.to_string());
    }
}

// 3. Shared Mutable Graph Node with Rc<RefCell<T>>
#[derive(Debug)]
pub struct DeviceNode {
    pub name: String,
    pub connections: Vec<Rc<RefCell<DeviceNode>>>,
}

fn main() {
    // A. Testing the Mock Logger
    let mock = MockLogger::new();
    let logger: &dyn Logger = &mock;

    logger.log("Packet 1 arrived");
    logger.log("Packet 2 arrived");

    println!("Total log calls: {}", mock.call_count());
    println!("Log entries: {:?}", mock.history());
    assert_eq!(mock.call_count(), 2);

    // B. Shared Mutable Nodes with Rc<RefCell<T>>
    let router = Rc::new(RefCell::new(DeviceNode {
        name: "Main-Router".to_string(),
        connections: Vec::new(),
    }));

    let switch = Rc::new(RefCell::new(DeviceNode {
        name: "Floor-Switch".to_string(),
        connections: Vec::new(),
    }));

    // Connect switch to router
    router.borrow_mut().connections.push(Rc::clone(&switch));

    println!("Router connections count: {}", router.borrow().connections.len());
    println!("Switch name: {}", router.borrow().connections[0].borrow().name);
}
```

## Common Mistakes

### 1. Holding a `RefMut` Guard Across Nested Borrow Calls
```rust
let data = RefCell::new(vec![1, 2, 3]);

let mut guard = data.borrow_mut();
// ❌ PANIC at runtime: already mutably borrowed!
let length = data.borrow().len(); 
```
*Fix*: Restrict the scope of `guard` using a block `{ let mut guard = ...; guard.push(4); }` or call `drop(guard)` before borrowing again.

---

### 2. Using `try_borrow` vs `borrow` in Fault-Tolerant Systems
Calling `.borrow_mut()` unconditionally can cause unexpected panics if unexpected recursion occurs. Use `.try_borrow_mut()` which returns `Result<RefMut<T>, BorrowMutError>` when handling untrusted dynamic call graphs.

---

### 3. Attempting to Share `RefCell` Across Threads
`RefCell<T>` is strictly `!Sync`. Attempting to send an `Arc<RefCell<T>>` to a background thread fails at compile time. Use `Arc<Mutex<T>>` or `Arc<RwLock<T>>` for multi-threaded interior mutability.

## Solutions

### Solution to Exercise 1
```rust
use std::cell::RefCell;
use std::collections::HashMap;

pub trait DatabaseStore {
    fn set(&self, key: &str, val: &str);
    fn get(&self, key: &str) -> Option<String>;
}

pub struct MockDatabase {
    store: RefCell<HashMap<String, String>>,
}

impl MockDatabase {
    pub fn new() -> Self {
        MockDatabase {
            store: RefCell::new(HashMap::new()),
        }
    }
}

impl DatabaseStore for MockDatabase {
    fn set(&self, key: &str, val: &str) {
        self.store.borrow_mut().insert(key.to_string(), val.to_string());
    }

    fn get(&self, key: &str) -> Option<String> {
        self.store.borrow().get(key).cloned()
    }
}
```

---

### Solution to Exercise 2
```rust
use std::cell::RefCell;

fn demonstrate_scope_fix() {
    let cell = RefCell::new(10);

    // Using inner scope to release RefMut before borrowing again
    {
        let mut m = cell.borrow_mut();
        *m += 5;
    } // `m` is dropped here

    let r = cell.borrow();
    assert_eq!(*r, 15);
}
```

---

### Solution to Exercise 3
```rust
pub struct ExpensiveCalculator {
    cache: RefCell<HashMap<u32, u32>>,
}

impl ExpensiveCalculator {
    pub fn new() -> Self {
        ExpensiveCalculator {
            cache: RefCell::new(HashMap::new()),
        }
    }

    pub fn compute(&self, x: u32) -> u32 {
        if let Some(&cached) = self.cache.borrow().get(&x) {
            return cached;
        }

        let result = x * x; // Expensive calculation
        self.cache.borrow_mut().insert(x, result);
        result
    }
}

fn main() {
    let db = MockDatabase::new();
    db.set("user:1", "Alice");
    assert_eq!(db.get("user:1"), Some("Alice".to_string()));

    demonstrate_scope_fix();

    let calc = ExpensiveCalculator::new();
    assert_eq!(calc.compute(7), 49);
    assert_eq!(calc.compute(7), 49); // Read from cache
    println!("All interior mutability exercises verified!");
}
```
