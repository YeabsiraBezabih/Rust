## Concept

Rust is uniquely powerful because it contains two languages:
1. **Safe Rust**: The standard statically verified language where the borrow checker proves memory safety, thread safety, and bounds checks at compile time.
2. **Unsafe Rust**: An opt-in escape hatch that allows systems programmers to interact directly with hardware, operating system syscalls, and foreign C libraries.

> [!IMPORTANT]
> `unsafe` does **not** turn off the borrow checker or disable type checking. It simply gives you **5 specific superpowers** that the compiler cannot automatically verify.

---

### 1. The 5 Unsafe Superpowers

Within an `unsafe { ... }` block or `unsafe fn`, you are permitted to:
1. **Dereference Raw Pointers** (`*const T` and `*mut T`).
2. **Call Unsafe Functions or Methods** (including FFI C functions and compiler intrinsics).
3. **Implement Unsafe Traits** (such as `unsafe impl Send` or `unsafe impl Sync`).
4. **Mutate Mutable Static Variables** (`static mut`).
5. **Access Fields of a `union`**.

---

### 2. Raw Pointers vs. Safe References

| Property | Safe Reference (`&T`, `&mut T`) | Raw Pointer (`*const T`, `*mut T`) |
| :--- | :--- | :--- |
| **Nullability** | Guaranteed never null | Can be null (`std::ptr::null()`) |
| **Borrowing Rules** | Enforced (Aliasing XOR Mutability) | Ignored (Multiple `*mut` pointers allowed) |
| **Validity & Alignment** | Guaranteed valid and aligned | May point to unallocated or unaligned memory |
| **Automatic Cleanup** | Governed by lifetimes | No lifetime tracking or automatic `Drop` |
| **Creation** | Safe | Safe (`&val as *const _`) |
| **Dereferencing** | Safe (`*reference`) | **Requires `unsafe`** (`unsafe { *raw_ptr }`) |

```
Stack:
let mut x = 42;
let p1: *const i32 = &x; ──┐
let p2: *mut i32   = &mut x; ─┼─► [ Memory Address 0x7ffd_10a0: Value 42 ]
                              │
(Both raw pointers point to the same memory simultaneously without compiler error!)
```

---

### 3. The Encapsulation Contract (Safe Abstraction over Unsafe Cores)

Almost all core standard library types (`Vec<T>`, `String`, `Box<T>`, `HashMap<K, V>`, `Mutex<T>`) are internally implemented using small, carefully verified `unsafe` blocks wrapped inside **100% safe public APIs**.

> **The Golden Rule of Unsafe**: The programmer assumes full responsibility for proving that the code never triggers **Undefined Behavior (UB)**. If an unsafe block is exposed to users, its safety invariants must be completely guarded by the surrounding safe API.

---

### 4. Foreign Function Interface (FFI) and `#[repr(C)]`

FFI allows Rust to call existing C libraries (or be called from C, Python, Go):
- **`extern "C"`**: Specifies the C Application Binary Interface (ABI) calling convention.
- **`#[repr(C)]`**: Guarantees that a Rust struct's memory layout matches standard C struct field alignment.
- **`#[no_mangle]`**: Prevents the Rust compiler from mangling symbol names in the exported object binary.

---

## Why it matters

- **Operating System Development**: Writing kernel interrupt handlers, page tables, and memory allocators requires raw pointer arithmetic.
- **Device Drivers & FFI**: Communicating with hardware memory-mapped I/O (MMIO) registers or calling OpenSSL, SQLite, and Linux kernel syscalls (`epoll`, `io_uring`).
- **SIMD & Micro-Optimizations**: High-performance game engines and cryptography libraries use unsafe intrinsics to achieve maximum CPU throughput.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::slice;

// 1. Implementing a Safe Abstraction over Unsafe Pointer Arithmetic:
// Custom slice splitter (Safe Rust cannot prove that two sub-slices don't overlap)
pub fn split_at_mut_custom<T>(slice: &mut [T], mid: usize) -> (&mut [T], &mut [T]) {
    let len = slice.len();
    assert!(mid <= len, "Split index out of bounds");

    let ptr = slice.as_mut_ptr(); // Get raw pointer to first element

    // SAFETY:
    // 1. `mid <= len`, so both sub-slices lie within the allocated memory range.
    // 2. The left slice covers `0..mid` and right slice covers `mid..len`.
    // 3. The two slices are strictly disjoint (non-overlapping), so creating
    //    two mutable references does not violate aliasing invariants.
    unsafe {
        (
            slice::from_raw_parts_mut(ptr, mid),
            slice::from_raw_parts_mut(ptr.add(mid), len - mid),
        )
    }
}

// 2. Foreign Function Interface (FFI): Calling C Standard Library functions
extern "C" {
    // C standard library absolute value function: int abs(int j);
    fn abs(input: i32) -> i32;
}

// Safe Rust wrapper around C FFI function
pub fn safe_c_abs(val: i32) -> i32 {
    // SAFETY: `abs` is a pure C function with no pointer dereferencing or side-effects.
    unsafe { abs(val) }
}

fn main() {
    // Part A: Raw Pointer Creation and Dereferencing
    let mut num: i32 = 42;

    // Creating raw pointers is completely SAFE
    let r1: *const i32 = &num;
    let r2: *mut i32 = &mut num;

    // Dereferencing raw pointers requires UNSAFE
    unsafe {
        println!("r1 points to: {}", *r1);
        *r2 = 100; // Mutate value via raw pointer
        println!("r2 modified value to: {}", *r2);
    }
    assert_eq!(num, 100);

    // Part B: Testing Safe Slice Splitter
    let mut buffer = [10, 20, 30, 40, 50, 60];
    let (left, right) = split_at_mut_custom(&mut buffer, 3);
    left[0] = 999;
    right[0] = 888;
    println!("Modified buffer: {:?}", buffer);
    assert_eq!(buffer, [999, 20, 30, 888, 50, 60]);

    // Part C: Testing C FFI Call
    let negative = -55;
    let positive = safe_c_abs(negative);
    println!("C abs({}) = {}", negative, positive);
    assert_eq!(positive, 55);
}
```

## Common Mistakes

### 1. Creating Overlapping Mutable References via Raw Pointers
```rust
let mut val = 42;
let p1: *mut i32 = &mut val;
let p2: *mut i32 = &mut val;

// ❌ INSTANT UNDEFINED BEHAVIOR: Violates Rust's core rule that &mut must never alias!
unsafe {
    let r1: &mut i32 = &mut *p1;
    let r2: &mut i32 = &mut *p2;
    *r1 += 1;
    *r2 += 1;
}
```

---

### 2. Forgetting `#[repr(C)]` on FFI Structs
Rust is free to reorder struct fields in memory to minimize padding. Passing a standard Rust struct to a C library will cause fields to be mismatched. Always annotate FFI structs with `#[repr(C)]`.

---

### 3. Writing Large, Unfocused `unsafe` Blocks
Wrapping an entire 50-line function in `unsafe { ... }` instead of restricting the `unsafe` keyword to the exact single line doing pointer dereferencing or FFI calling. Always minimize the scope of `unsafe`.

## Solutions

### Solution to Exercise 1
```rust
pub fn swap_raw<T>(a: &mut T, b: &mut T) {
    let p1: *mut T = a;
    let p2: *mut T = b;

    // SAFETY:
    // 1. `p1` and `p2` originate from valid mutable references `&mut T`.
    // 2. The caller guarantees that `a` and `b` do not alias each other.
    // 3. Memory is properly aligned and dereferenceable for type T.
    unsafe {
        std::ptr::swap(p1, p2);
    }
}
```

---

### Solution to Exercise 2
```rust
use std::ffi::CStr;
use std::os::raw::c_char;

extern "C" {
    fn strlen(cs: *const c_char) -> usize;
}

pub fn safe_c_strlen(s: &CStr) -> usize {
    // SAFETY: CStr guarantees null-termination and valid pointer memory.
    unsafe { strlen(s.as_ptr()) }
}
```

---

### Solution to Exercise 3
```rust
#[repr(C)]
#[derive(Debug, PartialEq, Eq)]
pub struct HardwarePacket {
    pub header: u16,      // 2 bytes
    pub payload_len: u16, // 2 bytes
    pub checksum: u32,    // 4 bytes
}

fn main() {
    let mut x = 10;
    let mut y = 20;
    swap_raw(&mut x, &mut y);
    assert_eq!(x, 20);
    assert_eq!(y, 10);

    let c_string = std::ffi::CString::new("Hello FFI").unwrap();
    let len = safe_c_strlen(&c_string);
    assert_eq!(len, 9);

    assert_eq!(std::mem::size_of::<HardwarePacket>(), 8);
    println!("All Unsafe Rust exercises verified successfully!");
}
```
