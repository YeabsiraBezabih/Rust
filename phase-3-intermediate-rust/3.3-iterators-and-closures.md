## Concept

Rust blends low-level systems control with high-level functional programming paradigms through two core constructs: **Closures** and **Iterators**. Both compile down to zero-cost assembly with no runtime garbage collection.

---

### 1. Closures: Environment-Capturing Functions

A **Closure** is an anonymous function that can capture variables from the lexical scope in which it is defined:

```rust
let threshold = 50;
let is_above = |val: i32| val > threshold; // Captures `threshold` from surrounding scope
```

#### The Three Capture Modes & Closure Traits

Closures automatically implement one or more of three traits based on how they use captured variables:

```
                  ┌────────────┐
                  │   FnOnce   │ (Consumes captured variables by value)
                  └─────▲──────┘
                        │
                  ┌─────┴──────┐
                  │   FnMut    │ (Mutates captured environment via &mut)
                  └─────▲──────┘
                        │
                  ┌─────┴──────┐
                  │     Fn     │ (Borrows captured environment via &)
                  └────────────┘
```

1. **`FnOnce`**:
   - Consumes captured variables by value.
   - Can only be called **once** because ownership is transferred.
2. **`FnMut`**:
   - Mutates captured variables in-place via mutable references (`&mut`).
   - Can be called multiple times.
3. **`Fn`**:
   - Borrows captured variables immutably (`&`).
   - Can be called multiple times concurrently across threads.

#### The `move` Keyword
Adding `move` before the pipe arguments (`move |x| ...`) forces the closure to take full ownership of all captured variables rather than borrowing them (essential when transferring closures across thread boundaries).

---

### 2. Iterators and Lazy Evaluation

An **Iterator** produces a sequence of values on demand.

The entire system is powered by a single standard library trait:
```rust
pub trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}
```

#### The Two Classes of Iterator Methods:
1. **Adapters (Lazy)**: Transform an iterator into another iterator (e.g., `.map()`, `.filter()`, `.zip()`, `.take()`, `.enumerate()`). **They do zero work until consumed!**
2. **Consumers (Terminal)**: Drive the iterator to completion (e.g., `.collect()`, `.sum()`, `.count()`, `.fold()`, `.for_each()`, `.find()`).

```
Data: [ 1, 2, 3, 4, 5 ]
         │
         ▼ .filter(|x| x % 2 == 0)   <── (Lazy: No work done yet)
         │
         ▼ .map(|x| x * 10)          <── (Lazy: No work done yet)
         │
         ▼ .collect::<Vec<_>>()      <── (Consumer: Pulls values one by one)
Result: [ 20, 40 ]
```

---

### 3. `iter()`, `iter_mut()`, and `into_iter()`

| Method | Borrow Type | Yields | Original Collection Status |
| :--- | :--- | :--- | :--- |
| `.iter()` | Immutable Borrow (`&self`) | `&T` | Retained (Unmodified) |
| `.iter_mut()` | Mutable Borrow (`&mut self`) | `&mut T` | Retained (Modified in-place) |
| `.into_iter()` | Consuming Move (`self`) | `T` | Destroyed / Moved |

---

## Why it matters

- **Zero-Cost Abstractions**: Rust's optimizing compiler (LLVM) fuses iterator pipelines (`map`, `filter`) into single tight loops without intermediate array allocations, often eliminating bounds checks entirely.
- **Thread Safety**: The `Fn`/`FnMut`/`FnOnce` hierarchy guarantees at compile time that multi-threaded task dispatchers cannot introduce data races.

---

## Analogy

- **Closure**: A Polaroid camera. It captures the scene (surrounding variables) at the moment the shutter is pressed and carries that captured picture with it.
- **Iterator Pipeline**: A factory assembly conveyor belt. Turning on valves (`map`, `filter`) sets up the machinery, but nothing moves until the packaging crane (`collect`) at the end starts pulling items.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
// 1. Custom Iterator: Generates Fibonacci numbers up to a maximum limit
pub struct FibonacciGenerator {
    curr: u64,
    next: u64,
    max_limit: u64,
}

impl FibonacciGenerator {
    pub fn new(max_limit: u64) -> Self {
        FibonacciGenerator {
            curr: 0,
            next: 1,
            max_limit,
        }
    }
}

impl Iterator for FibonacciGenerator {
    type Item = u64;

    fn next(&mut self) -> Option<Self::Item> {
        if self.curr > self.max_limit {
            None
        } else {
            let val = self.curr;
            let new_next = self.curr + self.next;
            self.curr = self.next;
            self.next = new_next;
            Some(val)
        }
    }
}

// 2. High-Performance Stream Pipeline
#[derive(Debug)]
struct NetworkPacket {
    id: u32,
    payload_size: usize,
    is_corrupted: bool,
}

fn main() {
    // A. Using Custom Iterator with Combinators
    let fib_evens: Vec<u64> = FibonacciGenerator::new(100)
        .filter(|&n| n % 2 == 0)
        .map(|n| n * 10)
        .collect();

    println!("Fibonacci even multiples of 10: {:?}", fib_evens);

    // B. Stream Processing Network Packets
    let packets = vec![
        NetworkPacket { id: 101, payload_size: 1420, is_corrupted: false },
        NetworkPacket { id: 102, payload_size: 64, is_corrupted: true },
        NetworkPacket { id: 103, payload_size: 1500, is_corrupted: false },
        NetworkPacket { id: 104, payload_size: 512, is_corrupted: false },
    ];

    // Compute total valid bandwidth without any intermediate allocations
    let total_valid_bytes: usize = packets
        .iter()
        .filter(|p| !p.is_corrupted)
        .map(|p| p.payload_size)
        .sum();

    println!("Total valid payload bandwidth: {} bytes", total_valid_bytes);

    // C. Demonstrating Fn vs FnMut vs FnOnce
    let mut counter = 0;
    let mut increment = || {
        counter += 1;
        counter
    }; // Implements FnMut

    println!("Counter step 1: {}", increment());
    println!("Counter step 2: {}", increment());
}
```

## Common Mistakes

### 1. Forgetting to Consume Lazy Iterators
Writing an iterator chain without a terminal consumer:
```rust
// ❌ WARNING / BUG: Iterator adapter does nothing because it is unused!
let nums = vec![1, 2, 3];
nums.iter().map(|x| println!("{}", x)); // Nothing prints!

// ✅ CORRECT: Use a consumer or for loop
nums.iter().for_each(|x| println!("{}", x));
```

---

### 2. Intermediate `.collect()` Allocations
Chaining multiple `.collect::<Vec<_>>()` calls across transformations:
```rust
// ❌ WASTEFUL: Allocates 2 temporary heap vectors!
let result = data.iter().filter(...).collect::<Vec<_>>().into_iter().map(...).collect::<Vec<_>>();

// ✅ EFFICIENT: Zero heap allocations until the single final collect
let result: Vec<_> = data.iter().filter(...).map(...).collect();
```

---

### 3. Calling an `FnOnce` Closure Multiple Times
```rust
fn execute_once<F: FnOnce()>(f: F) {
    f();
    f(); // ❌ COMPILE ERROR: use of moved value `f`
}
```

### Exercise 3 (Retry Wrapper with `FnMut`)
Write a higher-order function:
```rust
pub fn retry<T, E, F>(mut attempts: usize, mut operation: F) -> Result<T, E>
where
    F: FnMut() -> Result<T, E>,
```
that calls `operation` repeatedly up to `attempts` times until it succeeds or runs out of attempts.

## Solutions

### Solution to Exercise 1
```rust
pub struct StepRange {
    current: usize,
    end: usize,
    step: usize,
}

impl StepRange {
    pub fn new(start: usize, end: usize, step: usize) -> Self {
        assert!(step > 0, "Step must be greater than zero");
        StepRange {
            current: start,
            end,
            step,
        }
    }
}

impl Iterator for StepRange {
    type Item = usize;

    fn next(&mut self) -> Option<Self::Item> {
        if self.current >= self.end {
            None
        } else {
            let val = self.current;
            self.current += self.step;
            Some(val)
        }
    }
}
```

### Solution to Exercise 2
```rust
pub fn process_data_stream(inputs: &[&str]) -> u32 {
    inputs
        .iter()
        .filter_map(|s| s.parse::<u32>().ok())
        .filter(|&num| num > 10)
        .product()
}
```

### Solution to Exercise 3
```rust
pub fn retry<T, E, F>(mut attempts: usize, mut operation: F) -> Result<T, E>
where
    F: FnMut() -> Result<T, E>,
{
    loop {
        match operation() {
            Ok(val) => return Ok(val),
            Err(err) => {
                attempts -= 1;
                if attempts == 0 {
                    return Err(err);
                }
            }
        }
    }
}

fn main() {
    let steps: Vec<usize> = StepRange::new(0, 10, 3).collect();
    assert_eq!(steps, vec![0, 3, 6, 9]);

    let prod = process_data_stream(&["12", "invalid", "45", "90", "error", "3"]);
    assert_eq!(prod, 12 * 45 * 90);

    let mut tries = 0;
    let res: Result<i32, &str> = retry(3, || {
        tries += 1;
        if tries == 2 {
            Ok(100)
        } else {
            Err("failed")
        }
    });
    assert_eq!(res, Ok(100));
    println!("All functional Rust exercises verified!");
}
```
