## Concept

Rust's default model enforces **single ownership**: one value has exactly one owner. However, many real-world architectures (such as graph nodes, shared caches, and multi-threaded server configurations) require **shared ownership**, where multiple parts of a program hold simultaneous read access to the same heap allocation.

Rust provides two reference-counting smart pointers for this:
1. **`Rc<T>`**: Reference Counting for **single-threaded** execution.
2. **`Arc<T>`**: **Atomic** Reference Counting for **multi-threaded** execution.

---

### 1. `Rc<T>`: Single-Threaded Reference Counting

`Rc<T>` allocates the target value on the heap alongside two 64-bit integer counters:
- **`strong_count`**: Number of active owning `Rc<T>` handles.
- **`weak_count`**: Number of non-owning `Weak<T>` handles.

```
Stack:
┌──────────────┐
│ handle_1: Rc │ ──┐
└──────────────┘   │
┌──────────────┐   │   Heap:
│ handle_2: Rc │ ──┼─► ┌───────────────────────────────────────┐
└──────────────┘   │   │ strong_count: 3                       │
┌──────────────┐   │   │ weak_count:   0                       │
│ handle_3: Rc │ ──┘   │ value:        "ServerConfig: Port 80" │
└──────────────┘       └───────────────────────────────────────┘
```

#### Lifecycle Rules:
- **Cloning**: Calling `Rc::clone(&ptr)` does **not** deep-copy the underlying data; it simply increments `strong_count` by 1 ($O(1)$).
- **Dropping**: When an `Rc<T>` handle goes out of scope, its `Drop` implementation decrements `strong_count` by 1.
- **Deallocation**: When `strong_count` reaches **`0`**, the heap memory is immediately freed.

---

### 2. `Arc<T>`: Thread-Safe Atomic Reference Counting

`Rc<T>` is **not thread-safe**. It does not implement the `Send` or `Sync` marker traits because incrementing/decrementing standard integers across concurrent threads causes data races.

**`Arc<T>`** replaces standard integer arithmetic with **atomic CPU instructions** (`fetch_add` and `fetch_sub` with hardware memory barriers):
- Can be safely cloned and sent across thread boundaries (`std::thread::spawn`).
- Has a slight CPU overhead compared to `Rc<T>` due to hardware memory bus synchronization.

---

### 3. Reference Cycles and Memory Leaks

If two nodes hold strong `Rc<T>` references to each other, their `strong_count` will never drop to 0, causing a permanent **memory leak**:

```
Node A (strong: 1) ──► Node B (strong: 1)
       ▲                      │
       └──────────────────────┘ (Cycle: Neither is ever dropped!)
```

#### Breaking Cycles with `Weak<T>`
A **`Weak<T>`** pointer is a non-owning reference created via `Rc::downgrade(&rc)`:
- It increments `weak_count`, but does **not** prevent the value from being deallocated when all strong pointers drop.
- To read the value, you call `weak.upgrade()`, which returns `Option<Rc<T>>` (`None` if the value has already been freed).

---

## Why it matters

- **Multi-Threaded Server Configs**: High-throughput web servers store database connection pools and TLS certificates inside an `Arc<Config>`, allowing thousands of concurrent request worker threads to read configurations simultaneously without locks.
- **Graph & Tree Topologies**: Trees use `Rc<Node>` for parent-to-child links and `Weak<Node>` for child-to-parent links to avoid reference cycle memory leaks.

---

## Analogy

- **`Rc` / `Arc`**: A conference room television. Five people enter the room and watch the screen (`strong_count = 5`). As long as at least one person remains, the TV stays on. The last person to leave turns off the TV and locks the door (`strong_count == 0`).
- **`Weak`**: A person walking past in the hallway looking through the glass window. They can see the TV if it's on, but their presence does not keep the room open.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::rc::{Rc, Weak};
use std::sync::Arc;
use std::thread;

// 1. Single-Threaded Tree with Parent Pointers (Using Rc and Weak)
#[derive(Debug)]
pub struct TreeNode {
    pub id: u32,
    pub parent: std::cell::RefCell<Weak<TreeNode>>, // Non-owning back-pointer
    pub children: std::cell::RefCell<Vec<Rc<TreeNode>>>, // Owning forward-pointer
}

// 2. Multi-Threaded Shared State using Arc
#[derive(Debug)]
pub struct ServerConfig {
    pub bind_address: String,
    pub max_connections: usize,
}

fn main() {
    // -------------------------------------------------------------
    // Part A: Rc and Weak Demonstration
    // -------------------------------------------------------------
    let root = Rc::new(TreeNode {
        id: 1,
        parent: std::cell::RefCell::new(Weak::new()),
        children: std::cell::RefCell::new(Vec::new()),
    });

    println!("Root created. Strong count: {}", Rc::strong_count(&root)); // 1

    let child = Rc::new(TreeNode {
        id: 2,
        parent: std::cell::RefCell::new(Rc::downgrade(&root)), // Weak back-pointer
        children: std::cell::RefCell::new(Vec::new()),
    });

    // Add child to root
    root.children.borrow_mut().push(Rc::clone(&child));

    println!("Child added to root.");
    println!("Root Strong: {}, Weak: {}", Rc::strong_count(&root), Rc::weak_count(&root));
    println!("Child Strong: {}, Weak: {}", Rc::strong_count(&child), Rc::weak_count(&child));

    // Access parent from child via upgrade
    if let Some(parent_rc) = child.parent.borrow().upgrade() {
        println!("Child 2 verified parent ID: {}", parent_rc.id);
    }

    // -------------------------------------------------------------
    // Part B: Multi-Threaded Arc Demonstration
    // -------------------------------------------------------------
    let config = Arc::new(ServerConfig {
        bind_address: String::from("127.0.0.1:8080"),
        max_connections: 5000,
    });

    let mut handles = Vec::new();

    // Spawn 3 worker threads sharing the same Arc<ServerConfig>
    for worker_id in 0..3 {
        let config_clone = Arc::clone(&config); // Cheap atomic pointer clone

        let handle = thread::spawn(move || {
            println!(
                "[Worker {}] Listening on {} (Max Conns: {})",
                worker_id, config_clone.bind_address, config_clone.max_connections
            );
        });

        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("All worker threads finished. Arc strong count: {}", Arc::strong_count(&config));
}
```

## Common Mistakes

### 1. Attempting to Send `Rc<T>` to Another Thread
```rust
let data = Rc::new(vec![1, 2, 3]);
thread::spawn(move || {
    // ❌ COMPILE ERROR: `Rc<Vec<i32>>` cannot be sent between threads safely
    println!("{:?}", data);
});

// ✅ CORRECT: Use Arc<T> for multi-threaded sharing
let data = Arc::new(vec![1, 2, 3]);
```

---

### 2. Using `clone()` Directly Instead of `Rc::clone(&handle)`
Calling `handle.clone()` works, but in complex codebases it can be easily confused with a costly deep copy of the underlying type `T`. Writing `Rc::clone(&handle)` or `Arc::clone(&handle)` clearly communicates that only the reference counter pointer is cloned.

---

### 3. Cyclic Strong Reference Leaks
Creating two nodes that own each other via `Rc<T>`. When their external variables go out of scope, their `strong_count` remains 1, permanently leaking memory. Always use `Weak<T>` for child-to-parent or back-edges.

## Solutions

### Solution to Exercise 1
```rust
use std::rc::Rc;

struct DagNode {
    name: String,
    next: Option<Rc<DagNode>>,
}

fn test_shared_dag() {
    let shared_c = Rc::new(DagNode {
        name: "C".to_string(),
        next: None,
    });

    let root_a = DagNode {
        name: "A".to_string(),
        next: Some(Rc::clone(&shared_c)),
    };

    let root_b = DagNode {
        name: "B".to_string(),
        next: Some(Rc::clone(&shared_c)),
    };

    assert_eq!(Rc::strong_count(&shared_c), 3);
}
```

---

### Solution to Exercise 2
```rust
use std::rc::Rc;

fn test_weak_lifecycle() {
    let strong = Rc::new(100);
    let weak = Rc::downgrade(&strong);

    // Strong still alive
    assert!(weak.upgrade().is_some());
    assert_eq!(*weak.upgrade().unwrap(), 100);

    // Drop the strong owner
    drop(strong);

    // Weak upgrade now safely returns None
    assert!(weak.upgrade().is_none());
}
```

### Solution to Exercise 3
```rust
use std::sync::Arc;
use std::thread;

fn parallel_word_count() {
    let words: Vec<String> = (0..1000).map(|i| format!("word_{}", i)).collect();
    let shared_words = Arc::new(words);
    let mut handles = Vec::new();

    for t in 0..4 {
        let words_ref = Arc::clone(&shared_words);
        let handle = thread::spawn(move || {
            let chunk_size = words_ref.len() / 4;
            let start = t * chunk_size;
            let end = start + chunk_size;
            let count = words_ref[start..end].len();
            count
        });
        handles.push(handle);
    }

    let total: usize = handles.into_iter().map(|h| h.join().unwrap()).sum();
    assert_eq!(total, 1000);
}

fn main() {
    test_shared_dag();
    test_weak_lifecycle();
    parallel_word_count();
    println!("All reference counting exercises passed!");
}
```
