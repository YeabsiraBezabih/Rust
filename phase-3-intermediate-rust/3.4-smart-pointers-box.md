## Concept

A **Smart Pointer** is a data structure that acts like a pointer (stores a memory address) but includes additional metadata and memory management capabilities.

The simplest and most fundamental smart pointer in Rust is **`Box<T>`**.

---

### 1. What is `Box<T>`?

`Box<T>` provides **unique ownership of heap-allocated memory**:
- The actual value of type `T` is allocated on the **heap**.
- A small descriptor (a single 8-byte pointer on 64-bit systems) lives on the **stack**.
- When the `Box<T>` goes out of scope, its `Drop` implementation automatically deallocates the heap memory.

```
Stack:
┌─────────────────────────┐
│ Box<Data> (8 bytes)     │ ──┐
│ ptr: 0x7ffd_10a0        │   │
└─────────────────────────┘   │
                              ▼
Heap: (0x7ffd_10a0)
┌───────────────────────────────────────────────┐
│ Large Struct or Recursive Node                │
│ { payload: [0u8; 1024], id: 42 }              │
└───────────────────────────────────────────────┘
```

---

### 2. The Three Primary Use Cases for `Box<T>`

#### Case 1: Recursive Types with Unknown Compile-Time Size
Rust must know the exact byte size of every type at compile time. Recursive types without indirection have infinite size:

```rust
// ❌ COMPILE ERROR: recursive type `List` has infinite size
enum List {
    Cons(i32, List),
    Nil,
}

// ✅ FIXED: Box<List> has a fixed size of 8 bytes (pointer size)
enum List {
    Cons(i32, Box<List>),
    Nil,
}
```

#### Case 2: Storing Large Data to Prevent Stack Overflows
The OS thread stack is small ($2\text{MB}$ to $8\text{MB}$). Allocating a large buffer (e.g. $10\text{MB}$) directly on the stack causes an instant stack overflow crash. `Box::new()` places the data directly on the heap.

#### Case 3: Trait Objects for Dynamic Dispatch
`Box<dyn Trait>` provides ownership of an unsized trait object on the heap (as covered in Lesson 3.2).

---

### 3. The `Deref` Trait and Deref Coercion

`Box<T>` implements the `std::ops::Deref` trait, which allows smart pointers to be treated like standard references (`&T`):

```rust
let boxed_num = Box::new(42);
assert_eq!(*boxed_num, 42); // Explicit dereference via Deref
```

**Deref Coercion** automatically converts a reference to a type implementing `Deref` into a reference to its inner type (e.g., converting `&Box<String>` into `&str` seamlessly).

---

## Why it matters

- **Abstract Syntax Trees (ASTs)**: Compilers, template engines, and expression parsers represent code syntax as recursive tree structures interconnected by `Box<Node>`.
- **Zero-Copy Transfers**: Passing ownership of a 100MB heap buffer across functions or threads only copies an 8-byte `Box` pointer on the stack, taking fractions of a nanosecond.

---

## Analogy

Think of a **Luggage Claim Ticket**:
- You carry an 8-byte paper claim slip in your jacket pocket (the stack).
- Your heavy 50kg luggage trunk travels in the airplane's cargo hold (the heap).
- When you hand off the claim slip (move ownership), you only move the slip, not the heavy luggage.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::ops::Deref;

// 1. Recursive Data Structure: Abstract Syntax Tree (AST) for Arithmetic Expressions
#[derive(Debug)]
pub enum Expr {
    Number(f64),
    Add(Box<Expr>, Box<Expr>),
    Multiply(Box<Expr>, Box<Expr>),
}

impl Expr {
    // Evaluates the AST recursively
    pub fn eval(&self) -> f64 {
        match self {
            Expr::Number(val) => *val,
            Expr::Add(left, right) => left.eval() + right.eval(),
            Expr::Multiply(left, right) => left.eval() * right.eval(),
        }
    }
}

// 2. Custom Smart Pointer to demonstrate Deref and Drop mechanics
#[derive(Debug)]
pub struct CustomBox<T> {
    ptr: *mut T,
}

impl<T> CustomBox<T> {
    pub fn new(value: T) -> Self {
        // Allocate heap memory and place value into it
        let boxed = Box::new(value);
        CustomBox {
            ptr: Box::into_raw(boxed),
        }
    }
}

impl<T> Deref for CustomBox<T> {
    type Target = T;

    fn deref(&self) -> &Self::Target {
        // Safety: ptr is guaranteed valid and aligned
        unsafe { &*self.ptr }
    }
}

impl<T> Drop for CustomBox<T> {
    fn drop(&mut self) {
        println!("[CustomBox] Dropping and deallocating heap memory!");
        // Reconstruct Box to trigger automatic deallocation
        unsafe {
            let _ = Box::from_raw(self.ptr);
        }
    }
}

fn main() {
    // Construct AST for expression: (5 + 3) * 2
    // Expression Tree:
    //         *
    //       /   \
    //      +     2
    //    /   \
    //   5     3
    let ast = Expr::Multiply(
        Box::new(Expr::Add(
            Box::new(Expr::Number(5.0)),
            Box::new(Expr::Number(3.0)),
        )),
        Box::new(Expr::Number(2.0)),
    );

    println!("AST Evaluation ((5 + 3) * 2): {}", ast.eval());
    assert_eq!(ast.eval(), 16.0);

    // CustomBox Demonstration
    {
        let custom = CustomBox::new(String::from("Systems Rust"));
        // Deref coercion: CustomBox<String> -> String -> &str
        println!("CustomBox value: {}", *custom);
        println!("CustomBox length: {}", custom.len());
    } // CustomBox dropped here!
}
```

## Common Mistakes

### 1. Boxing Small Primitives Unnecessarily
Writing `Box<u32>` or `Box<bool>`:
```rust
// ❌ UNNECESSARY HEAP OVERHEAD: Adds heap allocation latency and pointer dereference
let age: Box<u32> = Box::new(25);

// ✅ EFFICIENT: Keep small Copy types directly on the stack
let age: u32 = 25;
```

---

### 2. Creating Infinite Recursive Types Without Boxing
```rust
// ❌ COMPILE ERROR: recursive type has infinite size
struct TreeNode {
    value: i32,
    left: TreeNode, // Needs Box<TreeNode>
}
```

---

### 3. Confusing Stack Ownership with Heap Deep Copies
Assuming that moving `let b2 = b1;` copies the heap memory. In Rust, moving a `Box` only copies the 8-byte stack pointer and invalidates `b1`. To duplicate the heap data, you must explicitly call `b1.clone()`.

## Solutions

### Solution to Exercise 1
```rust
#[derive(Debug)]
pub enum Expr {
    Number(f64),
    Add(Box<Expr>, Box<Expr>),
    Subtract(Box<Expr>, Box<Expr>),
    Multiply(Box<Expr>, Box<Expr>),
    Divide(Box<Expr>, Box<Expr>),
}

impl Expr {
    pub fn eval(&self) -> Result<f64, &'static str> {
        match self {
            Expr::Number(n) => Ok(*n),
            Expr::Add(l, r) => Ok(l.eval()? + r.eval()?),
            Expr::Subtract(l, r) => Ok(l.eval()? - r.eval()?),
            Expr::Multiply(l, r) => Ok(l.eval()? * r.eval()?),
            Expr::Divide(l, r) => {
                let divisor = r.eval()?;
                if divisor.abs() < 1e-9 {
                    Err("Division by zero")
                } else {
                    Ok(l.eval()? / divisor)
                }
            }
        }
    }
}
```

---

### Solution to Exercise 2
```rust
pub fn allocate_zeroed_buffer(mb: usize) -> Box<[u8]> {
    let byte_count = mb * 1024 * 1024;
    vec![0u8; byte_count].into_boxed_slice()
}
```

---

### Solution to Exercise 3
```rust
use std::ops::{Deref, DerefMut};

impl<T> DerefMut for CustomBox<T> {
    fn deref_mut(&mut self) -> &mut Self::Target {
        unsafe { &mut *self.ptr }
    }
}

fn main() {
    let ast = Expr::Divide(
        Box::new(Expr::Subtract(
            Box::new(Expr::Number(100.0)),
            Box::new(Expr::Number(20.0)),
        )),
        Box::new(Expr::Number(4.0)),
    );

    assert_eq!(ast.eval(), Ok(20.0));

    let buf = allocate_zeroed_buffer(10);
    assert_eq!(buf.len(), 10 * 1024 * 1024);

    let mut custom = CustomBox::new(50);
    *custom += 50;
    assert_eq!(*custom, 100);
    println!("All Box exercises verified successfully!");
}
```
