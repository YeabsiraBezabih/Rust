## Concept

In multi-threaded systems, multiple OS threads execute concurrently on multiple CPU cores. Without synchronization, concurrent access to shared memory leads to **Data Races** (undefined behavior where one thread writes while another reads).

Rust guarantees **Fearless Concurrency**: data races are impossible in safe Rust, enforced at compile time through ownership, the `Send`/`Sync` marker traits, and synchronization primitives.

---

### 1. The `Send` and `Sync` Marker Traits

`Send` and `Sync` are built-in language marker traits with no methods:

- **`Send`**: Ownership of the type can be transferred across thread boundaries.
- **`Sync`**: It is safe for multiple concurrent threads to share references (`&T`) to the type:
  $$T \text{ is } \texttt{Sync} \iff \&T \text{ is } \texttt{Send}$$

```
Type Safety Matrix:
┌─────────────────┬──────────┬──────────┬──────────────────────────────────────────┐
│ Type            │ Send?    │ Sync?    │ Reason                                   │
├─────────────────┼──────────┼──────────┼──────────────────────────────────────────┤
│ Primitives (i32)│ ✅ Yes   │ ✅ Yes   │ Immutable and trivially copyable         │
│ Rc<T>           │ ❌ No    │ ❌ No    │ Non-atomic reference counting            │
│ Arc<T>          │ ✅ Yes   │ ✅ Yes   │ Atomic reference counting (if T is Sync) │
│ RefCell<T>      │ ✅ Yes   │ ❌ No    │ Non-atomic runtime borrow counter        │
│ Mutex<T>        │ ✅ Yes   │ ✅ Yes   │ OS/atomic mutual exclusion lock          │
│ RwLock<T>       │ ✅ Yes   │ ✅ Yes   │ Multi-reader, single-writer lock         │
└─────────────────┴──────────┴──────────┴──────────────────────────────────────────┘
```

---

### 2. `Mutex<T>`: Mutual Exclusion

A **`Mutex<T>`** ("Mutual Exclusion") wraps data `T` and ensures that **only one thread at a time** can access it:
- **Acquiring Lock**: `.lock().unwrap()` blocks (sleeps) the current thread until the lock is acquired.
- **RAII Guard**: It returns a `MutexGuard<T>` smart pointer that implements `DerefMut`.
- **Automatic Unlock**: When `MutexGuard` goes out of scope, its `Drop` implementation automatically releases the lock.
- **Poisoning**: If a thread panics while holding the lock, the mutex becomes "poisoned" to notify other threads that shared state may be corrupted.

```
Thread 1:  ──► [ Acquires Mutex Lock ] ──► Mutates Data ──► [ Drops Guard (Unlock) ]
Thread 2:           (Blocked / Asleep) ───────────────────► [ Acquires Mutex Lock ] ──► ...
```

---

### 3. `RwLock<T>`: Reader-Writer Lock

For workloads where data is read frequently but rarely updated (e.g., routing tables, caches):
- **Multiple Readers**: Many threads can acquire read locks simultaneously via `.read().unwrap()`.
- **Exclusive Writer**: Only one thread can acquire a write lock via `.write().unwrap()`, blocking all readers and writers until finished.

---

### 4. Lock-Free Synchronization with Atomics

For simple counters, flags, and states, atomic primitives in `std::sync::atomic` (`AtomicUsize`, `AtomicBool`) manipulate memory directly using atomic CPU hardware instructions without locks:

```rust
use std::sync::atomic::{AtomicUsize, Ordering};

let counter = AtomicUsize::new(0);
counter.fetch_add(1, Ordering::Relaxed); // Thread-safe lock-free increment!
```

---

## Why it matters

- **Thread-Safe In-Memory Caching**: Shared HTTP caches and session stores use `Arc<RwLock<HashMap<K, V>>>` to support 100,000+ reads/sec with minimal contention.
- **Deadlock Prevention**: Understanding lock hierarchies prevents fatal deadlock freezes where Thread A waits for Thread B while Thread B waits for Thread A.

---

## Analogy

- **`Mutex`**: A single-person fitting room with a physical key. Only one shopper can be inside at a time; everyone else waits in line.
- **`RwLock`**: A public transit departure timetable. Fifty passengers can look at the board simultaneously (`read`), but when the operator updates the departures (`write`), everyone must pause until the new text is in place.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::collections::HashMap;
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::{Arc, Mutex, RwLock};
use std::thread;
use std::time::Duration;

// 1. Thread-Safe Shared Cache using Arc<RwLock>
#[derive(Debug)]
pub struct ConcurrentCache {
    store: RwLock<HashMap<String, String>>,
    hit_counter: AtomicUsize, // Lock-free metrics
}

impl ConcurrentCache {
    pub fn new() -> Self {
        ConcurrentCache {
            store: RwLock::new(HashMap::new()),
            hit_counter: AtomicUsize::new(0),
        }
    }

    pub fn set(&self, key: &str, val: &str) {
        let mut write_guard = self.store.write().unwrap();
        write_guard.insert(key.to_string(), val.to_string());
    }

    pub fn get(&self, key: &str) -> Option<String> {
        let read_guard = self.store.read().unwrap();
        if let Some(val) = read_guard.get(key) {
            self.hit_counter.fetch_add(1, Ordering::Relaxed);
            Some(val.clone())
        } else {
            None
        }
    }

    pub fn total_hits(&self) -> usize {
        self.hit_counter.load(Ordering::Relaxed)
    }
}

// 2. Thread-Safe Task Queue using Arc<Mutex>
pub struct TaskQueue {
    tasks: Mutex<Vec<String>>,
}

impl TaskQueue {
    pub fn new() -> Self {
        TaskQueue {
            tasks: Mutex::new(Vec::new()),
        }
    }

    pub fn push(&self, task: &str) {
        let mut guard = self.tasks.lock().unwrap();
        guard.push(task.to_string());
    }

    pub fn pop(&self) -> Option<String> {
        let mut guard = self.tasks.lock().unwrap();
        guard.pop()
    }
}

fn main() {
    let cache = Arc::new(ConcurrentCache::new());
    cache.set("cluster_region", "us-east-1");

    let mut handles = Vec::new();

    // Spawn 8 concurrent reader threads
    for thread_id in 0..8 {
        let cache_ref = Arc::clone(&cache);
        let handle = thread::spawn(move || {
            for _ in 0..100 {
                let val = cache_ref.get("cluster_region");
                assert_eq!(val, Some("us-east-1".to_string()));
            }
            println!("Reader thread {} finished 100 queries.", thread_id);
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("All readers done! Total cache hits: {}", cache.total_hits());
    assert_eq!(cache.total_hits(), 800);

    // Mutex Task Queue Example
    let queue = Arc::new(TaskQueue::new());
    queue.push("Process-Image-101");
    queue.push("Send-Email-202");

    println!("Popped task: {:?}", queue.pop());
}
```

## Common Mistakes

### 1. Holding a `MutexGuard` Across Blocking Operations
Holding a lock while making an HTTP network call, waiting on disk I/O, or sleeping:
```rust
// ❌ CRITICAL BUG: Freezes all other threads waiting for the lock!
{
    let mut guard = shared_state.lock().unwrap();
    std::thread::sleep(Duration::from_secs(5)); // Terrible!
    guard.update();
}

// ✅ CORRECT: Extract data quickly, drop the lock, then perform I/O
let data = {
    let guard = shared_state.lock().unwrap();
    guard.clone()
};
// Lock is released! Perform long operation outside critical section
```

---

### 2. Deadlocks Through Inconsistent Lock Acquisition Order
- Thread 1 locks `Mutex A`, then tries to lock `Mutex B`.
- Thread 2 locks `Mutex B`, then tries to lock `Mutex A`.
- Both threads wait forever on each other (**Deadlock**).
*Fix*: Always acquire multiple locks in a strictly defined, globally consistent order (e.g., sorted by memory address or struct ID).

---

### 3. Using `Mutex` When Atomic Primitives Are Sufficient
Wrapping a single `usize` counter in `Mutex<usize>` adds lock contention and OS syscall overhead. Use `AtomicUsize` for lock-free counters.

## Solutions

### Solution to Exercise 1
```rust
use std::sync::Mutex;

pub struct Account {
    pub id: u64,
    pub balance: Mutex<i64>,
}

pub fn transfer(from: &Account, to: &Account, amount: i64) -> Result<(), &'static str> {
    if from.id == to.id {
        return Err("Cannot transfer to self");
    }

    // Always acquire locks in ascending order of Account ID to prevent deadlocks
    let (mut first_guard, mut second_guard) = if from.id < to.id {
        let g1 = from.balance.lock().unwrap();
        let g2 = to.balance.lock().unwrap();
        (g1, g2)
    } else {
        let g2 = to.balance.lock().unwrap();
        let g1 = from.balance.lock().unwrap();
        (g1, g2)
    };

    if *first_guard < amount {
        return Err("Insufficient funds");
    }

    *first_guard -= amount;
    *second_guard += amount;
    Ok(())
}
```

### Solution to Exercise 2
```rust
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::{Arc, Mutex};
use std::thread;
use std::time::Instant;

fn bench_mutex_vs_atomic() {
    let iterations = 100_000;

    // Mutex Benchmark
    let mutex_counter = Arc::new(Mutex::new(0usize));
    let start = Instant::now();
    let mut handles = Vec::new();
    for _ in 0..4 {
        let c = Arc::clone(&mutex_counter);
        handles.push(thread::spawn(move || {
            for _ in 0..iterations {
                let mut guard = c.lock().unwrap();
                *guard += 1;
            }
        }));
    }
    for h in handles { h.join().unwrap(); }
    let mutex_time = start.elapsed();

    // Atomic Benchmark
    let atomic_counter = Arc::new(AtomicUsize::new(0));
    let start = Instant::now();
    let mut handles = Vec::new();
    for _ in 0..4 {
        let c = Arc::clone(&atomic_counter);
        handles.push(thread::spawn(move || {
            for _ in 0..iterations {
                c.fetch_add(1, Ordering::Relaxed);
            }
        }));
    }
    for h in handles { h.join().unwrap(); }
    let atomic_time = start.elapsed();

    println!("Mutex time : {:?}", mutex_time);
    println!("Atomic time: {:?}", atomic_time);
    assert!(atomic_time < mutex_time);
}
```

### Solution to Exercise 3
```rust
use std::collections::HashMap;
use std::sync::RwLock;

pub struct RoutingTable {
    routes: RwLock<HashMap<String, String>>,
}

impl RoutingTable {
    pub fn new() -> Self {
        RoutingTable {
            routes: RwLock::new(HashMap::new()),
        }
    }

    pub fn add_route(&self, path: &str, target: &str) {
        let mut write_guard = self.routes.write().unwrap();
        write_guard.insert(path.to_string(), target.to_string());
    }

    pub fn resolve(&self, path: &str) -> Option<String> {
        let read_guard = self.routes.read().unwrap();
        read_guard.get(path).cloned()
    }
}

fn main() {
    let acc1 = Account { id: 1, balance: Mutex::new(1000) };
    let acc2 = Account { id: 2, balance: Mutex::new(500) };
    assert_eq!(transfer(&acc1, &acc2, 200), Ok(()));
    assert_eq!(*acc1.balance.lock().unwrap(), 800);
    assert_eq!(*acc2.balance.lock().unwrap(), 700);

    bench_mutex_vs_atomic();

    let router = RoutingTable::new();
    router.add_route("/api/v1/login", "auth-service:8080");
    assert_eq!(router.resolve("/api/v1/login"), Some("auth-service:8080".to_string()));
    println!("All concurrency exercises verified successfully!");
}
```
