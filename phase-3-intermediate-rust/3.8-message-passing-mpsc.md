## Concept

While shared-state concurrency (using `Mutex` and `RwLock`) synchronizes access to shared memory, Rust also supports **Message-Passing Concurrency**, guided by the famous philosophy:
> *"Do not communicate by sharing memory; instead, share memory by communicating."*

In message passing, threads communicate by sending data through a **Channel**. When a thread sends a message, it transfers ownership of the data, guaranteeing that only the receiver can access it and eliminating data races by design.

---

### 1. `mpsc` Architecture: Multi-Producer, Single-Consumer

Rust's standard library provides the `std::sync::mpsc` module:

```
Sender 1 (Thread 1) ──┐
                      ▼
Sender 2 (Thread 2) ──► [=== Thread-Safe Message Buffer ===] ──► Receiver (Worker Thread)
                      ▲
Sender 3 (Thread 3) ──┘
```

- **Multiple Producers (`Sender<T>`)**: You can create multiple senders by calling `tx.clone()`.
- **Single Consumer (`Receiver<T>`)**: There is exactly one receiver endpoint that drains messages.

---

### 2. Unbounded vs. Bounded Channels (Backpressure)

#### A. Asynchronous / Unbounded (`mpsc::channel()`)
- Has an unlimited buffer.
- `tx.send(val)` **never blocks** and succeeds instantly.
- **Risk**: If the producer creates messages faster than the consumer can process them, the buffer grows indefinitely until the process crashes from Out-Of-Memory (OOM).

#### B. Synchronous / Bounded (`mpsc::sync_channel(bound)`)
- Has a fixed capacity (e.g. `bound = 100`).
- When the buffer is full, `tx.send(val)` **blocks (sleeps the producer thread)** until space is freed by the consumer.
- **Advantage**: Provides automatic **Backpressure**, preventing fast producers from overwhelming slow consumers.

---

### 3. Channel Closing and Iteration

- **`rx.recv()`**: Blocks until a message is received or **all senders are dropped** (returns `Err(RecvError)`).
- **`rx.try_recv()`**: Non-blocking check; returns `Ok(T)`, `Err(Empty)`, or `Err(Disconnected)`.
- **Iterating a Receiver**: `for msg in rx` automatically loops, receiving messages until every `Sender` is dropped, then cleanly exits.

---

## Why it matters

- **Thread Pool Task Schedulers**: Worker threads in web servers (e.g., Actix, Hyper) poll a shared receiver for incoming HTTP connection jobs.
- **Data Ingestion Pipelines**: Multi-stage processing pipelines (Capture $\to$ Parse $\to$ Normalize $\to$ Store) communicate between pipeline stages via bounded channels.
- **Graceful Shutdown**: Sending a `Shutdown` enum command through a channel instructs background worker threads to flush buffers and cleanly terminate.

---

## Analogy

Think of a **Mail Chute in a High-Rise Apartment**:
- Multiple tenants on different floors drop letters into the chute (`Senders`).
- The letters travel down into a single secure collection bin in the mailroom (`Receiver`).
- When the postal worker drains the bin, each letter is delivered to its destination without tenants ever bumping into each other in the hallway.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

// 1. Define Typed Job Protocol
#[derive(Debug)]
pub enum WorkerJob {
    ProcessTask { id: u32, payload: String },
    Flush,
    Terminate,
}

fn main() {
    // Create a bounded synchronous channel (capacity = 4)
    let (tx, rx) = mpsc::sync_channel::<WorkerJob>(4);

    // Spawn a dedicated background Consumer Worker thread
    let worker_handle = thread::spawn(move || {
        println!("[Worker] Background processing thread started.");

        // Iterate over incoming jobs until channel disconnects or Terminate is received
        while let Ok(job) = rx.recv() {
            match job {
                WorkerJob::ProcessTask { id, payload } => {
                    println!("[Worker] Processing Task #{}: {}", id, payload);
                    thread::sleep(Duration::from_millis(50)); // Simulate work
                }
                WorkerJob::Flush => {
                    println!("[Worker] Flushed pending disk writes.");
                }
                WorkerJob::Terminate => {
                    println!("[Worker] Received termination signal. Shutting down.");
                    break;
                }
            }
        }

        println!("[Worker] Background thread exited cleanly.");
    });

    // Spawn 2 Producer threads
    let mut producer_handles = Vec::new();

    for producer_id in 1..=2 {
        let tx_clone = tx.clone();
        let handle = thread::spawn(move || {
            for task_id in 1..=3 {
                let job = WorkerJob::ProcessTask {
                    id: producer_id * 10 + task_id,
                    payload: format!("Payload from producer {}", producer_id),
                };
                println!("[Producer {}] Sending Task", producer_id);
                tx_clone.send(job).unwrap();
            }
        });
        producer_handles.push(handle);
    }

    // Wait for producers to finish sending tasks
    for handle in producer_handles {
        handle.join().unwrap();
    }

    // Main thread sends Flush and Terminate
    tx.send(WorkerJob::Flush).unwrap();
    tx.send(WorkerJob::Terminate).unwrap();

    // Drop main thread's sender so receiver can disconnect if needed
    drop(tx);

    worker_handle.join().unwrap();
    println!("Pipeline completed successfully.");
}
```

## Common Mistakes

### 1. Forgetting to Drop the Original Main Thread `Sender`
When cloning senders into child threads, if the original `tx` in the main thread is never dropped or moved, `rx.recv()` in a `for msg in rx` loop will hang forever waiting for more messages.

```rust
let (tx, rx) = mpsc::channel();
for _ in 0..3 {
    let tx_clone = tx.clone();
    thread::spawn(move || { tx_clone.send(1).unwrap(); });
}
// ❌ HANGS FOREVER: The original `tx` is still alive on the main thread!
for val in rx { println!("{}", val); }

// ✅ CORRECT: Drop main tx before draining
drop(tx);
for val in rx { println!("{}", val); }
```

---

### 2. Using Unbounded Channels Without Backpressure
If producers ingest network packets at 100,000/sec while consumers write to disk at 10,000/sec, an unbounded `mpsc::channel()` will consume all system RAM and crash. Always use `mpsc::sync_channel(bound)` for production pipelines.

---

### 3. Attempting to Clone the Receiver
`mpsc` stands for **Multi-Producer, Single-Consumer**. Rust's standard library receiver cannot be cloned. If you need multiple consumers reading from the same channel, wrap `rx` in `Arc<Mutex<Receiver<T>>>` or use the `crossbeam-channel` crate.

## Exercises

### Exercise 1 (Multi-Stage Data Pipeline)
Build a 3-stage pipeline connected by two channels:
1. **Stage 1 (Generator)**: Produces integers `1..=10` into Channel A.
2. **Stage 2 (Transformer)**: Reads from Channel A, squares each number ($x^2$), and sends to Channel B.
3. **Stage 3 (Consumer)**: Reads from Channel B and calculates the total sum.

---

### Exercise 2 (Request-Response Pattern / Actor Model)
Create a request struct that contains a one-shot response sender:
```rust
pub struct Request {
    pub value: u32,
    pub response_tx: mpsc::Sender<u32>,
}
```
Spawn a server thread that processes requests by multiplying `value * 10` and sending the result back along `response_tx`. Send 3 requests from the main thread and assert the responses.

---

### Exercise 3 (Non-Blocking Poller with `try_recv`)
Write a receiver polling loop that checks for incoming messages using `try_recv()`, performs background work when the channel is empty, and terminates when the channel disconnects.

## Solutions

### Solution to Exercise 1
```rust
use std::sync::mpsc;
use std::thread;

fn run_pipeline() -> i32 {
    let (tx_a, rx_a) = mpsc::sync_channel::<i32>(4);
    let (tx_b, rx_b) = mpsc::sync_channel::<i32>(4);

    // Stage 1: Generator
    thread::spawn(move || {
        for i in 1..=10 {
            tx_a.send(i).unwrap();
        }
    });

    // Stage 2: Transformer
    thread::spawn(move || {
        for val in rx_a {
            tx_b.send(val * val).unwrap();
        }
    });

    // Stage 3: Consumer
    let mut total = 0;
    for squared in rx_b {
        total += squared;
    }
    total
}
```

### Solution to Exercise 2
```rust
use std::sync::mpsc;
use std::thread;

pub struct Request {
    pub value: u32,
    pub response_tx: mpsc::Sender<u32>,
}

fn test_request_response() {
    let (server_tx, server_rx) = mpsc::channel::<Request>();

    thread::spawn(move || {
        while let Ok(req) = server_rx.recv() {
            let res = req.value * 10;
            let _ = req.response_tx.send(res);
        }
    });

    // Client requests
    for val in [5, 12, 30] {
        let (resp_tx, resp_rx) = mpsc::channel();
        server_tx.send(Request { value: val, response_tx: resp_tx }).unwrap();
        let result = resp_rx.recv().unwrap();
        assert_eq!(result, val * 10);
    }
}
```

### Solution to Exercise 3
```rust
use std::sync::mpsc::{self, TryRecvError};
use std::thread;
use std::time::Duration;

fn poll_channel() {
    let (tx, rx) = mpsc::channel();
    thread::spawn(move || {
        thread::sleep(Duration::from_millis(50));
        tx.send("Task Complete").unwrap();
    });

    loop {
        match rx.try_recv() {
            Ok(msg) => {
                println!("Received: {}", msg);
                break;
            }
            Err(TryRecvError::Empty) => {
                // Do other useful work while waiting
                thread::sleep(Duration::from_millis(10));
            }
            Err(TryRecvError::Disconnected) => break,
        }
    }
}

fn main() {
    let sum = run_pipeline();
    println!("Pipeline sum of squares (1..=10): {}", sum);
    assert_eq!(sum, 385);

    test_request_response();
    poll_channel();
    println!("All channel exercises passed!");
}
```
