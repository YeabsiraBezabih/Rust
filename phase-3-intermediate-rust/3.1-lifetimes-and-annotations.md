## Concept

Every reference in Rust has a **lifetime** — the exact span of code during which the referenced data is guaranteed to reside safely in memory.

Rust's **Borrow Checker** analyzes these lifetimes at compile time to ensure no reference ever points to deallocated or invalid memory (preventing **Dangling Pointers** and **Use-After-Free** bugs without a Garbage Collector).

```
Scope of 'a (Data owner):  { let data = String::from("packet"); ──┐
Scope of 'b (Borrower):      { let ref_b = &data;                 │
                               println!("{}", ref_b);             │
                             } ───────────────────────────────────┼── Valid! 'b is strictly inside 'a
                           } ◄────────────────────────────────────┘
```

---

### 1. Why Explicit Lifetime Annotations Exist

Inside a single function body, the compiler infers all lifetimes automatically. However, when functions receive and return references, the compiler cannot know which input reference the output reference is connected to without your help:

```rust
// Which input parameter does the returned reference borrow from?
// Is it 'x' or 'y'?
fn longest(x: &str, y: &str) -> &str { ... }
```

**Lifetime annotations do not change how long a value lives.** Instead, they declare the **contractual relationship** between lifetimes so the compiler can prove safety across call sites.

---

### 2. Lifetime Syntax in Functions

Generic lifetimes begin with an apostrophe (`'a`):

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

#### What does `'a` mean here?
The returned reference will be valid for the **overlap (intersection)** of the lifetimes of `x` and `y`. If `x` lives for 10 lines and `y` lives for 5 lines, the returned reference can only be used for at most 5 lines.

---

### 3. The Three Lifetime Elision Rules

You don't have to write `'a` everywhere because the Rust compiler automatically applies three deterministic **Elision Rules**:

1. **Rule 1**: Each parameter that is a reference gets its own distinct lifetime parameter:
   `fn parse(s: &str)` becomes `fn parse<'a>(s: &'a str)`.
2. **Rule 2**: If there is exactly **one input lifetime**, that lifetime is automatically assigned to all output references:
   `fn first_word(s: &str) -> &str` becomes `fn first_word<'a>(s: &'a str) -> &'a str`.
3. **Rule 3**: If there are multiple input lifetimes, but one of them is `&self` or `&mut self`, the lifetime of `self` is assigned to all output references.

If a function has multiple input references and returns a reference without `&self`, Rule 2 and 3 do not apply, and explicit annotations are required.

---

### 4. Structs Holding References

If a `struct` stores a borrowed reference, you must declare a generic lifetime parameter on the struct:

```rust
struct LogEntry<'a> {
    level: &'a str,
    message: &'a str,
}
```
**Invariant**: An instance of `LogEntry<'a>` cannot outlive the underlying strings it references.

---

### 5. The `'static` Lifetime

The `'static` lifetime means the referenced data is stored in the program's read-only binary text/data segment and is valid for the **entire duration of the program execution**:
- String literals: `let s: &'static str = "hello";`
- Leaked heap memory: `Box::leak(boxed_data)`.

---

## Why it matters

- **Zero-Copy Parsers**: High-performance network proxies (e.g., NGINX, Envoy, Cloudflare Workers) parse gigabytes of HTTP headers without allocating heap strings by borrowing directly from incoming TCP socket buffers.
- **Zero Garbage Collection Overhead**: Lifetimes allow safe sharing of memory across threads and functions with zero runtime CPU cost or reference counting overhead.

---

## Analogy

Think of a **Visitor Badge at a High-Security Facility**:
- When you enter building $A$, you are handed a visitor badge with an expiration timestamp (`'a`).
- You can freely pass through rooms inside building $A$.
- But you cannot take that badge into building $B$ after building $A$ closes, because your badge's lifetime is bound to the lifespan of building $A$.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
// Zero-Copy Log Parser: Borrows slices from raw log strings with zero heap allocations!
#[derive(Debug)]
pub struct ZeroCopyLogParser<'a> {
    raw_log: &'a str,
}

#[derive(Debug, PartialEq, Eq)]
pub struct ParsedLog<'a> {
    pub timestamp: &'a str,
    pub level: &'a str,
    pub message: &'a str,
}

impl<'a> ZeroCopyLogParser<'a> {
    pub fn new(raw_log: &'a str) -> Self {
        ZeroCopyLogParser { raw_log }
    }

    // Parses a single line format: "[TIMESTAMP] [LEVEL] MESSAGE"
    pub fn parse_line(&self, line: &'a str) -> Option<ParsedLog<'a>> {
        let trimmed = line.trim();
        if !trimmed.starts_with('[') {
            return None;
        }

        // Find first closing bracket for timestamp
        let ts_end = trimmed.find(']')?;
        let timestamp = &trimmed[1..ts_end];

        let remainder = trimmed[ts_end + 1..].trim_start();
        if !remainder.starts_with('[') {
            return None;
        }

        // Find second closing bracket for log level
        let lvl_end = remainder.find(']')?;
        let level = &remainder[1..lvl_end];

        let message = remainder[lvl_end + 1..].trim_start();

        Some(ParsedLog {
            timestamp,
            level,
            message,
        })
    }
}

// Function demonstrating two distinct input lifetimes
fn select_longer_message<'a, 'b>(log1: &'a ParsedLog<'a>, log2: &'b ParsedLog<'b>) -> &'a str
where
    'b: 'a, // 'b outlives or equals 'a
{
    if log1.message.len() >= log2.message.len() {
        log1.message
    } else {
        log2.message
    }
}

fn main() {
    let raw_syslog = "\
    [2026-09-04T08:00:00Z] [INFO] Connection established on port 8080\n\
    [2026-09-04T08:00:01Z] [ERROR] TLS handshake failure from 192.168.1.50\n\
    [2026-09-04T08:00:02Z] [WARN] High memory pressure detected\
    ";

    let parser = ZeroCopyLogParser::new(raw_syslog);

    let mut logs = Vec::new();
    for line in raw_syslog.lines() {
        if let Some(parsed) = parser.parse_line(line) {
            println!("Parsed -> Level: {:<5} | Time: {} | Msg: {}", 
                parsed.level, parsed.timestamp, parsed.message);
            logs.push(parsed);
        }
    }

    assert_eq!(logs.len(), 3);
    assert_eq!(logs[1].level, "ERROR");
    assert_eq!(logs[1].message, "TLS handshake failure from 192.168.1.50");

    let longer = select_longer_message(&logs[0], &logs[1]);
    println!("\nLonger message between first two: \"{}\"", longer);
}
```

## Common Mistakes

### 1. Returning a Reference to a Local Stack Variable
Attempting to return a reference to a variable created inside the function:
```rust
// ❌ COMPILE ERROR: returns a reference to data owned by the current function
fn build_header() -> &str {
    let s = String::from("Content-Type: application/json");
    &s // `s` is dropped at end of function! Dangling pointer!
}

// ✅ CORRECT: Return owned `String` or accept a buffer from the caller
fn build_header() -> String {
    String::from("Content-Type: application/json")
}
```

---

### 2. Silencing Compiler Errors with `'static`
Adding `'static` to a reference to bypass borrow errors without understanding its implications:
```rust
// ❌ BAD PRACTICE: Demands that the referenced string lives forever in binary memory
fn process_text(text: &'static str) { ... }
```
This prevents callers from passing temporary `String` references, forcing unnecessary heap leakage.

---

### 3. Conflating Struct Lifetime with Internal Reference Lifetime
Assuming that if a struct is dropped, the data it borrowed is also dropped. A struct holding `&'a str` does **not own** the string; dropping the struct leaves the original string intact.

## Solutions

### Solution to Exercise 1
```rust
pub fn split_csv_header<'a>(header_line: &'a str) -> Vec<&'a str> {
    header_line
        .split(',')
        .map(|col| col.trim())
        .collect()
}
```

---

### Solution to Exercise 2
```rust
#[derive(Debug, PartialEq, Eq)]
pub struct QueryParam<'a> {
    pub key: &'a str,
    pub value: &'a str,
}

pub fn parse_query_string<'a>(query: &'a str) -> Vec<QueryParam<'a>> {
    let mut params = Vec::new();
    for pair in query.split('&') {
        if let Some((k, v)) = pair.split_once('=') {
            params.push(QueryParam {
                key: k.trim(),
                value: v.trim(),
            });
        }
    }
    params
}
```

---

### Solution to Exercise 3
```rust
pub struct DualSource<'a, 'b> {
    pub host: &'a str,
    pub path: &'b str,
}

impl<'a, 'b> DualSource<'a, 'b> {
    pub fn new(host: &'a str, path: &'b str) -> Self {
        DualSource { host, path }
    }

    pub fn format_summary(&self) -> String {
        format!("https://{}/{}", self.host, self.path)
    }
}

fn main() {
    let headers = split_csv_header(" id , username , email , role ");
    assert_eq!(headers, vec!["id", "username", "email", "role"]);

    let query = "user=alice&role=admin";
    let params = parse_query_string(query);
    assert_eq!(params.len(), 2);
    assert_eq!(params[0], QueryParam { key: "user", value: "alice" });

    let host_string = String::from("api.example.com");
    {
        let path_literal = "v1/users";
        let dual = DualSource::new(&host_string, path_literal);
        assert_eq!(dual.format_summary(), "https://api.example.com/v1/users");
    }

    println!("All lifetime exercises verified successfully!");
}
```
