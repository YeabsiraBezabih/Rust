## Concept

In production systems, bad error handling leads to silent failures, uninformative log messages ("something went wrong"), and hard-to-diagnose outages.

Production Rust divides error handling into two distinct domains:
1. **Library Errors (Domain-Specific & Strongly Typed)**: Callers need structured enums so they can programmatically inspect, retry, or handle specific failure variants (powered by **`thiserror`**).
2. **Application Errors (Context-Rich & Actionable)**: Top-level binaries need human-readable error chains showing what failed, why it failed, and the full causal stack (powered by **`anyhow`**).

```
Application Layer (anyhow):
  "Failed to initialize server"
    └──► "Failed to load database config from /etc/app.toml"
           └──► Library Layer (thiserror):
                  "Disk read error: Permission Denied (os error 13)"
```

---

### 1. The Standard `Error` Trait and Causal Chaining

The standard library `std::error::Error` trait defines:
```rust
pub trait Error: Debug + Display {
    fn source(&self) -> Option<&(dyn Error + 'static)> { None }
}
```
The `.source()` method allows errors to form a linked list of causes, enabling diagnostic tools to print the full root-cause tree.

---

### 2. Structured Domain Errors with `thiserror`

In library crates, `thiserror` provides lightweight derive macros that automatically implement `Display`, `Error`, and `From` without boilerplate:

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum DatabaseError {
    #[error("Connection timed out after {timeout_ms}ms")]
    Timeout { timeout_ms: u64 },

    #[error("Authentication failed for user '{username}'")]
    AuthFailed { username: String },

    #[error("Underlying I/O error")]
    Io(#[from] std::io::Error), // Automatically implements From<std::io::Error>
}
```

---

### 3. Context-Driven Application Errors with `anyhow`

In application entrypoints (`main.rs`, CLI binaries, request handlers), `anyhow` allows attaching conversational context as errors bubble up:

```rust
use anyhow::{Context, Result};

fn load_server_config(path: &str) -> Result<Config> {
    let content = std::fs::read_to_string(path)
        .with_context(|| format!("Failed to read config file at '{}'", path))?;
    let config: Config = toml::from_str(&content)
        .context("Syntax error in TOML configuration")?;
    Ok(config)
}
```

---

### 4. Panics, Panic Hooks, and Resilience

A `panic!` represents an unrecoverable bug (e.g. index out of bounds). In production:
- **`std::panic::set_hook`**: Intercepts panics to log structured JSON telemetry, flush metrics, and print thread backtraces before exiting.
- **`std::panic::catch_unwind`**: Wraps dangerous operations (e.g. executing untrusted WASM plugins or isolated HTTP requests) to prevent a localized crash from terminating the entire server process.

---

## Why it matters

- **Faster Mean-Time-To-Resolution (MTTR)**: Instead of a cryptic `500 Internal Server Error`, operators see the exact causal chain: `Checkout failed -> Payment Gateway 402 -> Insufficient Funds on card ending in 4242`.
- **Zero Overhead**: `Result<T, E>` in Rust uses value return registers rather than heavy stack-unwinding exceptions used in Java/C++.

---

## Analogy

Think of an **Aviation Incident Report**:
- A generic error is like saying "the plane didn't arrive."
- A production error chain is the black box recording: "Flight delayed $\to$ Navigation subsystem rebooted $\to$ Sensor 4 lost power $\to$ Fuse 12 blew due to overvoltage."

## Code Example

Add `thiserror` and `anyhow` to `Cargo.toml`:
```toml
[dependencies]
thiserror = "1"
anyhow = "1"
```

Save this to `src/main.rs` and run `cargo run`:

```rust
use anyhow::{Context, Result};
use std::fs::File;
use std::io::Read;
use std::panic;
use thiserror::Error;

// 1. Library Domain Errors (Strongly Typed via thiserror)
#[derive(Error, Debug)]
pub enum ConfigError {
    #[error("Configuration file missing: {path}")]
    FileNotFound { path: String },

    #[error("Invalid port number: {port} (must be between 1 and 65535)")]
    InvalidPort { port: i32 },

    #[error("I/O error reading configuration")]
    Io(#[from] std::io::Error),
}

#[derive(Debug)]
pub struct ServerConfig {
    pub host: String,
    pub port: u16,
}

// Low-level function returning specific domain error
fn parse_config_file(path: &str) -> std::result::Result<ServerConfig, ConfigError> {
    if !std::path::Path::new(path).exists() {
        return Err(ConfigError::FileNotFound {
            path: path.to_string(),
        });
    }

    let mut file = File::open(path)?;
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;

    // Simulated parser
    let port = 90000; // Invalid port
    if !(1..=65535).contains(&port) {
        return Err(ConfigError::InvalidPort { port });
    }

    Ok(ServerConfig {
        host: "127.0.0.1".into(),
        port: port as u16,
    })
}

// 2. High-Level Application Service (Context Enrichment via anyhow)
fn initialize_app() -> Result<ServerConfig> {
    let config_path = "/etc/custom_app.conf";
    let config = parse_config_file(config_path)
        .with_context(|| format!("Application bootstrapping failed for config '{}'", config_path))?;
    Ok(config)
}

fn main() {
    // 3. Set a structured JSON Panic Hook for production observability
    panic::set_hook(Box::new(|panic_info| {
        eprintln!(
            r#"{{"level":"FATAL","message":"Process panicked!","payload":"{}"}}"#,
            panic_info
        );
    }));

    // Test error propagation with rich context
    println!("--- Testing Application Initialization ---");
    match initialize_app() {
        Ok(cfg) => println!("Server running: {:?}", cfg),
        Err(err) => {
            eprintln!("Error Encountered: {}", err);
            eprintln!("\nFull Error Cause Chain:");
            for (idx, cause) in err.chain().enumerate() {
                eprintln!("  [{}] {}", idx, cause);
            }
        }
    }

    // 4. Safe Panic Isolation via catch_unwind
    println!("\n--- Testing Panic Isolation ---");
    let safe_result = panic::catch_unwind(|| {
        println!("Inside isolated plugin execution...");
        // Simulating a panic in a sandboxed handler
        panic!("Plugin crashed due to division by zero!");
    });

    if safe_result.is_err() {
        println!("Caught plugin panic safely! Server continues running without crashing.");
    }
}
```

## Common Mistakes

### 1. Discarding Underlying Error Causes
Writing `.map_err(|_| "Failed")` throws away the original OS error code (e.g. Permission Denied vs. Out of Disk Space vs. Network Refused), making debugging impossible.

---

### 2. Exposing `anyhow::Result` in Public Library APIs
Using `anyhow` in a library crate forces consumers to parse strings to understand why a function failed. Always expose typed `thiserror` enums from library crates, and reserve `anyhow` for top-level binaries and application business logic.

---

### 3. Relying on `catch_unwind` for Regular Control Flow
`catch_unwind` has high runtime overhead when a panic occurs and fails if the binary is compiled with `panic = "abort"`. Use `Result<T, E>` for expected runtime failures.

## Solutions

### Solution to Exercise 1
```rust
use thiserror::Error;

#[derive(Error, Debug, PartialEq)]
pub enum PaymentError {
    #[error("Insufficient funds: balance is ${balance}, but ${required} is required")]
    InsufficientFunds { balance: u64, required: u64 },

    #[error("Card expired on {expiry_month}/{expiry_year}")]
    CardExpired { expiry_month: u8, expiry_year: u16 },
}

fn test_payment_error() {
    let err = PaymentError::InsufficientFunds { balance: 50, required: 100 };
    assert_eq!(
        err.to_string(),
        "Insufficient funds: balance is $50, but $100 is required"
    );
}
```

---

### Solution to Exercise 2
```rust
use anyhow::{Context, Result, bail};

fn query_database(query: &str) -> Result<String> {
    bail!("Connection pool exhausted (max 50 active connections)");
}

fn fetch_user_record(uid: u64) -> Result<String> {
    query_database(&format!("SELECT * FROM users WHERE id = {}", uid))
        .with_context(|| format!("Failed to query DB for user ID {}", uid))
}

fn load_user_profile(uid: u64) -> Result<String> {
    fetch_user_record(uid)
        .with_context(|| "Failed in user profile service pipeline")
}
```

### Solution to Exercise 3
```rust
use anyhow::{Context, Result};

pub fn safe_parse_integer(input: &str, line_num: usize) -> Result<i64> {
    input
        .trim()
        .parse::<i64>()
        .with_context(|| format!("Invalid integer format '{}' at line {}", input, line_num))
}

fn main() {
    test_payment_error();

    let err = load_user_profile(999).unwrap_err();
    let causes: Vec<String> = err.chain().map(|c| c.to_string()).collect();
    assert_eq!(causes.len(), 3);
    println!("Root cause: {}", causes.last().unwrap());

    let parse_err = safe_parse_integer("42x", 15).unwrap_err();
    assert!(parse_err.to_string().contains("line 15"));
    println!("All advanced error handling exercises verified!");
}
```
