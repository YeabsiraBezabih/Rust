## Concept

When writing high-throughput network servers (handling 100,000+ simultaneous client connections), allocating one OS thread per connection fails because:
1. Each OS thread reserves a dedicated stack ($2\text{MB}$), consuming 200GB of RAM for 100,000 threads.
2. The operating system kernel spends excessive CPU cycles on thread context switching.

**Asynchronous Programming (Async Rust)** provides **Cooperative Multitasking**: lightweight user-space tasks (taking only a few hundred bytes each) multiplexed across a small pool of CPU worker threads.

---

### 1. The Pull-Based `Future` Trait

In languages like JavaScript or C#, async execution is *push-based* (callbacks fire automatically). In Rust, async execution is **pull-based**:
> **A `Future` in Rust does absolutely nothing unless it is polled!**

The foundation of async Rust is the `std::future::Future` trait:

```rust
pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),   // Operation complete, value produced
    Pending,    // Operation waiting on I/O or timer; will wake later
}
```

---

### 2. How the Async Event Loop Works: Reactor and Waker

```
1. Runtime Executor calls future.poll()
                 │
   Is I/O ready? ├──► YES ──► Returns Poll::Ready(data)
                 │
                 └──► NO  ──► Registers task `Waker` with OS epoll/kqueue
                              Returns Poll::Pending (Worker thread executes other tasks!)
                                         │
                 ┌───────────────────────┘
                 ▼
2. Network packet arrives on socket from OS kernel
                 │
3. OS Reactor triggers task `Waker`
                 │
4. Runtime Executor wakes and re-polls the specific future: future.poll() ──► Poll::Ready!
```

---

### 3. `async fn` and `.await`

- **`async fn`**: Syntactic sugar that instructs the compiler to transform the function into an anonymous **state machine** implementing `Future`.
- **`.await`**: Suspends the current async function if the inner future returns `Poll::Pending`, yielding execution back to the runtime.

---

### 4. Why `Pin` is Required

When an `async fn` yields at an `.await` point, local variables that borrow each other must be preserved across polls inside the generated state machine (a **self-referential struct**). 

If this struct were moved to a different location in memory, internal pointers would become invalid dangling references. **`Pin<&mut T>`** guarantees that the memory address of the future will remain fixed until it is dropped.

---

### 5. The Tokio Runtime Architecture

Rust's standard library does not bundle an async runtime. Instead, the industry-standard runtime is **Tokio**:
- **`#[tokio::main]`**: Initializes the multi-threaded work-stealing reactor and executor.
- **`tokio::spawn`**: Launches a background async task concurrently (equivalent to `thread::spawn`, but cost-free).
- **`tokio::select!`**: Awaits multiple async operations simultaneously, handling whichever finishes first.

---

## Why it matters

- **C10M Network Scale**: High-performance HTTP engines (e.g. Cloudflare Pingora, Discord backend, Actix-web) serve millions of concurrent requests using a handful of CPU cores.
- **Microsecond Latencies**: Eliminating OS thread blocking ensures that slow network clients cannot starve fast database queries.

---

## Analogy

- **Synchronous Threads**: A restaurant where every table gets its own dedicated waiter who stands frozen next to the table for 25 minutes while the kitchen prepares the meal.
- **Async Tasks**: A single waiter serving 20 tables. The waiter takes an order, submits it to the kitchen, and immediately takes orders from other tables. When the kitchen bell dings (the **Waker**), the waiter returns to deliver the hot plate.

## Code Example

Add `tokio` to `Cargo.toml`:
```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::future::Future;
use std::pin::Pin;
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Waker};
use std::thread;
use std::time::Duration;

// 1. Manual Implementation of a Future from Scratch: Custom Timer
pub struct SimpleTimerFuture {
    shared_state: Arc<Mutex<TimerState>>,
}

struct TimerState {
    completed: bool,
    waker: Option<Waker>,
}

impl SimpleTimerFuture {
    pub fn new(duration: Duration) -> Self {
        let state = Arc::new(Mutex::new(TimerState {
            completed: false,
            waker: None,
        }));

        let state_clone = Arc::clone(&state);
        thread::spawn(move || {
            thread::sleep(duration);
            let mut lock = state_clone.lock().unwrap();
            lock.completed = true;
            // Wake the executor to re-poll this future!
            if let Some(waker) = lock.waker.take() {
                waker.wake();
            }
        });

        SimpleTimerFuture { shared_state: state }
    }
}

impl Future for SimpleTimerFuture {
    type Output = &'static str;

    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output> {
        let mut lock = self.shared_state.lock().unwrap();
        if lock.completed {
            Poll::Ready("Timer elapsed successfully!")
        } else {
            // Save the current waker so the background thread can notify when done
            lock.waker = Some(cx.waker().clone());
            Poll::Pending
        }
    }
}

// 2. High-Level Async Application with Tokio
async fn fetch_user_profile(user_id: u64) -> String {
    tokio::time::sleep(Duration::from_millis(50)).await; // Non-blocking async sleep
    format!("UserProfile(ID: {})", user_id)
}

async fn fetch_user_orders(user_id: u64) -> Vec<String> {
    tokio::time::sleep(Duration::from_millis(80)).await;
    vec![format!("Order-101 for User {}", user_id)]
}

#[tokio::main]
async fn main() {
    println!("--- Testing Custom Future ---");
    let timer = SimpleTimerFuture::new(Duration::from_millis(100));
    let timer_result = timer.await;
    println!("Custom Future Result: {}", timer_result);

    println!("\n--- Testing Concurrent Async Tasks ---");
    // Run two network fetches concurrently using join!
    let (profile, orders) = tokio::join!(
        fetch_user_profile(42),
        fetch_user_orders(42)
    );

    println!("Fetched: {}", profile);
    println!("Fetched: {:?}", orders);

    // Using select! for race/timeout conditions
    tokio::select! {
        _ = tokio::time::sleep(Duration::from_millis(200)) => {
            println!("Operation completed within timeout window.");
        }
        _ = tokio::time::sleep(Duration::from_millis(500)) => {
            println!("Timed out!");
        }
    }
}
```

## Common Mistakes

### 1. Calling Blocking Code Inside Async Functions
Calling `std::thread::sleep` or standard library synchronous file/socket I/O inside an `async fn`:
```rust
// ❌ DISASTROUS: Freezes the entire Tokio worker thread, blocking thousands of other tasks!
async fn handle_request() {
    std::thread::sleep(Duration::from_secs(5));
}

// ✅ CORRECT: Use non-blocking async primitives
async fn handle_request() {
    tokio::time::sleep(Duration::from_secs(5)).await;
}
```

---

### 2. Forgetting that Futures Are Lazy
```rust
async fn log_metric() { println!("Metric sent"); }

fn main() {
    // ❌ WARNING: Future does nothing because it is never .awaited or spawned!
    let _ = log_metric();
}
```

---

### 3. Holding a Standard `std::sync::MutexGuard` Across `.await`
A standard `MutexGuard` does not implement `Send` across await points and can cause thread deadlocks if another task on the same thread tries to lock it. Use `tokio::sync::Mutex` when a lock must be held across `.await` points.

## Solutions

### Solution to Exercise 1
```rust
use std::time::Duration;

pub async fn aggregate_metrics(endpoints: &[String]) -> Vec<(String, u64)> {
    let mut handles = Vec::new();

    for ep in endpoints {
        let endpoint_name = ep.clone();
        let handle = tokio::spawn(async move {
            tokio::time::sleep(Duration::from_millis(20)).await;
            (endpoint_name, 100u64)
        });
        handles.push(handle);
    }

    let mut results = Vec::new();
    for handle in handles {
        if let Ok(res) = handle.await {
            results.push(res);
        }
    }
    results
}
```

### Solution to Exercise 2
```rust
use std::future::Future;
use std::time::Duration;

pub async fn with_timeout<F, T>(fut: F, timeout_duration: Duration) -> Result<T, &'static str>
where
    F: Future<Output = T>,
{
    tokio::select! {
        res = fut => Ok(res),
        _ = tokio::time::sleep(timeout_duration) => Err("Operation timed out"),
    }
}
```

### Solution to Exercise 3
```rust
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::time::Duration;

pub struct TokenBucketRateLimiter {
    tokens: Arc<AtomicUsize>,
    max_tokens: usize,
}

impl TokenBucketRateLimiter {
    pub fn new(max_tokens: usize, refill_interval: Duration) -> Self {
        let tokens = Arc::new(AtomicUsize::new(max_tokens));
        let tokens_clone = Arc::clone(&tokens);

        // Background refill task
        tokio::spawn(async move {
            let mut interval = tokio::time::interval(refill_interval);
            loop {
                interval.tick().await;
                tokens_clone.store(max_tokens, Ordering::Relaxed);
            }
        });

        TokenBucketRateLimiter { tokens, max_tokens }
    }

    pub async fn acquire(&self) {
        loop {
            let curr = self.tokens.load(Ordering::Relaxed);
            if curr > 0 {
                if self.tokens.compare_exchange(curr, curr - 1, Ordering::SeqCst, Ordering::Relaxed).is_ok() {
                    return;
                }
            }
            tokio::time::sleep(Duration::from_millis(10)).await;
        }
    }
}

#[tokio::main]
async fn main() {
    let endpoints = vec!["api.srv1.internal".into(), "api.srv2.internal".into()];
    let res = aggregate_metrics(&endpoints).await;
    assert_eq!(res.len(), 2);

    let fast_task = async { 42 };
    let timed_res = with_timeout(fast_task, Duration::from_millis(100)).await;
    assert_eq!(timed_res, Ok(42));

    let slow_task = async {
        tokio::time::sleep(Duration::from_millis(200)).await;
        99
    };
    let timeout_res = with_timeout(slow_task, Duration::from_millis(50)).await;
    assert_eq!(timeout_res, Err("Operation timed out"));

    println!("All async exercises verified successfully!");
}
```
