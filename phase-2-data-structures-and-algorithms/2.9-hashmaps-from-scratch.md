## Concept

A **Hash Map** (or Hash Table) is an associative key-value data structure that provides average **$O(1)$ constant time** for insertions, lookups, and deletions.

It achieves this by converting arbitrary keys (strings, structs, numbers) into an array index using a **hash function**.

---

### 1. The Anatomy of a Hash Table

A hash map consists of an underlying contiguous array called **buckets**:

```
 Key: "alice" ──► [ Hash Function ] ──► Hash Code: 893149812 
                                               │
                                       % Capacity (8)
                                               │
                                               ▼
                                         Bucket Index: 4

 Bucket Array:
 [0] -> []
 [1] -> []
 [2] -> []
 [3] -> []
 [4] -> [ ("alice", 98) ]   <── Item stored at index 4!
 [5] -> []
 [6] -> []
 [7] -> []
```

---

### 2. Hash Collisions and Separate Chaining

Because there are infinitely more possible keys than array buckets (the **Pigeonhole Principle**), two distinct keys will eventually hash to the same bucket index. This is called a **Hash Collision**.

#### Collision Resolution Strategies:
1. **Separate Chaining (Used here)**: Each bucket contains a small list or vector of key-value pairs (`Vec<(K, V)>`). When collisions occur, both entries are appended to the bucket's list.
2. **Open Addressing (Linear Probing / Robin Hood Hashing)**: All entries live directly in the main array. If a bucket is occupied, the algorithm probes forward (`index + 1`, `index + 2`...) to find the next empty slot.

```
Collision Example in Separate Chaining:
"alice" -> Index 4
"clara" -> Index 4

Bucket [4]: [ ("alice", 98) ] ──► [ ("clara", 74) ]
```

---

### 3. Load Factor and Dynamic Resizing

The **Load Factor** ($\alpha$) measures how full the hash table is:
$$\alpha = \frac{\text{Total Key-Value Entries}}{\text{Total Bucket Capacity}}$$

- When $\alpha$ is low ($< 0.5$), buckets are mostly empty, lookups are nearly instantaneous ($1$ step).
- When $\alpha$ exceeds **$0.75$**, collision chains grow longer, degrading lookup performance towards $O(N)$.
- **Dynamic Resizing**: When $\alpha > 0.75$, the hash map doubles its capacity (e.g., $16 \to 32$), creates a new bucket table, and **re-hashes** all existing keys into the new table.

---

## Why it matters

- **Key-Value Stores**: Systems like Redis, Memcached, and in-memory caches rely on optimized hash tables to serve millions of operations per second with microsecond latencies.
- **Symbol Tables in Compilers**: When a compiler resolves variable and function names, it queries a hash map of identifiers.
- **Hardware Sympathy**: Understanding how hashing distributes memory across CPU cache lines enables writing high-throughput systems code.

---

## Analogy

Think of a **Coat Check at a Theater**:
- When you hand the attendant your coat, they give you a claim ticket with a number (the hash index).
- Your coat is hung on the hook matching that ticket number.
- When you return your ticket, the attendant walks straight to that exact hook in $O(1)$ time rather than checking every single coat in the building one by one.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::collections::hash_map::DefaultHasher;
use std::hash::{Hash, Hasher};

const INITIAL_CAPACITY: usize = 8;
const MAX_LOAD_FACTOR: f64 = 0.75;

#[derive(Debug)]
pub struct CustomHashMap<K, V> {
    buckets: Vec<Vec<(K, V)>>,
    num_entries: usize,
}

impl<K: Hash + Eq, V> CustomHashMap<K, V> {
    pub fn new() -> Self {
        let mut buckets = Vec::with_capacity(INITIAL_CAPACITY);
        for _ in 0..INITIAL_CAPACITY {
            buckets.push(Vec::new());
        }

        CustomHashMap {
            buckets,
            num_entries: 0,
        }
    }

    pub fn len(&self) -> usize {
        self.num_entries
    }

    pub fn is_empty(&self) -> bool {
        self.num_entries == 0
    }

    // Compute bucket index for a given key
    fn get_bucket_index(&self, key: &K, capacity: usize) -> usize {
        let mut hasher = DefaultHasher::new();
        key.hash(&mut hasher);
        (hasher.finish() as usize) % capacity
    }

    // Insert or update a key-value pair. Returns previous value if key existed.
    pub fn insert(&mut self, key: K, value: V) -> Option<V> {
        // Check load factor and resize if necessary
        if (self.num_entries + 1) as f64 / self.buckets.len() as f64 > MAX_LOAD_FACTOR {
            self.resize();
        }

        let idx = self.get_bucket_index(&key, self.buckets.len());
        let bucket = &mut self.buckets[idx];

        // If key already exists in bucket, update value
        for pair in bucket.iter_mut() {
            if pair.0 == key {
                return Some(std::mem::replace(&mut pair.1, value));
            }
        }

        // New key: append to bucket chain
        bucket.push((key, value));
        self.num_entries += 1;
        None
    }

    // Retrieve a shared reference to the value associated with key
    pub fn get(&self, key: &K) -> Option<&V> {
        let idx = self.get_bucket_index(key, self.buckets.len());
        let bucket = &self.buckets[idx];

        for pair in bucket {
            if &pair.0 == key {
                return Some(&pair.1);
            }
        }
        None
    }

    // Retrieve a mutable reference to the value associated with key
    pub fn get_mut(&mut self, key: &K) -> Option<&mut V> {
        let idx = self.get_bucket_index(key, self.buckets.len());
        let bucket = &mut self.buckets[idx];

        for pair in bucket.iter_mut() {
            if &pair.0 == key {
                return Some(&mut pair.1);
            }
        }
        None
    }

    // Remove an entry by key
    pub fn remove(&mut self, key: &K) -> Option<V> {
        let idx = self.get_bucket_index(key, self.buckets.len());
        let bucket = &mut self.buckets[idx];

        if let Some(pos) = bucket.iter().position(|pair| &pair.0 == key) {
            self.num_entries -= 1;
            Some(bucket.swap_remove(pos).1)
        } else {
            None
        }
    }

    // Double capacity and re-hash all existing elements
    fn resize(&mut self) {
        let new_capacity = self.buckets.len() * 2;
        let mut new_buckets = Vec::with_capacity(new_capacity);
        for _ in 0..new_capacity {
            new_buckets.push(Vec::new());
        }

        // Drain entries from old buckets and move into new buckets
        for mut old_bucket in self.buckets.drain(..) {
            for (k, v) in old_bucket.drain(..) {
                let new_idx = self.get_bucket_index(&k, new_capacity);
                new_buckets[new_idx].push((k, v));
            }
        }

        self.buckets = new_buckets;
    }
}

fn main() {
    let mut session_store = CustomHashMap::new();

    // Insert user sessions
    session_store.insert("sess_alpha", 1001);
    session_store.insert("sess_bravo", 1002);
    session_store.insert("sess_charlie", 1003);

    println!("Total sessions: {}", session_store.len());

    // Lookup session
    if let Some(uid) = session_store.get(&"sess_bravo") {
        println!("Found user ID for sess_bravo: {}", uid);
    }

    // Mutate session in place
    if let Some(uid) = session_store.get_mut(&"sess_bravo") {
        *uid = 9999;
    }
    println!("Updated user ID: {:?}", session_store.get(&"sess_bravo"));

    // Remove session
    let removed = session_store.remove(&"sess_alpha");
    println!("Removed: {:?}", removed);
    println!("Contains sess_alpha? {}", session_store.get(&"sess_alpha").is_some());
}
```

## Common Mistakes

### 1. Forgetting to Re-Hash on Resize
When capacity changes from $8$ to $16$, a key whose hash was `10` had index `10 % 8 = 2`. In the new table, its index must be `10 % 16 = 10`. Simply copying buckets without recalculating indices will render entries permanently lost.

---

### 2. Modifying a Key While Inside a Map
If a key is mutated after being inserted into a hash table, its hash value changes. The hash table will look for it in the new bucket and report that the key does not exist, creating a memory leak of "orphaned" entries.

---

### 3. Hash Denial of Service (HashDoS)
Using a deterministic, non-cryptographic hash function (like simple polynomial rolling hash) allows malicious HTTP clients to send crafted request payloads that all produce identical hash values. This turns an $O(1)$ server hash table into an $O(N)$ linked list, consuming 100% CPU. Rust's standard library `std::collections::HashMap` uses **SipHash 1-3** by default with randomized keys per-process to prevent HashDoS attacks.

    pub fn contains_key(&self, key: &K) -> bool {
        self.get(key).is_some()
    }

### Solution to Exercise 2
```rust
impl<K: Hash + Eq, V> CustomHashMap<K, V> {
    pub fn keys(&self) -> Vec<&K> {
        let mut keys_vec = Vec::with_capacity(self.num_entries);
        for bucket in &self.buckets {
            for pair in bucket {
                keys_vec.push(&pair.0);
            }
        }
        keys_vec
    }
}
```

---

### Solution to Exercise 3
```rust
impl<K: Hash + Eq, V> CustomHashMap<K, V> {
    pub fn get_or_insert_default<F>(&mut self, key: K, default_fn: F) -> &mut V
    where
        F: FnOnce() -> V,
    {
        if !self.contains_key(&key) {
            let val = default_fn();
            self.insert(key.clone(), val);
        }
        self.get_mut(&key).unwrap()
    }
}

fn main() {
    let mut word_counts: CustomHashMap<String, u32> = CustomHashMap::new();

    let word = "systems".to_string();
    let count = word_counts.get_or_insert_default(word.clone(), || 0);
    *count += 1;

    assert_eq!(word_counts.get(&"systems".to_string()), Some(&1));
    assert!(word_counts.contains_key(&"systems".to_string()));
    assert_eq!(word_counts.keys(), vec![&"systems".to_string()]);
    println!("All hash map exercise tests passed!");
}
```
