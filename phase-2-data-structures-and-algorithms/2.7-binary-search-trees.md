## Concept

A **Tree** is a non-linear, hierarchical data structure composed of nodes connected by directed edges. Unlike arrays and linked lists (which are linear sequences), trees represent branching relationships such as file systems, JSON documents, and database indexes.

```
                  [ 50 (Root) ]
                 /             \
        [ 30 (Left) ]       [ 70 (Right) ]
        /           \       /            \
     [ 20 ]       [ 40 ]  [ 60 ]        [ 80 ] (Leaves)
```

---

### 1. Tree Terminology

- **Root**: The topmost node with no parent (e.g., `50`).
- **Parent / Child**: An upper node connected to lower nodes directly below it (`50` is parent to `30` and `70`).
- **Leaf**: A node with no children (`20`, `40`, `60`, `80`).
- **Subtree**: Any node and all descendants beneath it.
- **Height**: The length of the longest path from the node down to a leaf. A tree with a single root has height 0.
- **Depth**: The number of edges from the root to the given node.

---

### 2. The Binary Search Tree (BST) Invariant

A **Binary Tree** is a tree where every node has **at most two children** (`left` and `right`).

A **Binary Search Tree (BST)** adds a strict ordering property (the **BST Invariant**):
> For every node with value $V$:
> 1. All values in its **left subtree** must be strictly **less than** $V$.
> 2. All values in its **right subtree** must be strictly **greater than** $V$.

This invariant guarantees that searching for an element eliminates half of the remaining tree at each comparison, yielding average time complexity of **$O(\log N)$**.

---

### 3. Tree Traversals

Visiting every node in a tree systematically is called **traversal**:

1. **In-Order Traversal** (`Left` $\to$ `Root` $\to$ `Right`):
   - Visits nodes in **strictly sorted ascending order**.
   - Output for above tree: `20, 30, 40, 50, 60, 70, 80`.
2. **Pre-Order Traversal** (`Root` $\to$ `Left` $\to$ `Right`):
   - Useful for serializing, cloning, or saving a tree structure to disk.
   - Output: `50, 30, 20, 40, 70, 60, 80`.
3. **Post-Order Traversal** (`Left` $\to$ `Right` $\to$ `Root`):
   - Useful for bottom-up computation (e.g., calculating subtree sizes or freeing resources).
   - Output: `20, 40, 30, 60, 80, 70, 50`.
4. **Level-Order (Breadth-First) Traversal**:
   - Visits nodes top-to-bottom, level by level using a queue.
   - Output: `50, 30, 70, 20, 40, 60, 80`.

---

### 4. Representation in Safe Rust

Because a tree node contains optional child nodes that are also heap-allocated, we use `Option<Box<Node<T>>>`:

```rust
struct Node<T> {
    value: T,
    left: Option<Box<Node<T>>>,
    right: Option<Box<Node<T>>>,
}

pub struct BinarySearchTree<T> {
    root: Option<Box<Node<T>>>,
    size: usize,
}
```

```
Stack: BinarySearchTree { root: ptr, size: 3 }
          │
Heap:     ▼
      ┌────────────────────────┐
      │ Node {                 │
      │   value: 50,           │
      │   left: ───► [Node 30] │
      │   right: ──► [Node 70] │
      │ }                      │
      └────────────────────────┘
```

## Why it matters

- **Database Indexes**: Databases like PostgreSQL and SQLite use balanced B-Trees (multi-way search trees) to execute SQL queries in $O(\log N)$ disk reads rather than scanning millions of rows.
- **Compilers and Interpreters**: Programming language source code is parsed into an Abstract Syntax Tree (AST), where expressions like `2 + 3 * 4` become tree nodes evaluated via post-order traversal.
- **`std::collections::BTreeMap`**: Rust's standard library provides `BTreeMap` and `BTreeSet`, offering $O(\log N)$ search, insert, and range queries.

---

## Analogy

Think of a **Binary Search Tree** as a well-organized file cabinet with labelled dividers. When searching for "Invoice #500":
- You look at the drawer midpoint (labeled `#400`).
- Because $500 > 400$, you immediately ignore the entire left half of the cabinet and open the right drawer.
- At each step, you cut the search space in half.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::cmp::Ordering;

// Internal tree node
#[derive(Debug)]
struct Node<T> {
    value: T,
    left: Option<Box<Node<T>>>,
    right: Option<Box<Node<T>>>,
}

impl<T> Node<T> {
    fn new(value: T) -> Self {
        Node {
            value,
            left: None,
            right: None,
        }
    }
}

// Public Binary Search Tree wrapper
#[derive(Debug)]
pub struct BinarySearchTree<T> {
    root: Option<Box<Node<T>>>,
    size: usize,
}

impl<T: Ord> BinarySearchTree<T> {
    pub fn new() -> Self {
        BinarySearchTree {
            root: None,
            size: 0,
        }
    }

    pub fn is_empty(&self) -> bool {
        self.size == 0
    }

    pub fn len(&self) -> usize {
        self.size
    }

    // Insert a value. Returns true if newly inserted, false if already present.
    pub fn insert(&mut self, value: T) -> bool {
        let inserted = Self::insert_recursive(&mut self.root, value);
        if inserted {
            self.size += 1;
        }
        inserted
    }

    fn insert_recursive(node: &mut Option<Box<Node<T>>>, value: T) -> bool {
        match node {
            None => {
                *node = Some(Box::new(Node::new(value)));
                true
            }
            Some(current) => match value.cmp(&current.value) {
                Ordering::Less => Self::insert_recursive(&mut current.left, value),
                Ordering::Greater => Self::insert_recursive(&mut current.right, value),
                Ordering::Equal => false, // Value already exists (no duplicates)
            },
        }
    }

    // Search for a value in O(log N) average time
    pub fn contains(&self, value: &T) -> bool {
        Self::contains_recursive(&self.root, value)
    }

    fn contains_recursive(node: &Option<Box<Node<T>>>, value: &T) -> bool {
        match node {
            None => false,
            Some(current) => match value.cmp(&current.value) {
                Ordering::Less => Self::contains_recursive(&current.left, value),
                Ordering::Greater => Self::contains_recursive(&current.right, value),
                Ordering::Equal => true,
            },
        }
    }

    // Collect all elements in ascending order via In-Order traversal
    pub fn to_sorted_vec(&self) -> Vec<&T> {
        let mut result = Vec::with_capacity(self.size);
        Self::in_order_walk(&self.root, &mut result);
        result
    }

    fn in_order_walk<'a>(node: &'a Option<Box<Node<T>>>, acc: &mut Vec<&'a T>) {
        if let Some(current) = node {
            Self::in_order_walk(&current.left, acc);
            acc.push(&current.value);
            Self::in_order_walk(&current.right, acc);
        }
    }

    // Calculate maximum tree depth (height)
    pub fn height(&self) -> usize {
        Self::height_recursive(&self.root)
    }

    fn height_recursive(node: &Option<Box<Node<T>>>) -> usize {
        match node {
            None => 0,
            Some(current) => {
                let left_h = Self::height_recursive(&current.left);
                let right_h = Self::height_recursive(&current.right);
                1 + std::cmp::max(left_h, right_h)
            }
        }
    }
}

fn main() {
    let mut bst = BinarySearchTree::new();

    // Insert user IDs
    let user_ids = [50, 30, 70, 20, 40, 60, 80];
    for id in user_ids {
        bst.insert(id);
    }

    println!("Tree size   : {}", bst.len());
    println!("Tree height : {}", bst.height());

    // Membership checks
    println!("Contains 40 : {}", bst.contains(&40));
    println!("Contains 99 : {}", bst.contains(&99));

    // In-Order traversal yields sorted output
    let sorted = bst.to_sorted_vec();
    println!("Sorted values: {:?}", sorted);
    assert_eq!(sorted, vec![&20, &30, &40, &50, &60, &70, &80]);
}
```

## Common Mistakes

### 1. Moving Out of Node References During Traversal
Attempting to match on `node` instead of `&node` or `node.as_ref()`:
```rust
// ❌ COMPILE ERROR: Cannot move out of `current.left` which is behind a shared reference
match current.left {
    Some(child) => { ... }
}

// ✅ CORRECT: Borrow the child inside the Option
match &current.left {
    Some(child) => { ... }
}
```

---

### 2. Degenerate Trees (Unbalanced BSTs)
Inserting pre-sorted data (e.g., `[1, 2, 3, 4, 5]`) into a naive BST:
```
1
 \
  2
   \
    3
     \
      4
       \
        5
```
This degrades the tree into a linked list with **$O(N)$ lookup and insertion time**. Production systems use self-balancing trees (AVL trees, Red-Black trees, B-Trees) to maintain $O(\log N)$ height automatically.

---

### 3. Deep Recursion Stack Overflow on Large Unbalanced Trees
When a tree has $100,000$ elements aligned as a single linear branch, recursive methods will exhaust the thread stack and crash. Safe production implementations use iterative loops or explicit heap-allocated stacks for traversal.

## Solutions

### Solution to Exercise 1
```rust
impl<T: Ord> BinarySearchTree<T> {
    pub fn min(&self) -> Option<&T> {
        let mut current = &self.root;
        while let Some(node) = current {
            if node.left.is_none() {
                return Some(&node.value);
            }
            current = &node.left;
        }
        None
    }

    pub fn max(&self) -> Option<&T> {
        let mut current = &self.root;
        while let Some(node) = current {
            if node.right.is_none() {
                return Some(&node.value);
            }
            current = &node.right;
        }
        None
    }
}
```

### Solution to Exercise 2
```rust
impl<T: Ord> BinarySearchTree<T> {
    pub fn to_pre_order_vec(&self) -> Vec<&T> {
        let mut result = Vec::with_capacity(self.size);
        Self::pre_order_walk(&self.root, &mut result);
        result
    }

    fn pre_order_walk<'a>(node: &'a Option<Box<Node<T>>>, acc: &mut Vec<&'a T>) {
        if let Some(current) = node {
            acc.push(&current.value); // Root
            Self::pre_order_walk(&current.left, acc);  // Left
            Self::pre_order_walk(&current.right, acc); // Right
        }
    }
}
```

### Solution to Exercise 3
```rust
pub fn is_valid_bst<T: Ord>(tree: &BinarySearchTree<T>) -> bool {
    let sorted = tree.to_sorted_vec();
    // In-order traversal of a valid BST is strictly increasing
    sorted.windows(2).all(|pair| pair[0] < pair[1])
}

fn main() {
    let mut bst = BinarySearchTree::new();
    bst.insert(50);
    bst.insert(30);
    bst.insert(70);
    bst.insert(20);
    bst.insert(40);

    assert_eq!(bst.min(), Some(&20));
    assert_eq!(bst.max(), Some(&70));
    assert_eq!(bst.to_pre_order_vec(), vec![&50, &30, &20, &40, &70]);
    assert!(is_valid_bst(&bst));
    println!("All exercise tests passed successfully!");
}
```
