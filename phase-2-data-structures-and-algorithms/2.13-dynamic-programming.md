## Concept

**Dynamic Programming (DP)** is an algorithmic optimization technique that converts exponential-time problems ($O(2^N)$) into polynomial-time ($O(N)$ or $O(N^2)$) by solving each subproblem **exactly once** and remembering the result.

```
Naive Recursive Fibonacci(5) computes Fib(2) 3 separate times:
                      Fib(5)
                   /          \
             Fib(4)            Fib(3)
            /      \          /      \
        Fib(3)    Fib(2)   Fib(2)   Fib(1)
        /    \
     Fib(2) Fib(1)
```

---

### 1. The Two Prerequisites for Dynamic Programming

A problem can be solved using DP if and only if it exhibits:
1. **Optimal Substructure**: The optimal solution to the overall problem is constructed from the optimal solutions of its smaller subproblems.
2. **Overlapping Subproblems**: The recursive solution computes the exact same subproblem states repeatedly across different branches.

---

### 2. Strategy 1: Top-Down DP (Memoization)

Memoization preserves the natural recursive structure of the problem but introduces a lookup table (cache) to store computed answers:
- Before doing work, check if the state exists in the cache (`memo.get(&state)`).
- If present, return the cached value in $O(1)$.
- If not present, compute the result, save it to the cache, and return it.

---

### 3. Strategy 2: Bottom-Up DP (Tabulation)

Tabulation eliminates recursion entirely:
- It starts from the smallest base cases (`dp[0]`, `dp[1]`).
- It iteratively populates an array or table, filling values forward in order until reaching the target state `dp[N]`.
- **Advantages**: No recursion stack frames (zero stack-overflow risk), highly predictable memory layout, and excellent CPU cache prefetching.

```
Tabulation Table for Fibonacci:
 Index:   0   1   2   3   4   5
 dp:    [ 0,  1,  1,  2,  3,  5 ]
```

---

### 4. Space Optimization (State Rolling)

If the value of `dp[i]` depends only on the previous $K$ values (e.g., `dp[i - 1]` and `dp[i - 2]`), you do not need to store the entire array of size $N$. You can keep just $K$ variables, reducing auxiliary space from **$O(N)$ to $O(1)$**.

---

## Why it matters

- **Git Diff & Spellcheck**: The Myers Diff algorithm and Levenshtein Edit Distance use DP matrices to find the minimal number of insertions and deletions between file versions.
- **Network Packet Optimization**: The 0/1 Knapsack algorithm decides which network packets to pack into a Maximum Transmission Unit (MTU) frame to maximize throughput.
- **SQL Query Optimizers**: Relational databases use DP to determine the most efficient join order for multi-table queries.

---

## Analogy

Write `1 + 1 + 1 + 1 + 1` on a whiteboard and ask someone for the sum: they count and say `5`.
Now write `+ 1` at the end and ask for the new sum.
They immediately answer `6` without recounting from scratch. They **memoized** the previous state (`5`) and added `1`.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::collections::HashMap;

// 1. Top-Down DP: Memoized Fibonacci (O(N) time, O(N) space)
pub fn fib_memo(n: u32, memo: &mut HashMap<u32, u64>) -> u64 {
    if n <= 1 {
        return n as u64;
    }
    if let Some(&val) = memo.get(&n) {
        return val;
    }
    let res = fib_memo(n - 1, memo) + fib_memo(n - 2, memo);
    memo.insert(n, res);
    res
}

// 2. Bottom-Up DP: Space-Optimized Tabulation (O(N) time, O(1) space)
pub fn fib_iterative(n: u32) -> u64 {
    if n <= 1 {
        return n as u64;
    }
    let mut prev2 = 0;
    let mut prev1 = 1;

    for _ in 2..=n {
        let curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }

    prev1
}

// 3. 0/1 Knapsack Problem (Bottom-Up Tabulation)
// Maximize item values under a strict weight capacity limit
#[derive(Debug)]
pub struct Item {
    pub weight: usize,
    pub value: u32,
}

pub fn knapsack(items: &[Item], capacity: usize) -> u32 {
    let n = items.len();
    // dp[i][w] = max value considering first i items with weight capacity w
    let mut dp = vec![vec![0u32; capacity + 1]; n + 1];

    for i in 1..=n {
        let item = &items[i - 1];
        for w in 0..=capacity {
            if item.weight <= w {
                // Choice: Leave item vs. Take item
                dp[i][w] = std::cmp::max(
                    dp[i - 1][w],
                    dp[i - 1][w - item.weight] + item.value,
                );
            } else {
                dp[i][w] = dp[i - 1][w];
            }
        }
    }

    dp[n][capacity]
}

// 4. Levenshtein Distance (Minimum edits to transform string A into string B)
pub fn edit_distance(s1: &str, s2: &str) -> usize {
    let chars1: Vec<char> = s1.chars().collect();
    let chars2: Vec<char> = s2.chars().collect();
    let m = chars1.len();
    let n = chars2.len();

    let mut dp = vec![vec![0usize; n + 1]; m + 1];

    for i in 0..=m {
        dp[i][0] = i;
    }
    for j in 0..=n {
        dp[0][j] = j;
    }

    for i in 1..=m {
        for j in 1..=n {
            if chars1[i - 1] == chars2[j - 1] {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + std::cmp::min(
                    dp[i - 1][j], // Deletion
                    std::cmp::min(
                        dp[i][j - 1],     // Insertion
                        dp[i - 1][j - 1], // Substitution
                    ),
                );
            }
        }
    }

    dp[m][n]
}

fn main() {
    // Fibonacci DP
    let mut memo = HashMap::new();
    println!("Fib(50) Memoized : {}", fib_memo(50, &mut memo));
    println!("Fib(50) Tabulated: {}", fib_iterative(50));

    // Knapsack DP
    let items = [
        Item { weight: 2, value: 6 },
        Item { weight: 2, value: 10 },
        Item { weight: 3, value: 12 },
    ];
    let max_val = knapsack(&items, 5);
    println!("Knapsack (Cap: 5) Max Value: {}", max_val); // 22 (Items 2 and 3)

    // Edit distance DP
    let dist = edit_distance("rustc", "cargo");
    println!("Edit Distance ('rustc' -> 'cargo'): {} operations", dist);
}
```

## Common Mistakes

### 1. Off-by-One Matrix Allocation
Allocating DP matrices with dimensions `[m][n]` instead of `[m + 1][n + 1]`. 
*Why it fails*: DP tables require an extra row and column at index `0` to represent the empty base case (0 items or empty string).

---

### 2. Forgetting Base Cases in Memoization
Failing to terminate recursion on base conditions (e.g., `if n <= 1`) before querying the hash map, leading to negative underflow or infinite recursion.

---

### 3. Iterating the Wrong Direction in Space-Optimized Knapsack
When optimizing 2D knapsack DP to a single 1D array of size `capacity + 1`, the inner weight loop must iterate **backwards** (`capacity down to item.weight`). Iterating forwards allows an item to be selected multiple times, incorrectly solving the *Unbounded Knapsack* problem instead of the *0/1 Knapsack* problem.

## Solutions

### Solution to Exercise 1
```rust
pub fn min_coins(coins: &[usize], amount: usize) -> Option<usize> {
    let mut dp = vec![usize::MAX; amount + 1];
    dp[0] = 0; // 0 coins needed for amount 0

    for i in 1..=amount {
        for &coin in coins {
            if coin <= i && dp[i - coin] != usize::MAX {
                dp[i] = std::cmp::min(dp[i], dp[i - coin] + 1);
            }
        }
    }

    if dp[amount] == usize::MAX {
        None
    } else {
        Some(dp[amount])
    }
}
```

### Solution to Exercise 2
```rust
pub fn climb_stairs(n: usize) -> u64 {
    if n == 0 { return 1; }
    if n == 1 { return 1; }
    if n == 2 { return 2; }

    let mut a = 1; // n-3
    let mut b = 1; // n-2
    let mut c = 2; // n-1

    for _ in 3..=n {
        let current = a + b + c;
        a = b;
        b = c;
        c = current;
    }

    c
}
```

---

### Solution to Exercise 3
```rust
pub fn longest_increasing_subsequence(nums: &[i32]) -> usize {
    if nums.is_empty() {
        return 0;
    }

    let mut dp = vec![1usize; nums.len()];

    for i in 1..nums.len() {
        for j in 0..i {
            if nums[j] < nums[i] {
                dp[i] = std::cmp::max(dp[i], dp[j] + 1);
            }
        }
    }

    *dp.iter().max().unwrap_or(&0)
}

fn main() {
    assert_eq!(min_coins(&[1, 2, 5], 11), Some(3)); // 5 + 5 + 1
    assert_eq!(min_coins(&[2], 3), None);
    assert_eq!(climb_stairs(4), 7);
    assert_eq!(longest_increasing_subsequence(&[10, 9, 2, 5, 3, 7, 101, 18]), 4);
    println!("All Dynamic Programming exercises passed!");
}
```
