## Concept

In Lesson 2.1, we saw that **Dynamic Arrays (`Vec<T>`)** store elements in contiguous memory. While this gives $O(1)$ random access, inserting or removing elements at the *front* takes $O(N)$ time because every subsequent element must be shifted in RAM.

A **Linked List** is a non-contiguous data structure where each element is an independent **Node** allocated separately on the **Heap**. Each node contains its data plus a pointer to the next node in the chain.

```
Head Pointer (Stack)               Heap Nodes
┌─────────────────┐               ┌──────────┬──────────┐       ┌──────────┬──────────┐
│ ptr: 0x1000     │ ────────────> │ Data: A  │ 0x2000   │ ────> │ Data: B  │ None     │
└─────────────────┘               └──────────┴──────────┘       └──────────┴──────────┘
```

---

### 1. The Recursive Type Problem and `Box<T>`

If you try to define a linked list node directly:

```rust
// COMPILE ERROR: Recursive type has infinite size!
struct Node<T> {
    elem: T,
    next: Option<Node<T>>, 
}
```

#### Why the compiler rejects this:
Rust must know the exact byte size of every struct at compile time. A `Node` containing an optional `Node` containing another `Node` creates an infinite recursion of nested memory.

#### The Solution: Indirection with `Box<T>`:
A **`Box<T>`** is a smart pointer that allocates type `T` on the **Heap**. A `Box` pointer on the stack always has a **fixed, known size** (8 bytes on a 64-bit system), regardless of how large `T` is.

```rust
type Link<T> = Option<Box<Node<T>>>;

struct Node<T> {
    elem: T,
    next: Link<T>, // Fixed 8-byte pointer size on stack!
}
```

---

### 2. The `Option::take()` Idiom

When inserting or removing from the head of the list, you must take ownership of the current `head` node without violating the borrow checker.

`Option::take()` replaces the value inside an `Option` with `None` and returns the original `Some(value)`:

```rust
// Atomically takes the old head and replaces self.head with None
let old_head = self.head.take(); 
```

---

### 3. Big-O Complexity: `Vec<T>` vs. `LinkedList<T>`

| Operation | Dynamic Array (`Vec<T>`) | Singly Linked List |
| :--- | :--- | :--- |
| **Insert at Front (`push_front`)** | **$O(N)$** (Shifts elements) | **$O(1)$** (Swap head pointer) |
| **Remove from Front (`pop_front`)**| **$O(N)$** (Shifts elements) | **$O(1)$** (Advance head pointer) |
| **Append to End (`push_back`)** | **$O(1)$ amortized** | **$O(N)$** (Must traverse chain) |
| **Random Access (`list[i]`)** | **$O(1)$** (Direct memory offset) | **$O(N)$** (Follow pointers) |
| **CPU Cache Efficiency** | **Excellent** (Contiguous) | **Poor** (Scattered heap nodes) |

## Why it matters

In systems kernels, asynchronous job queues, and lock-free thread schedulers, linked nodes allow tasks to be linked and unlinked in strictly guaranteed $O(1)$ constant time without triggering array resizing. 

Building a linked list in Rust teaches you the fundamental interplay between ownership, recursive heap allocation with `Box<T>`, and safe memory reclamation.

---

## Analogy

Think of a **City-Wide Scavenger Hunt**:
- You hold a card in your hand with the address of Clue 1 (**Head Pointer**).
- At Clue 1, you find a prize (`elem`) and an envelope containing the address of Clue 2 (`Box<Node>`).
- Clue 2 has the address of Clue 3.
- The final clue says "Finished" (`None`).
- To add a new first clue (`push_front`), you write a new card pointing to Clue 1 and put it in your hand ($O(1)$). You do not have to move or touch any of the other clues across the city.

## Code Example

```rust
// 1. Defining Link alias and recursive Node structure
type Link<T> = Option<Box<Node<T>>>;

struct Node<T> {
    elem: T,
    next: Link<T>,
}

pub struct SinglyLinkedList<T> {
    head: Link<T>,
    size: usize,
}

impl<T> SinglyLinkedList<T> {
    // Constructor: Creates an empty linked list
    pub fn new() -> Self {
        SinglyLinkedList { head: None, size: 0 }
    }

    pub fn len(&self) -> usize {
        self.size
    }

    pub fn is_empty(&self) -> bool {
        self.size == 0
    }

    // O(1) Push to Front: Creates a new node pointing to the current head
    pub fn push_front(&mut self, elem: T) {
        let new_node = Box::new(Node {
            elem,
            next: self.head.take(), // Take the old head, leaving None temporarily
        });

        self.head = Some(new_node);
        self.size += 1;
    }

    // O(1) Pop from Front: Removes and returns the head element
    pub fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|node| {
            self.head = node.next;
            self.size -= 1;
            node.elem
        })
    }

    // O(1) Peek at the front element without consuming it
    pub fn peek_front(&self) -> Option<&T> {
        self.head.as_ref().map(|node| &node.elem)
    }
}

// Custom Drop implementation to prevent stack overflow on massive lists
impl<T> Drop for SinglyLinkedList<T> {
    fn drop(&mut self) {
        let mut cur_link = self.head.take();
        while let Some(mut boxed_node) = cur_link {
            cur_link = boxed_node.next.take();
            // `boxed_node` goes out of scope here and is deallocated iteratively
        }
    }
}

fn main() {
    let mut task_queue = SinglyLinkedList::new();

    println!("--- 1. Pushing to Linked List (O(1)) ---");
    task_queue.push_front("Task C (Low Priority)");
    task_queue.push_front("Task B (Medium Priority)");
    task_queue.push_front("Task A (High Priority)");

    println!("Total tasks in list: {}", task_queue.len());
    println!("Current front task: {:?}", task_queue.peek_front());

    println!("\n--- 2. Popping from Linked List (O(1)) ---");
    while let Some(task) = task_queue.pop_front() {
        println!("Processing: {}", task);
    }

    println!("Remaining tasks: {}", task_queue.len());
}
```

## Common Mistakes

### 1. Defining Recursive Structs Without `Box<T>`
Creating a struct that directly contains an instance of itself without pointer indirection.

**Broken Code:**
```rust
struct Node {
    value: i32,
    next: Option<Node>, // Error: infinite size!
}
```

**Compiler Output:**
```text
error[E0072]: recursive type `Node` has infinite size
 --> src/main.rs:1:1
  |
1 | struct Node {
  | ^^^^^^^^^^^
2 |     value: i32,
3 |     next: Option<Node>,
  |                  ---- recursive without indirection
  |
  = help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
```

---

### 2. Trying to Move Out of Borrowed `self.head`
Writing `let old_head = self.head;` inside a `&mut self` method. Rust will not allow you to leave `self.head` in an uninitialized state. Use `self.head.take()`.

---

### 3. Relying on Default Recursive `Drop` for Deep Lists
By default, when a linked list drops, `Node 1` drops `Node 2`, which drops `Node 3`, etc. On a list of 1,000,000 nodes, this recursive cleanup exhausts the CPU call stack and causes a **Stack Overflow Crash**. An iterative loop with `Option::take()` solves this.

## Solutions

### Solution to Exercise 1
```rust
impl<T: PartialEq> SinglyLinkedList<T> {
    pub fn contains(&self, target: &T) -> bool {
        let mut current = &self.head;
        while let Some(node) = current {
            if &node.elem == target {
                return true;
            }
            current = &node.next;
        }
        false
    }
}

fn main() {
    let mut list = SinglyLinkedList::new();
    list.push_front(10);
    list.push_front(20);
    list.push_front(30);

    println!("Contains 20: {}", list.contains(&20));
    println!("Contains 99: {}", list.contains(&99));
}
```

### Solution to Exercise 2
```rust
impl<T: Clone> SinglyLinkedList<T> {
    pub fn to_vec(&self) -> Vec<T> {
        let mut result = Vec::with_capacity(self.size);
        let mut current = &self.head;
        while let Some(node) = current {
            result.push(node.elem.clone());
            current = &node.next;
        }
        result
    }
}

fn main() {
    let mut list = SinglyLinkedList::new();
    list.push_front("Alpha");
    list.push_front("Beta");

    let vec_copy = list.to_vec();
    println!("As Vector: {:?}", vec_copy); // ["Beta", "Alpha"]
}
```

### Solution to Exercise 3
```rust
impl<T> SinglyLinkedList<T> {
    pub fn count_matching<F>(&self, predicate: F) -> usize
    where
        F: Fn(&T) -> bool,
    {
        let mut count = 0;
        let mut current = &self.head;
        while let Some(node) = current {
            if predicate(&node.elem) {
                count += 1;
            }
            current = &node.next;
        }
        count
    }
}

fn main() {
    let mut numbers = SinglyLinkedList::new();
    numbers.push_front(10);
    numbers.push_front(25);
    numbers.push_front(30);
    numbers.push_front(7);

    let evens = numbers.count_matching(|&n| n % 2 == 0);
    println!("Even numbers count: {}", evens); // 2 (10 and 30)
}
```
