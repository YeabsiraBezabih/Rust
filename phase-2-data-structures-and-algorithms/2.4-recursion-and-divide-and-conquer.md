## Concept

When solving complex algorithmic problems, we often find that a large problem is composed of smaller instances of the exact same problem.

**Recursion** is a programming technique where a function solves a problem by **calling itself** with a smaller sub-problem.

---

### 1. The Two Mandatory Rules of Recursion

Every recursive function must have two components:

1. **The Base Case (Termination Condition)**: A condition where the problem is small enough to return a direct answer **without making another recursive call**.
2. **The Recursive Step**: The logic that reduces the input size and calls the function again, **guaranteed to move closer to the base case**.

```
factorial(3)
  ├── 3 * factorial(2)
  │         ├── 2 * factorial(1)
  │         │         ├── 1 (Base Case reached!)
  │         │         ▼
  │         └── 2 * 1 = 2
  └── 3 * 2 = 6
```

---

### 2. How the Call Stack Executes Recursion

In Lesson 0.5, we learned that every function call pushes a **Stack Frame** to the CPU stack.

When function `A` calls itself:
1. A new frame is pushed on top of the stack with its own local variables.
2. This continues until the **Base Case** is reached.
3. The stack frames then **unwind (pop)** in LIFO order, passing return values back down the chain.

#### The Stack Overflow Danger:
If a function lacks a base case, or if the recursion is too deep (e.g., 200,000 calls), the stack frames consume all allocated thread stack memory, causing a fatal **Stack Overflow Panic**.

---

### 3. The Divide-and-Conquer Paradigm

**Divide-and-Conquer** is an algorithmic design strategy that operates in three distinct phases:

1. **Divide**: Split the problem into smaller, independent sub-problems of the same type.
2. **Conquer**: Recursively solve each sub-problem. If a sub-problem is trivial, solve it immediately (Base Case).
3. **Combine**: Merge the sub-solutions to form the final result.

```
                  [ 8, 3, 5, 1, 9, 2, 7, 4 ]       (Divide)
                            │
               ┌────────────┴────────────┐
               ▼                         ▼
        [ 8, 3, 5, 1 ]            [ 9, 2, 7, 4 ]   (Divide)
               │                         │
          ┌────┴────┐               ┌────┴────┐
          ▼         ▼               ▼         ▼
       [8, 3]    [5, 1]          [9, 2]    [7, 4]  (Conquer & Combine)
```

---

## Why it matters

Divide-and-conquer is the algorithmic foundation for the most efficient algorithms in computer science:
- **Binary Search** ($O(\log N)$ in Lesson 2.5).
- **Merge Sort and Quicksort** ($O(N \log N)$ in Lesson 2.6).
- **Binary Search Tree Traversals** (Lesson 2.7).
- **Abstract Syntax Tree (AST) Parsers** in our Markdown and AI Agent engine.

---

## Analogy

Think of **Russian Nesting Dolls (Matryoshka)**:
- You want to find the gold coin hidden in the smallest doll.
- **Recursive Step**: You open the outermost doll, find a smaller doll inside, and hand it to yourself to repeat the process.
- **Base Case**: You reach the final, solid wooden doll that cannot be opened. You take the coin and close each shell back up as you return.

## Code Example

```rust
// 1. Classic Linear Recursion: Calculating Factorial (N!)
// Mathematical definition: 0! = 1, N! = N * (N - 1)!
fn factorial(n: u64) -> u64 {
    // BASE CASE: Stop when n is 0 or 1
    if n <= 1 {
        return 1;
    }

    // RECURSIVE STEP: n * factorial(n - 1)
    n * factorial(n - 1)
}

// 2. Divide-and-Conquer: Finding the Maximum Value in a Slice
// Divides the slice into two halves, recursively finds the max of each, and combines them.
fn find_max_divide_and_conquer(slice: &[i32]) -> Option<i32> {
    match slice.len() {
        // BASE CASE 1: Empty slice has no maximum
        0 => None,
        // BASE CASE 2: Single-element slice is trivially its own maximum
        1 => Some(slice[0]),
        // DIVIDE & CONQUER STEP
        len => {
            let mid = len / 2;
            let left_half = &slice[..mid];   // Left sub-problem
            let right_half = &slice[mid..];  // Right sub-problem

            let left_max = find_max_divide_and_conquer(left_half)?;
            let right_max = find_max_divide_and_conquer(right_half)?;

            // COMBINE STEP: Return the greater of the two sub-maxima
            Some(std::cmp::max(left_max, right_max))
        }
    }
}

// 3. Recursive Directory Size Calculation (Simulated Tree Traversal)
enum FileSystemNode {
    File { size_bytes: u64 },
    Directory { children: Vec<FileSystemNode> },
}

fn calculate_total_size(node: &FileSystemNode) -> u64 {
    match node {
        // BASE CASE: A file simply returns its own size
        FileSystemNode::File { size_bytes } => *size_bytes,
        // RECURSIVE STEP: A directory sums the sizes of all its children
        FileSystemNode::Directory { children } => {
            let mut total = 0;
            for child in children {
                total += calculate_total_size(child); // Recursive call
            }
            total
        }
    }
}

fn main() {
    println!("--- 1. Linear Recursion ---");
    let num = 5;
    println!("{}! = {}", num, factorial(num)); // 120

    println!("\n--- 2. Divide and Conquer Max Finding ---");
    let telemetry_data = [14, 82, 39, 99, 45, 12, 78, 63];
    println!("Data: {:?}", telemetry_data);
    println!("Peak Value: {:?}", find_max_divide_and_conquer(&telemetry_data));

    println!("\n--- 3. Tree Traversal Recursion ---");
    let mock_fs = FileSystemNode::Directory {
        children: vec![
            FileSystemNode::File { size_bytes: 500 },
            FileSystemNode::Directory {
                children: vec![
                    FileSystemNode::File { size_bytes: 1200 },
                    FileSystemNode::File { size_bytes: 800 },
                ],
            },
            FileSystemNode::File { size_bytes: 150 },
        ],
    };

    println!("Total Directory Tree Size: {} bytes", calculate_total_size(&mock_fs)); // 2650
}
```

## Common Mistakes

### 1. Missing or Unreachable Base Case
Omitting the base case causes infinite recursion until the stack overflows.

**Broken Code:**
```rust
fn countdown(n: i32) {
    println!("{}", n);
    countdown(n - 1); // Error: Never stops! Panics with stack overflow!
}
```

---

### 2. Failing to Shrink the Problem Size
Calling `func(n)` instead of `func(n - 1)` or `func(&slice[..mid])`.

---

### 3. Naive Exponential Tree Recursion ($O(2^N)$)
Writing recursive Fibonacci without memoization, where every step branches into two sub-calls (`fib(n-1) + fib(n-2)`). For $N=50$, this requires over $1,000,000,000,000,000$ function calls and freezes the CPU. (Solved via Dynamic Programming in Lesson 2.13).

## Solutions

### Solution to Exercise 1
```rust
fn sum_slice(slice: &[i64]) -> i64 {
    if slice.is_empty() {
        0
    } else {
        slice[0] + sum_slice(&slice[1..])
    }
}

fn main() {
    let numbers = [10, 20, 30, 40];
    println!("Sum: {}", sum_slice(&numbers)); // 100
}
```

---

### Solution to Exercise 2
```rust
fn count_occurrences<T: PartialEq>(slice: &[T], target: &T) -> usize {
    match slice.len() {
        0 => 0,
        1 => if &slice[0] == target { 1 } else { 0 },
        len => {
            let mid = len / 2;
            let left_count = count_occurrences(&slice[..mid], target);
            let right_count = count_occurrences(&slice[mid..], target);
            left_count + right_count
        }
    }
}

fn main() {
    let responses = [200, 404, 200, 500, 200, 404];
    let count_200 = count_occurrences(&responses, &200);
    let count_404 = count_occurrences(&responses, &404);

    println!("200 count: {}", count_200); // 3
    println!("404 count: {}", count_404); // 2
}
```

---

### Solution to Exercise 3
**Explanation**: The function is missing a **Base Case** for when the string has length `0` or `1`. When `s` becomes `""` or a single character `"e"`, trying to access `bytes[0]` on an empty slice panics, or the recursion continues endlessly without stopping.

**Corrected Code**:
```rust
fn is_palindrome(s: &str) -> bool {
    let bytes = s.as_bytes();

    // BASE CASE: Empty string or single-character string is always a palindrome
    if bytes.len() <= 1 {
        return true;
    }

    // Check boundary characters
    if bytes[0] != bytes[bytes.len() - 1] {
        return false;
    }

    // RECURSIVE STEP: Strip first and last character and recurse
    is_palindrome(&s[1..s.len() - 1])
}

fn main() {
    println!("racecar: {}", is_palindrome("racecar")); // true
    println!("hello:   {}", is_palindrome("hello"));   // false
    println!("a:       {}", is_palindrome("a"));       // true
}
```
