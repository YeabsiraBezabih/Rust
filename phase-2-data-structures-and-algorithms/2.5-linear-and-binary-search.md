## Concept

Searching is the process of locating a specific target value within a collection. The two fundamental searching algorithms are **Linear Search** and **Binary Search**.

---

### 1. Linear Search ($O(N)$)

Linear Search checks every single element sequentially from the first index to the last until the target is found or the collection ends.

```
Looking for Target 42:
[ 14,  82,  39,  42,  99,  12 ]
  ▲    ▲    ▲    ▲
  1    2    3    4 (Found at index 3 in 4 steps)
```

- **Prerequisites**: None. Works on **any** collection (sorted or unsorted, contiguous arrays or linked lists).
- **Time Complexity**:
  - Best Case: **$O(1)$** (Target is at index 0).
  - Worst / Average Case: **$O(N)$** (Target is at the end or absent).
- **Space Complexity**: **$O(1)$** constant space.

---

### 2. Binary Search ($O(\log N)$)

Binary Search uses **Divide-and-Conquer** on a **sorted array** to eliminate half of the remaining search space with every comparison.

```
Target: 78
Array (Sorted): [ 12, 14, 39, 45, 63, 78, 82, 99 ]  (low=0, high=7, mid=3: val=45)
                                      ▲   ▲   ▲
                      45 < 78 -> Search Right Half: [ 63, 78, 82, 99 ] (low=4, high=7, mid=5: val=78)
                                                          ▲
                                              78 == 78 -> Found in 2 steps!
```

- **Prerequisites**: 
  1. The collection **must be sorted**.
  2. The collection must support **$O(1)$ random indexing** (slices, arrays, vectors).
- **Time Complexity**: **$O(\log_2 N)$**.
  - For $N = 1,000,000$ elements, Linear Search requires up to $1,000,000$ comparisons; Binary Search requires at most **20 comparisons**.
- **Space Complexity**: **$O(1)$** for iterative implementation.

---

### 3. The Midpoint Calculation and Unsigned Underflow

In many languages, developers write `mid = (low + high) / 2`. 
- In Rust, indices use **`usize`** (unsigned integers).
- If `low + high` exceeds `usize::MAX`, it triggers an arithmetic overflow panic in debug mode.
- If `mid == 0` and you execute `high = mid - 1`, unsigned `0 - 1` panics with an underflow!

#### The Safe Formulas:
- **Midpoint calculation**: `let mid = low + (high - low) / 2;`
- **Safe high adjustment**: `if mid == 0 { break; } else { high = mid - 1; }`

---

## Why it matters

In high-performance networking and database engines:
- Looking up IP subnets in routing tables.
- Querying sorted index files in database engines (B-Trees).
- Matching HTTP URL endpoints against pre-sorted route lists.

Binary Search provides the logarithmic speed necessary to search millions of records in microseconds.

---

## Analogy

Think of **The Number Guessing Game (1 to 100)**:
- **Linear Search**: You guess $1, 2, 3, 4, \dots, 100$. If the secret number is 99, you need 99 guesses.
- **Binary Search**: You guess $50$. The host says *"Higher"*. You guess $75$ (*"Higher"*). You guess $88$ (*"Lower"*). You guess $81$... You find any number between 1 and 100 in at most **7 guesses**.

## Code Example

```rust
use std::cmp::Ordering;

// 1. Linear Search: Works on ANY unsorted slice
pub fn linear_search<T: PartialEq>(slice: &[T], target: &T) -> Option<usize> {
    for (index, item) in slice.iter().enumerate() {
        if item == target {
            return Some(index); // Found
        }
    }
    None // Not found
}

// 2. Binary Search from Scratch: Requires sorted slice
pub fn binary_search<T: Ord>(slice: &[T], target: &T) -> Option<usize> {
    if slice.is_empty() {
        return None;
    }

    let mut low: usize = 0;
    let mut high: usize = slice.len() - 1;

    while low <= high {
        // Safe midpoint calculation preventing overflow
        let mid = low + (high - low) / 2;

        match slice[mid].cmp(target) {
            Ordering::Equal => return Some(mid), // Target found!
            Ordering::Less => {
                // Target is in the right half
                low = mid + 1;
            }
            Ordering::Greater => {
                // Target is in the left half; avoid unsigned underflow if mid == 0
                if mid == 0 {
                    break;
                }
                high = mid - 1;
            }
        }
    }

    None // Target does not exist in slice
}

fn main() {
    let unsorted_ports = [8080, 443, 22, 5432, 80, 3000];
    let sorted_ports = [22, 80, 443, 3000, 5432, 8080];

    println!("--- 1. Linear Search (Unsorted) ---");
    let target = 5432;
    let linear_result = linear_search(&unsorted_ports, &target);
    println!("Found port {} at index: {:?}", target, linear_result);

    println!("\n--- 2. Custom Binary Search (Sorted) ---");
    let binary_result = binary_search(&sorted_ports, &target);
    println!("Found port {} at index: {:?}", target, binary_result);

    println!("\n--- 3. Rust Standard Library binary_search ---");
    // Standard library returns Result<usize, usize>:
    // Ok(index) if found, Err(insertion_index) if absent
    match sorted_ports.binary_search(&80) {
        Ok(idx) => println!("Stdlib found 80 at index: {}", idx),
        Err(insert_idx) => println!("Not found; could insert at index: {}", insert_idx),
    }

    match sorted_ports.binary_search(&9000) {
        Ok(idx) => println!("Stdlib found 9000 at index: {}", idx),
        Err(insert_idx) => println!("9000 missing; would insert at index: {}", insert_idx),
    }
}
```

## Common Mistakes

### 1. Running Binary Search on Unsorted Data
Running `binary_search` on `[50, 10, 40, 20]`.

*Why it fails*: Binary search assumes elements to the left are smaller and elements to the right are larger. If unsorted, it will discard the half containing the target, returning `None` even when the element exists.

---

### 2. Unsigned Integer Underflow on `high = mid - 1`
When `low = 0` and `mid = 0`, computing `high = mid - 1` in `usize` wraps around to `18,446,744,073,709,551,615` (panicking in debug mode). Always check `if mid == 0 { break; }`.

---

### 3. Using Inefficient Data Structures for Binary Search
Attempting to run binary search on a `LinkedList<T>`. Because a linked list cannot access elements in $O(1)$ time, jumping to `mid` requires walking $N/2$ pointers, destroying the $O(\log N)$ efficiency and making it slower than linear search!

## Solutions

### Solution to Exercise 1
```rust
use std::cmp::Ordering;

fn binary_search_with_steps(slice: &[i32], target: i32) -> (Option<usize>, usize) {
    if slice.is_empty() {
        return (None, 0);
    }

    let mut low = 0;
    let mut high = slice.len() - 1;
    let mut steps = 0;

    while low <= high {
        steps += 1;
        let mid = low + (high - low) / 2;

        match slice[mid].cmp(&target) {
            Ordering::Equal => return (Some(mid), steps),
            Ordering::Less => low = mid + 1,
            Ordering::Greater => {
                if mid == 0 { break; }
                high = mid - 1;
            }
        }
    }

    (None, steps)
}

fn main() {
    let data = [10, 20, 30, 40, 50, 60, 70, 78, 90, 100];
    let (res, steps) = binary_search_with_steps(&data, 78);
    println!("Found at index {:?} in {} steps", res, steps);
}
```

### Solution to Exercise 2
```rust
fn find_first_occurrence(slice: &[i32], target: i32) -> Option<usize> {
    if slice.is_empty() {
        return None;
    }

    let mut low = 0;
    let mut high = slice.len() - 1;
    let mut result = None;

    while low <= high {
        let mid = low + (high - low) / 2;

        if slice[mid] == target {
            result = Some(mid);
            // Continue searching left half for an earlier occurrence!
            if mid == 0 { break; }
            high = mid - 1;
        } else if slice[mid] < target {
            low = mid + 1;
        } else {
            if mid == 0 { break; }
            high = mid - 1;
        }
    }

    result
}

fn main() {
    let data = [1, 2, 2, 2, 3, 4, 5];
    println!("First occurrence of 2: {:?}", find_first_occurrence(&data, 2)); // Some(1)
}
```

### Solution to Exercise 3
```rust
fn main() {
    let mut ports = vec![80, 443, 8080];
    let new_port = 8000;

    // binary_search returns Err(index) where new_port should be inserted
    match ports.binary_search(&new_port) {
        Ok(idx) => println!("Port {} already present at index {}", new_port, idx),
        Err(insert_idx) => {
            ports.insert(insert_idx, new_port);
            println!("Inserted {} at index {}. Updated: {:?}", new_port, insert_idx, ports);
        }
    }
}
```
