## Concept

In computer science, **Abstract Data Types (ADTs)** specify *what* operations a data structure supports, while concrete implementations dictate *how* data is laid out in RAM.

Two of the most fundamental ADTs are **The Stack** and **The Queue**.

---

### 1. The Stack (LIFO: Last-In, First-Out)

A **Stack** enforces a strict order: the last element added is the first element removed.

```
       Push (In)          Pop (Out)
          │                   ▲
          ▼                   │
    ┌───────────────────────────────┐
    │       Top Item (Newest)       │ <─── Insertion & Removal point
    ├───────────────────────────────┤
    │          Middle Item          │
    ├───────────────────────────────┤
    │      Bottom Item (Oldest)     │
    └───────────────────────────────┘
```

#### Core Operations (All $O(1)$ Time):
- **`push(elem)`**: Adds an element to the top.
- **`pop() -> Option<T>`**: Removes and returns the top element.
- **`peek() -> Option<&T>`**: Inspects the top element without removing it.

#### Optimal Implementation:
A dynamic array (`Vec<T>`) is the optimal backing storage for a stack. Pushing and popping at the end of a `Vec` (`vec.push()`, `vec.pop()`) requires zero element shifting and runs in **$O(1)$ amortized time** with optimal CPU cache locality.

---

### 2. The Queue (FIFO: First-In, First-Out)

A **Queue** enforces fair scheduling: the first element added is the first element removed (like a line at a ticket counter).

```
   Enqueue (In)                                            Dequeue (Out)
       │                                                         ▲
       ▼                                                         │
┌──────────────┬──────────────┬──────────────┬──────────────┬──────────────┐
│  New Item    │   Item N-1   │     ...      │    Item 1    │  Oldest Item │
└──────────────┴──────────────┴──────────────┴──────────────┴──────────────┘
    (Back)                                                      (Front)
```

#### Core Operations (All $O(1)$ Time):
- **`enqueue(elem)`**: Adds an element to the back.
- **`dequeue() -> Option<T>`**: Removes and returns the front element.
- **`peek() -> Option<&T>`**: Inspects the front element without removing it.

#### The "Naive `Vec`" Trap:
If you implement a queue using `Vec<T>` by pushing to the back (`vec.push()`) and removing from the front (`vec.remove(0)`), every single `dequeue()` call shifts all $N$ remaining elements in memory—causing an **$O(N)$ penalty per dequeue ($O(N^2)$ overall)**.

#### The Optimal Solution: Ring Buffers (`VecDeque<T>`):
A **Double-Ended Queue / Ring Buffer** uses a contiguous array with wrapping `head` and `tail` indices. When the front element is removed, the `head` index simply increments by 1 without moving any elements in RAM, guaranteeing **$O(1)$ enqueue and $O(1)$ dequeue**.

---

## Why it matters

- **Stacks**: Critical for syntax parsers (e.g., matching HTML tags, JSON brackets, Markdown formatting), undo/redo systems, and call-stack execution in virtual machines.
- **Queues**: The foundational backbone of networking and backend servers. When thousands of TCP connections arrive simultaneously, they sit in a FIFO connection queue so that clients are served in the order they arrived without starving early requests.

---

## Analogy

- **Stack (LIFO)**: A spring-loaded cafeteria tray dispenser. Clean trays are loaded onto the top (`push`). Customers take the topmost tray (`pop`). The last tray cleaned is the first one used.
- **Queue (FIFO)**: Passengers boarding an airplane. The first passenger in line (`enqueue`) is the first passenger to step onto the plane (`dequeue`). Cutting to the front is forbidden.

## Code Example

```rust
use std::collections::VecDeque;

// 1. A High-Performance Generic Stack backed by Vec<T>
#[derive(Debug)]
pub struct ArrayStack<T> {
    storage: Vec<T>,
}

impl<T> ArrayStack<T> {
    pub fn new() -> Self {
        ArrayStack { storage: Vec::new() }
    }

    pub fn push(&mut self, item: T) {
        self.storage.push(item); // O(1) amortized
    }

    pub fn pop(&mut self) -> Option<T> {
        self.storage.pop() // O(1)
    }

    pub fn peek(&self) -> Option<&T> {
        self.storage.last() // O(1)
    }

    pub fn is_empty(&self) -> bool {
        self.storage.is_empty()
    }
}

// 2. A High-Performance FIFO Queue backed by VecDeque<T>
#[derive(Debug)]
pub struct FifoQueue<T> {
    storage: VecDeque<T>,
}

impl<T> FifoQueue<T> {
    pub fn new() -> Self {
        FifoQueue { storage: VecDeque::new() }
    }

    pub fn enqueue(&mut self, item: T) {
        self.storage.push_back(item); // O(1) amortized
    }

    pub fn dequeue(&mut self) -> Option<T> {
        self.storage.pop_front() // O(1) via wrapping ring-buffer index!
    }

    pub fn len(&self) -> usize {
        self.storage.len()
    }
}

// 3. Real-World Application: Validating Balanced HTML/XML Tags with a Stack
fn validate_balanced_tags(tags: &[&str]) -> bool {
    let mut tag_stack = ArrayStack::new();

    for &tag in tags {
        if tag.starts_with('/') {
            // Closing tag: must match the most recently opened tag
            let expected_opening = &tag[1..]; // Strip '/'
            match tag_stack.pop() {
                Some(open_tag) if open_tag == expected_opening => continue,
                _ => return false, // Mismatched or missing opening tag
            }
        } else {
            // Opening tag: push onto stack
            tag_stack.push(tag);
        }
    }

    tag_stack.is_empty() // Must have no unclosed tags remaining
}

fn main() {
    println!("--- 1. Testing LIFO Stack ---");
    let mut stack = ArrayStack::new();
    stack.push(10);
    stack.push(20);
    stack.push(30);

    println!("Top element: {:?}", stack.peek());
    while let Some(val) = stack.pop() {
        print!("{} ", val); // Prints: 30 20 10 (Reverse order)
    }
    println!();

    println!("\n--- 2. Testing FIFO Queue ---");
    let mut queue = FifoQueue::new();
    queue.enqueue("Packet_1");
    queue.enqueue("Packet_2");
    queue.enqueue("Packet_3");

    while let Some(packet) = queue.dequeue() {
        print!("{} -> ", packet); // Prints: Packet_1 -> Packet_2 -> Packet_3 (Arrival order)
    }
    println!("Done");

    println!("\n--- 3. Testing HTML Tag Validator ---");
    let valid_doc = ["html", "body", "h1", "/h1", "p", "/p", "/body", "/html"];
    let corrupted_doc = ["html", "body", "h1", "/body", "/html"]; // Closed body before h1!

    println!("Valid Doc Validated: {}", validate_balanced_tags(&valid_doc));
    println!("Corrupted Doc Validated: {}", validate_balanced_tags(&corrupted_doc));
}
```

## Common Mistakes

### 1. Using `Vec::remove(0)` to Implement a Queue
Using a raw `Vec` and removing from index 0 inside high-throughput server loops.

*Why it happens*: Beginners don't know that `Vec::remove(0)` forces an $O(N)$ memory shift on every call. Always use `std::collections::VecDeque` for $O(1)$ front removals.

---

### 2. Forgetting to Check if Stack is Empty at End of Validation
In delimiter validation, assuming that never popping the wrong character is enough. If an opening bracket `{` is never closed, the stack will still contain it at the end; you must check `stack.is_empty()`.

---

### 3. Confusing Stacks with Queues in Priority and Event Handling
Using a stack where a queue was required, accidentally processing the newest incoming network requests while older requests starve indefinitely at the bottom.

## Exercises

### Exercise 1 (Balanced Bracket Validator)
Write a function `is_balanced_parentheses(s: &str) -> bool` using `ArrayStack<char>`:
- When encountering `'('`, `'['`, or `'{'`, push it onto the stack.
- When encountering `')'`, `']'`, or `'}'`, pop from the stack and verify that the types match.
- Any other characters should be ignored.
- Return `true` if all brackets match and the stack is empty at the end, or `false` otherwise.

Test with `"({[]})"` (true), `"([)]"` (false), and `"((("` (false).

---

### Exercise 2 (Evaluating Postfix Expressions)
In **Postfix Notation (Reverse Polish Notation)**, operators follow their operands:
`"5 3 + 2 *"` means $(5 + 3) \times 2 = 16$.

Write a function `evaluate_postfix(tokens: &[&str]) -> Result<i32, String>` using a stack:
- If a token is an integer, push it onto the stack.
- If a token is `"+"`, `"-"`, or `"*"`, pop the top two numbers, apply the operation, and push the result.
- At the end, pop and return the final single number.

---

### Exercise 3 (Building a Request Rate Limiter Queue)
Using `VecDeque<u64>` (where numbers represent request arrival timestamps in seconds):
Write a struct `SlidingWindowRateLimiter`:
- Fields: `requests: VecDeque<u64>`, `max_requests: usize`, `window_seconds: u64`.
- Method `allow_request(&mut self, current_timestamp: u64) -> bool`:
  1. Dequeue all timestamps older than `current_timestamp - window_seconds`.
  2. If remaining count `< max_requests`, enqueue `current_timestamp` and return `true`.
  3. Otherwise, return `false` (rate limit exceeded).

## Solutions

### Solution to Exercise 1
```rust
fn is_balanced_parentheses(s: &str) -> bool {
    let mut stack = Vec::new();

    for c in s.chars() {
        match c {
            '(' | '[' | '{' => stack.push(c),
            ')' => if stack.pop() != Some('(') { return false; },
            ']' => if stack.pop() != Some('[') { return false; },
            '}' => if stack.pop() != Some('{') { return false; },
            _ => (),
        }
    }

    stack.is_empty()
}

fn main() {
    println!("({[]}): {}", is_balanced_parentheses("({[]})")); // true
    println!("([)]  : {}", is_balanced_parentheses("([)]"));   // false
    println!("(((   : {}", is_balanced_parentheses("((("));   // false
}
```

### Solution to Exercise 2
```rust
fn evaluate_postfix(tokens: &[&str]) -> Result<i32, String> {
    let mut stack: Vec<i32> = Vec::new();

    for &token in tokens {
        match token {
            "+" | "-" | "*" => {
                let right = stack.pop().ok_or("Malformed expression: missing operand")?;
                let left = stack.pop().ok_or("Malformed expression: missing operand")?;
                let result = match token {
                    "+" => left + right,
                    "-" => left - right,
                    "*" => left * right,
                    _ => unreachable!(),
                };
                stack.push(result);
            }
            number_str => {
                let num = number_str.parse::<i32>().map_err(|_| format!("Invalid token: {}", number_str))?;
                stack.push(num);
            }
        }
    }

    if stack.len() == 1 {
        Ok(stack.pop().unwrap())
    } else {
        Err(String::from("Malformed expression: leftover operands on stack"))
    }
}

fn main() {
    let expr = ["5", "3", "+", "2", "*"]; // (5 + 3) * 2 = 16
    println!("Result: {:?}", evaluate_postfix(&expr));
}
```

### Solution to Exercise 3
```rust
use std::collections::VecDeque;

struct SlidingWindowRateLimiter {
    requests: VecDeque<u64>,
    max_requests: usize,
    window_seconds: u64,
}

impl SlidingWindowRateLimiter {
    fn new(max_requests: usize, window_seconds: u64) -> Self {
        SlidingWindowRateLimiter {
            requests: VecDeque::new(),
            max_requests,
            window_seconds,
        }
    }

    fn allow_request(&mut self, current_timestamp: u64) -> bool {
        let cutoff = if current_timestamp >= self.window_seconds {
            current_timestamp - self.window_seconds
        } else {
            0
        };

        // Evict expired timestamps from front of queue in O(1)
        while let Some(&timestamp) = self.requests.front() {
            if timestamp <= cutoff {
                self.requests.pop_front();
            } else {
                break;
            }
        }

        if self.requests.len() < self.max_requests {
            self.requests.push_back(current_timestamp);
            true
        } else {
            false
        }
    }
}

fn main() {
    let mut limiter = SlidingWindowRateLimiter::new(2, 5); // 2 requests per 5-second window

    println!("t=1: {}", limiter.allow_request(1)); // true (1/2)
    println!("t=2: {}", limiter.allow_request(2)); // true (2/2)
    println!("t=3: {}", limiter.allow_request(3)); // false (Rate limited!)
    println!("t=7: {}", limiter.allow_request(7)); // true (t=1 expired; 2/2)
}
```
