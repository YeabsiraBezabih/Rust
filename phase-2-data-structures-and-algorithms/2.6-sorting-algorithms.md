## Concept

Sorting is the process of arranging elements in ascending or descending order. Sorting unlocks **$O(\log N)$ Binary Search**, eliminates duplicate records, and aligns data for maximum CPU cache efficiency.

---

### 1. Insertion Sort ($O(N^2)$ — Simple, Adaptive, In-Place)

Insertion sort works like sorting a hand of playing cards:
- It maintains a sorted sublist on the left.
- It takes the next unsorted element and shifts it leftward until it lands in its correct position.

```
[ 4,  2,  7,  1 ]  -> Pick 2: Compare with 4, shift 4 right -> [ 2,  4,  7,  1 ]
[ 2,  4,  7,  1 ]  -> Pick 7: 7 > 4, stays in place        -> [ 2,  4,  7,  1 ]
[ 2,  4,  7,  1 ]  -> Pick 1: Shift 7, 4, 2 right           -> [ 1,  2,  4,  7 ]
```

- **Best Case**: **$O(N)$** (When the input is already sorted).
- **Worst / Average Case**: **$O(N^2)$**.
- **Auxiliary Space**: **$O(1)$** (Modifies the slice in-place).
- **Use Case**: Outstanding for tiny arrays ($N \le 16$) or nearly-sorted data.

---

### 2. Merge Sort ($O(N \log N)$ — Stable, Divide-and-Conquer)

Merge sort uses **Divide-and-Conquer**:
1. **Divide**: Recursively split the slice in half until slices have length 1.
2. **Conquer**: A slice of length 1 is already sorted.
3. **Combine (Merge)**: Merge two sorted sub-slices by repeatedly comparing their smallest elements.

```
                     [ 8, 3, 2, 9 ]
               ┌───────────┴───────────┐
            [ 8, 3 ]                [ 2, 9 ]
          ┌────┴────┐             ┌────┴────┐
         [8]       [3]           [2]       [9]
          └────┬────┘             └────┬────┘
            [ 3, 8 ]                [ 2, 9 ]
               └───────────┬───────────┘
                     [ 2, 3, 8, 9 ]
```

- **Time Complexity**: **Guaranteed $O(N \log N)$** in all cases (best, average, worst).
- **Auxiliary Space**: **$O(N)$** (Requires a temporary buffer to merge).
- **Stability**: **Stable** (Preserves the original relative order of duplicate elements).

---

### 3. Quicksort ($O(N \log N)$ Average — In-Place Partitioning)

Quicksort is the industry-standard general-purpose sorting algorithm:
1. **Choose a Pivot**: Pick an element (e.g., the last item).
2. **Partition**: Rearrange the slice in-place so all elements $\le \text{pivot}$ are on the left, and all elements $> \text{pivot}$ are on the right. The pivot is now at its permanent sorted position.
3. **Recurse**: Recursively quicksort the left and right partitions.

```
Partitioning [ 7, 2, 1, 6, 8, 5 ] with Pivot = 5:
Left Partition (<= 5)   Pivot   Right Partition (> 5)
   [ 2, 1 ]               5            [ 7, 8, 6 ]
```

- **Time Complexity**: **$O(N \log N)$ average**, $O(N^2)$ worst-case (if pivot is poorly chosen).
- **Auxiliary Space**: **$O(\log N)$** stack frames (In-place sorting in RAM).
- **Cache Locality**: Outstanding hardware cache efficiency because all partitioning is done in-place.

---

### 4. Algorithm Comparison Table

| Algorithm | Best Time | Average Time | Worst Time | Extra Space | Stable? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Insertion Sort** | $O(N)$ | $O(N^2)$ | $O(N^2)$ | $O(1)$ | ✅ Yes |
| **Merge Sort** | $O(N \log N)$ | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | ✅ Yes |
| **Quicksort** | $O(N \log N)$ | $O(N \log N)$ | $O(N^2)$ | $O(\log N)$ | ❌ No |

## Why it matters

In database query engines and log aggregators, sorting is a core operation. Rust's standard library `slice::sort()` uses an advanced hybrid algorithm (Pattern-Defeating Quicksort / Timsort): it uses Quicksort for large partitions, falls back to Heap Sort if recursion gets too deep, and switches to Insertion Sort for sub-slices smaller than 20 elements.

---

## Analogy

- **Insertion Sort**: Sorting cards in your hand as you are dealt them one by one.
- **Merge Sort**: Two clerks each alphabetize a stack of 500 invoices, then zip the two sorted stacks together into a master filing cabinet.
- **Quicksort**: A gym teacher dividing students into those shorter than the teacher (left) and those taller (right), then having each group repeat the same test.

## Code Example

```rust
// 1. Insertion Sort: O(N^2) in-place
pub fn insertion_sort<T: Ord>(slice: &mut [T]) {
    for i in 1..slice.len() {
        let mut j = i;
        // Shift left while previous element is greater
        while j > 0 && slice[j - 1] > slice[j] {
            slice.swap(j - 1, j);
            j -= 1;
        }
    }
}

// 2. Merge Sort: Guaranteed O(N log N), O(N) extra space
pub fn merge_sort<T: Ord + Clone>(slice: &mut [T]) {
    let len = slice.len();
    if len <= 1 {
        return; // Base case
    }

    let mid = len / 2;
    merge_sort(&mut slice[..mid]);
    merge_sort(&mut slice[mid..]);

    // Merge two sorted halves using an auxiliary buffer
    let mut merged = Vec::with_capacity(len);
    let mut left = 0;
    let mut right = mid;

    while left < mid && right < len {
        if slice[left] <= slice[right] {
            merged.push(slice[left].clone());
            left += 1;
        } else {
            merged.push(slice[right].clone());
            right += 1;
        }
    }

    // Collect remaining elements
    while left < mid {
        merged.push(slice[left].clone());
        left += 1;
    }
    while right < len {
        merged.push(slice[right].clone());
        right += 1;
    }

    // Copy back into original slice
    slice.clone_from_slice(&merged);
}

// 3. Quicksort: O(N log N) average, O(1) extra space in RAM
pub fn quicksort<T: Ord>(slice: &mut [T]) {
    if slice.len() <= 1 {
        return; // Base case
    }

    let pivot_index = partition(slice);
    quicksort(&mut slice[..pivot_index]);
    quicksort(&mut slice[pivot_index + 1..]);
}

// Lomuto partition scheme
fn partition<T: Ord>(slice: &mut [T]) -> usize {
    let len = slice.len();
    let pivot_idx = len - 1;
    let mut i = 0;

    for j in 0..pivot_idx {
        if slice[j] <= slice[pivot_idx] {
            slice.swap(i, j);
            i += 1;
        }
    }

    slice.swap(i, pivot_idx);
    i // Final pivot position
}

fn main() {
    let mut latencies_ms = [450, 12, 89, 320, 15, 890, 42];
    println!("Original Latencies: {:?}", latencies_ms);

    insertion_sort(&mut latencies_ms);
    println!("Insertion Sorted  : {:?}", latencies_ms);

    let mut packet_ids = [908, 102, 544, 12, 334, 876, 21];
    merge_sort(&mut packet_ids);
    println!("Merge Sorted      : {:?}", packet_ids);

    let mut ports = [8080, 22, 443, 80, 5432, 3000, 21];
    quicksort(&mut ports);
    println!("Quicksorted       : {:?}", ports);
}
```

## Common Mistakes

### 1. Off-by-One Range Errors in Quicksort Recursion
Calling `quicksort(&mut slice[pivot_index..])` instead of `quicksort(&mut slice[pivot_index + 1..])`. 

*Why it fails*: Including the pivot in the right recursive partition prevents the slice from shrinking when the pivot is at index 0, causing infinite recursion and a stack overflow panic.

---

### 2. Using Merge Sort When Auxiliary RAM is Strictly Constrained
Merge sort requires allocating temporary heap vectors of size $O(N)$. If you are sorting a 2GB file on an embedded device with 512MB of RAM, Merge Sort will crash with Out-Of-Memory (OOM). Use in-place Quicksort or Heapsort instead.

---

### 3. Choosing a Fixed Pivot on Pre-Sorted Data
In naive quicksort with the last element as pivot, running on an already sorted array produces partitions of sizes $N-1$ and $0$, degrading time complexity to $O(N^2)$.

## Solutions

### Solution to Exercise 1
```rust
pub fn insertion_sort_by<T, F>(slice: &mut [T], mut compare: F)
where
    F: FnMut(&T, &T) -> bool,
{
    for i in 1..slice.len() {
        let mut j = i;
        while j > 0 && compare(&slice[j], &slice[j - 1]) {
            slice.swap(j - 1, j);
            j -= 1;
        }
    }
}

fn main() {
    let mut numbers = [10, 50, 20, 80];
    // Sort descending: true if left element should come before right
    insertion_sort_by(&mut numbers, |a, b| a > b);
    println!("Descending: {:?}", numbers); // [80, 50, 20, 10]
}
```

---

### Solution to Exercise 2
**Answer**: In a **stable sort**, `("Alice", 50)` will appear **before** `("Alice", 10)` because it appeared first in the original input. Stability guarantees that elements with equal sorting keys preserve their original relative order.

---

### Solution to Exercise 3
**Explanation**: On already-sorted data (`[1, 2, 3, 4, 5]`), choosing the last element (`5`) produces completely unbalanced partitions ($[1, 2, 3, 4]$ and $[]$), taking $O(N^2)$ steps. By sampling the first (`1`), middle (`3`), and last (`5`) elements and choosing the median (`3`), the slice is partitioned into two roughly equal halves ($[1, 2]$ and $[4, 5]$), guaranteeing balanced $O(N \log N)$ recursion depth.
