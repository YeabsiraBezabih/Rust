## Concept

In traditional database drivers in Python, Node.js, Go, or Java, SQL queries are passed as arbitrary strings. If you misspell a column name, query a non-existent table, or expect an integer when the database returns a string, the error is only caught at **runtime in production**.

**SQLx** is an async, pure-Rust SQL toolkit that connects to your database at **compile time** using procedural macros (`query!`, `query_as!`), validating every SQL query against your actual database schema before a single line of machine code is produced.

```
                      During `cargo build`:
                      ────────────────────
┌──────────────────────────────┐                ┌──────────────────────────────┐
│  Rust Source Code            │                │  Running PostgreSQL Instance │
│                              │                │  (DATABASE_URL)              │
│  sqlx::query_as!(            │                │                              │
│    User,                     │ ─── 1. Parse ─►│  Checks Table Schema         │
│    "SELECT id, email         │ ◄── 2. Type ───│  Verifies Nullability        │
│     FROM users WHERE id=$1", │     Metadata   │  Validates Param Types       │
│    user_id                   │                └──────────────────────────────┘
│  )                           │                               │
└──────────────┬───────────────┘                               │
               │                                               ▼
               │ 3. If Valid: Generates strongly-typed Rust struct mapping
               │    If Invalid: Fails compilation with exact SQL error!
               ▼
┌──────────────────────────────┐
│  100% Type-Safe Binary       │
└──────────────────────────────┘
```

### 1. The Core Macros: `query!`, `query_as!`, `query_scalar!`

#### `sqlx::query!` (Anonymous Struct Generation)
Generates an anonymous struct where field names match column names exactly:

```rust
let user = sqlx::query!(
    "SELECT id, username, balance_cents FROM accounts WHERE id = $1",
    account_id
)
.fetch_one(&pool)
.await?;

// `user` has typed fields: `user.id: i64`, `user.username: String`, `user.balance_cents: i64`
println!("User {} balance: ${:.2}", user.username, user.balance_cents as f64 / 100.0);
```

#### `sqlx::query_as!` (Mapping to Explicit Structs)
Maps query results directly into your domain struct:

```rust
#[derive(sqlx::FromRow, Debug)]
pub struct Account {
    pub id: i64,
    pub username: String,
    pub balance_cents: i64,
    pub is_active: bool,
    pub created_at: chrono::DateTime<chrono::Utc>,
}

let account = sqlx::query_as!(
    Account,
    "SELECT id, username, balance_cents, is_active, created_at FROM accounts WHERE id = $1",
    account_id
)
.fetch_one(&pool)
.await?;
```

#### `sqlx::query_scalar!` (Single Value Extraction)
Extracts a single column directly without struct wrapping:

```rust
let total_users: i64 = sqlx::query_scalar!(
    "SELECT COUNT(*) FROM accounts"
)
.fetch_one(&pool)
.await?
.unwrap_or(0);
```

### 2. Automatic Nullability Inference

SQLx inspects the PostgreSQL schema `NOT NULL` constraints:
- If a column is defined as `NOT NULL`, SQLx types it as `T` (e.g., `String`).
- If a column allows `NULL`, SQLx automatically types it as `Option<T>` (e.g., `Option<String>`).
- If you use an outer join or expression where nullability cannot be proven, you can force non-null or null in SQLx using type overrides:
  - `"SELECT description as \"description!\" FROM products"` (Force `T`)
  - `"SELECT id as \"id?\" FROM products"` (Force `Option<T>`)

---

### 3. Dynamic Queries with `QueryBuilder`

Compile-time macros require constant SQL strings. For dynamic queries (e.g., filtering a product search by optional category, min price, max price, and sorting), SQLx provides the type-safe **`QueryBuilder`**:

```rust
let mut builder: sqlx::QueryBuilder<sqlx::Postgres> = sqlx::QueryBuilder::new(
    "SELECT id, name, price FROM products WHERE 1=1"
);

if let Some(category) = search_category {
    builder.push(" AND category = ");
    builder.push_bind(category);
}

if let Some(max_price) = search_max_price {
    builder.push(" AND price <= ");
    builder.push_bind(max_price);
}

builder.push(" ORDER BY id DESC LIMIT 50");

let query = builder.build_query_as::<ProductSummary>();
let products = query.fetch_all(&pool).await?;
```

### 4. Offline Compilation (`sqlx-data.json`)

In CI/CD environments where a live PostgreSQL instance is not running, SQLx uses offline metadata:
1. Run locally with active DB: `cargo sqlx prepare`
2. This creates `.sqlx/query-*.json` files caching database schemas and query types.
3. In CI, set `SQLX_OFFLINE=true` and run `cargo build` — SQLx validates queries against the offline JSON metadata with zero live database connection!

---

## Why It Matters in Systems Programming

1. **Eliminates SQL Injection by Default**: SQLx macros mandate parameterized query binding (`$1, $2`). Attempting string interpolation (`format!("WHERE id = {}", id)`) is rejected by the macro.
2. **Zero Runtime Overhead**: Unlike traditional ORMs that inspect object reflection and construct SQL dynamically on every request, SQLx compiles SQL strings and column indices into native Rust machine code ahead of time.
3. **Refactoring Confidence**: If a DBA renames a column in the database migration, running `cargo check` instantly highlights every single handler and query across your entire codebase that needs to be updated.

## Complete, Compilable Code Example

Below is a complete async service demonstrating compile-time SQLx patterns, transaction management, and `QueryBuilder` dynamic filtering:

```rust
use sqlx::postgres::PgPoolOptions;
use sqlx::{PgPool, Postgres, QueryBuilder, Row};
use std::time::Duration;

#[derive(Debug, Clone, sqlx::FromRow)]
pub struct UserAccount {
    pub id: i64,
    pub email: String,
    pub full_name: String,
    pub balance_cents: i64,
    pub is_active: bool,
}

pub struct UserFilter {
    pub email_contains: Option<String>,
    pub min_balance_cents: Option<i64>,
    pub is_active_only: bool,
}

pub struct UserRepository {
    pool: PgPool,
}

impl UserRepository {
    pub fn new(pool: PgPool) -> Self {
        Self { pool }
    }

    /// Insert user with parameterized bindings
    pub async fn create_user(
        &self,
        email: &str,
        full_name: &str,
        initial_balance: i64,
    ) -> Result<UserAccount, sqlx::Error> {
        let user = sqlx::query_as!(
            UserAccount,
            r#"
            INSERT INTO accounts (email, full_name, balance_cents, is_active)
            VALUES ($1, $2, $3, true)
            RETURNING id, email, full_name, balance_cents, is_active
            "#,
            email,
            full_name,
            initial_balance
        )
        .fetch_one(&self.pool)
        .await?;

        Ok(user)
    }

    /// Atomic transfer between two accounts inside a SQL transaction
    pub async fn transfer_funds(
        &self,
        from_id: i64,
        to_id: i64,
        amount_cents: i64,
    ) -> Result<(), sqlx::Error> {
        let mut tx = self.pool.begin().await?;

        // 1. Deduct from source
        let updated_rows = sqlx::query!(
            r#"
            UPDATE accounts
            SET balance_cents = balance_cents - $1
            WHERE id = $2 AND balance_cents >= $1
            "#,
            amount_cents,
            from_id
        )
        .execute(&mut *tx)
        .await?
        .rows_affected();

        if updated_rows == 0 {
            // Insufficient funds or invalid source account
            return Err(sqlx::Error::RowNotFound);
        }

        // 2. Credit destination
        sqlx::query!(
            r#"
            UPDATE accounts
            SET balance_cents = balance_cents + $1
            WHERE id = $2
            "#,
            amount_cents,
            to_id
        )
        .execute(&mut *tx)
        .await?;

        // 3. Commit transaction
        tx.commit().await?;
        Ok(())
    }

    /// Dynamic search with QueryBuilder
    pub async fn search_users(&self, filter: UserFilter) -> Result<Vec<UserAccount>, sqlx::Error> {
        let mut qb: QueryBuilder<Postgres> = QueryBuilder::new(
            "SELECT id, email, full_name, balance_cents, is_active FROM accounts WHERE 1=1"
        );

        if let Some(ref email_part) = filter.email_contains {
            qb.push(" AND email ILIKE ");
            qb.push_bind(format!("%{}%", email_part));
        }

        if let Some(min_bal) = filter.min_balance_cents {
            qb.push(" AND balance_cents >= ");
            qb.push_bind(min_bal);
        }

        if filter.is_active_only {
            qb.push(" AND is_active = true");
        }

        qb.push(" ORDER BY id ASC LIMIT 100");

        let query = qb.build_query_as::<UserAccount>();
        let users = query.fetch_all(&self.pool).await?;
        Ok(users)
    }
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    println!("=== SQLx Compile-Time Safety & Repository Pattern ===");
    println!("To connect to a live Postgres instance:");
    println!("1. Set DATABASE_URL=postgres://postgres:password@localhost:5432/finance_db");
    println!("2. Run sqlx migrate run");
    println!("3. Build with cargo build");

    // In a live environment:
    // let pool = PgPoolOptions::new()
    //     .max_connections(20)
    //     .acquire_timeout(Duration::from_secs(3))
    //     .connect(&std::env::var("DATABASE_URL")?)
    //     .await?;
    // let repo = UserRepository::new(pool);

    Ok(())
}
```

## Common Pitfalls & Compiler Errors

### 1. `DATABASE_URL must be set to compile with `query!``
If `DATABASE_URL` is missing from your `.env` file or environment variables, running `cargo build` will fail immediately with:
```
error: error returned from database: DATABASE_URL must be set to compile with `query!`
```
**Fix**: Provide a valid connection string or use `cargo sqlx prepare` with `SQLX_OFFLINE=true`.

### 2. Mismatched Primitive Types (e.g., `BIGINT` vs `i32`)
In PostgreSQL, `BIGINT` maps to `i64`. If your Rust struct uses `i32`, SQLx fails at compile time:
```
error: type `i32` does not match column `balance_cents` of type `INT8` (i64)
```

## Complete Solutions to Exercises

### Solution 1: Soft-Delete Function

```rust
impl UserRepository {
    pub async fn soft_delete_user(&self, user_id: i64) -> Result<bool, sqlx::Error> {
        let result = sqlx::query!(
            "UPDATE accounts SET is_active = false WHERE id = $1 AND is_active = true",
            user_id
        )
        .execute(&self.pool)
        .await?;

        Ok(result.rows_affected() > 0)
    }
}
```

### Solution 2: Force Non-Null Type Override

```rust
pub async fn get_total_vault_balance(pool: &PgPool) -> Result<i64, sqlx::Error> {
    let row = sqlx::query!(
        r#"
        SELECT COALESCE(SUM(balance_cents), 0)::BIGINT as "total!"
        FROM accounts
        "#
    )
    .fetch_one(pool)
    .await?;

    Ok(row.total) // row.total is `i64`, not `Option<i64>`
}
```
