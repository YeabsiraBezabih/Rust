## Concept

When you query PostgreSQL using drivers like `sqlx` or `diesel`, your application does not send raw SQL text over plain HTTP. Instead, it communicates over a stateful TCP connection using the **PostgreSQL Frontend/Backend Protocol (v3.0)**.

Understanding this binary wire format allows systems engineers to write high-performance database proxies, connection poolers (like PgBouncer), protocol parsers, and custom zero-overhead drivers.

```
 Client (Frontend)                                       Postgres Server (Backend)
 ─────────────────                                       ────────────────────────
         │                                                           │
         │ ─── 1. StartupMessage (user, db, version 3.0) ──────────► │
         │ ◄── 2. AuthenticationOk ('R') ─────────────────────────── │
         │ ◄── 3. ReadyForQuery ('Z') ────────────────────────────── │
         │                                                           │
         │ ─── 4. Query ('Q'): "SELECT id, name FROM users" ───────► │
         │ ◄── 5. RowDescription ('T'): [Col 1: id, Col 2: name] ── │
         │ ◄── 6. DataRow ('D'): [4 bytes: 101, 5 bytes: "Alice"] ── │
         │ ◄── 7. DataRow ('D'): [4 bytes: 102, 3 bytes: "Bob"] ──── │
         │ ◄── 8. CommandComplete ('C'): "SELECT 2" ──────────────── │
         │ ◄── 9. ReadyForQuery ('Z'): (idle / transaction status) ─ │
         │                                                           │
```

---

### 1. General Packet Framing

Almost every message in PostgreSQL protocol v3.0 follows a strict binary layout:

| Offset | Size | Type | Description |
| :--- | :--- | :--- | :--- |
| `0` | 1 byte | `u8` (ASCII char) | **Message Type Identifier** (e.g., `'Q'`, `'T'`, `'D'`, `'R'`, `'Z'`) |
| `1` | 4 bytes | `i32` (Big-Endian) | **Payload Length** (includes the 4 length bytes themselves, excluding the 1-byte type tag) |
| `5` | `N` bytes | Binary | **Message Payload** |

> **Special Exception**: The initial `StartupMessage` does NOT contain a 1-byte type tag. It starts directly with the 4-byte length followed by the protocol version (`0x0003_0000` = 196608).

---

### 2. Core Protocol Message Types

| Tag | Name | Direction | Meaning |
| :---: | :--- | :---: | :--- |
| `'p'` | `PasswordMessage` | Client ➔ Server | Password string or SASL/SCRAM token. |
| `'R'` | `Authentication` | Server ➔ Client | Auth status (0 = Ok, 3 = Cleartext, 5 = MD5, 10 = SASL). |
| `'Q'` | `Query` | Client ➔ Server | Execute raw SQL string (Simple Query Protocol). |
| `'T'` | `RowDescription` | Server ➔ Client | Metadata about returned columns (column names, types, OIDs). |
| `'D'` | `DataRow` | Server ➔ Client | A single row of data (column count + byte slices). |
| `'C'` | `CommandComplete`| Server ➔ Client | Query termination tag (e.g., `"SELECT 42"` or `"INSERT 0 1"`). |
| `'Z'` | `ReadyForQuery` | Server ➔ Client | Server is ready for new command (`'I'` = Idle, `'T'` = In Transaction, `'E'` = Failed Transaction). |
| `'X'` | `Terminate` | Client ➔ Server | Gracefully close connection. |

---

### 3. Extended Query Protocol (Prepared Statements)

For high-throughput execution with parameterized queries, PostgreSQL provides the **Extended Query Protocol**:
1. **Parse (`'P'`)**: Compiles SQL string with placeholders (`$1, $2`) into a prepared statement name.
2. **Bind (`'B'`)**: Binds binary parameters to the prepared statement to create a portal.
3. **Describe (`'D'`)**: Requests metadata about the prepared statement or portal.
4. **Execute (`'E'`)**: Executes the portal with maximum row fetch limits.
5. **Sync (`'S'`)**: Flushes pipeline buffers and signals end of batch.

---

## Why It Matters in Systems Programming

1. **Zero-Copy Data Extraction**: Drivers like `sqlx` parse `DataRow` packets directly into Rust structs without allocating intermediate strings, using pointer offsets and network-to-host endian conversions (`i32::from_be_bytes`).
2. **Writing Database Proxies & Load Balancers**: To build tools like PgBouncer or connection multiplexers, you must parse the `'Z'` (ReadyForQuery) packet to know when a transaction completes before reassigning the backend connection.
3. **Binary vs Text Format**: In the Extended Protocol, data can be transferred in raw binary format (e.g., 4-byte integer in binary vs string `"12345678"` in text), cutting network bandwidth and CPU parsing overhead by over 60%.

## Real-World Analogy

Imagine ordering food via an intercom at a drive-through restaurant:
- **Simple Query (`'Q'`)**: You speak your full order into the microphone; the kitchen cooks, packs, delivers all boxes (`'D'`), and says "Order complete" (`'C'`).
- **Extended Query (`'P'/'B'/'E'`)**: You hand the restaurant a reusable recipe template card (`'P'`); each day, you just hand them an envelope with the specific ingredient quantities (`'B'`), they cook it immediately (`'E'`), and give you your meal with zero time wasted re-explaining the recipe.

## Complete, Compilable Code Example

Below is a complete, working PostgreSQL protocol v3.0 packet encoder and decoder in Rust, parsing raw binary frames:

```rust
use std::collections::HashMap;

// ============================================================================
// 1. Protocol Constants & Frame Types
// ============================================================================

pub const PG_PROTOCOL_VERSION_3: i32 = 196608; // 0x00030000

#[derive(Debug, PartialEq, Eq)]
pub enum PgBackendMessage {
    AuthenticationOk,
    AuthenticationCleartextPassword,
    AuthenticationMD5Password([u8; 4]),
    ReadyForQuery(char), // 'I' = Idle, 'T' = In Transaction, 'E' = Error
    CommandComplete(String),
    RowDescription(Vec<String>),
    DataRow(Vec<Option<Vec<u8>>>),
    ErrorResponse(String),
}

// ============================================================================
// 2. Client Packet Encoders (Frontend ➔ Backend)
// ============================================================================

pub struct PgEncoder;

impl PgEncoder {
    /// Encodes the initial StartupMessage (no 1-byte type tag)
    pub fn encode_startup(user: &str, database: &str) -> Vec<u8> {
        let mut payload = Vec::new();
        payload.extend_from_slice(&PG_PROTOCOL_VERSION_3.to_be_bytes());

        // Key-value pairs terminated with null byte (0x00)
        payload.extend_from_slice(b"user\0");
        payload.extend_from_slice(user.as_bytes());
        payload.push(0x00);

        payload.extend_from_slice(b"database\0");
        payload.extend_from_slice(database.as_bytes());
        payload.push(0x00);

        // Final terminating null byte
        payload.push(0x00);

        let total_len = (payload.len() + 4) as i32;
        let mut frame = Vec::with_capacity(total_len as usize);
        frame.extend_from_slice(&total_len.to_be_bytes());
        frame.extend_from_slice(&payload);
        frame
    }

    /// Encodes a Simple Query message ('Q' + len + query_str + \0)
    pub fn encode_query(sql: &str) -> Vec<u8> {
        let mut frame = Vec::new();
        frame.push(b'Q'); // Type tag

        let payload_len = (sql.len() + 1 + 4) as i32; // +1 for null terminator, +4 for len
        frame.extend_from_slice(&payload_len.to_be_bytes());
        frame.extend_from_slice(sql.as_bytes());
        frame.push(0x00); // Null terminator
        frame
    }

    /// Encodes password authentication response ('p')
    pub fn encode_password(password: &str) -> Vec<u8> {
        let mut frame = Vec::new();
        frame.push(b'p');

        let payload_len = (password.len() + 1 + 4) as i32;
        frame.extend_from_slice(&payload_len.to_be_bytes());
        frame.extend_from_slice(password.as_bytes());
        frame.push(0x00);
        frame
    }
}

// ============================================================================
// 3. Server Packet Decoder (Backend ➔ Frontend)
// ============================================================================

pub struct PgDecoder;

impl PgDecoder {
    /// Parses a single Postgres frame from a raw byte slice
    pub fn decode_message(buf: &[u8]) -> Result<(PgBackendMessage, usize), &'static str> {
        if buf.len() < 5 {
            return Err("Buffer too short for header");
        }

        let msg_type = buf[0];
        let length = i32::from_be_bytes([buf[1], buf[2], buf[3], buf[4]]) as usize;
        let total_frame_len = 1 + length;

        if buf.len() < total_frame_len {
            return Err("Incomplete frame payload");
        }

        let payload = &buf[5..total_frame_len];

        let message = match msg_type {
            b'R' => {
                let auth_type = i32::from_be_bytes([payload[0], payload[1], payload[2], payload[3]]);
                match auth_type {
                    0 => PgBackendMessage::AuthenticationOk,
                    3 => PgBackendMessage::AuthenticationCleartextPassword,
                    5 => {
                        let salt = [payload[4], payload[5], payload[6], payload[7]];
                        PgBackendMessage::AuthenticationMD5Password(salt)
                    }
                    _ => return Err("Unsupported authentication method"),
                }
            }
            b'Z' => {
                let tx_status = payload[0] as char;
                PgBackendMessage::ReadyForQuery(tx_status)
            }
            b'C' => {
                let tag = String::from_utf8_lossy(&payload[..payload.len().saturating_sub(1)]).to_string();
                PgBackendMessage::CommandComplete(tag)
            }
            b'T' => {
                // RowDescription: NumFields (2B) -> for each: name\0, tableOID(4B), colIdx(2B), typeOID(4B), typeLen(2B), typeMod(4B), format(2B)
                let num_fields = u16::from_be_bytes([payload[0], payload[1]]) as usize;
                let mut col_names = Vec::with_capacity(num_fields);
                let mut cursor = 2;

                for _ in 0..num_fields {
                    let null_pos = payload[cursor..]
                        .iter()
                        .position(|&b| b == 0)
                        .ok_or("Malformed column name")?;
                    let col_name = String::from_utf8_lossy(&payload[cursor..cursor + null_pos]).to_string();
                    col_names.push(col_name);
                    cursor += null_pos + 1 + 18; // skip name + null + 18 bytes field metadata
                }
                PgBackendMessage::RowDescription(col_names)
            }
            b'D' => {
                // DataRow: NumColumns (2B) -> for each: ColLen (4B) -> ColData
                let num_cols = u16::from_be_bytes([payload[0], payload[1]]) as usize;
                let mut row_values = Vec::with_capacity(num_cols);
                let mut cursor = 2;

                for _ in 0..num_cols {
                    let col_len = i32::from_be_bytes([
                        payload[cursor],
                        payload[cursor + 1],
                        payload[cursor + 2],
                        payload[cursor + 3],
                    ]);
                    cursor += 4;

                    if col_len == -1 {
                        row_values.push(None); // SQL NULL
                    } else {
                        let len = col_len as usize;
                        let val_bytes = payload[cursor..cursor + len].to_vec();
                        row_values.push(Some(val_bytes));
                        cursor += len;
                    }
                }
                PgBackendMessage::DataRow(row_values)
            }
            _ => return Err("Unrecognized message type tag"),
        };

        Ok((message, total_frame_len))
    }
}

// ============================================================================
// 4. Verification & Protocol Simulation
// ============================================================================

fn main() {
    println!("=== 1. Encoding Postgres Startup & Query Messages ===");
    let startup_packet = PgEncoder::encode_startup("postgres", "finance_db");
    println!("Startup Packet ({} bytes): {:02X?}", startup_packet.len(), startup_packet);

    let query_packet = PgEncoder::encode_query("SELECT id, username FROM accounts;");
    println!("Query Packet   ({} bytes): {:02X?}", query_packet.len(), query_packet);

    println!("\n=== 2. Decoding Postgres Backend Response Frames ===");
    
    // Simulate Backend: AuthenticationOk ('R', len=8, type=0)
    let auth_ok_bytes = vec![b'R', 0, 0, 0, 8, 0, 0, 0, 0];
    let (msg, consumed) = PgDecoder::decode_message(&auth_ok_bytes).unwrap();
    println!("Decoded [{} bytes]: {:?}", consumed, msg);

    // Simulate Backend: ReadyForQuery ('Z', len=5, status='I' (Idle))
    let ready_bytes = vec![b'Z', 0, 0, 0, 5, b'I'];
    let (msg, consumed) = PgDecoder::decode_message(&ready_bytes).unwrap();
    println!("Decoded [{} bytes]: {:?}", consumed, msg);

    // Simulate Backend: DataRow ('D', len=18, cols=2, col1=4B "1001", col2=5B "Alice")
    let mut datarow_bytes = Vec::new();
    datarow_bytes.push(b'D');
    let total_len = (4 + 2 + (4 + 4) + (4 + 5)) as i32; // 23 bytes
    datarow_bytes.extend_from_slice(&total_len.to_be_bytes());
    datarow_bytes.extend_from_slice(&2u16.to_be_bytes()); // 2 cols
    // Col 1: length 4, "1001"
    datarow_bytes.extend_from_slice(&4i32.to_be_bytes());
    datarow_bytes.extend_from_slice(b"1001");
    // Col 2: length 5, "Alice"
    datarow_bytes.extend_from_slice(&5i32.to_be_bytes());
    datarow_bytes.extend_from_slice(b"Alice");

    let (msg, consumed) = PgDecoder::decode_message(&datarow_bytes).unwrap();
    println!("Decoded [{} bytes]: {:?}", consumed, msg);

    if let PgBackendMessage::DataRow(cols) = msg {
        let col1_str = String::from_utf8_lossy(cols[0].as_ref().unwrap());
        let col2_str = String::from_utf8_lossy(cols[1].as_ref().unwrap());
        println!("  Extracted Row Data -> ID: {}, Username: {}", col1_str, col2_str);
    }
}
```

## Common Pitfalls & Compiler Errors

### 1. Big-Endian vs Host Byte Ordering
Network protocols are almost universally **Big-Endian** (Network Byte Order). On x86_64 systems (which are Little-Endian), calling `as i32` directly on un-swapped bytes produces invalid numbers. Always use `i32::from_be_bytes()` and `value.to_be_bytes()`.

### 2. SQL NULL Column Representation
In a `DataRow` packet, a column length of `-1` (`0xFFFFFFFF` in 4-byte two's complement) indicates a **SQL NULL** value. If a decoder attempts to read `col_len as usize` without checking for `-1`, it will attempt to allocate $4\text{GB}$ of memory and panic with out-of-bounds index errors.

### Solution 2: Stream Buffer Framing

```rust
pub struct PgFrameBuffer {
    buffer: Vec<u8>,
}

impl PgFrameBuffer {
    pub fn new() -> Self {
        Self { buffer: Vec::new() }
    }

    pub fn feed(&mut self, chunk: &[u8]) {
        self.buffer.extend_from_slice(chunk);
    }

    pub fn pop_message(&mut self) -> Result<Option<PgBackendMessage>, &'static str> {
        if self.buffer.len() < 5 {
            return Ok(None); // Need more bytes for header
        }

        let length = i32::from_be_bytes([
            self.buffer[1],
            self.buffer[2],
            self.buffer[3],
            self.buffer[4],
        ]) as usize;
        let total_frame_len = 1 + length;

        if self.buffer.len() < total_frame_len {
            return Ok(None); // Incomplete frame, wait for next network packet
        }

        let (msg, consumed) = PgDecoder::decode_message(&self.buffer[..total_frame_len])?;
        self.buffer.drain(..consumed);
        Ok(Some(msg))
    }
}
```
