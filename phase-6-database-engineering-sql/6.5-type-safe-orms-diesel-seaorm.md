## Concept

In the Rust database ecosystem, developers choose between two dominant Object-Relational Mapping (ORM) philosophies:

1. **Diesel**: Ultra-strict, compile-time DSL. It uses Rust's type system to verify that queries are structurally valid (you cannot `SELECT` columns from a table not in the `FROM` clause, and you cannot join unrelated tables).
2. **SeaORM**: An async-first, dynamic ActiveModel ORM built on top of `SQLx`. It offers high productivity, dynamic relation chaining, and native async/await support similar to ActiveRecord (Rails) or Prisma (Node.js).

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Rust Database Tooling Spectrum                  │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   [ Raw TCP Protocol ]  ──► [ SQLx ] ──► [ SeaORM ] ──► [ Diesel ]    │
│   (Max Control, Bytes)     (Raw SQL)    (Async Active   (Compile-Time  │
│                                           Model ORM)      Trait DSL)   │
│                                                                        │
│   ◄─── Dynamic / Low-Level ────────────── Strongly Typed / DSL ───►   │
└────────────────────────────────────────────────────────────────────────┘
```

---

### 1. Diesel: Compile-Time Rust DSL

Diesel represents tables and columns as native Rust types generated in a `schema.rs` file:

```rust
// Generated schema.rs
diesel::table! {
    users (id) {
        id -> Int8,
        email -> Text,
        balance_cents -> Int8,
        is_active -> Bool,
    }
}
```

#### Querying with Diesel:
```rust
use crate::schema::users::dsl::*;

// Type-safe query builder checked at compile time by the trait system
let active_users: Vec<User> = users
    .filter(is_active.eq(true))
    .filter(balance_cents.ge(10000))
    .order(id.desc())
    .limit(10)
    .load::<User>(&mut conn)?;
```

If you try to filter `users` by a column belonging to a `posts` table without joining it, **the Rust compiler rejects the code with a trait error**.

---

### 2. SeaORM: Async ActiveModel Architecture

SeaORM generates **Entities**, **Models**, and **ActiveModels** for every table.

- **`Model`**: An immutable snapshot of a database row (`struct User { id, email, ... }`).
- **`ActiveModel`**: A mutable state tracking wrapper where every field is wrapped in `ActiveValue::Set(T)` or `ActiveValue::Unchanged(T)` to execute minimal `UPDATE` statements containing only modified columns.

```rust
use sea_orm::entity::prelude::*;
use sea_orm::{ActiveValue::Set, DatabaseConnection, EntityTrait};

// Update only the email column:
let mut user_active: user::ActiveModel = user_model.into();
user_active.email = Set("new_email@company.com".to_string());
// `balance_cents` remains Unchanged, so SeaORM generates:
// "UPDATE users SET email = $1 WHERE id = $2"

let updated_user = user_active.update(&db).await?;
```

### 3. Feature Comparison

| Feature | SQLx | SeaORM | Diesel |
| :--- | :--- | :--- | :--- |
| **Async Support** | Native (Tokio/Async-std) | Native (Built on SQLx) | Sync (or `diesel-async`) |
| **Query Syntax** | Raw SQL strings | Rust Method Chaining | Rust Macro / Type DSL |
| **Compile-Time Safety**| Checks SQL with live DB | Schema types & Relations | Rust trait-level proof |
| **Active Record Pattern**| No (Raw DTOs) | Yes (`ActiveModel`) | Changeset pattern |
| **Dynamic Queries** | `QueryBuilder` | Built-in `.filter()` | `into_boxed()` |
| **Binary Compilation Speed**| Fast | Medium | Slower (Deep trait tree) |

---

## Why It Matters in Systems Programming

1. **Eliminate Over-Updating**: In high-throughput databases, updating all 30 columns of a table when only 1 column changed causes massive WAL generation and cache invalidation. SeaORM's `ActiveModel` tracks dirty fields to produce minimal SQL updates.
2. **Type-Level Relational Constraints**: Diesel prevents invalid joins and mismatched foreign keys directly in the type system before running queries.
3. **Migration & Code Synchronization**: Both ORMs generate strongly typed entity structs directly from database migrations, ensuring backend logic always stays aligned with SQL DDL.

---

## Real-World Analogy

- **SQLx** is like driving a manual sports car: you control every gear shift (raw SQL), but you get raw performance and precision.
- **SeaORM** is like a modern automatic luxury sedan: you steer with high-level handles (`ActiveModel::insert`, `.filter()`), while the engine manages transmission and gear ratios automatically.
- **Diesel** is like a train on a railway track: the tracks (Rust traits) physically prevent you from steering off course or making a wrong turn, but laying the tracks requires strict adherence to the compiler's rules.

## Complete, Compilable Code Example

Below is a complete implementation demonstrating the **ActiveModel Pattern** and **Type-Safe Entity Lifecycle** in Rust:

```rust
use std::collections::HashMap;

// ============================================================================
// 1. Simulating ActiveValue (Dirty Field Tracking)
// ============================================================================

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ActiveValue<T> {
    Unchanged(T),
    Set(T),
    NotSet,
}

impl<T> ActiveValue<T> {
    pub fn is_dirty(&self) -> bool {
        matches!(self, ActiveValue::Set(_))
    }

    pub fn value(&self) -> Option<&T> {
        match self {
            ActiveValue::Unchanged(v) | ActiveValue::Set(v) => Some(v),
            ActiveValue::NotSet => None,
        }
    }
}

// ============================================================================
// 2. Entity & Model Definitions
// ============================================================================

#[derive(Debug, Clone)]
pub struct AccountModel {
    pub id: i64,
    pub email: String,
    pub balance_cents: i64,
    pub status: String,
}

#[derive(Debug, Clone)]
pub struct AccountActiveModel {
    pub id: ActiveValue<i64>,
    pub email: ActiveValue<String>,
    pub balance_cents: ActiveValue<i64>,
    pub status: ActiveValue<String>,
}

impl From<AccountModel> for AccountActiveModel {
    fn from(model: AccountModel) -> Self {
        Self {
            id: ActiveValue::Unchanged(model.id),
            email: ActiveValue::Unchanged(model.email),
            balance_cents: ActiveValue::Unchanged(model.balance_cents),
            status: ActiveValue::Unchanged(model.status),
        }
    }
}

// ============================================================================
// 3. ActiveModel SQL Generator (Dirty Tracking)
// ============================================================================

impl AccountActiveModel {
    pub fn new() -> Self {
        Self {
            id: ActiveValue::NotSet,
            email: ActiveValue::NotSet,
            balance_cents: ActiveValue::NotSet,
            status: ActiveValue::NotSet,
        }
    }

    /// Generates minimal SQL UPDATE statement containing only modified fields
    pub fn generate_update_sql(&self) -> Option<(String, Vec<String>)> {
        let id_val = match &self.id {
            ActiveValue::Unchanged(id) | ActiveValue::Set(id) => *id,
            ActiveValue::NotSet => return None, // Cannot update without primary key
        };

        let mut set_clauses = Vec::new();
        let mut bind_params = Vec::new();
        let mut param_idx = 1;

        if let ActiveValue::Set(email) = &self.email {
            set_clauses.push(format!("email = ${}", param_idx));
            bind_params.push(email.clone());
            param_idx += 1;
        }

        if let ActiveValue::Set(balance) = &self.balance_cents {
            set_clauses.push(format!("balance_cents = ${}", param_idx));
            bind_params.push(balance.to_string());
            param_idx += 1;
        }

        if let ActiveValue::Set(status) = &self.status {
            set_clauses.push(format!("status = ${}", param_idx));
            bind_params.push(status.clone());
            param_idx += 1;
        }

        if set_clauses.is_empty() {
            return None; // No fields changed! Zero SQL queries needed.
        }

        let sql = format!(
            "UPDATE accounts SET {} WHERE id = ${};",
            set_clauses.join(", "),
            param_idx
        );
        bind_params.push(id_val.to_string());

        Some((sql, bind_params))
    }
}

// ============================================================================
// 4. Verification & ActiveModel Lifecycle
// ============================================================================

fn main() {
    println!("=== 1. Fetching Existing Account Row ===");
    let account = AccountModel {
        id: 42,
        email: "alice@fintech.io".to_string(),
        balance_cents: 250_000,
        status: "ACTIVE".to_string(),
    };
    println!("Loaded Model: {:?}", account);

    println!("\n=== 2. Converting to ActiveModel and Mutating Single Field ===");
    let mut active_account: AccountActiveModel = account.into();

    // Modify ONLY the email field
    active_account.email = ActiveValue::Set("alice_new@fintech.io".to_string());

    println!("Dirty Email? {}", active_account.email.is_dirty());
    println!("Dirty Balance? {}", active_account.balance_cents.is_dirty());

    if let Some((sql, params)) = active_account.generate_update_sql() {
        println!("\nGenerated Optimized SQL:");
        println!("  SQL:    {}", sql);
        println!("  PARAMS: {:?}", params);
    }

    println!("\n=== 3. Mutating Balance as well ===");
    active_account.balance_cents = ActiveValue::Set(300_000);
    if let Some((sql, params)) = active_account.generate_update_sql() {
        println!("  SQL:    {}", sql);
        println!("  PARAMS: {:?}", params);
    }

    println!("\n=== 4. Attempting Update with Zero Changes ===");
    let clean_model = AccountModel {
        id: 99,
        email: "bob@fintech.io".to_string(),
        balance_cents: 10_000,
        status: "ACTIVE".to_string(),
    };
    let clean_active: AccountActiveModel = clean_model.into();
    match clean_active.generate_update_sql() {
        Some(_) => println!("Error: Generated SQL for clean model"),
        None => println!("Success: 0 SQL queries generated when no fields changed!"),
    }
}
```

## Common Pitfalls & Compiler Errors

### 1. The "N+1 Queries" Problem
Using ORMs can make it deceptively easy to load parent records in one query and iterate over their children in a loop, triggering hundreds of individual database queries:
```rust
// ANTI-PATTERN: N+1 queries
let users = user::Entity::find().all(&db).await?;
for user in users {
    let posts = user.find_related(post::Entity).all(&db).await?; // 100 extra queries!
}
```
**Fix**: Use `find_with_related` or eager loading `.find_also_related()` to fetch records in a single `JOIN` query.

### 2. Diesel Sync vs Tokio Runtime Blocking
Classic Diesel is synchronous and blocking. Calling Diesel functions inside an `async fn` blocks the Tokio worker thread.
**Fix**: Always use `diesel-async` or execute queries inside `tokio::task::spawn_blocking`.

## Complete Solutions to Exercises

### Solution 1: ActiveModel Insert Statement

```rust
impl AccountActiveModel {
    pub fn insert_sql(&self) -> Result<(String, Vec<String>), &'static str> {
        let mut cols = Vec::new();
        let mut placeholders = Vec::new();
        let mut binds = Vec::new();
        let mut idx = 1;

        if let ActiveValue::Set(email) = &self.email {
            cols.push("email");
            placeholders.push(format!("${}", idx));
            binds.push(email.clone());
            idx += 1;
        }

        if let ActiveValue::Set(balance) = &self.balance_cents {
            cols.push("balance_cents");
            placeholders.push(format!("${}", idx));
            binds.push(balance.to_string());
            idx += 1;
        }

        if cols.is_empty() {
            return Err("Cannot insert empty ActiveModel");
        }

        let sql = format!(
            "INSERT INTO accounts ({}) VALUES ({}) RETURNING id;",
            cols.join(", "),
            placeholders.join(", ")
        );

        Ok((sql, binds))
    }
}
```
