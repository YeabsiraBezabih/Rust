# Lesson 4.6: Handling Multiple Concurrent Connections: Thread Pools vs. Async I/O

## Concept

A network server cannot simply handle connections sequentially. If a client connects and takes 10 seconds to send its request, a single-threaded server blocks all other users for 10 seconds (**Head-of-Line Blocking**).

However, spawning a new OS thread for every single incoming connection (`thread::spawn(move || handle(stream))`) is dangerous: under a traffic spike or DDoS attack (10,000 connections), the server will exhaust OS memory and thread limits, causing an instant crash.

The standard systems solution is a **Bounded Worker Thread Pool**.

```
TcpListener::bind() ──► listener.incoming()
                              │
                              ▼ [ Incoming Connection Job ]
                   ┌───────────────────────┐
                   │  Shared Job Queue     │ (mpsc Channel + Arc<Mutex<Receiver>>)
                   └──────────┬────────────┘
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│ Worker Thread 1 │  │ Worker Thread 2 │  │ Worker Thread 3 │  (Fixed Pool Size: e.g. 4)
└─────────────────┘  └─────────────────┘  └─────────────────┘
```

---

### 1. The Thread Pool Architecture

A Thread Pool pre-allocates a fixed number of long-running worker threads at startup:
1. **The Job Type**: An owned closure boxed as a trait object:
   `type Job = Box<dyn FnOnce() + Send + 'static>;`
2. **The Queue**: An `mpsc::channel()` where incoming jobs are pushed by the listener and pulled by idle worker threads.
3. **Shared Receiver**: Because `mpsc::Receiver` is single-consumer (`!Sync`), it is wrapped in **`Arc<Mutex<Receiver<Job>>>`** so workers can take turns pulling tasks safely.

---

### 2. Thread Pool vs. Async I/O Trade-Offs

| Architecture | Memory per Connection | Concurrency Scale | Best Used For |
| :--- | :--- | :--- | :--- |
| **Thread-per-Connection** | High (~2MB stack) | Low ($< 1,000$) | Small scripts, local tooling |
| **Bounded Thread Pool** | Medium (Fixed total RAM) | Medium ($1,000 - 10,000$) | CPU-heavy compute, database pools |
| **Asynchronous I/O (Tokio)** | Tiny (~300 bytes) | Massive ($100,000+$) | High-throughput web servers, proxies |

---

### 3. The Graceful Shutdown Protocol

When the `ThreadPool` struct is dropped (e.g. server receives `SIGINT`/`Ctrl+C`):
1. The pool drops its sender channel, signaling EOF to all worker threads.
2. The pool iterates through all worker handles and calls `.join()` to ensure all in-flight requests finish processing before the process exits.

---

## Why it matters

- **Resource Safety**: Hard caps on thread count prevent out-of-memory cascading server failures.
- **CPU Cache Warmth**: Reusing a fixed set of worker threads keeps CPU core caches warm and minimizes OS scheduler thrashing.

---

## Analogy

Think of a **Bank Lobby**:
- **Unbounded Threads**: Hiring a brand-new teller every time a customer walks through the revolving door (the bank runs out of desks and crashes).
- **Bounded Thread Pool**: Having exactly 4 teller windows. Customers wait in a single line. As soon as a teller finishes with a customer, they call the next in line.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::io::{Read, Write};
use std::net::{TcpListener, TcpStream};
use std::sync::{mpsc, Arc, Mutex};
use std::thread;
use std::time::Duration;

// 1. Define the Job Trait Object
type Job = Box<dyn FnOnce() + Send + 'static>;

// 2. Worker Thread Container
struct Worker {
    id: usize,
    thread: Option<thread::JoinHandle<()>>,
}

impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Self {
        let thread = thread::spawn(move || loop {
            // Lock the receiver, pull next job, then immediately drop the lock
            let message = receiver.lock().unwrap().recv();

            match message {
                Ok(job) => {
                    println!("[Worker {}] Executing connection job.", id);
                    job();
                }
                Err(_) => {
                    println!("[Worker {}] Channel closed. Shutting down worker thread.", id);
                    break;
                }
            }
        });

        Worker {
            id,
            thread: Some(thread),
        }
    }
}

// 3. Public ThreadPool Struct
pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: Option<mpsc::Sender<Job>>,
}

impl ThreadPool {
    pub fn new(size: usize) -> Self {
        assert!(size > 0, "ThreadPool size must be greater than zero");

        let (sender, receiver) = mpsc::channel();
        let receiver = Arc::new(Mutex::new(receiver));

        let mut workers = Vec::with_capacity(size);
        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }

        ThreadPool {
            workers,
            sender: Some(sender),
        }
    }

    // Submit a closure job to the worker pool
    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let job = Box::new(f);
        self.sender.as_ref().unwrap().send(job).unwrap();
    }
}

// 4. Graceful Shutdown on Drop
impl Drop for ThreadPool {
    fn drop(&mut self) {
        println!("[ThreadPool] Dropping sender to signal termination...");
        drop(self.sender.take()); // Closes the channel

        for worker in &mut self.workers {
            println!("[ThreadPool] Waiting for worker {} to exit...", worker.id);
            if let Some(thread) = worker.thread.take() {
                thread.join().unwrap();
            }
        }
        println!("[ThreadPool] All workers terminated cleanly.");
    }
}

// Mock HTTP client handler
fn handle_connection(mut stream: TcpStream) {
    let mut buffer = [0u8; 512];
    if let Ok(n) = stream.read(&mut buffer) {
        if n > 0 {
            let response = "HTTP/1.1 200 OK\r\nContent-Length: 13\r\n\r\nHello Systems";
            let _ = stream.write_all(response.as_bytes());
            let _ = stream.flush();
        }
    }
}

fn main() {
    let pool = ThreadPool::new(4);
    println!("ThreadPool created with 4 workers.");

    // Simulate dispatching 6 concurrent jobs
    for job_id in 1..=6 {
        pool.execute(move || {
            thread::sleep(Duration::from_millis(50));
            println!("  --> Job #{} completed.", job_id);
        });
    }

    // Allow jobs to process
    thread::sleep(Duration::from_millis(200));
    println!("Main exiting, pool will now drop and shut down...");
}
```

## Common Mistakes

### 1. Holding the `MutexGuard` While Executing the Job
If you write `let job = receiver.lock().unwrap().recv().unwrap(); job();` in one line, the mutex lock is held **during the entire execution of `job()`**, turning the entire multi-threaded pool into a slow single-threaded queue!
*Fix*: Make sure the lock is dropped before calling `job()`:
```rust
let job = {
    let lock = receiver.lock().unwrap();
    lock.recv()
}; // Lock is dropped here!
if let Ok(task) = job { task(); }
```

---

### 2. Forgetting to Drop the Channel Sender in `Drop`
If `sender` is not dropped or taken via `self.sender.take()`, the receiver's `recv()` call will block forever, and `worker.thread.join()` will hang the entire application shutdown process.

---

### 3. Setting Thread Pool Size to Arbitrary Massive Numbers
Setting a thread pool to 10,000 threads will overwhelm the Linux kernel scheduler with context-switching overhead. A general rule of thumb for CPU-bound pools is `num_cpus` or `num_cpus * 2`.

## Solutions

### Solution to Exercise 1
```rust
use std::net::TcpListener;

fn run_pool_server() {
    let listener = TcpListener::bind("127.0.0.1:0").unwrap();
    let addr = listener.local_addr().unwrap();
    let pool = ThreadPool::new(4);

    thread::spawn(move || {
        for stream in listener.incoming().take(5) {
            if let Ok(stream) = stream {
                pool.execute(move || {
                    handle_connection(stream);
                });
            }
        }
    });

    // Client verification
    let mut client = TcpStream::connect(addr).unwrap();
    client.write_all(b"GET / HTTP/1.1\r\n\r\n").unwrap();
    let mut resp = [0u8; 128];
    let n = client.read(&mut resp).unwrap();
    assert!(String::from_utf8_lossy(&resp[..n]).contains("200 OK"));
}
```

### Solution to Exercise 2
```rust
use std::sync::atomic::{AtomicUsize, Ordering};

pub struct MonitoredThreadPool {
    pool: ThreadPool,
    active_count: Arc<AtomicUsize>,
}

impl MonitoredThreadPool {
    pub fn new(size: usize) -> Self {
        MonitoredThreadPool {
            pool: ThreadPool::new(size),
            active_count: Arc::new(AtomicUsize::new(0)),
        }
    }

    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let counter = Arc::clone(&self.active_count);
        counter.fetch_add(1, Ordering::SeqCst);

        self.pool.execute(move || {
            f();
            counter.fetch_sub(1, Ordering::SeqCst);
        });
    }

    pub fn active_jobs(&self) -> usize {
        self.active_count.load(Ordering::SeqCst)
    }
}
```

### Solution to Exercise 3
```rust
pub struct BoundedThreadPool {
    workers: Vec<Worker>,
    sender: Option<mpsc::SyncSender<Job>>,
}

impl BoundedThreadPool {
    pub fn new(size: usize, queue_bound: usize) -> Self {
        let (sender, receiver) = mpsc::sync_channel(queue_bound);
        let receiver = Arc::new(Mutex::new(receiver));

        let mut workers = Vec::with_capacity(size);
        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }

        BoundedThreadPool {
            workers,
            sender: Some(sender),
        }
    }
}

fn main() {
    run_pool_server();

    let monitored = MonitoredThreadPool::new(2);
    monitored.execute(|| { thread::sleep(Duration::from_millis(50)); });
    assert_eq!(monitored.active_jobs(), 1);

    println!("All thread pool exercises verified!");
}
```
