## Concept

To build a high-performance network server from scratch in Rust, you must understand how data travels from a remote client over physical wire and fiber optic cables into your application memory.

---

### 1. The Internet Protocol Suite (Layer 4 vs. Layer 7)

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 7: Application Layer (HTTP, DNS, SSH, WebSocket)      │ ◄── Our Code (Phase 4)
├─────────────────────────────────────────────────────────────┤
│ Layer 4: Transport Layer (TCP, UDP)                         │ ◄── OS Kernel & Sockets
├─────────────────────────────────────────────────────────────┤
│ Layer 3: Network Layer (IPv4, IPv6)                         │ ◄── IP Routing & Packets
├─────────────────────────────────────────────────────────────┤
│ Layer 2/1: Data Link & Physical (Ethernet, Wi-Fi, Fiber)    │ ◄── Hardware NIC & Cables
└─────────────────────────────────────────────────────────────┘
```

---

### 2. Sockets: The OS Abstraction

A **Socket** is an operating system abstraction (represented as a **File Descriptor** in Linux) that acts as an endpoint for sending and receiving network data.

A socket is identified by a **Socket Address**:
$$\text{Socket Address} = (\text{IP Address}, \text{Port Number})$$
- **`127.0.0.1` (Loopback / Localhost)**: Accessible only from the local machine.
- **`0.0.0.0` (Any Interface)**: Listens for connections on all available network cards (Wi-Fi, Ethernet, Docker bridges).
- **Port Numbers**: 16-bit integers ($0$ to $65535$). Ports $< 1024$ (e.g. $80$ for HTTP, $443$ for HTTPS) require administrative/root privileges on UNIX systems.

---

### 3. TCP (Transmission Control Protocol) Mechanics

TCP provides a **reliable, ordered, full-duplex byte stream**:
1. **Connection-Oriented**: Established via the **3-Way Handshake** (`SYN` $\to$ `SYN-ACK` $\to$ `ACK`).
2. **Guaranteed Delivery**: Lost packets are automatically detected and retransmitted by the OS kernel.
3. **In-Order Sequencing**: Out-of-order packets are buffered and reassembled before being exposed to the application.

```
Client                                     Server
  │                                           │
  ├─── SYN (Synchronize Sequence #) ─────────►│ (Server allocates connection state)
  │◄── SYN-ACK (Acknowledge & Sync) ──────────┤
  ├─── ACK (Connection Established!) ────────►│
  │                                           │
  │========= Full-Duplex TCP Byte Stream =====│
```

---

### 4. The Critical Rule: TCP Has NO Message Boundaries!

> [!IMPORTANT]
> **TCP is a stream of bytes, not a stream of packets.**
> If a client sends two separate 50-byte messages, the server's `read()` call might return:
> - All 100 bytes at once.
> - One 50-byte chunk, then another 50-byte chunk.
> - 30 bytes first, 40 bytes second, and 30 bytes third.

The application layer (HTTP, Redis protocol, gRPC) is **100% responsible** for delimiting where one message ends and the next begins.

---

### 5. Network Byte Order (Big-Endian)

Different CPU architectures store multi-byte numbers differently:
- **x86 / ARM (Little-Endian)**: Stores the least significant byte first in RAM.
- **Network Byte Order (Big-Endian)**: The internet standard stores the most significant byte first.

Rust provides built-in endianness methods:
```rust
let port: u16 = 8080;
let network_bytes: [u8; 2] = port.to_be_bytes(); // Convert to Big-Endian
let decoded: u16 = u16::from_be_bytes(network_bytes);
```

---

## Why it matters

- **Zero Allocation Wire Protocols**: Understanding frame delimiters and network byte order allows parsing binary protocols (DNS, Redis RESP, WebSockets) directly from byte slices without string parsing overhead.
- **Preventing Truncation Bugs**: Knowing that TCP can split data across multiple packets prevents fatal bugs where an incomplete HTTP header causes the server to drop connections prematurely.

---

## Analogy

Think of TCP as a **Garden Hose**:
- You pour water (bytes) into one end, and it flows out the other end as a continuous stream.
- If you want to send two separate "cups" of water through the hose, you must place physical markers (delimiters or length headers) into the stream so the receiver knows when one cup ends and the next begins.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
// Length-Prefixed Binary Packet Protocol
// Wire Format: [Payload Length (4 bytes, Big-Endian)] + [Raw Payload Bytes]

#[derive(Debug, PartialEq, Eq)]
pub struct Packet<'a> {
    pub payload: &'a [u8],
}

impl<'a> Packet<'a> {
    pub fn new(payload: &'a [u8]) -> Self {
        Packet { payload }
    }

    // Serialize packet into a contiguous byte buffer
    pub fn serialize(&self) -> Vec<u8> {
        let length = self.payload.len() as u32;
        let mut buffer = Vec::with_capacity(4 + self.payload.len());

        // 1. Write length in Network Byte Order (Big-Endian)
        buffer.extend_from_slice(&length.to_be_bytes());

        // 2. Write payload bytes
        buffer.extend_from_slice(self.payload);
        buffer
    }

    // Zero-copy deserializer: Parses packet without copying payload memory
    pub fn deserialize(buffer: &'a [u8]) -> Result<(Self, &'a [u8]), &'static str> {
        if buffer.len() < 4 {
            return Err("Buffer too short to contain 4-byte header");
        }

        // Read 4-byte length prefix
        let length_bytes: [u8; 4] = buffer[0..4].try_into().unwrap();
        let payload_len = u32::from_be_bytes(length_bytes) as usize;

        if buffer.len() < 4 + payload_len {
            return Err("Incomplete packet payload in buffer");
        }

        let payload = &buffer[4..4 + payload_len];
        let remaining_buffer = &buffer[4 + payload_len..];

        Ok((Packet { payload }, remaining_buffer))
    }
}

fn main() {
    println!("--- Testing Wire Serialization ---");
    let msg1 = b"PING";
    let msg2 = b"METRICS_REPORT_OK";

    let packet1 = Packet::new(msg1);
    let packet2 = Packet::new(msg2);

    // Simulate sending packets back-to-back over a TCP stream
    let mut tcp_stream_buffer = Vec::new();
    tcp_stream_buffer.extend_from_slice(&packet1.serialize());
    tcp_stream_buffer.extend_from_slice(&packet2.serialize());

    println!("Total bytes on wire: {} bytes", tcp_stream_buffer.len());

    // Receiver decodes stream frame by frame
    let mut stream_slice = &tcp_stream_buffer[..];
    let mut received_packets = Vec::new();

    while !stream_slice.is_empty() {
        let (packet, remainder) = Packet::deserialize(stream_slice).unwrap();
        println!("Received packet: \"{}\" (length: {} bytes)", 
            String::from_utf8_lossy(packet.payload), packet.payload.len());
        received_packets.push(packet);
        stream_slice = remainder;
    }

    assert_eq!(received_packets.len(), 2);
    assert_eq!(received_packets[0].payload, b"PING");
    assert_eq!(received_packets[1].payload, b"METRICS_REPORT_OK");
    println!("Stream reassembly succeeded!");
}
```

## Common Mistakes

### 1. Assuming a Single Read Returns a Full Application Message
Writing code that assumes `stream.read(&mut buf)` will always receive all bytes in a single call. If a network router fragments the packet, the header and payload will arrive in separate reads.

---

### 2. Using Host Byte Order on the Wire
Serializing integers using `to_ne_bytes()` (native endianness). If a Little-Endian server communicates with a Big-Endian mainframe, multi-byte integers will be reversed and corrupt data. Always use `to_be_bytes()` (Big-Endian).

---

### 3. Binding to `127.0.0.1` Inside Docker Containers
When running a service inside Docker or a cloud VM, binding to `127.0.0.1` prevents host machines and external load balancers from connecting. Always bind to `0.0.0.0` for public network listeners.

## Solutions

### Solution to Exercise 1
```rust
pub struct MessagePacket<'a> {
    pub msg_id: u16,
    pub payload: &'a [u8],
}

impl<'a> MessagePacket<'a> {
    pub fn serialize(&self) -> Vec<u8> {
        let len = (2 + self.payload.len()) as u32;
        let mut buf = Vec::with_capacity(4 + 2 + self.payload.len());
        buf.extend_from_slice(&len.to_be_bytes());
        buf.extend_from_slice(&self.msg_id.to_be_bytes());
        buf.extend_from_slice(self.payload);
        buf
    }

    pub fn deserialize(buf: &'a [u8]) -> Result<(Self, &'a [u8]), &'static str> {
        if buf.len() < 6 {
            return Err("Buffer too short");
        }
        let len = u32::from_be_bytes(buf[0..4].try_into().unwrap()) as usize;
        if buf.len() < 4 + len {
            return Err("Incomplete payload");
        }
        let msg_id = u16::from_be_bytes(buf[4..6].try_into().unwrap());
        let payload = &buf[6..4 + len];
        let rem = &buf[4 + len..];
        Ok((MessagePacket { msg_id, payload }, rem))
    }
}
```

### Solution to Exercise 2
```rust
#[derive(Debug, PartialEq, Eq)]
pub enum PacketStatus {
    Complete { length: usize },
    NeedsMoreData { expected: usize, available: usize },
    InvalidHeader,
}

pub fn check_packet_status(buffer: &[u8]) -> PacketStatus {
    if buffer.len() < 4 {
        return PacketStatus::NeedsMoreData { expected: 4, available: buffer.len() };
    }
    let length = u32::from_be_bytes(buffer[0..4].try_into().unwrap()) as usize;
    let total_required = 4 + length;
    if buffer.len() < total_required {
        PacketStatus::NeedsMoreData {
            expected: total_required,
            available: buffer.len(),
        }
    } else {
        PacketStatus::Complete { length: total_required }
    }
}
```

### Solution to Exercise 3
```rust
fn test_endianness_roundtrip() {
    let timestamp: u64 = 1756982400000;
    let be_bytes = timestamp.to_be_bytes();
    let decoded = u64::from_be_bytes(be_bytes);
    assert_eq!(timestamp, decoded);
}

fn main() {
    let pkt = MessagePacket { msg_id: 1001, payload: b"STATUS_OK" };
    let bytes = pkt.serialize();
    let (decoded, _) = MessagePacket::deserialize(&bytes).unwrap();
    assert_eq!(decoded.msg_id, 1001);
    assert_eq!(decoded.payload, b"STATUS_OK");

    assert_eq!(check_packet_status(&bytes), PacketStatus::Complete { length: bytes.len() });
    assert_eq!(check_packet_status(&bytes[0..3]), PacketStatus::NeedsMoreData { expected: 4, available: 3 });

    test_endianness_roundtrip();
    println!("All networking foundations exercises verified!");
}
```
