## Concept

In a production web service, every HTTP request requires **cross-cutting infrastructure** operations:
- Measuring request latency for performance monitoring.
- Printing structured access logs.
- Verifying authentication tokens (`Authorization: Bearer ...`).
- Setting security headers (`X-Frame-Options: DENY`).

Hardcoding these concerns into every route handler creates massive code duplication. **Middleware** solves this through the **Onion / Pipeline Model (Chain of Responsibility)**.

```
Incoming HTTP Request
       │
       ▼ [ 1. Logger Middleware (Start Timer) ]
       │
       ▼ [ 2. Auth Middleware (Validate Token) ]
       │
       ▼ [ 3. Route Handler: /api/orders ] ──► Returns HttpResponse::ok()
       │
       ▼ [ 2. Auth Middleware (Passes through) ]
       │
       ▼ [ 1. Logger Middleware (Calculates Elapsed Time & Logs: "200 OK in 1.2ms") ]
       │
       ▼
Outbound Response to Client
```

---

### 1. The Middleware Trait Definition

A middleware wraps around the execution of the next stage in the pipeline:

```rust
pub trait Middleware: Send + Sync + 'static {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse;
}
```

- **Pre-Processing**: Inspect or mutate `req` before calling `next(req)`.
- **Short-Circuiting**: Return an early `HttpResponse::unauthorized()` without ever calling `next(req)`.
- **Post-Processing**: Inspect or mutate the returned `HttpResponse` after `next(req)` completes (e.g. attaching timing headers).

---

## Why it matters

- **Separation of Concerns**: Your business logic handlers focus 100% on domain data, while security, rate-limiting, and telemetry remain isolated in reusable modules.
- **Composable Pipelines**: You can attach global middleware across all routes or apply specific middleware (e.g. Admin Role Check) to specific route groups.

---

## Analogy

Think of **Airport Security and Boarding**:
- Before reaching your airplane seat (the Route Handler):
  1. **Checkpoint 1 (ID Scanner)**: Confirms your identity (Auth Middleware). If invalid, you are turned away immediately (**Short-Circuit**).
  2. **Checkpoint 2 (Baggage Scan)**: Checks baggage size (Validation Middleware).
- When you land, your passport is stamped with the arrival time (Logging Middleware).

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use std::collections::HashMap;
use std::time::Instant;

#[derive(Debug, Clone)]
pub struct HttpRequest {
    pub method: String,
    pub path: String,
    pub headers: HashMap<String, String>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct HttpResponse {
    pub status: u16,
    pub headers: HashMap<String, String>,
    pub body: String,
}

impl HttpResponse {
    pub fn ok(body: &str) -> Self {
        HttpResponse {
            status: 200,
            headers: HashMap::new(),
            body: body.to_string(),
        }
    }

    pub fn unauthorized(msg: &str) -> Self {
        HttpResponse {
            status: 401,
            headers: HashMap::new(),
            body: msg.to_string(),
        }
    }
}

pub trait Middleware: Send + Sync + 'static {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse;
}

// 1. Concrete Middleware: Request Logger & Timer
pub struct LoggingMiddleware;

impl Middleware for LoggingMiddleware {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        let start = Instant::now();
        println!("[LOG PRE]  --> {} {}", req.method, req.path);

        // Call downstream handler
        let mut response = next(req);

        let elapsed = start.elapsed();
        println!(
            "[LOG POST] <-- {} {} | Status: {} | Elapsed: {:?}",
            req.method, req.path, response.status, elapsed
        );

        // Inject timing header into response
        response.headers.insert(
            "X-Response-Time-Micros".to_string(),
            elapsed.as_micros().to_string(),
        );

        response
    }
}

// 2. Concrete Middleware: Token Authentication & Short-Circuiting
pub struct AuthMiddleware {
    valid_token: String,
}

impl AuthMiddleware {
    pub fn new(valid_token: &str) -> Self {
        AuthMiddleware {
            valid_token: valid_token.to_string(),
        }
    }
}

impl Middleware for AuthMiddleware {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        if let Some(token) = req.headers.get("authorization") {
            if token == &format!("Bearer {}", self.valid_token) {
                // Token valid: Proceed to route handler
                return next(req);
            }
        }

        // Token missing or invalid: Short-circuit with 401!
        println!("[AUTH] Unauthorized access attempt blocked!");
        HttpResponse::unauthorized("Invalid or missing Bearer token")
    }
}

// 3. Composable Middleware Pipeline
pub struct Pipeline {
    middlewares: Vec<Box<dyn Middleware>>,
}

impl Pipeline {
    pub fn new() -> Self {
        Pipeline {
            middlewares: Vec::new(),
        }
    }

    pub fn use_middleware<M: Middleware>(&mut self, middleware: M) {
        self.middlewares.push(Box::new(middleware));
    }

    // Executes the entire middleware chain ending with the final handler
    pub fn execute<H>(&self, mut req: HttpRequest, handler: H) -> HttpResponse
    where
        H: Fn(&mut HttpRequest) -> HttpResponse + 'static,
    {
        Self::dispatch_recursive(&self.middlewares, &mut req, &handler)
    }

    fn dispatch_recursive(
        middlewares: &[Box<dyn Middleware>],
        req: &mut HttpRequest,
        handler: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        if let Some((first, rest)) = middlewares.split_first() {
            first.handle(req, &|next_req| {
                Self::dispatch_recursive(rest, next_req, handler)
            })
        } else {
            handler(req)
        }
    }
}

fn main() {
    let mut pipeline = Pipeline::new();
    pipeline.use_middleware(LoggingMiddleware);
    pipeline.use_middleware(AuthMiddleware::new("secret-token-123"));

    // Core Business Logic Handler
    let order_handler = |_req: &mut HttpRequest| -> HttpResponse {
        println!("  [Handler] Processing order creation business logic...");
        HttpResponse::ok(r#"{"order_id": 9001, "status": "created"}"#)
    };

    println!("--- Scenario 1: Request with Valid Token ---");
    let mut valid_req = HttpRequest {
        method: "POST".into(),
        path: "/api/orders".into(),
        headers: HashMap::new(),
    };
    valid_req.headers.insert("authorization".into(), "Bearer secret-token-123".into());

    let resp1 = pipeline.execute(valid_req, order_handler);
    assert_eq!(resp1.status, 200);
    println!("Response Headers: {:?}", resp1.headers);

    println!("\n--- Scenario 2: Request with Invalid Token (Short-Circuit) ---");
    let unauth_req = HttpRequest {
        method: "POST".into(),
        path: "/api/orders".into(),
        headers: HashMap::new(),
    };

    let resp2 = pipeline.execute(unauth_req, order_handler);
    assert_eq!(resp2.status, 401);
    assert_eq!(resp2.body, "Invalid or missing Bearer token");
}
```

## Common Mistakes

### 1. Forgetting to Call `next(req)` in Pass-Through Middleware
If your middleware is meant to inspect the request (e.g. metrics) but omits `next(req)` or returns a static response prematurely, downstream handlers will never execute.

---

### 2. Mutating Request Headers While Retaining Stale Borrows
Modifying `req.headers` while holding an active reference to a header value causes a borrow checker collision. Clone values before mutating the map.

---

### 3. Reordering Middleware Chains
Putting `LoggingMiddleware` *after* `AuthMiddleware`. If an unauthenticated request is rejected by Auth, the Logger would never be invoked and the 401 response would never be recorded in access logs! Always place observability middleware at the outermost layer.

## Solutions

### Solution to Exercise 1
```rust
pub struct SecurityHeadersMiddleware;

impl Middleware for SecurityHeadersMiddleware {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        let mut response = next(req);
        response.headers.insert("X-Content-Type-Options".into(), "nosniff".into());
        response.headers.insert("X-Frame-Options".into(), "DENY".into());
        response.headers.insert(
            "Strict-Transport-Security".into(),
            "max-age=31536000; includeSubDomains".into(),
        );
        response
    }
}
```

### Solution to Exercise 2
```rust
use std::collections::HashSet;

pub struct IpFilterMiddleware {
    allowed_ips: HashSet<String>,
}

impl IpFilterMiddleware {
    pub fn new(ips: &[&str]) -> Self {
        let mut allowed = HashSet::new();
        for &ip in ips { allowed.insert(ip.to_string()); }
        IpFilterMiddleware { allowed_ips: allowed }
    }
}

impl Middleware for IpFilterMiddleware {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        if let Some(client_ip) = req.headers.get("x-forwarded-for") {
            if self.allowed_ips.contains(client_ip) {
                return next(req);
            }
        }

        HttpResponse {
            status: 403,
            headers: HashMap::new(),
            body: "Forbidden: IP not authorized".into(),
        }
    }
}
```

### Solution to Exercise 3
```rust
use std::sync::atomic::{AtomicU64, Ordering};

pub struct RequestIdMiddleware {
    counter: AtomicU64,
}

impl RequestIdMiddleware {
    pub fn new() -> Self {
        RequestIdMiddleware { counter: AtomicU64::new(1) }
    }
}

impl Middleware for RequestIdMiddleware {
    fn handle(
        &self,
        req: &mut HttpRequest,
        next: &dyn Fn(&mut HttpRequest) -> HttpResponse,
    ) -> HttpResponse {
        let req_id = req
            .headers
            .entry("x-request-id".into())
            .or_insert_with(|| format!("req-{}", self.counter.fetch_add(1, Ordering::Relaxed)))
            .clone();

        let mut response = next(req);
        response.headers.insert("X-Request-ID".into(), req_id);
        response
    }
}

fn main() {
    let mut pipeline = Pipeline::new();
    pipeline.use_middleware(SecurityHeadersMiddleware);
    pipeline.use_middleware(RequestIdMiddleware::new());

    let req = HttpRequest {
        method: "GET".into(),
        path: "/status".into(),
        headers: HashMap::new(),
    };

    let resp = pipeline.execute(req, |_| HttpResponse::ok("all green"));
    assert_eq!(resp.headers.get("X-Frame-Options"), Some(&"DENY".to_string()));
    assert!(resp.headers.contains_key("X-Request-ID"));
    println!("All middleware architecture exercises verified!");
}
```
