## Concept

**HTTP/1.1** (Hypertext Transfer Protocol, RFC 7230 / RFC 9112) is the foundational application-layer protocol of the World Wide Web.

At the wire level, HTTP/1.1 is a **plain-text, request-response protocol** built on top of a TCP byte stream.

---

### 1. The Wire Format of an HTTP Request

An HTTP request consists of 4 distinct sections separated by **`\r\n` (CRLF — Carriage Return + Line Feed)**:

```http
GET /api/v1/users?limit=10 HTTP/1.1\r\n
Host: api.example.com\r\n
User-Agent: RustSystemsClient/1.0\r\n
Accept: application/json\r\n
Content-Length: 0\r\n
\r\n
[Optional Request Body Bytes]
```

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Request Line: METHOD + " " + PATH + " " + VERSION + \r\n │
├─────────────────────────────────────────────────────────────┤
│ 2. Headers: KEY + ": " + VALUE + \r\n (Repeated)            │
├─────────────────────────────────────────────────────────────┤
│ 3. Empty Line: \r\n (The Double CRLF delimiter "\r\n\r\n")  │
├─────────────────────────────────────────────────────────────┤
│ 4. Message Body: (Length specified by Content-Length header)│
└─────────────────────────────────────────────────────────────┘
```

---

### 2. The Wire Format of an HTTP Response

```http
HTTP/1.1 200 OK\r\n
Content-Type: application/json; charset=utf-8\r\n
Content-Length: 26\r\n
Connection: close\r\n
\r\n
{"status":"healthy","id":1}
```

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Status Line: VERSION + " " + CODE + " " + REASON + \r\n  │
├─────────────────────────────────────────────────────────────┤
│ 2. Headers: Content-Type, Content-Length, Date, etc. + \r\n │
├─────────────────────────────────────────────────────────────┤
│ 3. Empty Line: \r\n                                         │
├─────────────────────────────────────────────────────────────┤
│ 4. Response Body: Raw HTML, JSON, or Binary Bytes           │
└─────────────────────────────────────────────────────────────┘
```

---

### 3. HTTP Methods & Status Codes

#### Standard HTTP Methods
- **`GET`**: Retrieve a resource (Idempotent & Safe, no body).
- **`POST`**: Create a new resource or submit data.
- **`PUT`**: Replace an entire existing resource (Idempotent).
- **`PATCH`**: Partially update an existing resource.
- **`DELETE`**: Remove a resource (Idempotent).
- **`HEAD`**: Same as `GET`, but server returns **only headers**, no body.
- **`OPTIONS`**: Query supported methods (CORS preflight).

#### HTTP Status Code Categories
- **`2xx Success`**: `200 OK`, `201 Created`, `204 No Content`.
- **`3xx Redirection`**: `301 Moved Permanently`, `302 Found`, `304 Not Modified`.
- **`4xx Client Error`**: `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `405 Method Not Allowed`.
- **`5xx Server Error`**: `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`.

---

### 4. The Critical Role of `\r\n\r\n` and `Content-Length`

- **Header Termination**: The double carriage return + line feed (`\r\n\r\n` or `[13, 10, 13, 10]` in bytes) marks the absolute end of the HTTP headers.
- **Body Framing**: If a body is present, the server **must** read exactly the number of bytes declared in the `Content-Length` header.

> [!WARNING]
> `Content-Length` is the number of **raw bytes**, NOT the number of UTF-8 characters! An emoji like `🚀` is 1 character but **4 bytes**.

---

## Why it matters

- **Writing HTTP Engines**: Reverse proxies (like Envoy or NGINX) parse millions of HTTP request lines per second. Understanding every byte delimiter enables writing high-speed, zero-copy parsers.
- **Security & HTTP Request Smuggling**: If a proxy and a backend server disagree on where an HTTP message ends (e.g., due to malformed CRLF or conflicting `Content-Length` headers), attackers can bypass firewall rules.

---

## Analogy

Think of an **Official Postal Letter**:
- The **Request Line & Headers** are the envelope with the recipient address, stamp, and sender ID.
- The **`\r\n\r\n` double CRLF** is the physical seal of the envelope.
- The **Body** is the letter inside. You can't read the letter without opening the seal.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
#[derive(Debug, PartialEq, Eq, Clone, Copy)]
pub enum Method {
    Get,
    Post,
    Put,
    Delete,
    Head,
}

impl Method {
    pub fn from_str(s: &str) -> Result<Self, &'static str> {
        match s {
            "GET" => Ok(Method::Get),
            "POST" => Ok(Method::Post),
            "PUT" => Ok(Method::Put),
            "DELETE" => Ok(Method::Delete),
            "HEAD" => Ok(Method::Head),
            _ => Err("Unsupported HTTP Method"),
        }
    }

    pub fn as_str(&self) -> &'static str {
        match self {
            Method::Get => "GET",
            Method::Post => "POST",
            Method::Put => "PUT",
            Method::Delete => "DELETE",
            Method::Head => "HEAD",
        }
    }
}

#[derive(Debug, PartialEq, Eq, Clone, Copy)]
pub enum StatusCode {
    Ok = 200,
    Created = 201,
    BadRequest = 400,
    NotFound = 404,
    InternalServerError = 500,
}

impl StatusCode {
    pub fn reason_phrase(&self) -> &'static str {
        match self {
            StatusCode::Ok => "OK",
            StatusCode::Created => "Created",
            StatusCode::BadRequest => "Bad Request",
            StatusCode::NotFound => "Not Found",
            StatusCode::InternalServerError => "Internal Server Error",
        }
    }

    pub fn code(&self) -> u16 {
        *self as u16
    }
}

// Locate the header-body delimiter "\r\n\r\n" in a raw byte stream
pub fn find_crlf_crlf(buffer: &[u8]) -> Option<usize> {
    buffer
        .windows(4)
        .position(|window| window == b"\r\n\r\n")
}

fn main() {
    let raw_http_request = b"\
GET /api/v1/health HTTP/1.1\r\n\
Host: localhost:8080\r\n\
User-Agent: curl/8.5.0\r\n\
Accept: */*\r\n\
\r\n\
";

    // 1. Locate end of headers
    if let Some(header_end_idx) = find_crlf_crlf(raw_http_request) {
        println!("Header section ends at byte index: {}", header_end_idx);
        let header_bytes = &raw_http_request[..header_end_idx];
        println!("--- Raw Header Text ---");
        println!("{}", String::from_utf8_lossy(header_bytes));
    }

    // 2. Status code demonstration
    let status = StatusCode::NotFound;
    let status_line = format!("HTTP/1.1 {} {}\r\n", status.code(), status.reason_phrase());
    print!("\nFormatted Response Status Line:\n{}", status_line);
    assert_eq!(status_line, "HTTP/1.1 404 Not Found\r\n");
}
```

## Common Mistakes

### 1. Using `\n\n` Instead of `\r\n\r\n`
Many UNIX developers assume line breaks are just `\n` (`0x0A`). Standard HTTP strictly mandates `\r\n` (`0x0D 0x0A`). Looking only for `\n\n` can cause parse errors on compliant clients.

---

### 2. Case-Sensitive Header Comparison
Checking `if header_name == "Content-Length"` will fail if a client sends `content-length: 42` or `Content-length: 42`. The HTTP specification explicitly declares header names to be **case-insensitive**. Always convert header keys to lowercase before comparison.

---

### 3. Measuring `Content-Length` by Character Count
Writing `body.chars().count()` instead of `body.as_bytes().len()`. If the body contains multibyte UTF-8 characters (e.g. `{"msg": "🦀"}`), character count is smaller than byte length, causing the HTTP client to truncate the body and hang.

## Solutions

### Solution to Exercise 1
```rust
use std::collections::HashMap;

#[derive(Debug, Default)]
pub struct HeaderMap {
    headers: HashMap<String, String>,
}

impl HeaderMap {
    pub fn new() -> Self {
        HeaderMap { headers: HashMap::new() }
    }

    pub fn insert(&mut self, key: &str, value: &str) {
        self.headers.insert(key.to_ascii_lowercase(), value.to_string());
    }

    pub fn get(&self, key: &str) -> Option<&str> {
        self.headers.get(&key.to_ascii_lowercase()).map(|s| s.as_str())
    }
}
```

### Solution to Exercise 2
```rust
pub fn build_http_response(status: StatusCode, content_type: &str, body: &[u8]) -> Vec<u8> {
    let mut response = Vec::new();

    // 1. Status line
    let status_line = format!("HTTP/1.1 {} {}\r\n", status.code(), status.reason_phrase());
    response.extend_from_slice(status_line.as_bytes());

    // 2. Headers
    let headers = format!(
        "Content-Type: {}\r\nContent-Length: {}\r\nConnection: close\r\n\r\n",
        content_type,
        body.len() // Accurate byte count!
    );
    response.extend_from_slice(headers.as_bytes());

    // 3. Body
    response.extend_from_slice(body);
    response
}
```

### Solution to Exercise 3
```rust
pub fn parse_request_line(line: &str) -> Result<(Method, &str, &str), &'static str> {
    let mut parts = line.split_whitespace();

    let method_str = parts.next().ok_or("Missing HTTP Method")?;
    let path = parts.next().ok_or("Missing URI Path")?;
    let version = parts.next().ok_or("Missing HTTP Version")?;

    if parts.next().is_some() {
        return Err("Too many tokens in request line");
    }

    if version != "HTTP/1.1" && version != "HTTP/1.0" {
        return Err("Unsupported HTTP Version");
    }

    let method = Method::from_str(method_str)?;
    Ok((method, path, version))
}

fn main() {
    let mut headers = HeaderMap::new();
    headers.insert("Content-Type", "text/plain");
    assert_eq!(headers.get("content-type"), Some("text/plain"));
    assert_eq!(headers.get("CONTENT-TYPE"), Some("text/plain"));

    let body = "🚀 Rust Systems Server 🚀".as_bytes();
    let resp = build_http_response(StatusCode::Ok, "text/plain", body);
    let resp_str = String::from_utf8_lossy(&resp);
    assert!(resp_str.contains("Content-Length: 32")); // Emojis are 4 bytes each!

    let (m, p, v) = parse_request_line("GET /index.html HTTP/1.1").unwrap();
    assert_eq!(m, Method::Get);
    assert_eq!(p, "/index.html");
    assert_eq!(v, "HTTP/1.1");

    println!("All HTTP specification exercises verified!");
}
```
