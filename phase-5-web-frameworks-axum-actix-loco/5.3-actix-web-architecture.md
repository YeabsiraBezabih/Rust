## Concept

While Axum multiplexes all connections across a shared Tokio multi-threaded work-stealing pool, **Actix-web** uses an isolated **Multi-Worker Thread Architecture**:
- When you launch `HttpServer::new(|| App::new()...)`, Actix spawns **$N$ independent OS worker threads** (defaulting to the number of physical CPU cores).
- The closure passed to `HttpServer::new` is an **App Factory**: it is executed separately on each worker thread to construct an independent instance of the web application.

```
OS Socket Listener (Port 8080)
           │
           ├──► [ Worker Thread 1 ] ──► App Instance 1 (Thread-Local Event Loop)
           ├──► [ Worker Thread 2 ] ──► App Instance 2 (Thread-Local Event Loop)
           ├──► [ Worker Thread 3 ] ──► App Instance 3 (Thread-Local Event Loop)
           └──► [ Worker Thread 4 ] ──► App Instance 4 (Thread-Local Event Loop)
```

---

### 1. State Management: `web::Data<T>`

Because applications are instantiated per worker thread, sharing state requires **`web::Data<T>`** (which uses an internal `Arc<T>`):

```rust
// ✅ CORRECT: State created OUTSIDE the factory is shared across ALL workers
let shared_db = web::Data::new(DatabasePool::connect());

HttpServer::new(move || {
    App::new()
        .app_data(shared_db.clone()) // Clones Arc pointer to each worker
        .route("/users", web::get().to(get_users))
})
```

> [!WARNING]
> If you call `web::Data::new(State)` *inside* the `HttpServer::new(|| ...)` closure, each worker thread will allocate its own separate state, causing counters and in-memory caches to be disjoint across threads!

---

### 2. Declarative Route Attributes vs. Fluent Routing

Actix-web supports both procedural macro routing and fluent registration:

```rust
// Macro style
#[get("/api/v1/orders/{order_id}")]
async fn get_order(
    path: web::Path<u64>,
    data: web::Data<AppState>,
) -> impl Responder {
    let order_id = path.into_inner();
    HttpResponse::Ok().json(Order { id: order_id })
}

// Fluent style
App::new().service(web::resource("/api/v1/orders/{order_id}").route(web::get().to(get_order)))
```

### 3. High-Throughput Request Pipelines

To achieve top-tier performance:
- Set worker count explicitly based on core affinity: `.workers(num_cpus::get())`.
- Enable keep-alive connection reuse: `.keep_alive(Duration::from_secs(75))`.
- Enable automatic payload compression with `actix_web::middleware::Compress::default()`.

---

## Why it matters

- **Benchmark-Leading Throughput**: By keeping event loops and socket descriptors local to individual CPU cores, Actix-web avoids cross-core CPU cache invalidation and atomic synchronization locks.
- **Battle-Tested Resilience**: High-traffic production services (e.g. at Microsoft, 1Password, and Brave) rely on Actix-web for mission-critical endpoints.

---

## Analogy

Think of a **Multi-Lane Supermarket**:
- Each checkout lane has its own dedicated cashier, scanner, and belt (an Actix worker thread).
- Cashiers do not share a single scanner across lanes; they work completely in parallel, leading to maximum customer throughput.

## Code Example

Save this to `src/main.rs` and run `cargo run` (requires `actix-web = "4"` and `serde = { version = "1", features = ["derive"] }` in `Cargo.toml`):

```rust
use actix_web::{
    get, post, web, App, HttpResponse, HttpServer, Responder, Result
};
use serde::{Deserialize, Serialize};
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;

// 1. Shared Global Application State
pub struct AppMetrics {
    total_requests: AtomicUsize,
    db_name: String,
}

// 2. Request & Response Models
#[derive(Serialize)]
struct SystemStatus {
    status: &'static str,
    database: String,
    total_requests_served: usize,
}

#[derive(Deserialize)]
struct CreateProduct {
    name: String,
    price_cents: u64,
}

#[derive(Serialize)]
struct ProductResponse {
    id: u64,
    name: String,
    price_cents: u64,
}

// 3. Route Handlers
#[get("/health")]
async fn health_check(data: web::Data<AppMetrics>) -> impl Responder {
    let count = data.total_requests.fetch_add(1, Ordering::Relaxed) + 1;
    HttpResponse::Ok().json(SystemStatus {
        status: "healthy",
        database: data.db_name.clone(),
        total_requests_served: count,
    })
}

#[get("/products/{product_id}")]
async fn get_product(
    path: web::Path<u64>,
    data: web::Data<AppMetrics>,
) -> Result<impl Responder> {
    data.total_requests.fetch_add(1, Ordering::Relaxed);
    let id = path.into_inner();

    Ok(HttpResponse::Ok().json(ProductResponse {
        id,
        name: format!("Product #{}", id),
        price_cents: 1999,
    }))
}

#[post("/products")]
async fn create_product(
    payload: web::Json<CreateProduct>,
    data: web::Data<AppMetrics>,
) -> impl Responder {
    data.total_requests.fetch_add(1, Ordering::Relaxed);

    HttpResponse::Created().json(ProductResponse {
        id: 501,
        name: payload.name.clone(),
        price_cents: payload.price_cents,
    })
}

#[actix_web::main]
async fn main() -> std::io::Result<()> {
    // Initialize shared state OUTSIDE the worker factory
    let metrics = web::Data::new(AppMetrics {
        total_requests: AtomicUsize::new(0),
        db_name: "cluster_pg_master".to_string(),
    });

    println!("🚀 Actix-web High-Throughput Server on http://127.0.0.1:8080");

    HttpServer::new(move || {
        App::new()
            .app_data(metrics.clone()) // Share state across all threads
            .wrap(actix_web::middleware::Logger::default())
            .wrap(actix_web::middleware::Compress::default())
            .service(health_check)
            .service(get_product)
            .service(create_product)
    })
    .workers(4) // 4 OS worker threads
    .bind(("127.0.0.1", 8080))?
    .run()
    .await
}
```

## Common Mistakes

### 1. Creating Database Pools Inside the `HttpServer::new` Closure
If you connect to PostgreSQL *inside* the closure, each worker creates its own pool (e.g., 8 workers $\times$ 50 connections $= 400$ connections!), crashing the database server from connection exhaustion. Always initialize pools outside the closure and wrap in `web::Data::new()`.

---

### 2. Blocking the Actix Event Loop
Calling synchronous operations (`std::thread::sleep`, file reads) inside async handlers freezes that specific worker thread. Use `actix_web::web::block(move || expensive_work())` to offload CPU-blocking tasks to a dedicated worker thread pool.

---

### 3. Extracting Path Parameters with Mismatched Tuples
When a route has multiple path segments like `/users/{uid}/posts/{pid}`, trying to extract `web::Path<u32>` instead of `web::Path<(u32, u32)>` causes a runtime deserialization error.

## Solutions

### Solution to Exercise 1
```rust
use actix_web::{http::StatusCode, HttpResponse, ResponseError};
use serde_json::json;
use std::fmt;

#[derive(Debug)]
pub enum ApiError {
    NotFound(String),
    Internal(String),
}

impl fmt::Display for ApiError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ApiError::NotFound(msg) => write!(f, "Not Found: {}", msg),
            ApiError::Internal(msg) => write!(f, "Internal Error: {}", msg),
        }
    }
}

impl ResponseError for ApiError {
    fn status_code(&self) -> StatusCode {
        match self {
            ApiError::NotFound(_) => StatusCode::NOT_FOUND,
            ApiError::Internal(_) => StatusCode::INTERNAL_SERVER_ERROR,
        }
    }

    fn error_response(&self) -> HttpResponse {
        HttpResponse::build(self.status_code()).json(json!({
            "error": self.to_string()
        }))
    }
}
```

### Solution to Exercise 2
```rust
use actix_web::{web, HttpResponse, Result};

pub async fn compute_hash(payload: web::Json<String>) -> Result<HttpResponse, actix_web::Error> {
    let input = payload.into_inner();

    // Offload CPU-heavy computation to blocking thread pool
    let hashed = web::block(move || {
        // Simulating heavy hashing
        format!("sha256_mock_{}", input.len())
    })
    .await
    .map_err(actix_web::error::ErrorInternalServerError)?;

    Ok(HttpResponse::Ok().json(serde_json::json!({ "hash": hashed })))
}
```
