## Concept

Having built an HTTP server from scratch using raw sockets in Phase 4, you understand the underlying mechanics: TCP byte streaming, zero-copy header parsing, routing trees, and middleware chains.

In production, you leverage battle-tested web frameworks that build on these exact primitives. Today, three frameworks dominate the Rust backend ecosystem:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   Rust Web Framework Hierarchy                         │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Axum       │ Built on Tokio & Tower │ Ergonomic, modular, microservices│
│ 2. Actix-web  │ Multi-Worker Runtime   │ Maximum throughput, battle-tested│
│ 3. Loco.rs    │ Built on Axum & SeaORM │ "Rails for Rust", full-stack MVC │
└────────────────────────────────────────────────────────────────────────┘
```

---

### 1. Axum: The Flagship Tokio Web Framework

Maintained by the core **Tokio** team, **Axum** is designed to feel like native Rust:
- **Zero Macro Magic**: Uses standard functions, closures, and traits rather than heavy procedural attributes.
- **The Extractor Pattern**: Handlers declare what they need as function arguments (e.g. `Path(id): Path<u32>`, `Json(payload): Json<User>`), and Axum automatically parses and injects them.
- **Tower Ecosystem**: Directly compatible with the vast ecosystem of `tower` and `tower-http` middleware (tracing, metrics, rate-limiting, compression).

---

### 2. Actix-web: The High-Throughput Heavyweight

**Actix-web** is one of the fastest web frameworks across all programming languages (consistently leading TechEmpower benchmarks):
- **Per-Thread Workers**: Spawns an independent OS worker thread for each CPU core, creating an isolated instance of the application on each thread.
- **State via `web::Data<T>`**: Explicitly shares state (like database connection pools) across thread boundaries.
- **Mature Feature Set**: Built-in HTTP/2, HTTP/3, and WebSocket implementations.

---

### 3. Loco.rs: "Ruby on Rails for Rust"

While Axum and Actix provide minimalist routing and HTTP handling, **Loco.rs** is a batteries-included full-stack framework built on top of **Axum** and **SeaORM**:
- **Code Generators**: Scaffolds controllers, models, and migrations via CLI (`loco generate scaffold`).
- **Integrated Tooling**: Built-in authentication (JWT), background workers, mailers, task schedulers, and environment configs out of the box.

---

### 4. Framework Comparison Matrix

| Feature | Axum | Actix-web | Loco.rs |
| :--- | :--- | :--- | :--- |
| **Backing Runtime** | Standard Tokio | Actix Multi-Worker | Tokio (via Axum) |
| **Design Philosophy** | Modular & Minimalist | High-Performance Engine | Batteries-Included Full-Stack |
| **ORM / DB Support** | Agnostic (SQLx / Diesel) | Agnostic | Deep SeaORM Integration |
| **Middleware Model** | Tower Services | Actix Middleware | Tower + Loco Initializers |
| **Scaffolding CLI** | None (Manual setup) | None (Manual setup) | Powerful code generators |
| **Best Used For** | Cloud Microservices, APIs | High-Frequency Real-Time | Enterprise Apps, SaaS Backends |

---

## Why it matters

Choosing the right framework dictates development velocity and maintenance cost:
- Use **Axum** for flexible, composable microservices and cloud-native Kubernetes deployments.
- Use **Actix-web** when raw benchmark-leading CPU throughput is the top constraint.
- Use **Loco.rs** when bootstrapping complete SaaS applications with auth, migrations, and background workers in record time.

---

## Analogy

- **Axum**: A modular LEGO architecture set that snaps seamlessly into your existing Tokio and Tower motors.
- **Actix-web**: A precision-tuned Formula 1 racecar designed for maximum lap speed.
- **Loco.rs**: A fully equipped luxury RV with kitchen, bedding, and generator ready for an immediate cross-country road trip.

## Code Example

Save this to `src/main.rs` and run `cargo run` (requires `axum = "0.7"` and `tokio = { version = "1", features = ["full"] }` in `Cargo.toml`):

```rust
use axum::{
    extract::{Path, Query, State},
    http::StatusCode,
    response::IntoResponse,
    routing::{get, post},
    Json, Router,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;

// 1. Define Shared Application State
#[derive(Clone)]
struct AppState {
    app_name: String,
}

// 2. Request / Response Data Models
#[derive(Deserialize)]
struct FilterQuery {
    page: Option<usize>,
}

#[derive(Serialize)]
struct UserResponse {
    id: u64,
    username: String,
    organization: String,
}

#[derive(Deserialize)]
struct CreateUserRequest {
    username: String,
}

// 3. Type-Safe Route Handlers
async fn health_check() -> &'static str {
    "OK"
}

// Handlers extract parameters declaratively as function arguments
async fn get_user(
    Path(user_id): Path<u64>,
    Query(query): Query<FilterQuery>,
    State(state): State<Arc<AppState>>,
) -> impl IntoResponse {
    let page_num = query.page.unwrap_or(1);

    let user = UserResponse {
        id: user_id,
        username: format!("user_{}", user_id),
        organization: state.app_name.clone(),
    };

    println!("[API] Fetching user {} on page {}", user_id, page_num);
    (StatusCode::OK, Json(user))
}

async fn create_user(
    State(state): State<Arc<AppState>>,
    Json(payload): Json<CreateUserRequest>, // Body extractor must come LAST!
) -> impl IntoResponse {
    let new_user = UserResponse {
        id: 101,
        username: payload.username,
        organization: state.app_name.clone(),
    };

    (StatusCode::CREATED, Json(new_user))
}

#[tokio::main]
async fn main() {
    let state = Arc::new(AppState {
        app_name: "Antigravity SaaS".to_string(),
    });

    // 4. Construct Router
    let app = Router::new()
        .route("/health", get(health_check))
        .route("/api/v1/users/:id", get(get_user))
        .route("/api/v1/users", post(create_user))
        .with_state(state);

    println!("🚀 Axum Web API running on http://127.0.0.1:3000");

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    // Start listening
    tokio::spawn(async move {
        axum::serve(listener, app).await.unwrap();
    });

    println!("Server booted successfully.");
}
```

## Common Mistakes

### 1. Placing the `Json<T>` Body Extractor Before Path or Query Extractors
In Axum, an extractor that consumes the request body (like `Json<T>` or `Bytes`) **must be the last parameter** in the handler function signature. Placing it first causes a compilation error because once the stream body is consumed, subsequent extractors cannot access headers or query strings.

---

### 2. Storing Non-Clone State in `Router::with_state`
Axum requires that the state type passed to `.with_state()` implement `Clone`. If your state contains heavy resources (like database pools or caches), wrap it in `Arc<T>` so that cloning only increments an atomic pointer count.

---

### 3. Forgetting `#[derive(Serialize, Deserialize)]` on JSON Structs
Attempting to use `Json<MyStruct>` without adding `serde::{Serialize, Deserialize}` derives triggers cryptic compiler errors regarding trait bounds on `FromRequest`.

## Solutions

### Solution to Exercise 1
```rust
use axum::{extract::Path, http::StatusCode, response::IntoResponse, Json};
use serde_json::json;

pub async fn delete_user(
    Path(id): Path<u64>,
) -> Result<StatusCode, (StatusCode, Json<serde_json::Value>)> {
    if id < 100 {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err((
            StatusCode::NOT_FOUND,
            Json(json!({ "error": "User does not exist", "id": id })),
        ))
    }
}
```

---

### Solution to Exercise 2
**Explanation**: In raw SQLx/Axum, developers manually write SQL queries, map database columns to structs, write input validation, and connect route handlers. In Loco.rs, running `loco generate scaffold movie title:string year:int` generates:
1. A SeaORM Entity definition (`Entity`, `Model`, `ActiveModel`).
2. A database migration file with reversible `up`/`down` schema changes.
3. An Axum Controller with pre-built REST endpoints (`GET /movies`, `POST /movies`, `GET /movies/:id`, `PUT /movies/:id`, `DELETE /movies/:id`).
4. Automatic validation and standardized JSON response wrappers.

---

### Solution to Exercise 3
```rust
use axum::Router;
use tower_http::cors::{Any, CorsLayer};
use tower_http::trace::TraceLayer;

pub fn configure_middleware(app: Router) -> Router {
    let cors = CorsLayer::new()
        .allow_origin(Any)
        .allow_methods(Any)
        .allow_headers(Any);

    app.layer(TraceLayer::new_for_http())
       .layer(cors)
}
```
