## Concept

At the architectural core of Axum is the **`tower::Service`** trait and the **Extractor Pattern**. 

Instead of manually checking tokens, parsing headers, and querying database pools inside every endpoint handler, Axum delegates this to **Type-Safe Extractors**:

```
Incoming HTTP Request (Headers + Path + Body)
                      │
                      ▼
   [ Axum Extractor Pipeline (Type-Driven) ]
   ├── Step 1: Extracts `State(db)` via `FromRef`
   ├── Step 2: Extracts `Path(id)` from URL segments
   └── Step 3: Extracts `AuthUser` via `FromRequestParts` (Validates JWT)
                      │
   If valid? ─────────┴─────────► Invokes Handler: `async fn update_profile(user: AuthUser, ...)`
   If invalid? ─────────────────► Returns `401 Unauthorized` (Handler NEVER executes!)
```

---

### 1. `FromRequestParts` vs. `FromRequest`

Axum divides extractors into two categories:

1. **`FromRequestParts<S>`**:
   - Inspects the request *metadata* (Headers, URI, Method, Extensions) **without** touching the body stream.
   - Can be used in any order and as many times as needed in a handler signature.
   - Used for authentication tokens, cookies, client IPs, and query parameters.
2. **`FromRequest<S>`**:
   - Consumes the incoming *payload stream* (`Body`, `Bytes`, `Json<T>`).
   - **Must be the final argument** in the handler function parameter list.

---

### 2. Writing a Custom `AuthUser` Extractor

By implementing `FromRequestParts` for a custom struct, authentication becomes declarative:

```rust
pub struct AuthUser {
    pub user_id: u64,
    pub role: String,
}

#[axum::async_trait]
impl<S> FromRequestParts<S> for AuthUser
where
    S: Send + Sync,
{
    type Rejection = (StatusCode, &'static str);

    async fn from_request_parts(parts: &mut Parts, _state: &S) -> Result<Self, Self::Rejection> {
        if let Some(auth_header) = parts.headers.get("Authorization") {
            if let Ok(auth_str) = auth_header.to_str() {
                if auth_str == "Bearer secret-token-42" {
                    return Ok(AuthUser { user_id: 42, role: "admin".into() });
                }
            }
        }
        Err((StatusCode::UNAUTHORIZED, "Invalid or missing Bearer token"))
    }
}
```

### 3. Nested Routers & Sub-Applications

Large APIs are split into modular sub-routers merged using `.nest()`:

```rust
let users_router = Router::new().route("/:id", get(get_user));
let orders_router = Router::new().route("/:id", get(get_order));

let app = Router::new()
    .nest("/api/v1/users", users_router)
    .nest("/api/v1/orders", orders_router);
```

---

## Why it matters

- **Compile-Time Security Enforcement**: It is impossible to forget authentication on a protected endpoint. If a handler requires `AuthUser` in its signature, Axum guarantees the request was validated before the handler code is reached.
- **Zero Handler Boilerplate**: Route handlers focus 100% on business logic, receiving pre-parsed, validated domain objects directly.

---

## Analogy

Think of an **Automated Biometric Turnstile**:
- If your handler is the VIP boarding lounge, `AuthUser` is the automated turnstile at the entrance.
- If the boarding pass or facial scan fails, the turnstile gates remain shut (`401 Unauthorized`). The VIP lounge staff (your handler) never even sees the rejected visitor.

## Code Example

Save this to `src/main.rs` and run `cargo run`:

```rust
use axum::{
    async_trait,
    extract::{FromRequestParts, Path, State},
    http::{request::Parts, StatusCode},
    response::{IntoResponse, Response},
    routing::{get, post},
    Json, Router,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;

// 1. Shared Database State
#[derive(Clone)]
pub struct DatabaseContext {
    pub db_name: String,
}

// 2. Custom Authenticated User Extractor
#[derive(Debug, Clone)]
pub struct CurrentUser {
    pub user_id: u64,
    pub username: String,
    pub is_admin: bool,
}

// Custom Rejection Type returning structured JSON on auth failure
pub struct AuthError(&'static str);

impl IntoResponse for AuthError {
    fn into_response(self) -> Response {
        let body = Json(serde_json::json!({
            "error": "Unauthorized",
            "message": self.0
        }));
        (StatusCode::UNAUTHORIZED, body).into_response()
    }
}

#[async_trait]
impl<S> FromRequestParts<S> for CurrentUser
where
    S: Send + Sync,
{
    type Rejection = AuthError;

    async fn from_request_parts(parts: &mut Parts, _state: &S) -> Result<Self, Self::Rejection> {
        let auth_header = parts
            .headers
            .get("Authorization")
            .and_then(|value| value.to_str().ok())
            .ok_or(AuthError("Missing Authorization header"))?;

        if let Some(token) = auth_header.strip_prefix("Bearer ") {
            if token == "admin-super-secret" {
                return Ok(CurrentUser {
                    user_id: 1,
                    username: "root_admin".into(),
                    is_admin: true,
                });
            } else if token == "user-valid-token" {
                return Ok(CurrentUser {
                    user_id: 42,
                    username: "alice_smith".into(),
                    is_admin: false,
                });
            }
        }

        Err(AuthError("Invalid bearer token credentials"))
    }
}

// 3. Handlers
#[derive(Serialize)]
struct ProfileResponse {
    user_id: u64,
    username: String,
    database: String,
}

// Protected Profile Endpoint
async fn get_my_profile(
    user: CurrentUser, // Automatically extracted & validated!
    State(db): State<Arc<DatabaseContext>>,
) -> impl IntoResponse {
    (
        StatusCode::OK,
        Json(ProfileResponse {
            user_id: user.user_id,
            username: user.username,
            database: db.db_name.clone(),
        }),
    )
}

// Admin-Only Metric Endpoint
async fn get_admin_metrics(user: CurrentUser) -> Result<impl IntoResponse, StatusCode> {
    if !user.is_admin {
        return Err(StatusCode::FORBIDDEN);
    }
    Ok((StatusCode::OK, "Active Cluster Nodes: 12"))
}

#[tokio::main]
async fn main() {
    let db = Arc::new(DatabaseContext {
        db_name: "prod_postgres_cluster".into(),
    });

    let app = Router::new()
        .route("/api/v1/me", get(get_my_profile))
        .route("/api/v1/admin/metrics", get(get_admin_metrics))
        .with_state(db);

    println!("🚀 Axum Extractor Server listening on http://127.0.0.1:3000");

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    tokio::spawn(async move {
        axum::serve(listener, app).await.unwrap();
    });

    println!("Server running ready for tests.");
}
```

## Common Mistakes

### 1. Using `FromRequest` Instead of `FromRequestParts` for Headers
Implementing `FromRequest` consumes the request body, preventing subsequent extractors like `Json<T>` from reading the payload. **Always implement `FromRequestParts` for header, cookie, or metadata extractors.**

---

### 2. Returning Plain Strings on Extractor Rejection
Returning `type Rejection = String` causes Axum to return an HTTP `200 OK` with the error string in the body! Always return an explicit `(StatusCode, ...)` tuple or a custom struct implementing `IntoResponse`.

---

### 3. State Type Mismatch in Sub-Routers
When using `.nest()`, if the child router expects a different State type than the parent router, compilation will fail. Use `axum::extract::FromRef` or match state types across nested routers.

## Solutions

### Solution to Exercise 1
```rust
use axum::{async_trait, extract::FromRequestParts, http::{request::Parts, StatusCode}};

pub struct ApiKey(pub String);

#[async_trait]
impl<S: Send + Sync> FromRequestParts<S> for ApiKey {
    type Rejection = (StatusCode, &'static str);

    async fn from_request_parts(parts: &mut Parts, _state: &S) -> Result<Self, Self::Rejection> {
        let key = parts
            .headers
            .get("X-API-Key")
            .and_then(|val| val.to_str().ok())
            .ok_or((StatusCode::BAD_REQUEST, "Missing X-API-Key header"))?;

        Ok(ApiKey(key.to_string()))
    }
}
```

---

### Solution to Exercise 2
```rust
pub struct RequireAdmin(pub CurrentUser);

#[async_trait]
impl<S: Send + Sync> FromRequestParts<S> for RequireAdmin {
    type Rejection = (StatusCode, &'static str);

    async fn from_request_parts(parts: &mut Parts, state: &S) -> Result<Self, Self::Rejection> {
        let user = CurrentUser::from_request_parts(parts, state)
            .await
            .map_err(|_| (StatusCode::UNAUTHORIZED, "Authentication failed"))?;

        if !user.is_admin {
            return Err((StatusCode::FORBIDDEN, "Admin privileges required"));
        }

        Ok(RequireAdmin(user))
    }
}
```

### Solution to Exercise 3
```rust
pub trait Validate {
    fn validate(&self) -> Result<(), String>;
}

pub struct ValidatedJson<T>(pub T);

#[async_trait]
impl<T, S> axum::extract::FromRequest<S> for ValidatedJson<T>
where
    T: serde::de::DeserializeOwned + Validate,
    S: Send + Sync,
{
    type Rejection = (StatusCode, String);

    async fn from_request(req: axum::extract::Request, state: &S) -> Result<Self, Self::Rejection> {
        let Json(data) = Json::<T>::from_request(req, state)
            .await
            .map_err(|e| (StatusCode::BAD_REQUEST, e.to_string()))?;

        data.validate()
            .map_err(|err| (StatusCode::UNPROCESSABLE_ENTITY, err))?;

        Ok(ValidatedJson(data))
    }
}
```
