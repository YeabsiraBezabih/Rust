## Concept

Modern web applications require instant, server-driven updates. Rather than having clients repeatedly poll the server with HTTP requests every second (wasteful network polling), we use two specialized real-time protocols:

1. **Server-Sent Events (SSE)**: One-way, server-to-client streaming over standard HTTP (`text/event-stream`). Ideal for live dashboards, stock tickers, and AI token streaming.
2. **WebSockets (WS/WSS)**: Full-duplex, bi-directional communication established via an HTTP `101 Switching Protocols` handshake. Ideal for live multiplayer gaming, collaborative editors, and chat apps.

```
SSE (One-Way):
Server ──────────────────[ Event 1 ]───[ Event 2 ]───[ Event 3 ]───► Client (Browser)

WebSocket (Bi-Directional Full-Duplex):
Server ◄═════════════════[ Messages Both Directions ]════════════════► Client (Browser)
```

---

### 1. Axum WebSocket Architecture

In Axum, a WebSocket route uses the **`WebSocketUpgrade`** extractor:

```rust
async fn ws_handler(
    ws: WebSocketUpgrade,
    State(state): State<Arc<AppState>>,
) -> Response {
    // Upgrades HTTP socket to RFC 6455 WebSocket stream
    ws.on_upgrade(|socket| handle_socket(socket, state))
}
```

#### Splitting the Socket Stream
Inside the upgraded socket handler, you split the full-duplex socket into independent **Sender** and **Receiver** halves using `futures::StreamExt`:
```rust
let (mut ws_sender, mut ws_receiver) = socket.split();
```

---

### 2. Multi-Client Fan-Out Broadcasting (`tokio::sync::broadcast`)

To broadcast messages to thousands of connected clients simultaneously, we use a **Tokio Broadcast Channel**:
- The server maintains a central `broadcast::Sender<String>`.
- When a new WebSocket client connects, it calls `tx.subscribe()` to receive its own private receiver handle (`broadcast::Receiver<String>`).
- When any client sends a message, it publishes to `tx.send(msg)`, instantly fanning out to all active subscribers.

```
Client A ──► [ ws_receiver ] ──► tx.send("Hello All!")
                                         │
                   ┌─────────────────────┴─────────────────────┐
                   ▼                                           ▼
       [ Subscriber 1 (Client B) ]                 [ Subscriber 2 (Client C) ]
                   │                                           │
                   ▼                                           ▼
             ws_sender.send()                            ws_sender.send()
```

---

### 3. Server-Sent Events (SSE) in Axum

Axum provides native SSE support via `axum::response::sse::{Event, Sse, KeepAlive}`:
- Returns an `impl Stream<Item = Result<Event, Infallible>>`.
- Automatically sends periodic `:keep-alive` comments to prevent intermediate proxies from closing idle streams.

---

## Why it matters

- **Sub-Millisecond Real-Time Updates**: Eliminates HTTP connection setup handshakes for every individual message.
- **AI Streaming (ChatGPT Style)**: Modern AI applications stream generated tokens to the browser via SSE using negligible memory overhead.

---

## Analogy

- **SSE**: A live FM radio station: the tower continuously broadcasts music to thousands of cars listening passively.
- **WebSocket**: A multi-party walkie-talkie channel: all participants can transmit voice messages and listen to others simultaneously.

## Code Example

Save this to `src/main.rs` and run `cargo run` (requires `axum = { version = "0.7", features = ["ws"] }`, `tokio = { version = "1", features = ["full"] }`, `futures = "0.3"`, `tokio-stream = "0.1"` in `Cargo.toml`):

```rust
use axum::{
    extract::{
        ws::{Message, WebSocket, WebSocketUpgrade},
        State,
    },
    response::{
        sse::{Event, KeepAlive, Sse},
        IntoResponse, Response,
    },
    routing::get,
    Router,
};
use futures::{sink::SinkExt, stream::StreamExt, Stream};
use std::{convert::Infallible, sync::Arc, time::Duration};
use tokio::sync::broadcast;
use tokio_stream::wrappers::BroadcastStream;

// 1. Application State holding Broadcast Hub
struct AppState {
    tx: broadcast::Sender<String>,
}

// 2. WebSocket Upgrade Handler
async fn websocket_handler(
    ws: WebSocketUpgrade,
    State(state): State<Arc<AppState>>,
) -> Response {
    ws.on_upgrade(move |socket| handle_websocket_socket(socket, state))
}

// Full-duplex client socket loop
async fn handle_websocket_socket(socket: WebSocket, state: Arc<AppState>) {
    let (mut sender, mut receiver) = socket.split();
    let mut rx = state.tx.subscribe();

    // Task A: Forward incoming broadcast messages out to the client
    let mut send_task = tokio::spawn(async move {
        while let Ok(msg) = rx.recv().await {
            if sender.send(Message::Text(msg)).await.is_err() {
                break; // Client disconnected
            }
        }
    });

    // Task B: Read incoming messages from client and broadcast to everyone
    let tx = state.tx.clone();
    let mut recv_task = tokio::spawn(async move {
        while let Some(Ok(Message::Text(text))) = receiver.next().await {
            println!("[WS Chat] Broadcasted: {}", text);
            let _ = tx.send(text);
        }
    });

    // If either task finishes (disconnect or error), abort the other
    tokio::select! {
        _ = (&mut send_task) => recv_task.abort(),
        _ = (&mut recv_task) => send_task.abort(),
    };
    println!("[WS Chat] Client disconnected cleanly.");
}

// 3. Server-Sent Events (SSE) Token / Metric Stream
async fn sse_metric_stream() -> Sse<impl Stream<Item = Result<Event, Infallible>>> {
    let mut counter = 0u64;

    // Stream an event every 500ms
    let stream = async_stream::stream! {
        loop {
            tokio::time::sleep(Duration::from_millis(500)).await;
            counter += 1;
            let event = Event::default()
                .event("metric_tick")
                .data(format!(r#"{{"tick":{},"cpu_load":{:.2}}}"#, counter, 42.5));
            yield Ok(event);
        }
    };

    Sse::new(stream).keep_alive(KeepAlive::default())
}

#[tokio::main]
async fn main() {
    let (tx, _rx) = broadcast::channel(100);
    let state = Arc::new(AppState { tx });

    let app = Router::new()
        .route("/ws", get(websocket_handler))
        .route("/api/v1/stream/metrics", get(sse_metric_stream))
        .with_state(state);

    println!("🚀 Real-Time Server running on http://127.0.0.1:3000");
    println!("   WebSocket Chat: ws://127.0.0.1:3000/ws");
    println!("   SSE Stream    : http://127.0.0.1:3000/api/v1/stream/metrics");

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

## Common Mistakes

### 1. Blocking the Async Loop with a Single Task
Trying to read and write to a `WebSocket` sequentially in a single loop. If the client is silent, the server never sends broadcast messages! **Always split the socket into `(sender, receiver)` and run them as concurrent tasks.**

---

### 2. Slow Consumers in Broadcast Channels (`Lagged` Error)
If a client has a poor internet connection, its internal `broadcast::Receiver` buffer fills up, causing it to return `Err(RecvError::Lagged(skipped_count))`. Handle this error gracefully by catching `Lagged` and continuing the loop rather than crashing.

---

### 3. Missing SSE Keep-Alives Behind Reverse Proxies
Deploying SSE without `.keep_alive(KeepAlive::default())`. Reverse proxies (NGINX, Cloudflare, AWS ALB) will kill idle HTTP connections after 30–60 seconds if no bytes are sent.

## Solutions

### Solution to Exercise 1
```rust
use axum::extract::Query;
use serde::Deserialize;

#[derive(Deserialize)]
pub struct WsQuery {
    pub username: Option<String>,
}

pub async fn ws_handler_with_name(
    ws: WebSocketUpgrade,
    Query(query): Query<WsQuery>,
    State(state): State<Arc<AppState>>,
) -> Response {
    let name = query.username.unwrap_or_else(|| "Anonymous".to_string());
    ws.on_upgrade(move |socket| handle_socket_with_name(socket, state, name))
}

async fn handle_socket_with_name(socket: WebSocket, state: Arc<AppState>, username: String) {
    let (mut sender, mut receiver) = socket.split();
    let mut rx = state.tx.subscribe();

    let mut send_task = tokio::spawn(async move {
        while let Ok(msg) = rx.recv().await {
            if sender.send(Message::Text(msg)).await.is_err() { break; }
        }
    });

    let tx = state.tx.clone();
    let u_name = username.clone();
    let mut recv_task = tokio::spawn(async move {
        while let Some(Ok(Message::Text(text))) = receiver.next().await {
            let formatted = format!("[{}]: {}", u_name, text);
            let _ = tx.send(formatted);
        }
    });

    tokio::select! {
        _ = (&mut send_task) => recv_task.abort(),
        _ = (&mut recv_task) => send_task.abort(),
    };
}
```

### Solution to Exercise 2
```rust
use tokio::sync::broadcast::error::RecvError;

pub async fn safe_broadcast_forwarder(
    mut rx: broadcast::Receiver<String>,
    mut sender: futures::stream::SplitSink<WebSocket, Message>,
) {
    loop {
        match rx.recv().await {
            Ok(msg) => {
                if sender.send(Message::Text(msg)).await.is_err() {
                    break; // Client disconnected
                }
            }
            Err(RecvError::Lagged(count)) => {
                eprintln!("[WS] Warning: Client fell behind, dropped {} messages.", count);
            }
            Err(RecvError::Closed) => break,
        }
    }
}
```

### Solution to Exercise 3
```rust
pub async fn sse_llm_stream() -> Sse<impl Stream<Item = Result<Event, Infallible>>> {
    let text = "Rust gives you memory safety without garbage collection.";
    let words: Vec<&'static str> = text.split_whitespace().collect();

    let stream = async_stream::stream! {
        for word in words {
            tokio::time::sleep(Duration::from_millis(100)).await;
            yield Ok(Event::default().event("token").data(word));
        }
        yield Ok(Event::default().event("done").data("[DONE]"));
    };

    Sse::new(stream).keep_alive(KeepAlive::default())
}
```
