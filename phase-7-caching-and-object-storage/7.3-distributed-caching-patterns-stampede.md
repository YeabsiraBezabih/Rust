## Concept

A caching layer is only beneficial if it reliably shields your database from load spikes. Under extreme traffic, naive caching implementations suffer from catastrophic failure modes that can knock entire systems offline.

```
                           The Cache Stampede (Thundering Herd)
                           ────────────────────────────────────
   10,000 Concurrent Requests (All requesting hot key `product:101`)
                │
                ▼
   ┌─────────────────────────┐
   │ Redis Cache             │ ◄─── Cache Key Expired 1ms ago! (CACHE MISS)
   └────────────┬────────────┘
                │
                │ 10,000 Simultaneous DB Queries Fired at the Same Millisecond!
                ▼
   ┌─────────────────────────┐
   │ PostgreSQL Primary DB   │ ◄─── CPU 100%, Max Connections Exhausted! CRASH!
   └─────────────────────────┘
```

---

### 1. The Four Major Caching Disasters & Defenses

| Disaster | Symptom & Cause | Systems Defense |
| :--- | :--- | :--- |
| **Cache Stampede / Breakdown** | Hot key expires; thousands of concurrent threads rush to rebuild it simultaneously. | **Singleflight (Request Collapsing)** or **XFetch (Probabilistic Early Expiration)**. |
| **Cache Avalanche** | Millions of keys expire at the exact same second, dumping all load onto the DB. | **TTL Jitter**: Add random offset to TTL (`TTL = 3600 + rand(0..300)`). |
| **Cache Penetration** | Attackers query millions of non-existent IDs, forcing full DB scans on every request. | **Bloom Filters** or **Null Object Caching** (cache `Null` with short 60s TTL). |
| **Stale Cache / Inconsistency** | Database updated, but cache still holds old data. | **Cache-Aside Invalidation** or Transactional Outbox Pattern. |

---

### 2. Defense 1: Singleflight (Request Collapsing)

In Rust, the **Singleflight** pattern ensures that if 1,000 concurrent async tasks miss the cache for key `user:42`, **only the first task executes the database query**. The remaining 999 tasks subscribe to the result of that single in-flight future.

```
Task 1 (Miss) ──► [ DB Fetch Leader ] ──────────► Queries DB (1 Query)
Task 2 (Miss) ──┐                                       │
Task 3 (Miss) ──┼──► [ Awaiting Leader Future ] ◄───────┘ (Broadcasts Result)
Task 4 (Miss) ──┘
```

---

### 3. Defense 2: XFetch (Optimal Probabilistic Early Expiration)

Published in VLDB 2015, **XFetch** recomputes a cached value in the background *before* it expires with an exponentially increasing probability:

$$\text{Recompute If: } -\beta \times \delta \times \ln(\text{rand}()) > (\text{TTL}_{\text{remaining}})$$

- $\delta$: Time taken to compute the value from the database (in seconds).
- $\beta$: Aggressiveness parameter ($\beta > 0$, default `1.0`).
- $\text{rand}()$: Uniform random number between $(0, 1]$.
- As $\text{TTL}_{\text{remaining}}$ approaches 0, the probability of early background recomputation approaches 100%, **guaranteeing the key never expires for incoming readers**.

---

## Why It Matters in Systems Programming

1. **Protect Core Databases**: Without singleflight or XFetch, deploying an e-commerce flash sale or breaking news alert will cause database connection pools to immediately exhaust.
2. **Preventing Latency Spikes (P99/P999)**: XFetch eliminates the massive latency spikes users experience when they hit an expired cache key.
3. **Resilient High-Load Systems**: Adding TTL jitter prevents synchronized cache expirations across millions of cached records.

---

## Real-World Analogy

- **Naive Caching** is like a restaurant kitchen where the coffee pot runs out, and 50 waiters simultaneously run into the kitchen to brew 50 separate pots of coffee on 1 stove.
- **Singleflight** is the first waiter shouting "I'm brewing a fresh pot now!", and the other 49 waiters waiting at the counter to pour from that single pot when it's done.
- **XFetch** is a sensor noticing the coffee pot is at 10% capacity and automatically starting a new brew cycle before any customer ever sees an empty pot.

## Complete, Compilable Code Example

Below is a complete, production-grade Rust implementation of **Singleflight Request Collapsing** and **XFetch Probabilistic Caching**:

```rust
use std::collections::HashMap;
use std::sync::Arc;
use std::time::{Duration, Instant};
use tokio::sync::{broadcast, Mutex};

// ============================================================================
// 1. Singleflight Group (Request Collapsing)
// ============================================================================

pub struct Singleflight<T> {
    in_flight: Mutex<HashMap<String, broadcast::Sender<T>>>,
}

impl<T: Clone + Send + Sync + 'static> Singleflight<T> {
    pub fn new() -> Self {
        Self {
            in_flight: Mutex::new(HashMap::new()),
        }
    }

    /// Executes `loader` only once for concurrent callers with the same key
    pub async fn execute<F, Fut>(&self, key: &str, loader: F) -> Result<T, String>
    where
        F: FnOnce() -> Fut,
        Fut: std::future::Future<Output = Result<T, String>>,
    {
        let mut map = self.in_flight.lock().await;

        if let Some(sender) = map.get(key) {
            // Another task is currently computing this key! Subscribe to its result.
            let mut receiver = sender.subscribe();
            drop(map); // Release mutex so other tasks can proceed

            return match receiver.recv().await {
                Ok(val) => Ok(val),
                Err(_) => Err("In-flight leader failed".to_string()),
            };
        }

        // Leader task: create broadcast channel and register in map
        let (tx, _) = broadcast::channel(1);
        map.insert(key.to_string(), tx.clone());
        drop(map);

        // Execute the expensive computation
        let result = loader().await;

        // Clean up map and broadcast result to all awaiting followers
        let mut map = self.in_flight.lock().await;
        map.remove(key);

        if let Ok(ref val) = result {
            let _ = tx.send(val.clone());
        }

        result
    }
}

// ============================================================================
// 2. XFetch Probabilistic Cache Entry
// ============================================================================

#[derive(Clone, Debug)]
pub struct XFetchEntry<V> {
    pub value: V,
    pub delta_ms: u64, // Time taken to compute value from database
    pub expiry: Instant,
}

impl<V> XFetchEntry<V> {
    /// Determines whether the cache entry should be recomputed early
    pub fn should_recompute_early(&self, beta: f64) -> bool {
        let now = Instant::now();
        if now >= self.expiry {
            return true; // Already expired
        }

        let ttl_remaining_secs = (self.expiry - now).as_secs_f64();
        let delta_secs = self.delta_ms as f64 / 1000.0;

        // Generate pseudo-random float (0, 1]
        let rand_val: f64 = (1..=1000).rev().next().unwrap() as f64 / 1000.0; // Deterministic sample for demo

        let xfetch_threshold = -beta * delta_secs * rand_val.ln();
        xfetch_threshold >= ttl_remaining_secs
    }
}

// ============================================================================
// 3. Stress Test & Stampede Simulation
// ============================================================================

#[tokio::main]
async fn main() {
    println!("=== 1. Simulating Cache Stampede with Singleflight Collapsing ===");
    let singleflight: Arc<Singleflight<String>> = Arc::new(Singleflight::new());
    let db_query_counter = Arc::new(std::sync::atomic::AtomicUsize::new(0));

    let mut handles = Vec::new();

    // Spawn 10 concurrent requests for the exact same expired cache key
    for task_id in 1..=10 {
        let sf = Arc::clone(&singleflight);
        let counter = Arc::clone(&db_query_counter);

        let handle = tokio::spawn(async move {
            let res = sf
                .execute("product:hero_gadget_101", || async {
                    println!("  [DATABASE LEADER] Task {} querying slow PostgreSQL...", task_id);
                    counter.fetch_add(1, std::sync::atomic::Ordering::Relaxed);
                    tokio::time::sleep(Duration::from_millis(80)).await; // Simulate slow DB query
                    Ok("Heavy Database Computed Payload (Product Specs)".to_string())
                })
                .await;

            println!("  [Task {:<2}] Received result: {}", task_id, res.unwrap());
        });
        handles.push(handle);
    }

    for h in handles {
        h.await.unwrap();
    }

    let queries_fired = db_query_counter.load(std::sync::atomic::Ordering::Relaxed);
    println!("\nTotal Database Queries Fired for 10 Concurrent Requests: {}", queries_fired);
    assert_eq!(queries_fired, 1, "Singleflight collapsed 10 requests into exactly 1 DB query!");
    println!("✅ Cache stampede 100% prevented by Singleflight!\n");

    println!("=== 2. Testing XFetch Early Expiration Check ===");
    let entry = XFetchEntry {
        value: "Hot Article Content",
        delta_ms: 250, // 250ms DB compute time
        expiry: Instant::now() + Duration::from_millis(50), // Expires very soon
    };

    let needs_refresh = entry.should_recompute_early(1.0);
    println!("Entry TTL: ~50ms, DB Delta: 250ms -> Should recompute in background? {}", needs_refresh);
}
```

## Common Pitfalls & Compiler Errors

### 1. Forgetting to Drop the Mutex Before Awaiting Loader
In Singleflight implementations, if you hold the `in_flight` Mutex across the `loader().await` call, all other concurrent tasks will block trying to acquire the mutex instead of subscribing to the broadcast channel!

**Fix**: Always register the channel, clone the sender, and `drop(map)` before executing the async loader.

### 2. Missing TTL Jitter
Hardcoding `TTL = Duration::from_secs(3600)` on all keys written during a morning bulk-load job guarantees a massive spike exactly 1 hour later when all keys simultaneously expire.

## Complete Solutions to Exercises

### Solution 1: TTL Jitter Calculation

```rust
pub fn compute_jittered_ttl(base_secs: u64, max_jitter_secs: u64) -> Duration {
    use std::time::SystemTime;
    let seed = SystemTime::now()
        .duration_since(SystemTime::UNIX_EPOCH)
        .unwrap()
        .subsec_nanos() as u64;
    let jitter = seed % (max_jitter_secs + 1);
    Duration::from_secs(base_secs + jitter)
}
```
