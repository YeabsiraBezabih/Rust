## Concept

Modern cloud systems do not store user-uploaded images, videos, audio, machine learning models, or database backups inside relational databases (which causes massive database bloat).

Instead, binary blobs are stored in **Object Storage** (Amazon S3, Google Cloud Storage, Cloudflare R2, MinIO).

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Storage Architecture Types                      │
├───────────────────┬──────────────────────────────┬─────────────────────┤
│ Storage Type      │ Interface                    │ Best Used For       │
├───────────────────┼──────────────────────────────┼─────────────────────┤
│ **Block Storage** │ Raw device blocks (`/dev/sda`)| OS, DB Files (WAL)  │
│ **File Storage**  │ POSIX hierarchy (`/mnt/data`)| Shared NFS / SMB    │
│ **Object Storage**│ HTTP REST API (`/bucket/key`)| Images, Videos, Logs│
└───────────────────┴──────────────────────────────┴─────────────────────┘
```

---

### 1. Object Storage Architecture

- **Flat Key-Value Namespace**: There are no real "directories" in S3. A key named `uploads/2026/09/avatar.png` is simply a single string identifier inside a **Bucket**.
- **Immutable Blobs**: Objects cannot be modified in-place. Modifying a 1-byte typo in a 5GB file requires uploading a completely new object or using multipart copy.
- **Strong Read-After-Write Consistency**: Modern S3 and MinIO guarantee that immediately after a `PUT` or `DELETE`, all subsequent `GET` requests return the latest version.

```
 Client (Rust App)                                      S3 / MinIO Server
 ─────────────────                                      ─────────────────
         │ ─── HTTP PUT /my-bucket/videos/clip.mp4 ────────────► │
         │     (Content-Length: 10485760, SHA256 Checksum)       │ Writes to Disk Storage
         │ ◄── HTTP 200 OK (ETag: "d41d8cd98f00b204e9800998ecf8") │
         │                                                       │
         │ ─── HTTP GET /my-bucket/videos/clip.mp4 ────────────► │
         │     (Range: bytes=0-1048575)                          │ Reads first 1MB slice
         │ ◄── HTTP 206 Partial Content (Content-Range: 0-1MB) ─ │
```

### 2. Local MinIO Setup for Testing & Development

MinIO is an open-source, S3-compatible high-performance object storage server written in Go. Running MinIO locally allows 100% realistic S3 testing without paying AWS bills:

```bash
docker run -p 9000:9000 -p 9001:9001 \
  -e "MINIO_ROOT_USER=minioadmin" \
  -e "MINIO_ROOT_PASSWORD=miniopassword" \
  quay.io/minio/minio server /data --console-address ":9001"
```

- **S3 API Port**: `http://localhost:9000`
- **Web Console**: `http://localhost:9001`

### 3. AWS Signature Version 4 (SigV4)

Every S3 HTTP request is authenticated using HMAC-SHA256 signatures:
1. Construct a **Canonical Request** (Method, Path, Query Params, Headers, Hashed Payload).
2. Create a **String to Sign** containing timestamp, date, and canonical hash.
3. Derive a signing key: $\text{HMAC}(\text{HMAC}(\text{HMAC}(\text{SecretKey, Date}), \text{Region}), \text{Service})$.
4. Calculate signature and send in the `Authorization: AWS4-HMAC-SHA256 ...` header.

## Why It Matters in Systems Programming

1. **Massive Scale at Minimal Cost**: Storing 100TB in PostgreSQL costs thousands of dollars per month and destroys backup performance. Storing 100TB in S3/MinIO costs a fraction and scales infinitely.
2. **HTTP Range Requests for Streaming**: Video players and large file processors use the `Range: bytes=START-END` header to seek and stream chunks without loading multi-gigabyte files into RAM.
3. **Multi-Cloud Portability**: By writing against the standard S3 API, your Rust application can run seamlessly across AWS S3, Cloudflare R2, Wasabi, or self-hosted on-premise MinIO clusters.

## Real-World Analogy

- **Relational Databases** are like high-security bank safety deposit boxes: designed for small, high-value, strictly audited items (cash, deeds).
- **Object Storage** is like an automated 10-acre industrial shipping warehouse: you put any size cargo box into a container, label it with a barcode key (`"box_98412"`), and the crane stacks it anywhere in the warehouse.

## Complete, Compilable Code Example

Below is a complete, self-contained in-memory **S3 Object Storage Server & Client Engine** in pure Rust demonstrating bucket namespaces, ETag MD5 computation, metadata headers, and HTTP Range streaming:

```rust
use std::collections::HashMap;
use std::time::SystemTime;

// ============================================================================
// 1. S3 Object Entity & Storage Engine
// ============================================================================

#[derive(Debug, Clone)]
pub struct S3Object {
    pub key: String,
    pub content_type: String,
    pub data: Vec<u8>,
    pub etag: String,
    pub last_modified: SystemTime,
    pub metadata: HashMap<String, String>,
}

pub struct MiniS3Engine {
    buckets: HashMap<String, HashMap<String, S3Object>>,
}

impl MiniS3Engine {
    pub fn new() -> Self {
        Self {
            buckets: HashMap::new(),
        }
    }

    pub fn create_bucket(&mut self, bucket_name: &str) -> Result<(), &'static str> {
        if self.buckets.contains_key(bucket_name) {
            return Err("BucketAlreadyExists");
        }
        self.buckets.insert(bucket_name.to_string(), HashMap::new());
        Ok(())
    }

    /// Compute simulated ETag (deterministic hex hash)
    fn compute_etag(data: &[u8]) -> String {
        use std::collections::hash_map::DefaultHasher;
        use std::hash::{Hash, Hasher};
        let mut hasher = DefaultHasher::new();
        data.hash(&mut hasher);
        format!("\"{:016x}\"", hasher.finish())
    }

    /// S3 PutObject Operation
    pub fn put_object(
        &mut self,
        bucket: &str,
        key: &str,
        content_type: &str,
        data: Vec<u8>,
        metadata: HashMap<String, String>,
    ) -> Result<String, &'static str> {
        let bucket_map = self.buckets.get_mut(bucket).ok_or("NoSuchBucket")?;
        let etag = Self::compute_etag(&data);

        let obj = S3Object {
            key: key.to_string(),
            content_type: content_type.to_string(),
            data,
            etag: etag.clone(),
            last_modified: SystemTime::now(),
            metadata,
        };

        bucket_map.insert(key.to_string(), obj);
        Ok(etag)
    }

    /// S3 GetObject with Optional Byte Range Support (Range: bytes=start-end)
    pub fn get_object(
        &self,
        bucket: &str,
        key: &str,
        byte_range: Option<(usize, usize)>,
    ) -> Result<(Vec<u8>, String, usize), &'static str> {
        let bucket_map = self.buckets.get(bucket).ok_or("NoSuchBucket")?;
        let obj = bucket_map.get(key).ok_or("NoSuchKey")?;

        let total_size = obj.data.len();

        match byte_range {
            Some((start, end)) => {
                if start >= total_size || end >= total_size || start > end {
                    return Err("InvalidRange");
                }
                let slice = obj.data[start..=end].to_vec();
                Ok((slice, obj.content_type.clone(), total_size))
            }
            None => Ok((obj.data.clone(), obj.content_type.clone(), total_size)),
        }
    }

    /// S3 ListObjectsV2 with Prefix Filtering
    pub fn list_objects(&self, bucket: &str, prefix: &str) -> Result<Vec<&S3Object>, &'static str> {
        let bucket_map = self.buckets.get(bucket).ok_or("NoSuchBucket")?;
        let matches: Vec<&S3Object> = bucket_map
            .values()
            .filter(|obj| obj.key.starts_with(prefix))
            .collect();
        Ok(matches)
    }
}

// ============================================================================
// 2. Verification & Range Stream Simulation
// ============================================================================

fn main() {
    println!("=== 1. Creating Bucket & Uploading Assets (PutObject) ===");
    let mut s3 = MiniS3Engine::new();
    s3.create_bucket("production-media").unwrap();

    // Create a 1MB mock video file (1024 * 1024 bytes)
    let video_bytes = vec![0xAA; 1024 * 1024];
    let mut meta = HashMap::new();
    meta.insert("uploader".to_string(), "service_transcoder".to_string());

    let etag = s3
        .put_object("production-media", "videos/2026/rust_tutorial.mp4", "video/mp4", video_bytes, meta)
        .unwrap();

    println!("Uploaded 'videos/2026/rust_tutorial.mp4' (1MB) -> ETag: {}", etag);

    println!("\n=== 2. Simulating Video Streaming via HTTP Range Requests ===");
    // Video player requests only first 1KB (bytes 0 to 1023)
    let (chunk, content_type, total_size) = s3
        .get_object("production-media", "videos/2026/rust_tutorial.mp4", Some((0, 1023)))
        .unwrap();

    println!("HTTP/1.1 206 Partial Content");
    println!("Content-Type: {}", content_type);
    println!("Content-Range: bytes 0-1023/{}", total_size);
    println!("Fetched Chunk Size: {} bytes (Buffered in RAM)", chunk.len());

    println!("\n=== 3. Listing Objects by Prefix (ListObjectsV2) ===");
    s3.put_object("production-media", "videos/2026/intro.mp4", "video/mp4", vec![0xBB; 512], HashMap::new()).unwrap();
    s3.put_object("production-media", "thumbnails/2026/cover.jpg", "image/jpeg", vec![0xCC; 256], HashMap::new()).unwrap();

    let video_list = s3.list_objects("production-media", "videos/2026/").unwrap();
    println!("Found {} video objects matching prefix 'videos/2026/':", video_list.len());
    for obj in video_list {
        println!("  - Key: {:<35} | Size: {:>7} bytes | ETag: {}", obj.key, obj.data.len(), obj.etag);
    }
}
```

## Common Pitfalls & Compiler Errors

### 1. Hardcoding S3 Endpoint URLs
AWS S3 uses standard regional endpoints (e.g. `s3.us-east-1.amazonaws.com`), but MinIO, Wasabi, or Cloudflare R2 require custom endpoint URLs (e.g. `http://localhost:9000` or `https://<account_id>.r2.cloudflarestorage.com`).
**Fix**: Always allow the endpoint URL and `force_path_style(true)` to be configured via environment variables.

### 2. Loading Entire Multi-Gigabyte Objects into RAM
Calling `get_object()` and buffering the entire 10GB file into a `Vec<u8>` causes instant process OOM.
**Fix**: Always stream the object using `tokio::io::AsyncRead` or process chunk-by-chunk with `ByteStream`.

## Complete Solutions to Exercises

### Solution 1: DeleteObject Method

```rust
impl MiniS3Engine {
    pub fn delete_object(&mut self, bucket: &str, key: &str) -> Result<bool, &'static str> {
        let bucket_map = self.buckets.get_mut(bucket).ok_or("NoSuchBucket")?;
        Ok(bucket_map.remove(key).is_some())
    }
}
```
