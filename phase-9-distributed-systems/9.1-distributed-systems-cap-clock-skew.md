## Concept

A **Distributed System** is a collection of autonomous computing nodes communicating over an asynchronous, unreliable network to achieve a common goal.

Unlike single-node systems where memory is shared and hardware clocks are synchronized by the local motherboard crystal, distributed systems face three fundamental physical realities:
1. **Unreliable Networks**: Packets can be delayed arbitrarily, reordered, duplicated, or dropped.
2. **Independent Node Failures**: Any node can crash, freeze (e.g. stop-the-world GC or CPU stall), or reboot at any millisecond.
3. **Unsynchronized Clocks**: No two physical computers agree on the exact current time.

```
                  The Two Generals Problem (Network Uncertainty)
┌──────────────┐         Message: "Attack at Dawn" (LOST!)       ┌──────────────┐
│  General A   │ ─────────────────── X ────────────────────────► │  General B   │
│ (Node 1)     │ ◄────────────────── X ───────────────────────── │ (Node 2)     │
└──────────────┘         Ack: "Agreed" (LOST IN TRANSIT!)        └──────────────┘
Does General A attack? If General A attacks alone, they are defeated!
It is mathematically impossible to guarantee mutual agreement over an unreliable link.
```

---

### 1. The CAP Theorem (Brewer's Theorem)

In any distributed data store, you can choose at most **two** out of the following three properties during a **Network Partition ($P$)**:

- **Consistency ($C$)**: Every read receives the most recent write or an error (**Linearizability**).
- **Availability ($A$)**: Every non-failing node returns a non-error response for every request (without guaranteeing it is the latest write).
- **Partition Tolerance ($P$)**: The system continues to operate despite arbitrary packet loss or network split-brain.

$$\text{Because network cables can physically be cut or drop packets, } \mathbf{P} \text{ is non-negotiable.}$$
$$\text{You must choose between } \mathbf{CP} \text{ (Consistency over Availability) or } \mathbf{AP} \text{ (Availability over Consistency)}.$$

```
                                  The CAP Tradeoff
                     CP (e.g., Raft, Spanner, ZooKeeper, etcd)
                         - Strict consistency (Linearizability).
                         - During network split, minority partition rejects writes!
                     
                     AP (e.g., Cassandra, DynamoDB, DNS)
                         - Always accepts writes on all partitions.
                         - Replicas temporarily diverge (Eventual Consistency).
```

---

### 2. The Danger of Physical Clocks: Clock Skew & Drift

Physical quartz clocks on server motherboards drift due to temperature fluctuations and voltage noise (often $10 - 50\text{ms}$ of drift).

- **NTP (Network Time Protocol)** adjusts clocks, but NTP can jump backward or freeze time when synchronizing.
- **Clock Drift Disaster**: If Node 1 writes Record $X$ with local timestamp `12:00:00.005`, and Node 2 writes Record $Y$ with local timestamp `12:00:00.001` (due to a $10\text{ms}$ clock lag), a "Last-Write-Wins" database will **silently overwrite the newer write with the older write!**

```
Node 1 (Fast Clock: 12:00:00.050) ──► Writes: balance = $100
Node 2 (Slow Clock: 12:00:00.010) ──► Writes: balance = $200 (Happened AFTER Node 1!)
Database Last-Write-Wins Rule: Node 1's timestamp is higher -> balance = $100 (CORRUPTED!)
```

---

### 3. Logical Clocks: Lamport Timestamps

To establish ordering without physical clocks, Leslie Lamport invented **Logical Timestamps**:
1. Every node maintains a simple integer counter $L$ initialized to 0.
2. Before performing a local event, increment: $L = L + 1$.
3. When sending a message, attach $L$.
4. When receiving a message with timestamp $L_{\text{msg}}$, update:
$$L_{\text{local}} = \max(L_{\text{local}}, L_{\text{msg}}) + 1$$

---

## Why It Matters in Systems Programming

1. **Design Fail-Safe Consensus**: Understanding network partitions prevents split-brain disasters where two master nodes accept conflicting customer payments.
2. **Never Rely on `SystemTime::now()` for Distributed Ordering**: Use Monotonic Logical Clocks or Vector Clocks instead of wall-clock time for causality tracking.
3. **Idempotency & Deduplication**: Because networks duplicate packets, all distributed RPC handlers must be idempotent using unique transaction UUIDs.

---

## Real-World Analogy

- **Network Partitions** are like a phone line going dead in the middle of a business meeting: you don't know if your colleague hung up, drove into a tunnel, or had a heart attack.
- **Lamport Timestamps** are like numbered order tickets at a deli counter: even if the deli clock on the wall is 15 minutes slow, everyone still knows whose sandwich order came first based on the ticket number in their hand.

## Complete, Compilable Code Example

Below is a complete, self-contained **Lamport Logical Clock and Partition Simulation Engine** in pure Rust:

```rust
use std::cmp::max;
use std::collections::HashMap;

// ============================================================================
// 1. Lamport Logical Clock
// ============================================================================

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct LamportTimestamp {
    pub counter: u64,
    pub node_id: u32, // Tie-breaker for identical counters
}

pub struct NodeClock {
    pub node_id: u32,
    pub current_time: u64,
}

impl NodeClock {
    pub fn new(node_id: u32) -> Self {
        Self {
            node_id,
            current_time: 0,
        }
    }

    /// Increments clock for local event
    pub fn tick(&mut self) -> LamportTimestamp {
        self.current_time += 1;
        LamportTimestamp {
            counter: self.current_time,
            node_id: self.node_id,
        }
    }

    /// Synchronizes clock upon receiving a remote message
    pub fn update_on_receive(&mut self, remote_time: u64) -> LamportTimestamp {
        self.current_time = max(self.current_time, remote_time) + 1;
        LamportTimestamp {
            counter: self.current_time,
            node_id: self.node_id,
        }
    }
}

// ============================================================================
// 2. Distributed Partition Simulator
// ============================================================================

#[derive(Debug, Clone)]
pub struct Message {
    pub sender_id: u32,
    pub receiver_id: u32,
    pub timestamp: LamportTimestamp,
    pub payload: String,
}

pub struct DistributedNetwork {
    partition_matrix: HashMap<(u32, u32), bool>, // (from, to) -> is_blocked
}

impl DistributedNetwork {
    pub fn new() -> Self {
        Self {
            partition_matrix: HashMap::new(),
        }
    }

    /// Disconnect communication between two network partitions
    pub fn isolate_nodes(&mut self, partition_a: &[u32], partition_b: &[u32]) {
        for &a in partition_a {
            for &b in partition_b {
                self.partition_matrix.insert((a, b), true);
                self.partition_matrix.insert((b, a), true);
            }
        }
    }

    pub fn send_message(&self, msg: &Message) -> Result<(), &'static str> {
        let key = (msg.sender_id, msg.receiver_id);
        if *self.partition_matrix.get(&key).unwrap_or(&false) {
            Err("NetworkPartitionDrop: Packet dropped due to split-brain network partition!")
        } else {
            Ok(())
        }
    }
}

// ============================================================================
// 3. Simulation & Verification
// ============================================================================

fn main() {
    println!("=== 1. Simulating Lamport Logical Clocks across 3 Distributed Nodes ===");
    let mut node_a = NodeClock::new(1);
    let mut node_b = NodeClock::new(2);
    let mut node_c = NodeClock::new(3);

    // Node A local event
    let ts_a1 = node_a.tick();
    println!("Node A Event 1: Lamport Time {:?}", ts_a1);

    // Node A sends message to Node B
    let msg_a_to_b = Message {
        sender_id: 1,
        receiver_id: 2,
        timestamp: ts_a1,
        payload: "Deposit $500".to_string(),
    };

    // Node B receives message from Node A
    let ts_b1 = node_b.update_on_receive(msg_a_to_b.timestamp.counter);
    println!("Node B Received Msg from A: New Lamport Time {:?}", ts_b1);

    // Node B sends message to Node C
    let msg_b_to_c = Message {
        sender_id: 2,
        receiver_id: 3,
        timestamp: ts_b1,
        payload: "Audit Transfer".to_string(),
    };

    let ts_c1 = node_c.update_on_receive(msg_b_to_c.timestamp.counter);
    println!("Node C Received Msg from B: New Lamport Time {:?}\n", ts_c1);

    assert!(ts_a1 < ts_b1);
    assert!(ts_b1 < ts_c1);
    println!("Causal ordering preserved: A1 -> B1 -> C1 (Without using physical clocks!)\n");

    println!("=== 2. Simulating Network Partition (Split-Brain) ===");
    let mut net = DistributedNetwork::new();

    // Split network: {Node 1, Node 2} on Partition A, {Node 3} on Partition B
    net.isolate_nodes(&[1, 2], &[3]);

    println!("Sending message from Node 1 to Node 2 (Same Partition)...");
    let res_1_to_2 = net.send_message(&Message {
        sender_id: 1,
        receiver_id: 2,
        timestamp: node_a.tick(),
        payload: "Ping".to_string(),
    });
    println!("Result: {:?}", res_1_to_2);

    println!("\nSending message from Node 1 to Node 3 (Across Network Partition)...");
    let res_1_to_3 = net.send_message(&Message {
        sender_id: 1,
        receiver_id: 3,
        timestamp: node_a.tick(),
        payload: "Emergency Heartbeat".to_string(),
    });
    println!("Result: {:?}", res_1_to_3);
}
```

## Common Pitfalls & Compiler Errors

### 1. Comparing `SystemTime` for Distributed Event Ordering
Calling `SystemTime::now()` to determine if a write on Server 1 happened before a write on Server 2 fails because NTP drift of even $5\text{ms}$ will invert event causality.

### 2. Confusing `PartialOrd` with Causal Order
Lamport Timestamps guarantee that if $A \to B$ (A caused B), then $L(A) < L(B)$. However, $L(A) < L(B)$ does **NOT** imply that A caused B (they might be concurrent independent events). For true concurrency detection, use **Vector Clocks** (covered in Lesson 9.6).

pub fn can_commit_quorum(total_nodes: usize, reachable_nodes: usize) -> bool {
    let majority = (total_nodes / 2) + 1;
    reachable_nodes >= majority
}
