## Concept

A **Replicated State Machine (RSM)** relies on a mathematical truth:
$$\text{If a set of deterministic state machines start in state } S_0 \text{ and apply an identical sequence of inputs } [I_1, I_2, \dots, I_N], \text{ they will all end in the exact same state } S_N.$$

However, in a live cluster processing $10,000\text{ writes/sec}$, the Raft append-only log grows by **864,000,000 entries per day** ($\approx 100\text{GB/day}$).

Unbounded log growth creates two fatal problems:
1. **Disk Exhaustion**: The disk runs out of space.
2. **Slow Reboots**: A node restarting after a crash would have to replay billions of log entries from byte 0, taking hours to recover.

To solve this, Raft uses **Snapshots and Log Compaction**.

```
                           Raft Log Compaction (Compacting 100 Entries)
 Before Compaction:
 Index:  1      2      3      4               98     99     100    101    102
 Log:   [x=1]  [y=4]  [x=2]  [z=9]  ... ...  [x=50] [y=90] [z=12] [x=51] [a=3]
 
 1. Serialize State Machine at Index 100: Snapshot { x: 50, y: 90, z: 12 }
 2. Discard and Truncate Log Entries 1 through 100!
 
 After Compaction:
 Snapshot: (LastIncludedIndex: 100, LastIncludedTerm: 3) { x: 50, y: 90, z: 12 }
 Log:      Index 101: [x=51], Index 102: [a=3]   <--- 99% Disk Space Saved!
```

---

### 1. Snapshot Anatomy

A Raft Snapshot contains:
1. **`last_included_index`**: The highest log index applied to this snapshot.
2. **`last_included_term`**: The term of `last_included_index`.
3. **`state_machine_data`**: The raw serialized state (e.g. B-Tree KV table or RocksDB SSTable).

Once the snapshot is written to disk via `fsync()`, all log entries up to `last_included_index` are safely deleted.

---

### 2. The `InstallSnapshot` RPC

What happens if Follower Node 3 is turned off for two weeks, and while it is offline, the Leader creates a snapshot and discards entries 1 to 50,000?

When Follower 3 boots back up:
1. The Leader discovers that Follower 3's `nextIndex` ($1$) has already been discarded from the Leader's log.
2. The Leader cannot send `AppendEntries`.
3. The Leader sends an **`InstallSnapshot` RPC**, streaming the raw snapshot image directly to Follower 3.
4. Follower 3 replaces its local state machine with the snapshot, resets its log, and resumes following live `AppendEntries`.

---

## Why It Matters in Systems Programming

1. **Instant Crash Recovery**: On reboot, a database node loads the latest 50MB snapshot from disk in $20\text{ms}$ and replays only the last 100 uncompacted log entries, achieving instant restart.
2. **Bounded Memory & Disk Usage**: Keeps Raft log storage bounded to a fixed size (e.g. max 50,000 active entries).
3. **Seamless Node Catch-Up**: New replacement nodes joining the cluster catch up to terabytes of historical state in seconds via `InstallSnapshot`.

---

## Real-World Analogy

- **Without Snapshots** is like a bank accounting ledger keeping every single coffee purchase from 1950 to today: calculating your current account balance requires an accountant adding up 500 million transactions by hand.
- **With Snapshots** is like the bank sending you a monthly statement showing `"Starting Balance on Sept 1: $5,000.00"` and listing only the 5 transactions you made this week.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation demonstrating **Raft Log Compaction, Point-in-Time Snapshots, and `InstallSnapshot` Recovery** in pure Rust:

```rust
use std::collections::HashMap;

// ============================================================================
// 1. Snapshot & Compaction Data Structures
// ============================================================================

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct LogEntry {
    pub term: u64,
    pub index: usize,
    pub command: String,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Snapshot {
    pub last_included_index: usize,
    pub last_included_term: u64,
    pub kv_data: HashMap<String, String>,
}

// ============================================================================
// 2. Compactable Raft State Machine
// ============================================================================

pub struct CompactableRaftNode {
    pub id: u32,
    pub log: Vec<LogEntry>,
    pub log_start_index: usize, // Virtual offset of log[0]
    pub snapshot: Option<Snapshot>,
    pub state_machine: HashMap<String, String>,
    pub commit_index: usize,
}

impl CompactableRaftNode {
    pub fn new(id: u32) -> Self {
        Self {
            id,
            log: Vec::new(),
            log_start_index: 1, // Raft 1-based indexing
            snapshot: None,
            state_machine: HashMap::new(),
            commit_index: 0,
        }
    }

    /// Append and commit an entry
    pub fn append_and_commit(&mut self, term: u64, command: &str) {
        let global_index = self.log_start_index + self.log.len();
        let entry = LogEntry {
            term,
            index: global_index,
            command: command.to_string(),
        };
        self.log.push(entry);
        self.commit_index = global_index;

        // Apply to state machine
        if let Some((k, v)) = command.split_once('=') {
            self.state_machine.insert(k.to_string(), v.to_string());
        }
    }

    /// Take a point-in-time snapshot and compact all preceding log entries
    pub fn create_snapshot(&mut self, compact_up_to_index: usize) -> Result<Snapshot, &'static str> {
        if compact_up_to_index > self.commit_index {
            return Err("Cannot snapshot uncommitted entries");
        }
        if compact_up_to_index < self.log_start_index {
            return Err("Index already compacted");
        }

        // Relative index in local vector
        let offset = compact_up_to_index - self.log_start_index;
        let last_term = self.log[offset].term;

        let snap = Snapshot {
            last_included_index: compact_up_to_index,
            last_included_term: last_term,
            kv_data: self.state_machine.clone(),
        };

        // Discard log entries up to compact_up_to_index
        self.log.drain(0..=offset);
        self.log_start_index = compact_up_to_index + 1;
        self.snapshot = Some(snap.clone());

        println!(
            "  [Node {}] Compacted log up to index {}! Remaining log entries: {}",
            self.id, compact_up_to_index, self.log.len()
        );

        Ok(snap)
    }

    /// Handle InstallSnapshot RPC from Leader
    pub fn handle_install_snapshot(&mut self, snapshot: Snapshot) {
        println!(
            "  [Node {}] Installing Snapshot from Leader (Last Index: {}, Last Term: {})...",
            self.id, snapshot.last_included_index, snapshot.last_included_term
        );

        self.state_machine = snapshot.kv_data.clone();
        self.commit_index = snapshot.last_included_index;
        self.log_start_index = snapshot.last_included_index + 1;
        self.log.clear(); // Discard old stale log
        self.snapshot = Some(snapshot);
    }
}

// ============================================================================
// 3. Verification & Execution
// ============================================================================

fn main() {
    println!("=== 1. Leader Node Generating 5 Log Entries ===");
    let mut leader = CompactableRaftNode::new(1);
    leader.append_and_commit(1, "account:alice=100");
    leader.append_and_commit(1, "account:bob=200");
    leader.append_and_commit(1, "account:alice=300"); // Supersedes alice=100
    leader.append_and_commit(1, "account:charlie=500");
    leader.append_and_commit(1, "account:bob=250");   // Supersedes bob=200

    println!("Total Log Entries in Leader: {}", leader.log.len());
    println!("Leader State Machine: {:?}", leader.state_machine);

    println!("\n=== 2. Creating Snapshot & Compacting Entries 1..4 ===");
    let snapshot = leader.create_snapshot(4).unwrap();
    println!("Snapshot State: {:?}", snapshot.kv_data);
    println!("Leader Active Log Entries: {:?}", leader.log);

    println!("\n=== 3. Simulating Lagging Follower Receiving InstallSnapshot ===");
    let mut lagging_follower = CompactableRaftNode::new(2);
    println!("Lagging Follower Initial State: {:?}", lagging_follower.state_machine);

    // Leader sends InstallSnapshot to catch follower up instantly
    lagging_follower.handle_install_snapshot(snapshot);
    println!("Lagging Follower State after Snapshot: {:?}", lagging_follower.state_machine);

    // Follower receives entry 5 via standard AppendEntries
    lagging_follower.append_and_commit(1, "account:bob=250");
    println!("Lagging Follower Final State: {:?}", lagging_follower.state_machine);

    assert_eq!(leader.state_machine, lagging_follower.state_machine);
    println!("\nVerification: Follower state matches Leader 100%!");
}
```

## Common Pitfalls & Compiler Errors

### 1. Off-by-One Errors in Log Start Index
After log compaction, `log[0]` no longer corresponds to global Raft index `1`. It corresponds to `log_start_index`. Accessing global index $I$ requires indexing `log[I - log_start_index]`.

### 2. Snapshot Serialization Blocking the Main Event Loop
Serializing a 50GB state machine synchronously blocks the Raft thread, causing the node to miss heartbeats and lose leadership.
**Fix**: Use copy-on-write fork semantics (`fork()`) or asynchronous background serialization on an immutable checkpoint.

## Complete Solutions to Exercises

### Solution 1: Global Index Lookup

```rust
impl CompactableRaftNode {
    pub fn get_entry(&self, global_index: usize) -> Option<&LogEntry> {
        if global_index < self.log_start_index {
            return None; // Entry already compacted into snapshot
        }
        let local_offset = global_index - self.log_start_index;
        self.log.get(local_offset)
    }
}
```
