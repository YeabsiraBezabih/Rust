## Concept

In distributed databases (like CockroachDB, TiKV, etcd, Kafka Kraft), multiple nodes must agree on an identical append-only log of transactions, even when some nodes crash or the network drops packets.

The **Raft Consensus Algorithm** (designed by Stanford researchers Ongaro & Ousterhout) solves distributed consensus by decomposing it into three strictly separated subproblems:
1. **Leader Election**: Selecting one coordinator when the current leader crashes.
2. **Log Replication**: The leader accepts client writes and forces follower logs to match its own.
3. **Safety**: Guaranteeing that if any node applies a log entry to its state machine, no other node can apply a different command for that log index.

```
                           Raft Node Role State Machine
                       ┌──────────────────────────────┐
                       │           Follower           │
                       └──────────────┬───────────────┘
                                      │ Election Timeout Expires
                                      ▼
                       ┌──────────────────────────────┐
       ┌──────────────►│          Candidate           │
       │ Split Vote    └──────────────┬───────────────┘
       │                              │ Receives Majority Votes (Quorum)
       │                              ▼
       │               ┌──────────────────────────────┐
       └───────────────┤            Leader            │
   Discovers Higher    └──────────────────────────────┘
   Term on Cluster
```

---

### 1. Terms and Randomized Election Timeouts

Time in Raft is divided into arbitrary numbered **Terms** (acting as logical clocks):
- Every node has an **Election Timer** randomized between **$150\text{ms} - 300\text{ms}$**.
- If a Follower receives no `AppendEntries` heartbeat before its timer expires, it assumes the Leader has died.
- The Follower increments its `current_term`, transitions to `Candidate`, votes for itself, and broadcasts `RequestVote` RPCs.
- **Why Randomized Timeouts?** Randomization ensures that one candidate times out and wins the election before other followers can time out, completely preventing split-vote stalemates.

---

### 2. The Log Replication Pipeline

```
 Client ──► 1. "SET x = 10" ──► [ Leader (Term 1) ]
                                      │
           ┌──────────────────────────┴──────────────────────────┐
           ▼ AppendEntries(x=10)                                 ▼ AppendEntries(x=10)
     [ Follower 2 ] (ACK)                                  [ Follower 3 ] (ACK)
           │                                                     │
           └──────────────────────────┬──────────────────────────┘
                                      ▼
             2. Quorum Reached (2/3 Nodes ACK)!
             3. Leader commits log entry at index 1.
             4. Leader applies entry to local State Machine.
             5. Leader returns success (200 OK) to Client.
```

---

### 3. Raft Safety Guarantees

1. **Election Safety**: At most one leader can be elected per term.
2. **Leader Append-Only**: A leader never overwrites or truncates its own log entries; it only appends.
3. **Log Matching Property**: If two logs contain an entry with the same index and term, they are identical up to that index.
4. **Leader Completeness**: If a log entry is committed in a given term, that entry will be present in the logs of the leaders for all higher-numbered terms. A candidate whose log is less up-to-date than a voter's log is **denied votes**.

---

## Why It Matters in Systems Programming

1. **Linearizable Distributed Storage**: Raft powers the control planes of Kubernetes (`etcd`), distributed SQL databases (`TiKV`), and high-throughput streaming engines.
2. **Zero Split-Brain Disasters**: Majority quorum voting guarantees two competing leaders can never both believe they have write authority.
3. **High Availability**: A 5-node Raft cluster can tolerate the complete physical destruction of 2 nodes with zero data loss and automated sub-second leader failover.

---

## Real-World Analogy

- **Raft** is like a parliamentary democracy:
- Members are **Followers** listening to the Prime Minister (**Leader**).
- If the Prime Minister stops speaking for 15 minutes, an impatient MP (**Candidate**) calls for a vote of confidence.
- Whichever MP wins votes from a strict majority ($> 50\%$) becomes the new Prime Minister.
- When parliament votes on a new law (**Log Replication**), once more than half the MPs sign it, the law is formally enacted into the country's legal code (**State Machine**).

## Complete, Compilable Code Example

Below is a complete, working simulation of the **Raft Consensus State Machine** in pure Rust:

```rust
use std::collections::HashMap;

// ============================================================================
// 1. Log Entry & Role Definitions
// ============================================================================

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct LogEntry {
    pub term: u64,
    pub index: usize,
    pub command: String,
}

#[derive(Debug, PartialEq, Eq, Clone, Copy)]
pub enum RaftRole {
    Follower,
    Candidate,
    Leader,
}

// ============================================================================
// 2. Raft Node Consensus Engine
// ============================================================================

pub struct RaftNode {
    pub id: u32,
    pub role: RaftRole,
    pub current_term: u64,
    pub voted_for: Option<u32>,
    pub log: Vec<LogEntry>,
    pub commit_index: usize,
    pub state_machine: HashMap<String, String>,
}

impl RaftNode {
    pub fn new(id: u32) -> Self {
        Self {
            id,
            role: RaftRole::Follower,
            current_term: 0,
            voted_for: None,
            log: Vec::new(),
            commit_index: 0,
            state_machine: HashMap::new(),
        }
    }

    /// 1. Trigger Election on Timeout
    pub fn start_election(&mut self) -> (u64, usize, u64) {
        self.role = RaftRole::Candidate;
        self.current_term += 1;
        self.voted_for = Some(self.id);

        let last_log_index = self.log.len();
        let last_log_term = self.log.last().map(|e| e.term).unwrap_or(0);

        println!(
            "  [Node {}] Timed out! Starting Election for Term {} (Voted for self)",
            self.id, self.current_term
        );

        (self.current_term, last_log_index, last_log_term)
    }

    /// 2. Handle RequestVote RPC
    pub fn handle_request_vote(
        &mut self,
        candidate_term: u64,
        candidate_id: u32,
        last_log_index: usize,
        last_log_term: u64,
    ) -> bool {
        if candidate_term < self.current_term {
            return false;
        }

        if candidate_term > self.current_term {
            self.current_term = candidate_term;
            self.role = RaftRole::Follower;
            self.voted_for = None;
        }

        let my_last_index = self.log.len();
        let my_last_term = self.log.last().map(|e| e.term).unwrap_or(0);

        // Leader Completeness Check: Candidate's log must be at least as up-to-date as voter's
        let log_is_up_to_date = candidate_term > my_last_term
            || (candidate_term == my_last_term && last_log_index >= my_last_index);

        let can_vote = self.voted_for.is_none() || self.voted_for == Some(candidate_id);

        if can_vote && log_is_up_to_date {
            self.voted_for = Some(candidate_id);
            println!("  [Node {}] Voted YES for Candidate #{} in Term {}", self.id, candidate_id, self.current_term);
            true
        } else {
            println!("  [Node {}] Voted NO for Candidate #{} in Term {}", self.id, candidate_id, self.current_term);
            false
        }
    }

    /// 3. Leader Appends Client Command to Log
    pub fn client_write(&mut self, command: &str) -> Result<usize, &'static str> {
        if self.role != RaftRole::Leader {
            return Err("NotTheLeader: Client must redirect write to active Leader");
        }

        let new_index = self.log.len() + 1;
        let entry = LogEntry {
            term: self.current_term,
            index: new_index,
            command: command.to_string(),
        };
        self.log.push(entry);
        println!("  [Leader {}] Appended entry #{}: '{}'", self.id, new_index, command);
        Ok(new_index)
    }

    /// 4. Commit and Apply Entries to State Machine
    pub fn commit_entries_up_to(&mut self, new_commit_index: usize) {
        while self.commit_index < new_commit_index && self.commit_index < self.log.len() {
            let entry = &self.log[self.commit_index];
            // Apply command "KEY=VAL" to state machine
            if let Some((k, v)) = entry.command.split_once('=') {
                self.state_machine.insert(k.to_string(), v.to_string());
                println!("  [Node {}] Applied to State Machine: {} -> {}", self.id, k, v);
            }
            self.commit_index += 1;
        }
    }
}

// ============================================================================
// 3. Cluster Simulation & Verification
// ============================================================================

fn main() {
    println!("=== 1. Simulating 3-Node Raft Cluster ===");
    let mut node_1 = RaftNode::new(1);
    let mut node_2 = RaftNode::new(2);
    let mut node_3 = RaftNode::new(3);

    println!("Initial cluster created. All nodes in Follower role.\n");

    println!("=== 2. Node 1 Election Timeout & Quorum Voting ===");
    let (term, last_idx, last_term) = node_1.start_election();

    // Node 1 asks Node 2 and Node 3 for votes
    let vote_2 = node_2.handle_request_vote(term, 1, last_idx, last_term);
    let vote_3 = node_3.handle_request_vote(term, 1, last_idx, last_term);

    let votes_received = 1 + (vote_2 as usize) + (vote_3 as usize);
    println!("Candidate #1 received {} / 3 votes.", votes_received);

    if votes_received >= 2 {
        node_1.role = RaftRole::Leader;
        println!("🏆 Node 1 elected LEADER for Term {}!\n", term);
    }

    println!("=== 3. Leader Replicating Client Write ===");
    let entry_idx = node_1.client_write("balance:alice=5000").unwrap();

    // Simulate AppendEntries to Followers
    node_2.log = node_1.log.clone();
    node_3.log = node_1.log.clone();

    // Quorum acknowledged -> Commit on all nodes
    println!("Majority quorum (3/3 nodes) replicated entry #{}. Committing...", entry_idx);
    node_1.commit_entries_up_to(entry_idx);
    node_2.commit_entries_up_to(entry_idx);
    node_3.commit_entries_up_to(entry_idx);

    println!("\n=== Final State Machine Values Across All 3 Replicas ===");
    println!("Node 1 State: {:?}", node_1.state_machine);
    println!("Node 2 State: {:?}", node_2.state_machine);
    println!("Node 3 State: {:?}", node_3.state_machine);
    assert_eq!(node_1.state_machine.get("balance:alice").unwrap(), "5000");
    assert_eq!(node_2.state_machine.get("balance:alice").unwrap(), "5000");
    assert_eq!(node_3.state_machine.get("balance:alice").unwrap(), "5000");
}
```

## Common Pitfalls & Compiler Errors

### 1. Voting Twice in the Same Term
A node must vote for at most one candidate per term on a first-come, first-served basis. Violating this allows two candidates to each win 2 votes in a 3-node cluster, creating two simultaneous leaders.

### 2. Committing Entries from Older Terms Directly
In Raft, a leader cannot commit a log entry from an older term simply by counting replicas. The leader **MUST commit at least one entry from its current term** by replicating it to a majority, which indirectly commits all preceding entries.

## Complete Solutions to Exercises

### Solution 1: Step-Down Method

```rust
impl RaftNode {
    pub fn handle_heartbeat(&mut self, leader_term: u64, leader_id: u32) -> bool {
        if leader_term < self.current_term {
            return false;
        }

        if leader_term > self.current_term || self.role != RaftRole::Follower {
            self.current_term = leader_term;
            self.role = RaftRole::Follower;
            self.voted_for = Some(leader_id);
            println!("  [Node {}] Stepped down to FOLLOWER under Leader #{} (Term {})", self.id, leader_id, leader_term);
        }

        true
    }
}
```
