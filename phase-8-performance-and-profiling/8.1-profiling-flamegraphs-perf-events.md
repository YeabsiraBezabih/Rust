## Concept

When optimizing Rust systems code, **never guess where performance bottlenecks lie**. Human intuition about CPU execution is almost always wrong.

Systems engineers use **Statistical CPU Sampling**, **Hardware Performance Counters**, and **Flamegraphs** to measure nanosecond-level execution profiles.

```
                             Interactive Flamegraph Anatomy
┌────────────────────────────────────────────────────────────────────────┐
│                                [ main ]                                │
├───────────────────────────────────┬────────────────────────────────────┤
│           [ handle_request ]      │           [ garbage_collect ]      │
├─────────────────┬─────────────────┼────────────────────────────────────┤
│ [ parse_json ]  │ [ sql_query ]   │         [ deallocate_pages ]       │
├─────────────────┼─────────────────┼────────────────────────────────────┤
│ [ utf8_validate]│ [ socket_read ] │         [ free_arena_chunks ]      │
└─────────────────┴─────────────────┴────────────────────────────────────┘
  ◄────────────────────────── Total CPU Time ──────────────────────────►
```

- **X-axis**: Total sample population (width = % of total CPU time spent in that function).
- **Y-axis**: Call stack depth (top-most box is currently executing on CPU).

---

### 1. Profiling Tools in the Rust Ecosystem

1. **`cargo-flamegraph`**: Uses Linux `perf` or macOS `dtrace` to record instruction pointer addresses at $997\text{Hz}$ and renders an interactive SVG flamegraph.
   ```bash
   cargo install flamegraph
   cargo flamegraph --bin my_server
   ```
2. **Linux `perf`**: Inspects CPU hardware performance counters:
   ```bash
   perf stat ./target/release/my_server
   perf record -F 99 -g ./target/release/my_server
   perf report
   ```
3. **`criterion.rs`**: Statistical micro-benchmarking suite with outlier detection and regression analysis.

---

### 2. Hardware Performance Counters

Modern CPUs contain dedicated hardware counters inside the core that measure events with zero CPU overhead:

| Hardware Counter | What It Measures | Performance Implication |
| :--- | :--- | :--- |
| **`instructions per cycle` (IPC)** | CPU efficiency ($\text{IPC} > 2.0$ is good; $< 0.8$ is bad). | Low IPC means CPU is stalling on memory or branches. |
| **`cache-misses`** | L1/L2/L3 cache misses. | High misses mean memory bandwidth bottleneck. |
| **`branch-misses`** | Failed CPU branch predictions. | Pipeline flush penalty ($\sim 15 - 20\text{ cycles}$ wasted). |
| **`page-faults`** | Virtual memory page table allocations. | High allocations mean heap churn. |

---

### 3. Cargo Release Optimization Flags

For accurate profiling and maximum throughput, configure `Cargo.toml`:

```toml
[profile.release]
opt-level = 3          # Maximum compiler optimizations
lto = "fat"            # Link-Time Optimization across all crates
codegen-units = 1      # Reduces parallel compilation units for better optimizations
panic = "abort"        # Removes unwinding landing pads (smaller binary, faster execution)
debug = true           # Includes debug symbols so Flamegraphs show function names!
```

## Why It Matters in Systems Programming

1. **Pinpointing Microsecond Bottlenecks**: A flamegraph instantly reveals whether 70% of CPU time is spent in memory allocation (`malloc`/`free`), string formatting (`Display`), or cryptographic hashing.
2. **Preventing Premature Optimization**: Focus engineering effort exclusively on the top 2 widest bars in the flamegraph.
3. **Benchmarking Real Hardware Throughput**: Using IPC and cache-miss metrics ensures optimizations actually improve hardware utilization rather than shifting bottlenecks elsewhere.

## Complete, Compilable Code Example

Below is a complete, self-contained **Statistical CPU Sampler and Benchmark Engine** in pure Rust demonstrating call stack sampling, bottleneck detection, and instruction cost estimation:

```rust
use std::collections::HashMap;
use std::time::{Duration, Instant};

// ============================================================================
// 1. Mock Call Stack & Statistical Profiler
// ============================================================================

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct StackFrame {
    pub function_name: &'static str,
    pub module_path: &'static str,
}

pub struct Profiler {
    samples: HashMap<Vec<StackFrame>, usize>,
    total_samples: usize,
}

impl Profiler {
    pub fn new() -> Self {
        Self {
            samples: HashMap::new(),
            total_samples: 0,
        }
    }

    /// Record a stack trace sample
    pub fn record_sample(&mut self, stack: Vec<StackFrame>) {
        *self.samples.entry(stack).or_insert(0) += 1;
        self.total_samples += 1;
    }

    /// Render terminal flame report
    pub fn print_report(&self) {
        println!("\n=== Statistical Profiler Report (Total Samples: {}) ===", self.total_samples);
        println!("{:<40} | {:<10} | {:<10}", "Stack Frame (Leaf Function)", "Samples", "CPU Share");
        println!("{:-<40}-+-{:-<10}-+-{:-<10}", "", "", "");

        let mut aggregated: HashMap<&'static str, usize> = HashMap::new();
        for (stack, count) in &self.samples {
            if let Some(leaf) = stack.last() {
                *aggregated.entry(leaf.function_name).or_insert(0) += count;
            }
        }

        let mut sorted: Vec<(&'static str, usize)> = aggregated.into_iter().collect();
        sorted.sort_by(|a, b| b.1.cmp(&a.1));

        for (func, count) in sorted {
            let pct = (count as f64 / self.total_samples as f64) * 100.0;
            println!("{:<40} | {:<10} | {:>6.2}%", func, count, pct);
        }
    }
}

// ============================================================================
// 2. Simulated Workload Algorithms
// ============================================================================

pub struct Workload;

impl Workload {
    /// Fast memory-aligned computation (High IPC)
    pub fn fast_vector_math(n: usize) -> u64 {
        let mut sum = 0u64;
        for i in 0..n {
            sum = sum.wrapping_add((i ^ 0x5555) as u64);
        }
        sum
    }

    /// Slow un-cached memory traversal (Cache Thrashing / Low IPC)
    pub fn slow_pointer_chasing(size: usize) -> usize {
        let mut data: Vec<usize> = (0..size).collect();
        // Permute to create random memory access jumps
        let mut val = 0;
        let mut idx = 0;
        for _ in 0..size {
            idx = (idx * 31 + 7) % size;
            val ^= data[idx];
            data[idx] = val;
        }
        val
    }
}

// ============================================================================
// 3. Profiling Simulation
// ============================================================================

fn main() {
    println!("=== 1. Running Profiler on Workload Engine ===");
    let mut profiler = Profiler::new();

    let frame_main = StackFrame { function_name: "main", module_path: "app" };
    let frame_fast = StackFrame { function_name: "fast_vector_math", module_path: "app::math" };
    let frame_slow = StackFrame { function_name: "slow_pointer_chasing", module_path: "app::memory" };

    println!("Simulating 1,000 statistical timer interrupts during execution...");

    // Fast math executes in ~10% of samples
    for _ in 0..120 {
        profiler.record_sample(vec![frame_main.clone(), frame_fast.clone()]);
    }

    // Slow pointer chasing consumes ~88% of CPU time
    for _ in 0..880 {
        profiler.record_sample(vec![frame_main.clone(), frame_slow.clone()]);
    }

    profiler.print_report();

    println!("\n=== 2. Benchmarking Real Execution Wall-Clock Time ===");
    let start = Instant::now();
    let res_fast = Workload::fast_vector_math(1_000_000);
    println!("Fast Vector Math Result: {} (Took: {:?})", res_fast, start.elapsed());

    let start = Instant::now();
    let res_slow = Workload::slow_pointer_chasing(100_000);
    println!("Slow Pointer Chasing Result: {} (Took: {:?})", res_slow, start.elapsed());
}
```

## Common Pitfalls & Compiler Errors

### 1. Profiling Debug Builds
Profiling a binary compiled with `cargo run` (debug mode) measures compiler debug scaffolding, lack of function inlining, and bounds checks rather than real production performance.
**Fix**: Always profile with `cargo flamegraph --release` or `cargo build --release`.

### 2. Missing Debug Symbols in Release Mode
By default, `--release` strips debug line symbols, resulting in flamegraphs that display raw hex memory addresses (`0x55a189f2`) instead of function names (`parse_json`).
**Fix**: Add `debug = true` to `[profile.release]` in `Cargo.toml`.

## Complete Solutions to Exercises

### Solution 1 & 2: Folded Stack Formatter

```rust
impl Profiler {
    pub fn export_folded_stacks(&self) -> String {
        let mut out = String::new();
        for (stack, count) in &self.samples {
            let names: Vec<&str> = stack.iter().map(|f| f.function_name).collect();
            out.push_str(&format!("{} {}\n", names.join(";"), count));
        }
        out
    }
}
```
