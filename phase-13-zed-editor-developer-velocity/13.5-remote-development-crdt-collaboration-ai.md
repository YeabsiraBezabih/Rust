## Concept

Modern systems programming often requires running builds on powerful remote servers (e.g. 64-core Linux build boxes, cloud GPU instances, or bare-metal barebones kernels) while coding on a lightweight laptop.

Furthermore, engineering complex systems benefits immensely from **frictionless peer collaboration** and **context-aware AI assistance**.

Zed provides three killer features for modern distributed engineering teams:
1. **Zero-Latency Remote Development over SSH**: Runs a lightweight headless daemon on the remote server while rendering UI locally at 120 FPS via GPUI.
2. **Real-Time Multiplayer Collaboration via CRDTs**: Zero-conflict concurrent editing across multiple developers with real-time cursor tracking and voice audio.
3. **The Zed AI Assistant Panel**: Deeply integrated LLM reasoning with contextual prompt injection (`/file`, `/tab`, `/symbols`, `/terminal`).

### 1. Remote SSH Development in Zed

Unlike older remote extensions that serialize large UI states over the wire, Zed runs a tiny, headless binary (`zed-remote-server`) on the remote Linux host:
- File indexing, `rust-analyzer` LSP caching, and `cargo build` run on the powerful remote machine.
- Keystrokes and rendering happen entirely on your local GPU, meaning network lag **never causes typing or scrolling stutter**.
- To connect: Open Command Palette (`ctrl-shift-p` / `cmd-shift-p`) ➔ `projects: open remote` ➔ `ssh user@remote-box:/path/to/repo`.

---

### 2. CRDT-Powered Multiplayer Collaboration

Zed uses an operation-based **CRDT (Conflict-free Replicated Data Type)** tree:
- When Developer A and Developer B edit the same function simultaneously, edits are merged deterministically without merge conflicts or server locks.
- **Follow Mode**: Click an avatar to lock your viewport to their cursor in real time—ideal for debugging sessions, onboarding, and architectural reviews.

### 3. Mastering the Zed Assistant Panel

Open the Assistant panel with `ctrl-?` or `cmd-?`. Zed allows you to compose precise prompts by referencing your codebase with **Slash Commands**:

```markdown
I am getting a borrow checker error in my transaction pipeline.

/file src/ledger/transaction.rs
/symbols TransactionManager
/terminal

Explain why the mutable borrow of `self.wal` conflicts with the shared borrow in `validate_account()` and propose an idiomatic zero-copy refactor.
```

#### Supported Slash Commands:
- `/file <path>`: Injects file contents into the prompt.
- `/tab`: Injects the currently focused editor tab.
- `/symbols <query>`: Injects matching function/struct declarations.
- `/terminal`: Injects recent compiler errors and terminal logs.

## Complete, Compilable Code Example

To understand how Zed merges concurrent edits without locks, here is a complete, runnable Rust implementation of a **Character-Level LWW (Last-Write-Wins) CRDT Text Buffer**:

```rust
use std::collections::BTreeMap;
use std::time::{SystemTime, UNIX_EPOCH};

/// Unique identifier for each character operation in the CRDT
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Dot {
    pub client_id: u32,
    pub counter: u64,
}

/// A character node in the distributed CRDT document
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CrdtChar {
    pub id: Dot,
    pub value: char,
    pub timestamp_ns: u128,
    pub is_deleted: bool,
}

/// Conflict-Free Replicated Text Document
#[derive(Debug, Clone)]
pub struct CrdtTextDocument {
    pub client_id: u32,
    pub counter: u64,
    pub chars: BTreeMap<Dot, CrdtChar>,
}

impl CrdtTextDocument {
    pub fn new(client_id: u32) -> Self {
        Self {
            client_id,
            counter: 0,
            chars: BTreeMap::new(),
        }
    }

    /// Insert a new character locally
    pub fn insert(&mut self, ch: char) -> CrdtChar {
        self.counter += 1;
        let id = Dot {
            client_id: self.client_id,
            counter: self.counter,
        };
        let timestamp_ns = SystemTime::now()
            .duration_since(UNIX_EPOCH)
            .unwrap()
            .as_nanos();

        let crdt_char = CrdtChar {
            id,
            value: ch,
            timestamp_ns,
            is_deleted: false,
        };

        self.chars.insert(id, crdt_char.clone());
        crdt_char
    }

    /// Mark a character as deleted (Tombstone)
    pub fn delete(&mut self, id: Dot) {
        if let Some(c) = self.chars.get_mut(&id) {
            c.is_deleted = true;
        }
    }

    /// Merge incoming remote CRDT operation deterministically
    pub fn merge_remote_op(&mut self, op: CrdtChar) {
        self.chars
            .entry(op.id)
            .and_modify(|existing| {
                // If remote op is a tombstone with newer or equal timestamp, mark deleted
                if op.is_deleted {
                    existing.is_deleted = true;
                }
            })
            .or_insert(op);
    }

    /// Render visible text content
    pub fn render_text(&self) -> String {
        self.chars
            .values()
            .filter(|c| !c.is_deleted)
            .map(|c| c.value)
            .collect()
    }
}

fn main() {
    println!("=== Zed Real-Time CRDT Replication Demo ===\n");

    // Developer 1 (Alice) on Client 1
    let mut doc_alice = CrdtTextDocument::new(1);

    // Developer 2 (Bob) on Client 2
    let mut doc_bob = CrdtTextDocument::new(2);

    // Alice types "RUST"
    let op_r = doc_alice.insert('R');
    let op_u = doc_alice.insert('U');
    let op_s = doc_alice.insert('S');
    let op_t = doc_alice.insert('T');

    // Bob receives Alice's stream of operations
    doc_bob.merge_remote_op(op_r);
    doc_bob.merge_remote_op(op_u);
    doc_bob.merge_remote_op(op_s);
    doc_bob.merge_remote_op(op_t);

    println!("Alice's Buffer: \"{}\"", doc_alice.render_text());
    println!("Bob's Buffer:   \"{}\"", doc_bob.render_text());
    assert_eq!(doc_alice.render_text(), doc_bob.render_text());

    // Bob deletes 'S'
    doc_bob.delete(Dot { client_id: 1, counter: 3 });

    // Alice receives Bob's delete tombstone
    doc_alice.merge_remote_op(CrdtChar {
        id: Dot { client_id: 1, counter: 3 },
        value: 'S',
        timestamp_ns: 1000,
        is_deleted: true,
    });

    println!("\nAfter Bob Deletes 'S' & Replicates:");
    println!("Alice's Buffer: \"{}\"", doc_alice.render_text());
    println!("Bob's Buffer:   \"{}\"", doc_bob.render_text());
    assert_eq!(doc_alice.render_text(), "RUT");
}
```

## Common Pitfalls & Configuration Errors

### 1. SSH Remote Disconnects & Stale Sockets
- **Cause**: Linux SSH server dropping idle TCP connections on aggressive cloud firewalls.
- **Fix**: Add `ServerAliveInterval 30` and `ServerAliveCountMax 3` to `~/.ssh/config`.

### 2. Large File Context Blowup in AI Assistant
- **Cause**: Using `/file` on huge generated files (e.g. 50,000-line protobuf outputs) exhausting the LLM's context window.
- **Fix**: Use `/symbols` to extract only relevant structs/traits instead of dumping whole files.

## Complete Solutions to Exercises

### Solution 1: Multi-Client CRDT Convergence Test
```rust
#[test]
fn test_crdt_three_client_convergence() {
    let mut c1 = CrdtTextDocument::new(1);
    let mut c2 = CrdtTextDocument::new(2);
    let mut c3 = CrdtTextDocument::new(3);

    let op1 = c1.insert('A');
    let op2 = c2.insert('B');
    let op3 = c3.insert('C');

    // Deliver in order: 3, 1, 2 to Client 1
    c1.merge_remote_op(op3.clone());
    c1.merge_remote_op(op2.clone());

    // Deliver in order: 2, 3, 1 to Client 2
    c2.merge_remote_op(op1.clone());
    c2.merge_remote_op(op3.clone());

    // Deliver in order: 1, 2, 3 to Client 3
    c3.merge_remote_op(op1.clone());
    c3.merge_remote_op(op2.clone());

    // All documents must deterministically converge!
    assert_eq!(c1.render_text(), c2.render_text());
    assert_eq!(c2.render_text(), c3.render_text());
}
```
