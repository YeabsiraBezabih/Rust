## Concept

While Zed provides an ultra-fast rendering engine and text buffer, your deep language intelligence (auto-completion, type inference, go-to-definition, and refactoring) is powered by the **Language Server Protocol (LSP)** and **`rust-analyzer`**.

By default, standard IDE setups run generic LSP settings that can lead to high RAM usage, sluggish type checking on large workspaces, and missing diagnostics. 

In Zed, configuring `rust-analyzer` via `settings.json` allows you to unlock:
1. **Clippy on Save**: Real-time linting for performance anti-patterns, missing docs, and unidiomatic code.
2. **Precision Inlay Hints**: Visible inline type annotations, parameter names, lifetime bounds, and method chaining types without cluttering source files.
3. **Macro Expansion**: Instant visualization of declarative (`macro_rules!`) and procedural macros.
4. **Compile-Check Caching**: Offloading cargo check lock contention in large multi-crate workspaces.

### 2. High-Value Inlay Hints Explained

| Inlay Hint Type | What Zed Displays Inline | Why It Prevents Bugs |
| :--- | :--- | :--- |
| **Chaining Hints** | `vec.iter().map(...)` ➔ `: Map<Iter<i32>>` | Shows exact iterator adapter types without guessing. |
| **Parameter Hints** | `tcp_stream.set_nodelay(nodelay: true)` | Clarifies ambiguous boolean parameters. |
| **Lifetime Elision Hints**| `fn parse<'a>(input: &'a str)` | Explicitly reveals which lifetime output references borrow from. |
| **Closure Return Types**| `\|x\| -> Option<usize> { ... }` | Prevents accidental type mismatches in complex stream combinators. |

---

## Why It Matters in Systems Programming

1. **Catching Anti-Patterns Early**: Clippy flags inefficient allocations (such as unnecessary `.clone()`, unneeded `format!`, or missing `#[must_use]` on `Result` types) directly in the editor buffer.
2. **De-mystifying Complex Generics**: Systems crates (like `tokio`, `axum`, and `diesel`) produce deeply nested generic types. Inlay hints make types immediately visible.
3. **Macro Transparency**: Systems code makes heavy use of procedural macros (`#[derive(Serialize)]`, `#[tokio::main]`). Expanding macros inside Zed lets you debug generated code instantly.

## Complete, Compilable Code Example

The following Rust example showcases complex type inferences, lifetime elisions, and iterator chains that benefit directly from `rust-analyzer` inlay hints and Clippy optimizations:

```rust
use std::collections::HashMap;

/// Demonstrates types that rust-analyzer annotates with Inlay Hints
#[derive(Debug, PartialEq, Eq)]
pub struct MetricRecord {
    pub service_name: String,
    pub latency_ms: u64,
    pub status_code: u16,
}

pub struct MetricsAggregator {
    data: Vec<MetricRecord>,
}

impl MetricsAggregator {
    pub fn new() -> Self {
        Self { data: Vec::new() }
    }

    pub fn record(&mut self, service: &str, latency_ms: u64, status: u16) {
        self.data.push(MetricRecord {
            service_name: service.to_string(),
            latency_ms,
            status_code: status,
        });
    }

    /// Iterator chain where Zed displays Chaining Hints and Inferred Return Types:
    /// Inlay: -> impl Iterator<Item = (&String, usize)>
    pub fn calculate_p99_by_service(&self) -> HashMap<&str, u64> {
        let mut grouped: HashMap<&str, Vec<u64>> = HashMap::new();

        // Parameter hint: service_name: &record.service_name
        for record in &self.data {
            grouped
                .entry(&record.service_name)
                .or_default()
                .push(record.latency_ms);
        }

        grouped
            .into_iter()
            .map(|(service, mut latencies)| {
                latencies.sort_unstable(); // Clippy recommends sort_unstable over sort for primitive numbers!
                let p99_idx = ((latencies.len() as f64 * 0.99).ceil() as usize).saturating_sub(1);
                let p99_val = latencies[p99_idx.min(latencies.len() - 1)];
                (service, p99_val)
            })
            .collect()
    }
}

fn main() {
    println!("=== rust-analyzer & Clippy Integration Demo ===");

    let mut agg = MetricsAggregator::new();
    agg.record("auth-service", 12, 200);
    agg.record("auth-service", 15, 200);
    agg.record("auth-service", 150, 500);
    agg.record("payment-service", 45, 200);
    agg.record("payment-service", 85, 200);

    let p99_metrics = agg.calculate_p99_by_service();
    for (service, p99) in p99_metrics {
        println!("Service: {:<18} | P99 Latency: {} ms", service, p99);
    }
}
```

## Common Pitfalls & Configuration Errors

### 1. `rust-analyzer` High CPU or Stuck on `cargo check`
- **Cause**: Multiple external tools running `cargo check` or `cargo build` in parallel, acquiring the Cargo target lock (`target/.cargo-lock`).
- **Fix**: Set `"cargo": { "allTargets": false }` or use separate target directories for editor checks.

### 2. Proc-Macro Expansion Failures
- **Cause**: Procedural macro expansion is disabled by default in minimal LSP profiles, causing `#[derive(Serialize)]` or `#[async_trait]` to show false syntax errors.
- **Fix**: Ensure `"procMacro": { "enable": true }` is enabled in `settings.json`.

## Complete Solutions to Exercises

### Solution 1: Clippy Pedantic Clean-Up
```rust
use std::fmt::Write;

#[must_use]
pub fn format_user_summary(name: &str, age: u32, is_admin: bool) -> String {
    let mut summary = String::with_capacity(32 + name.len());
    let role = if is_admin { "Admin" } else { "User" };
    let _ = write!(summary, "User: {} (Age: {}, Role: {})", name, age, role);
    summary
}

#[test]
fn test_user_summary() {
    let output = format_user_summary("Alice", 28, true);
    assert_eq!(output, "User: Alice (Age: 28, Role: Admin)");
}
```

### Solution 2: Chained Iterator Inlay Verification
```rust
#[must_use]
pub fn sum_of_even_squares(numbers: &[i64]) -> i64 {
    numbers
        .iter()                // Hint: Iter<'_, i64>
        .copied()              // Hint: Copied<Iter<'_, i64>> -> i64
        .filter(|&n| n % 2 == 0) // Hint: Filter<..., closure: |&i64| -> bool>
        .map(|n| n * n)        // Hint: Map<..., closure: |i64| -> i64>
        .sum()                 // Hint: -> i64
}

#[test]
fn test_sum_of_even_squares() {
    let data = [1, 2, 3, 4, 5, 6];
    // 2^2 + 4^2 + 6^2 = 4 + 16 + 36 = 56
    assert_eq!(sum_of_even_squares(&data), 56);
}
```
