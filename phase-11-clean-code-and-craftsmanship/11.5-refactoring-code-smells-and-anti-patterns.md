## Concept

When engineers transition to Rust from languages like Python, Go, or Java, they often write code that compiles but violates Rust's architectural paradigms.

Recognizing and systematically refactoring **Rust Code Smells** transforms fragile, clunky code into elegant, high-performance systems.

```

│                      Common Rust Code Smells & Cures                   │
├───────────────────────────────┬────────────────────────────────────────┤
│ Code Smell / Anti-Pattern     │ Clean Code Refactoring                 │
├───────────────────────────────┼────────────────────────────────────────┤
│ 1. Defensive `.clone()` Spam  │ Borrows, Lifetimes, & `Cow<'a, T>`     │
│ 2. Match Pyramid of Doom      │ Functional Combinators (`and_then`, `?`)│

```

### 1. Code Smell 1: The "Match Pyramid of Doom"

#### The Anti-Pattern:
```rust
// Clunky, 5-level indentation pyramid
fn get_user_zipcode(user_id: u64) -> Option<String> {
    match find_user(user_id) {
        Some(user) => match user.profile {
            Some(profile) => match profile.address {
                Some(address) => match address.zipcode {
                    Some(zip) => Some(zip),
                    None => None,
                },
                None => None,
            },
            None => None,
        },
        None => None,
    }
}
```

#### Clean Refactoring (Monadic Combinators):
```rust
fn get_user_zipcode(user_id: u64) -> Option<String> {
    find_user(user_id)?
        .profile?
        .address?
        .zipcode
}
// Or using combinators:
// find_user(user_id).and_then(|u| u.profile).and_then(|p| p.address).and_then(|a| a.zipcode)
```

### 2. Code Smell 2: Clone-on-Write Optimization (`std::borrow::Cow`)

If a function takes a string and only modifies it occasionally (e.g. escaping HTML or sanitizing input), cloning every single input string wastes millions of allocations.

**`Cow<'a, str>` (Clone-On-Write)** borrows the input string at **$0\text{ allocations}$** if no changes are needed, and only allocates a new `String` on the heap if mutation occurs!

```rust
use std::borrow::Cow;

pub fn sanitize_text<'a>(input: &'a str) -> Cow<'a, str> {
    if input.contains('<') || input.contains('>') {
        // Mutation needed: Allocate fresh owned String
        Cow::Owned(input.replace('<', "&lt;").replace('>', "&gt;"))
    } else {
        // No mutation: Zero-cost borrowed slice!
        Cow::Borrowed(input)
    }
}
```

### 3. Code Smell 3: Boolean Parameter Blindness

#### The Anti-Pattern:
```rust
// What does `true, false, true` mean at the call site?!
create_account("Alice", true, false, true);
```

#### Clean Refactoring (Explicit Enums):
```rust
pub enum AccountRole { Admin, Member }
pub enum EmailNotification { SendWelcomeEmail, SuppressEmail }
pub enum AccountStatus { Active, Suspended }

create_account("Alice", AccountRole::Admin, EmailNotification::SuppressEmail, AccountStatus::Active);
```

---

## Why It Matters in Systems Programming

1. **Eliminate Hidden Memory Allocations**: Refactoring `.clone()` to `Cow` cuts heap allocations in API gateways by up to $80\%$.
2. **Prevent Call-Site Argument Swaps**: Replacing boolean flags with self-describing enums eliminates subtle logic bugs.
3. **Linear Concurrency Scaling**: Splitting a monolithic `Mutex<AppState>` into independent fine-grained locks prevents worker thread serialization.

---

## Real-World Analogy

- **The `.clone()` Crutch** is like photocopying an entire 500-page book every time someone asks you to read page 42, because you are afraid to let them hold the original book.
- **`Cow<'a, str>`** is letting them look at page 42 in the original book for free, and only photocopying a single page if they need to highlight a sentence in yellow ink.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation demonstrating **Cow Optimization, Combinator Refactoring, and Granular State Locking** in pure Rust:

```rust
use std::borrow::Cow;
use std::collections::HashMap;
use std::sync::{Arc, Mutex, RwLock};

// ============================================================================
// 1. Refactoring Clone Spam with Cow (Clone-on-Write)
// ============================================================================

pub struct HtmlSanitizer;

impl HtmlSanitizer {
    /// Zero-cost if no HTML tags exist; Allocates ONLY when tags are sanitized!
    pub fn sanitize<'a>(raw_text: &'a str) -> Cow<'a, str> {
        if !raw_text.contains('<') && !raw_text.contains('>') && !raw_text.contains('&') {
            Cow::Borrowed(raw_text) // 0 Heap Allocations!
        } else {
            let mut cleaned = String::with_capacity(raw_text.len() + 16);
            for c in raw_text.chars() {
                match c {
                    '<' => cleaned.push_str("&lt;"),
                    '>' => cleaned.push_str("&gt;"),
                    '&' => cleaned.push_str("&amp;"),
                    other => cleaned.push(other),
                }
            }
            Cow::Owned(cleaned) // Heap allocation only when needed
        }
    }
}

// ============================================================================
// 2. Refactoring Monolithic God Mutex into Granular Domain Locks
// ============================================================================

// ANTI-PATTERN:
// struct GodState { all_data: Mutex<(HashMap<u64, User>, HashMap<u64, Order>, Metrics)> }
// Every single user read BLOCKS order writes!

// CLEAN ARCHITECTURE: Granular Independent Domain Sub-States
#[derive(Default)]
pub struct AppState {
    pub users: RwLock<HashMap<u64, String>>, // Read-heavy -> RwLock
    pub orders: Mutex<HashMap<u64, i64>>,    // Write-heavy -> Mutex
    pub active_connections: std::sync::atomic::AtomicUsize, // Atomic counter (Zero locks!)
}

// ============================================================================
// 3. Monadic Combinator Pipeline Refactoring
// ============================================================================

#[derive(Debug)]
pub struct UserProfile {
    pub email: Option<String>,
}

#[derive(Debug)]
pub struct Account {
    pub id: u64,
    pub profile: Option<UserProfile>,
}

pub fn extract_domain_from_user(account: Option<Account>) -> Option<String> {
    // Clean, readable functional combinator chain
    account
        .and_then(|acc| acc.profile)
        .and_then(|prof| prof.email)
        .filter(|email| email.contains('@'))
        .and_then(|email| email.split('@').nth(1).map(|d| d.to_lowercase()))
}

// ============================================================================
// 4. Verification & Benchmark
// ============================================================================

fn main() {
    println!("=== 1. Testing Cow Zero-Allocation Sanitizer ===");
    
    // Test 1: Clean string -> Borrowed (0 allocations)
    let clean_str = "Hello world this is a safe sentence.";
    let result_1 = HtmlSanitizer::sanitize(clean_str);
    match result_1 {
        Cow::Borrowed(_) => println!("Clean String: Result is Borrowed (&str) -> ZERO ALLOCATIONS!"),
        Cow::Owned(_) => println!("Error: Unnecessary allocation!"),
    }

    // Test 2: Dirty string -> Owned (Allocates sanitized copy)
    let dirty_str = "Alert <script>steal()</script> & bye";
    let result_2 = HtmlSanitizer::sanitize(dirty_str);
    match result_2 {
        Cow::Owned(ref s) => println!("Dirty String: Result is Owned -> Sanitized: '{}'", s),
        Cow::Borrowed(_) => println!("Error: Failed to sanitize!"),
    }

    println!("\n=== 2. Testing Monadic Pipeline Combinator ===");
    let account = Some(Account {
        id: 42,
        profile: Some(UserProfile {
            email: Some("satoshi@BITCOIN.org".to_string()),
        }),
    });

    let domain = extract_domain_from_user(account);
    println!("Extracted Email Domain: {:?}", domain);
    assert_eq!(domain, Some("bitcoin.org".to_string()));

    println!("\n=== 3. Granular State Concurrency Inspection ===");
    let state = Arc::new(AppState::default());
    state.users.write().unwrap().insert(1, "Alice".to_string());
    state.orders.lock().unwrap().insert(101, 5000);
    state.active_connections.fetch_add(1, std::sync::atomic::Ordering::Relaxed);

    println!("Users count: {}", state.users.read().unwrap().len());
    println!("Orders count: {}", state.orders.lock().unwrap().len());
    println!("Active Conn:  {}", state.active_connections.load(std::sync::atomic::Ordering::Relaxed));
}
```

## Common Pitfalls & Compiler Errors

### 1. Lifetime Propagation with `Cow`
When returning `Cow<'a, str>`, the returned `Cow` cannot outlive the lifetime `'a` of the input string if it is borrowed.
**Fix**: If you need the result to have a `'static` lifetime, call `cow.into_owned()`.

### 2. Excessive Combinator Chains Hurting Readability
Writing a 30-line single-expression combinator chain with 8 nested closures can be as hard to read as a match pyramid.
**Clean Rule**: If a combinator chain exceeds 4 steps, extract intermediate helper functions or use early `?` returns.

## Complete Solutions to Exercises

### Solution 2: Clean Combinator Refactoring

```rust
fn parse_port(opt_str: Option<&str>) -> Option<u16> {
    opt_str?
        .parse::<u16>()
        .ok()
        .filter(|&port| port > 1024)
}
```
