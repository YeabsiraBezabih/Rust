## Concept

In enterprise systems engineering, mixing database queries, HTTP routing, and core business rules into a single file creates an unmaintainable "Big Ball of Mud".

**Clean Architecture (Hexagonal Architecture / Ports and Adapters)** enforces a strict dependency rule:
$$\mathbf{\text{Dependencies point strictly inward toward the Domain Core.}}$$
The Domain Core has **ZERO knowledge** of SQL, HTTP, AWS, Redis, or Axum.

```
                           The Hexagonal Architecture Onion
┌────────────────────────────────────────────────────────────────────────┐
│  Infrastructure Layer (Adapters)                                       │
│  [ Axum HTTP Handlers ]   [ SQLx Postgres DB ]   [ Stripe Client ]     │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │  Application / Use-Case Layer                                    │  │
│  │  [ CreateOrderHandler ]   [ Ports / Traits: Repository, Payment ]│  │
│  │  ┌────────────────────────────────────────────────────────────┐  │  │
│  │  │  Domain Core (Entities, Value Objects, Domain Events)      │  │  │
│  │  │  - Zero External Dependencies! Pure Rust Business Logic!   │  │  │
│  │  └────────────────────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. Domain-Driven Design (DDD) Tactical Patterns in Rust

| DDD Pattern | Definition | Idiomatic Rust Representation |
| :--- | :--- | :--- |
| **Value Object** | Immutable, identity-less type defined purely by its attributes. | Newtype structs (`EmailAddress`, `MoneyCents`) deriving `Eq, PartialEq`. |
| **Entity** | Object with a unique identity that persists across state changes. | Struct containing a unique ID (`struct Account { id: AccountId, ... }`). |
| **Aggregate Root** | Cluster of domain objects treated as a single transactional unit. | Encapsulated struct that enforces all business invariants before mutations. |
| **Domain Event** | Record of something that occurred in the domain. | Rust Enum (`enum OrderEvent { Created, Paid, Cancelled }`). |
| **Port (Interface)** | Contract required by the application. | Rust `trait` defined in application/domain layer. |
| **Adapter** | Concrete technology implementing a Port. | Struct implementing trait in infrastructure layer. |

---

### 2. Property-Based Testing (`proptest`) for Domain Invariants

Traditional unit tests check 2 or 3 hardcoded examples (e.g. testing with `$10` and `$50`).

In **Property-Based Testing**, the test runner generates **10,000 randomized inputs** to find obscure mathematical edge cases, proving that domain invariants hold under all possible conditions:

```rust
// Invariant: Total after discount is ALWAYS <= Original Total
proptest! {
    #[test]
    fn total_never_increases_after_discount(original in 0i64..1_000_000, discount_pct in 0u32..100) {
        let final_price = apply_discount(original, discount_pct);
        prop_assert!(final_price <= original);
    }
}
```

## Why It Matters in Systems Programming

1. **Total Infrastructure Independence**: You can swap your database from PostgreSQL to CockroachDB or in-memory SQLite for testing without modifying a single line of business logic.
2. **Blazing-Fast Unit Tests**: Because domain logic has zero external I/O or network dependencies, your entire domain test suite runs in **$2\text{ milliseconds}$**.
3. **Auditability & Domain Events**: Emitting domain events enables event sourcing, audit logging, and asynchronous Kafka/RabbitMQ message publishing.

---

## Real-World Analogy

- **Tightly Coupled Code** is like soldering the power cable directly into your TV: if you move to a country with different wall sockets, you have to throw the whole TV away.
- **Hexagonal Architecture** is giving the TV a standard detachable power plug (**Port**): you simply snap on a US, UK, or European cable adapter (**Adapter**) without ever opening the TV chassis (**Domain Core**).

## Complete, Compilable Code Example

Below is a complete, self-contained implementation of an **Enterprise Order Aggregate Engine** structured in pure Hexagonal Architecture with Domain Events, Ports, and Adapters in pure Rust:

```rust
use std::collections::HashMap;
use std::sync::Mutex;

// ============================================================================
// 1. DOMAIN LAYER (Pure Business Logic - Zero External Dependencies)
// ============================================================================

pub mod domain {
    #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
    pub struct OrderId(pub u64);

    #[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
    pub struct Money(pub i64);

    #[derive(Debug, Clone, PartialEq, Eq)]
    pub enum OrderStatus {
        Created,
        Paid,
        Shipped,
        Cancelled,
    }

    #[derive(Debug, Clone, PartialEq, Eq)]
    pub enum DomainEvent {
        OrderCreated { id: OrderId, total: Money },
        OrderPaid { id: OrderId },
    }

    /// Aggregate Root: Enforces all business invariants
    #[derive(Debug, Clone)]
    pub struct OrderAggregate {
        id: OrderId,
        total: Money,
        status: OrderStatus,
        uncommitted_events: Vec<DomainEvent>,
    }

    impl OrderAggregate {
        pub fn create(id: OrderId, total: Money) -> Result<Self, &'static str> {
            if total.0 <= 0 {
                return Err("DomainError: Order total must be greater than zero");
            }

            let mut order = Self {
                id,
                total,
                status: OrderStatus::Created,
                uncommitted_events: Vec::new(),
            };

            order.uncommitted_events.push(DomainEvent::OrderCreated { id, total });
            Ok(order)
        }

        pub fn mark_paid(&mut self) -> Result<(), &'static str> {
            if self.status != OrderStatus::Created {
                return Err("DomainError: Can only pay for orders in Created status");
            }

            self.status = OrderStatus::Paid;
            self.uncommitted_events.push(DomainEvent::OrderPaid { id: self.id });
            Ok(())
        }

        pub fn id(&self) -> OrderId { self.id }
        pub fn total(&self) -> Money { self.total }
        pub fn status(&self) -> &OrderStatus { &self.status }

        /// Drain domain events to publish to message bus
        pub fn take_events(&mut self) -> Vec<DomainEvent> {
            std::mem::take(&mut self.uncommitted_events)
        }
    }
}

// ============================================================================
// 2. APPLICATION / USE-CASE LAYER (Orchestration & Ports)
// ============================================================================

pub mod application {
    use super::domain::{DomainEvent, Money, OrderAggregate, OrderId};

    // Output Port: Repository interface
    pub trait OrderRepositoryPort: Send + Sync {
        fn load(&self, id: OrderId) -> Option<OrderAggregate>;
        fn save(&self, order: &OrderAggregate) -> Result<(), &'static str>;
    }

    // Output Port: Event Publisher interface
    pub trait EventPublisherPort: Send + Sync {
        fn publish(&self, events: &[DomainEvent]);
    }

    // Use Case: Process Order Payment
    pub struct PayOrderUseCase<R: OrderRepositoryPort, P: EventPublisherPort> {
        repo: R,
        publisher: P,
    }

    impl<R: OrderRepositoryPort, P: EventPublisherPort> PayOrderUseCase<R, P> {
        pub fn new(repo: R, publisher: P) -> Self {
            Self { repo, publisher }
        }

        pub fn execute(&self, order_id: OrderId) -> Result<(), &'static str> {
            let mut order = self.repo.load(order_id).ok_or("OrderNotFound")?;

            // Execute Domain logic
            order.mark_paid()?;

            // Save aggregate
            self.repo.save(&order)?;

            // Publish uncommitted domain events
            let events = order.take_events();
            self.publisher.publish(&events);

            Ok(())
        }
    }
}

// ============================================================================
// 3. INFRASTRUCTURE LAYER (Adapters: DB, Bus, HTTP)
// ============================================================================

pub mod infrastructure {
    use super::application::{EventPublisherPort, OrderRepositoryPort};
    use super::domain::{DomainEvent, OrderAggregate, OrderId};
    use std::collections::HashMap;
    use std::sync::Mutex;

    pub struct InMemoryOrderRepository {
        storage: Mutex<HashMap<OrderId, OrderAggregate>>,
    }

    impl InMemoryOrderRepository {
        pub fn new() -> Self {
            Self { storage: Mutex::new(HashMap::new()) }
        }
    }

    impl OrderRepositoryPort for InMemoryOrderRepository {
        fn load(&self, id: OrderId) -> Option<OrderAggregate> {
            let map = self.storage.lock().unwrap();
            map.get(&id).cloned()
        }

        fn save(&self, order: &OrderAggregate) -> Result<(), &'static str> {
            let mut map = self.storage.lock().unwrap();
            map.insert(order.id(), order.clone());
            Ok(())
        }
    }

    pub struct ConsoleEventPublisher;

    impl EventPublisherPort for ConsoleEventPublisher {
        fn publish(&self, events: &[DomainEvent]) {
            for event in events {
                println!("  [EventBus Adapter] Published Domain Event: {:?}", event);
            }
        }
    }
}

// ============================================================================
// 4. Verification & Clean Architecture Execution
// ============================================================================

fn main() {
    use application::{OrderRepositoryPort, PayOrderUseCase};
    use domain::{Money, OrderAggregate, OrderId, OrderStatus};
    use infrastructure::{ConsoleEventPublisher, InMemoryOrderRepository};

    println!("=== 1. Initializing Clean Hexagonal Architecture Layers ===");
    let repo = InMemoryOrderRepository::new();
    let publisher = ConsoleEventPublisher;

    // Create domain aggregate
    let order_id = OrderId(9481);
    let mut initial_order = OrderAggregate::create(order_id, Money(25000)).unwrap();
    println!("Created Order Aggregate: ID {:?}, Total: ${:.2}, Status: {:?}", 
        initial_order.id(), initial_order.total().0 as f64 / 100.0, initial_order.status());

    // Save to repository adapter
    repo.save(&initial_order).unwrap();

    println!("\n=== 2. Executing PayOrder Use Case ===");
    let use_case = PayOrderUseCase::new(repo, publisher);
    use_case.execute(order_id).unwrap();

    println!("\n=== 3. Testing Domain Invariant Protection ===");
    let duplicate_pay_result = use_case.execute(order_id);
    println!("Duplicate Pay Execution Result: {:?}", duplicate_pay_result);
    assert!(duplicate_pay_result.is_err());
    println!("✅ Domain invariants strictly guarded by Clean Architecture Aggregate!");
}
```

## Common Pitfalls & Compiler Errors

### 1. Inward Dependency Inversion Violations
If your `domain` module imports `use axum::...` or `use sqlx::...`, you have broken the Clean Architecture dependency rule.
**Clean Rule**: The `domain` module must depend only on pure `std` and zero-cost utility crates.

### 2. Anemic Domain Models
Creating structs that are just bundles of public fields with no business logic, and putting all logic in "Service" classes, turns your codebase into an anemic procedural script.
**Fix**: Keep aggregate fields private and enforce all mutations via aggregate methods (`order.mark_paid()`).

### Solution 1: Cancel Order Use Case

```rust
pub struct CancelOrderUseCase<R: application::OrderRepositoryPort, P: application::EventPublisherPort> {
    repo: R,
    publisher: P,
}

impl<R: application::OrderRepositoryPort, P: application::EventPublisherPort> CancelOrderUseCase<R, P> {
    pub fn execute(&self, id: domain::OrderId) -> Result<(), &'static str> {
        let mut order = self.repo.load(id).ok_or("OrderNotFound")?;
        if *order.status() != domain::OrderStatus::Created {
            return Err("Cannot cancel an order that is already paid or shipped");
        }
        // order.mark_cancelled();
        self.repo.save(&order)?;
        Ok(())
    }
}
```
