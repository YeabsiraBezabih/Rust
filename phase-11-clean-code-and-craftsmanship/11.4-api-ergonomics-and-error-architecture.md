## Concept

Writing clean, professional Rust is not just about writing code that compiles; it is about designing **ergonomic, delightful public APIs** and a **structured error architecture**.

A poorly designed API forces callers to perform tedious type conversions (`foo(x.to_string(), PathBuf::from(p))`) and obscures failure causes with opaque errors.

A clean Rust API follows the **Official Rust API Guidelines** and enforces a strict separation between **Library Errors** and **Application Errors**.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Rust Error Architecture Spectrum                │
├───────────────────────────────────┬────────────────────────────────────┤
│ Domain / Library Layer (thiserror)│ Application Layer (anyhow / miette)│
├───────────────────────────────────┼────────────────────────────────────┤
│ • Strongly typed enum variants    │ • Dynamic boxed error (`anyhow::Error`)
│ • Exhaustive pattern matching     │ • Rich context (`.context(...)`)   │
│ • Zero heap allocations           │ • Pretty stack traces & error logs │
│ • Callers can handle errors       │ • Top-level error reporting        │
└───────────────────────────────────┴────────────────────────────────────┘
```

---

### 1. Flexible Input Arguments (`Into`, `AsRef`, `Borrow`)

Instead of forcing callers to allocate or clone specific types, clean APIs accept generic conversions:

#### Strings: `impl Into<String>`
```rust
// Clunky: Caller must write .to_string() on every call
pub fn set_username(&mut self, name: String) { ... }

// Clean & Ergonomic: Accepts `"alice"`, `String`, or `Cow<'static, str>`!
pub fn set_username(&mut self, name: impl Into<String>) {
    self.username = name.into();
}
```

#### File Paths: `impl AsRef<Path>`
```rust
use std::path::Path;

// Accepts `&str`, `String`, `PathBuf`, or `&Path` seamlessly!
pub fn read_config(path: impl AsRef<Path>) -> Result<Config, AppError> {
    let p: &Path = path.as_ref();
    // ...
}
```

---

### 2. Standard Conversion Naming Conventions (C-CONV)

| Prefix | Cost | Ownership | Example |
| :--- | :--- | :--- | :--- |
| **`as_`** | **Free ($0\text{ns}$)** | Borrowed ➔ Borrowed | `as_str() -> &str`, `as_bytes() -> &[u8]` |
| **`to_`** | **Expensive (Allocates)** | Borrowed ➔ Owned | `to_string() -> String`, `to_vec() -> Vec<T>` |
| **`into_`** | **Variable (Consumes `self`)** | Owned ➔ Owned | `into_bytes() -> Vec<u8>`, `into_inner()` |

---

### 3. The `#[must_use]` Attribute

For functions returning results that must not be silently ignored (like futures, validations, or builder modifications), add the `#[must_use]` attribute:

```rust
#[must_use = "This function returns a new mutated state; the original is unchanged"]
pub fn set_timeout(mut self, timeout: Duration) -> Self {
    self.timeout = timeout;
    self
}
```

---

## Why It Matters in Systems Programming

1. **Eliminate Boilerplate for Callers**: Ergonomic argument conversions allow users of your library to pass string literals, paths, and slices directly.
2. **Actionable Failure Diagnostics**: Attaching context to errors (`.context("Failed to connect to Postgres on port 5432")`) makes production debugging $10\times$ faster.
3. **Never Panic in Public APIs**: High-reliability systems must return structured `Result<T, E>` so calling web servers can gracefully return a 400/500 HTTP response instead of crashing the process.

---

## Real-World Analogy

- **A Poorly Designed API** is like an electrical outlet that only accepts one proprietary European plug shape: every time you want to plug in a lamp, you have to buy and wire an adapter by hand.
- **An Ergonomic Rust API** is like a universal multi-region power socket: it seamlessly accepts US, UK, EU, and USB-C plugs directly without any manual adapters.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation demonstrating **Clean API Ergonomics, `#[must_use]` Attributes, and Domain vs Application Error Architecture** in pure Rust:

```rust
use std::fmt;
use std::path::Path;

// ============================================================================
// 1. Structured Domain / Library Errors (thiserror Pattern)
// ============================================================================

#[derive(Debug, PartialEq, Eq)]
pub enum VaultError {
    KeyNotFound { key_id: String },
    DecryptionFailed { reason: &'static str },
    StorageIoError { path: String, os_code: i32 },
}

impl fmt::Display for VaultError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            VaultError::KeyNotFound { key_id } => write!(f, "Cryptographic key '{}' not found in vault", key_id),
            VaultError::DecryptionFailed { reason } => write!(f, "Decryption failed: {}", reason),
            VaultError::StorageIoError { path, os_code } => write!(f, "I/O error accessing '{}' (OS Error: {})", path, os_code),
        }
    }
}

impl std::error::Error for VaultError {}

// ============================================================================
// 2. Application Context Wrapper (anyhow Pattern)
// ============================================================================

#[derive(Debug)]
pub struct AppContextError {
    pub context: String,
    pub source: Box<dyn std::error::Error + Send + Sync>,
}

impl fmt::Display for AppContextError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}: {}", self.context, self.source)
    }
}

impl std::error::Error for AppContextError {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        Some(&*self.source)
    }
}

pub trait ContextExt<T> {
    fn with_context(self, context: impl Into<String>) -> Result<T, AppContextError>;
}

impl<T, E: std::error::Error + Send + Sync + 'static> ContextExt<T> for Result<T, E> {
    fn with_context(self, context: impl Into<String>) -> Result<T, AppContextError> {
        self.map_err(|err| AppContextError {
            context: context.into(),
            source: Box::new(err),
        })
    }
}

// ============================================================================
// 3. Ergonomic Public Library API
// ============================================================================

pub struct SecretVault {
    storage_path: String,
    vault_name: String,
}

impl SecretVault {
    /// Ergonomic constructor accepting `impl AsRef<Path>` and `impl Into<String>`
    pub fn open(
        storage_path: impl AsRef<Path>,
        vault_name: impl Into<String>,
    ) -> Result<Self, VaultError> {
        let p = storage_path.as_ref();
        
        // Validate path existence
        if p.to_string_lossy().is_empty() {
            return Err(VaultError::StorageIoError {
                path: p.display().to_string(),
                os_code: 2, // No such file or directory
            });
        }

        Ok(Self {
            storage_path: p.display().to_string(),
            vault_name: vault_name.into(),
        })
    }

    /// Read secret key from vault
    pub fn get_secret(&self, key_id: impl AsRef<str>) -> Result<String, VaultError> {
        let key = key_id.as_ref();
        if key == "master_token" {
            Ok("sk_live_9841209384".to_string())
        } else {
            Err(VaultError::KeyNotFound {
                key_id: key.to_string(),
            })
        }
    }

    #[must_use = "set_vault_name returns a new modified vault instance"]
    pub fn with_renamed_vault(mut self, new_name: impl Into<String>) -> Self {
        self.vault_name = new_name.into();
        self
    }
}

// ============================================================================
// 4. Verification & Execution
// ============================================================================

fn main() {
    println!("=== 1. Testing Ergonomic API Calling Patterns ===");
    
    // Call with string literal &str
    let vault_1 = SecretVault::open("/etc/secrets/vault.db", "ProductionVault").unwrap();
    println!("Opened Vault 1: {}", vault_1.vault_name);

    // Call with String and PathBuf
    let path_buf = std::path::PathBuf::from("/var/lib/vault.db");
    let name_str = String::from("StagingVault");
    let vault_2 = SecretVault::open(&path_buf, name_str).unwrap();
    println!("Opened Vault 2: {}", vault_2.vault_name);

    println!("\n=== 2. Testing Structured Domain Error Match ===");
    match vault_1.get_secret("unknown_api_key") {
        Ok(secret) => println!("Found Secret: {}", secret),
        Err(VaultError::KeyNotFound { key_id }) => {
            println!("Caught Expected Domain Error: Key '{}' is missing!", key_id);
        }
        Err(e) => println!("Other error: {}", e),
    }

    println!("\n=== 3. Testing Application Context Attachment ===");
    let app_result: Result<String, AppContextError> = vault_1
        .get_secret("stripe_webhook_secret")
        .with_context("Failed to initialize Stripe Payment Webhook Listener");

    if let Err(err) = app_result {
        println!("Rich Application Error Report:\n  {}", err);
    }
}
```

## Common Pitfalls & Compiler Errors

### 1. `panic!` in Public API Code
Never write `assert!`, `unwrap()`, or `panic!` inside library code. A panic aborts the user's thread or entire web server. Always return a structured `Result<T, Error>`.

### 2. Over-Generic Argument Signatures
Writing `fn foo<T: Into<String>, U: AsRef<Path>, V: Borrow<[u8]>>` on internal private helper functions causes long compilation times and confusing error messages.
**Clean Rule**: Use generic argument conversions (`impl Into<String>`) on **public API entrypoints**, but pass concrete references (`&str`, `&Path`) to internal private helper functions.
