## Prerequisites
Lesson 0.1: Compiling vs Running (understanding source code, the compiler, and RAM).

## Concept

When a program runs, it needs a way to remember information—such as a user's ID, a server's port number, or whether a database connection is open.

### 1. What is a Variable?
A **variable** is a named storage slot in the computer's memory (RAM). When you create a variable, the computer reserves space in memory, places your data there, and associates it with a label (the variable's name) so you can read or update it later.

### 2. Bits, Bytes, and Data Types
Computer memory does not have separate compartments labeled "numbers" or "words." Everything in memory is stored as physical electronic charges representing binary digits called **bits** (`0` or `1`). Eight bits grouped together form one **byte**.

A **data type** tells the compiler two essential things:
1. **How much memory** to allocate for the value (how many bytes).
2. **How to interpret** the pattern of bits stored in those bytes.

For example, the exact same sequence of 32 bits could represent the number `65`, the letter `'A'`, or a pixel color on your monitor, depending on its data type.

### 3. Core Primitive Data Types in Rust

Rust provides several fundamental (primitive) types:

| Category | Type in Rust | Description | Example |
| :--- | :--- | :--- | :--- |
| **Integer (Signed)** | `i32`, `i64` | Whole numbers (positive, negative, or zero). | `-42`, `100` |
| **Integer (Unsigned)** | `u32`, `u64` | Positive whole numbers and zero only (no negative sign). | `8080`, `0` |
| **Floating-Point** | `f64` | Numbers with decimal points. | `99.95`, `-3.14` |
| **Boolean** | `bool` | Logical truth values: exactly `true` or `false`. | `true`, `false` |
| **Character** | `char` | A single Unicode character (enclosed in single quotes). | `'A'`, `'🚀'` |
| **String Slice** | `&str` | A sequence of text characters (enclosed in double quotes). | `"localhost"` |

*(Note on numbers: The letter `i` stands for "integer" and `u` stands for "unsigned". The number after it, like `32` or `64`, represents the number of bits of memory used.)*

### 4. Mutability: Immutable by Default
In Rust, variables are **immutable by default**. Once you assign a value to a variable, you cannot change it. 

If you want a variable's value to change over time (for example, incrementing a counter), you must explicitly mark it as **mutable** using the `mut` keyword:
- `let requests = 0;` $\rightarrow$ Cannot be changed later.
- `let mut requests = 0;` $\rightarrow$ Can be changed later (`requests = 1;`).

This default prevents accidental modifications in complex systems.

### 5. Type Annotations vs. Type Inference
Rust has **type inference**. This means the compiler is smart enough to deduce the type of a variable from the value you give it. However, you can also explicitly declare the type using a colon (`:`):

```rust
let port = 8080;         // The compiler infers type i32
let port: u16 = 8080;    // Explicitly declaring an unsigned 16-bit integer
```

---

## Why it matters

In low-level systems programming—like building an HTTP server or handling network packets—memory layout is critical. If an incoming network packet specifies a 16-bit port number (e.g., `8080`), you need an exact 16-bit unsigned integer type (`u16`) to store it without wasting memory or misinterpreting negative numbers. Rust's strict typing catches mismatches and prevents memory corruption before your program ever runs.

---

## Analogy

Think of variables as labeled storage containers:
- Declaring a variable (`let`) is ordering a specific bin from the warehouse.
- The **data type** is the bin's shape and size. A tiny cylindrical bin is made only for coins (`u8`), while a long rectangular folder is made for typed documents (`&str`). You cannot physically shove a document into the coin slot.
- **Immutability** is putting a tamper-evident seal on the container once filled. Adding `mut` means using an open-top bin where you can swap out the contents whenever needed.

## Code Example

```rust
fn main() {
    // 1. Immutable variable with type inference
    let server_name = "ApiGateway";

    // 2. Explicitly-typed unsigned integer (ports are strictly positive: 0 to 65535)
    let port: u16 = 8080;

    // 3. Floating-point number (e.g., latency measurement in milliseconds)
    let response_time_ms: f64 = 14.85;

    // 4. Boolean flag representing server health
    let is_healthy: bool = true;

    // 5. A single character
    let environment_tier: char = 'P'; // 'P' for Production

    // 6. A mutable variable that will change its value
    let mut total_requests_handled: u64 = 0;

    println!("--- Server Status ---");
    println!("Name: {}", server_name);
    println!("Port: {}", port);
    println!("Latency: {} ms", response_time_ms);
    println!("Online & Healthy: {}", is_healthy);
    println!("Environment Tier: {}", environment_tier);
    println!("Initial Requests Handled: {}", total_requests_handled);

    // Modifying the mutable variable
    total_requests_handled = total_requests_handled + 1;
    println!("Updated Requests Handled: {}", total_requests_handled);
}
```

## Common Mistakes

### 1. Reassigning an Immutable Variable
Attempting to change a variable without the `mut` keyword.

**Broken Code:**
```rust
fn main() {
    let active_users = 10;
    active_users = 11; // Error!
}
```

**Compiler Output:**
```text
error[E0384]: cannot assign twice to immutable variable `active_users`
 --> src/main.rs:3:5
  |
2 |     let active_users = 10;
  |         ------------
  |         |
  |         first assignment to `active_users`
  |         help: consider making this binding mutable: `mut active_users`
3 |     active_users = 11;
  |     ^^^^^^^^^^^^^^^^^ cannot assign twice to immutable variable
```

---

### 2. Type Mismatch (Assigning the Wrong Type)
Attempting to put a value of one type into a variable of a different type.

**Broken Code:**
```rust
fn main() {
    let mut max_connections: u32 = 500;
    max_connections = "unlimited"; // Error!
}
```

**Compiler Output:**
```text
error[E0308]: mismatched types
 --> src/main.rs:3:23
  |
3 |     max_connections = "unlimited";
  |                       ^^^^^^^^^^^ expected `u32`, found `&str`
```
*Why it happens*: Once a variable is created with a specific type, its type can never change.

---

### 3. Mixing Incompatible Types in Arithmetic
In Rust, you cannot perform math operations between different types without explicit conversion (e.g., adding an integer directly to a float).

**Broken Code:**
```rust
fn main() {
    let request_count: u32 = 10;
    let average_duration: f64 = 2.5;
    let total_time = request_count * average_duration; // Error!
}
```

**Compiler Output:**
```text
error[E0277]: cannot multiply `u32` by `f64`
```
*Why it happens*: Rust refuses to guess whether you want to truncate the float into an integer or convert the integer into a float. You must be explicit.

## Exercises

### Exercise 1 (Selecting the Right Type)
Choose the most appropriate Rust primitive data type (`u16`, `i32`, `f64`, `bool`, `char`, or `&str`) for each of the following:
1. A website domain name (e.g., `"example.com"`).
2. The number of CPU cores on a machine (e.g., `8`).
3. The temperature reading in Celsius, which can be negative and have decimal places (e.g., `-3.75`).
4. Whether a user is currently logged in (`true` or `false`).

---

### Exercise 2 (Fixing Mutability and Types)
The following program contains two compiler errors. Identify and fix them:

```rust
fn main() {
    let packet_count: u32 = 100;
    packet_count = 105;

    let status_code: u16 = 200;
    println!("Packets: {}, Status: {}", packet_count, status_code);
}
```

---

### Exercise 3 (Building a Server Metrics Tracker)
Write a complete Rust program that:
1. Declares an immutable string variable `service_name` set to `"TelemetryNode"`.
2. Declares an immutable `f64` variable `cpu_usage_percent` set to `42.8`.
3. Declares a mutable `u32` variable `error_count` initialized to `0`.
4. Prints the initial state.
5. Increments `error_count` by `1`.
6. Prints the updated `error_count`.

---

## Solutions

### Solution to Exercise 1
1. `&str` — A string slice is used for textual data.
2. `u32` (or `u8` / `usize`) — CPU core counts are strictly non-negative whole numbers.
3. `f64` (or `f32`) — Supports both negative values and fractional/decimal values.
4. `bool` — Represents binary true/false state.

---

### Solution to Exercise 2
**Explanation**:
1. `packet_count` is assigned twice, but it was declared without `mut`. It needs `let mut packet_count`.
2. (In the provided snippet, `status_code` is valid, but fixing `let mut packet_count` resolves the compiler error).

**Corrected Code**:
```rust
fn main() {
    let mut packet_count: u32 = 100; // Added `mut`
    packet_count = 105;

    let status_code: u16 = 200;
    println!("Packets: {}, Status: {}", packet_count, status_code);
}
```

---

### Solution to Exercise 3
**Approach**: Define `main`, assign the immutable variables with `let`, assign the mutable counter with `let mut`, print with `println!`, increment the counter with `error_count = error_count + 1` (or `error_count += 1`), and print the result.

```rust
fn main() {
    let service_name: &str = "TelemetryNode";
    let cpu_usage_percent: f64 = 42.8;
    let mut error_count: u32 = 0;

    println!("Service: {}", service_name);
    println!("CPU Usage: {}%", cpu_usage_percent);
    println!("Initial Errors: {}", error_count);

    // Increment error count
    error_count = error_count + 1;

    println!("Updated Errors: {}", error_count);
}
```
