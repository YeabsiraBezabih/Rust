## Concept

As programs grow in size, writing all instructions sequentially inside `main()` quickly becomes unreadable and error-prone. 

A **function** is a named, self-contained block of code designed to perform a specific task. Once defined, a function can be executed (**called**) multiple times from anywhere in your program.

```
       Parameters (Inputs)
      ┌────────────────────┐
      │  port: 80, secure  │
      └─────────┬──────────┘
                │
                ▼
      ┌────────────────────┐
      │   build_url(...)   │  <-- Function Body (Encapsulated Logic)
      └─────────┬──────────┘
                │
                ▼
      ┌────────────────────┐
      │ "https://site:80"  │
      └────────────────────┘
        Return Value (Output)
```

---

### 1. Anatomy of a Rust Function

A function definition in Rust consists of four main parts:
1. **The `fn` keyword**: Tells the compiler you are declaring a function.
2. **Function Name**: Written in `snake_case` (lowercase with underscores).
3. **Parameters (Inputs)**: Variables passed into the function, enclosed in parentheses `( )`. In Rust, you **must explicitly declare the type** of every parameter.
4. **Return Type (Output)**: The type of value the function sends back to the caller, declared with an arrow `->`.

```rust
fn function_name(parameter_name: DataType) -> ReturnType {
    // Function body (instructions)
}
```

If a function does not return a value (it only performs an action like printing), you omit the `-> ReturnType`.

---

### 2. Statements vs. Expressions in Rust

To understand how Rust returns values from functions, you must understand the difference between **statements** and **expressions**:

- **Statements**: Instructions that perform an action but **do not evaluate to a value**. Statements end with a semicolon (`;`).
  ```rust
  let max_limit = 1000; // Statement (declares a variable, produces no value)
  ```
- **Expressions**: Calculations or blocks that **evaluate to a resulting value**. Expressions do **not** end with a semicolon.
  ```rust
  5 + 3 // Expression (evaluates to 8)
  ```

#### Implicit Return (The Last Expression):
In Rust, the final expression in a function body is automatically returned as the function's output. You do not need the `return` keyword unless exiting early:

```rust
fn add_numbers(a: u32, b: u32) -> u32 {
    a + b // No semicolon -> this value is returned automatically
}
```

#### Explicit Return (`return` Keyword):
The `return` keyword is used when you need to exit a function **early** before reaching the end of the block:

```rust
fn validate_port(port: u16) -> bool {
    if port == 0 {
        return false; // Early exit
    }
    true // Default success
}
```

---

### 3. Scope and Encapsulation

A **scope** is the region of code enclosed within curly braces `{ ... }`.

Variables created inside a function are **local** to that function. They are born when the function starts and are automatically destroyed when the function finishes. Code outside the function cannot see or access them. This isolation is called **encapsulation**.

---

## Why it matters

In complex systems like an HTTP web framework or an AI agent runner, code is partitioned into hundreds of single-purpose functions (e.g., `parse_http_headers()`, `verify_jwt_signature()`, `serialize_json()`). Functions prevent bugs by keeping state isolated, preventing accidental modifications to global data, and enabling unit testing of small, isolated units of logic.

---

## Analogy

Think of a function as a **vending machine**:
- **Parameters**: The money and selection code you insert into the slot.
- **Function Body**: The hidden internal motors, sensors, and gears that process your selection.
- **Return Value**: The beverage dispensed at the bottom.
- **Encapsulation**: You do not need to know the wiring schematics of the motor inside the machine to get your drink; you only need to know what inputs to provide and what output to expect.

## Code Example

```rust
// 1. A function that takes two inputs and returns a calculated value
fn calculate_total_latency(network_latency_ms: f64, processing_latency_ms: f64) -> f64 {
    // The last expression without a semicolon is returned implicitly
    network_latency_ms + processing_latency_ms
}

// 2. A function with an early return for validation
fn is_privileged_port(port: u16) -> bool {
    // Ports 1 through 1023 are historically reserved/privileged system ports
    if port < 1024 {
        return true; // Early return
    }

    false // Standard unprivileged port
}

// 3. A function that performs an action (printing) without returning a value
fn log_service_startup(service_name: &str, port: u16) {
    println!("--- Service Initializing ---");
    println!("Service: {}", service_name);
    println!("Port: {}", port);

    if is_privileged_port(port) {
        println!("Warning: Running on a privileged system port (requires root permissions).");
    } else {
        println!("Port configuration: Unprivileged (Standard User).");
    }
}

fn main() {
    let service = "ApiGateway";
    let port = 80;

    // Calling the logging function
    log_service_startup(service, port);

    // Calling the math function and storing its return value in a variable
    let total_delay = calculate_total_latency(12.4, 3.8);
    println!("Total Request Latency: {} ms", total_delay);
}
```

## Common Mistakes

### 1. Accidental Semicolon on the Return Expression
Adding a semicolon to the last line turns it from an **expression** (which produces a value) into a **statement** (which produces nothing, written as `()`).

**Broken Code:**
```rust
fn square(number: i32) -> i32 {
    number * number; // Error: Semicolon prevents returning the value!
}
```

**Compiler Output:**
```text
error[E0308]: mismatched types
 --> src/main.rs:1:27
  |
1 | fn square(number: i32) -> i32 {
  |    ------                 ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     number * number;
  |                    - help: remove this semicolon
```

---

### 2. Missing Parameter Type Annotations
Unlike `let` variables where types can be inferred, Rust **requires** parameter types to be explicitly written in function signatures.

**Broken Code:**
```rust
fn print_port(port) { // Error!
    println!("Port: {}", port);
}
```

**Compiler Output:**
```text
error: expected one of `:`, `@`, or `|`, found `)`
 --> src/main.rs:1:19
  |
1 | fn print_port(port) {
  |                   ^ help: declare the type: `port: u16`
```

---

### 3. Attempting to Access Local Variables from Outside Their Scope
Variables created inside a function do not exist outside that function.

**Broken Code:**
```rust
fn compute_hash() {
    let secret_key = 42;
}

fn main() {
    compute_hash();
    println!("Key: {}", secret_key); // Error: `secret_key` is out of scope!
}
```

### Exercise 1 (Packet Payload Calculator)
Write a function named `calculate_packet_size` that:
- Takes two parameters: `header_bytes: u32` and `body_bytes: u32`.
- Returns their sum as a `u32`.
- Call this function from `main()` and print the result.

### Exercise 2 (HTTP Status Validator)
Write a function named `is_valid_http_status` that:
- Takes a single parameter `status_code: u16`.
- Returns `true` if `status_code` is between `100` and `599` inclusive.
- Returns `false` otherwise.
- Use explicit or implicit returns.

---

### Exercise 3 (Diagnosing the Compiler Error)
Explain why the following code fails to compile and provide the corrected version:

```rust
fn format_bandwidth(megabytes: f64) -> f64 {
    let gigabytes = megabytes / 1024.0;
    gigabytes;
}

fn main() {
    let gb = format_bandwidth(2048.0);
    println!("Bandwidth in GB: {}", gb);
}
```

## Solutions

### Solution to Exercise 1
```rust
fn calculate_packet_size(header_bytes: u32, body_bytes: u32) -> u32 {
    header_bytes + body_bytes
}

fn main() {
    let total_size = calculate_packet_size(54, 1400);
    println!("Total Packet Size: {} bytes", total_size);
}
```

---

### Solution to Exercise 2
```rust
fn is_valid_http_status(status_code: u16) -> bool {
    status_code >= 100 && status_code <= 599
}

fn main() {
    let test_status = 200;
    println!("Is {} valid? {}", test_status, is_valid_http_status(test_status));

    let invalid_status = 850;
    println!("Is {} valid? {}", invalid_status, is_valid_http_status(invalid_status));
}
```

---

### Solution to Exercise 3
**Explanation**: In `format_bandwidth`, the last line `gigabytes;` ends with a semicolon. This turns the expression into a statement, causing the function to return the unit type `()` instead of the expected `f64`.

**Corrected Code**:
```rust
fn format_bandwidth(megabytes: f64) -> f64 {
    let gigabytes = megabytes / 1024.0;
    gigabytes // Removed the trailing semicolon
}

fn main() {
    let gb = format_bandwidth(2048.0);
    println!("Bandwidth in GB: {}", gb);
}
```
