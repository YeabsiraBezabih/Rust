# Lesson 0.1: Compiling vs Running

## Prerequisites
None. This is the starting point of the curriculum and assumes zero prior programming knowledge.

---

## Concept

At its core, a computer consists of two main hardware components:
1. **The Processor (Central Processing Unit, or CPU)**: The electronic engine that performs mathematical calculations and carries out instructions.
2. **Memory (RAM)**: The temporary storage area where data and active instructions are kept while the computer is turned on.

A **program** is simply a list of exact, step-by-step instructions that tells the CPU what to do. 

However, CPUs do not understand human languages, nor do they understand programming languages directly. A CPU can only understand **machine code**—a sequence of electrical signals represented as binary numbers (zeros and ones: `01101001...`). 

Because writing millions of raw zeros and ones is impractical and error-prone for humans, we write **source code** in high-level programming languages like **Rust**. Source code is plain text written using structured rules and keywords that humans can read and write.

To bridge the gap between human-readable source code and machine-executable binary, we use a specialized tool called a **compiler**.

```
┌─────────────────────────┐          ┌───────────────────┐          ┌─────────────────────────┐
│       Source Code       │          │   Rust Compiler   │          │    Executable Binary    │
│  (e.g., main.rs text)   │ ───────> │     (rustc)       │ ───────> │     (Machine Code)      │
│  Written by a human     │          │ Checks & Translates│         │ Directly run by the CPU │
└─────────────────────────┘          └───────────────────┘          └─────────────────────────┘
```

This workflow introduces two distinct phases in software development:

1. **Compile Time**:
   - The compiler reads your source code text file.
   - It verifies that you followed all the grammatical rules of the language (**syntax**).
   - It checks that the types and operations make logical sense (such as ensuring you do not try to divide a sentence by a number).
   - If everything is valid, it translates your source code into an **executable binary file** (machine code).
   - If there is an error, the compiler stops and reports the problem (**compile-time error**). No executable binary is produced.

2. **Run Time (Execution Time)**:
   - The operating system loads the compiled executable binary into memory and instructs the CPU to start executing the instructions.
   - This happens *after* compilation is completely finished. The compiler is no longer involved.
   - If the program contains a flaw in its logic (such as trying to read a file that does not exist on disk), a **runtime error** or unexpected behavior occurs while the program is actively running.

---

## Why it matters

Rust is a **compiled language** designed for systems programming. Unlike languages that rely on an interpreter (a separate program that translates and executes code line-by-line while it runs), Rust translates your entire project directly into optimized machine code before you run it. 

This design has two critical advantages:
1. **Maximum Speed**: The CPU executes the binary directly at native hardware speed with no translation overhead. This is essential when building high-throughput HTTP servers or low-latency networking tools.
2. **Early Error Catching**: Rust's compiler performs rigorous checks during compilation. It catches bugs, memory errors, and concurrency flaws *before* your software is ever launched or deployed.

---

## Analogy

Think of writing a recipe for a foreign kitchen:

- **Interpreted execution**: You stand next to a chef in a foreign country with an in-person translator. The translator reads one sentence of your English recipe, translates it into the chef's language in real time, and waits for the chef to chop the onion before translating the next sentence. If you wrote a typo on step 10, the chef only discovers it halfway through dinner.
- **Compiled execution (Rust)**: You hand your English recipe to a master editor (the compiler). The editor reads the entire recipe from start to finish, checks that all ingredients and measurements make sense, and prints a polished book entirely in the chef's native language. The chef can now execute the recipe at full speed without stopping. If there is an error on step 10, the editor rejects the recipe before anyone ever enters the kitchen.

## Code Example

Below is a complete, valid Rust program. 

```rust
// The "fn main()" function is the mandatory entry point of every Rust program.
// When the compiled binary is executed, the CPU begins here.
fn main() {
    // "let" creates a named container (a variable) to hold information in memory.
    let server_name = "AuthService";
    let port_number = 8080;

    // "println!" is a built-in macro that prints text to the screen (terminal).
    // The "{}" acts as a placeholder that gets replaced by the value of the variable.
    println!("Initializing server: {}", server_name);
    println!("Listening for incoming network requests on port: {}", port_number);

    // Mathematical calculation performed by the CPU at runtime
    let active_connections = 5 + 3;
    println!("Current active connections: {}", active_connections);
}
```

When you compile this file, the Rust compiler inspects every line, validates the types and syntax, and outputs a binary file. When you run the resulting binary, the CPU executes the instructions and prints:

```text
Initializing server: AuthService
Listening for incoming network requests on port: 8080
Current active connections: 8
```

## Common Mistakes

### 1. Missing Syntax Delimiters (Compile-Time Error)
Rust requires statements to end with a semicolon (`;`) and code blocks to be enclosed in curly braces (`{ ... }`).

**Broken Code:**
```rust
fn main() {
    let port_number = 8080 // Missing semicolon
    println!("Port: {}", port_number);
}
```

**Compiler Output:**
```text
error: expected `;`, found `println`
 --> src/main.rs:2:27
  |
2 |     let port_number = 8080
  |                           ^ help: add `;` here
```
*Why it happens*: The compiler cannot separate the end of the variable declaration from the next instruction.

---

### 2. Modifying Source Code Without Recompiling
A beginner changes `"AuthService"` to `"PaymentService"` in their `.rs` text file, runs their previous binary, and is surprised to see `"AuthService"` printed.

*Why it happens*: The binary file is a standalone snapshot of machine code produced during the last compilation. Modifying the text file does not automatically update the already-compiled binary. You must re-run the compiler to generate a fresh binary.

---

### 3. Confusing Compile-Time Checks with Runtime Calculations
A beginner might assume the compiler knows the exact data a user will type into the program while it is running.

*Why it happens*: Compile-time only knows what is written in the source code text. Runtime is when external conditions (user keystrokes, network packets, file contents) occur.

## Exercises

### Exercise 1 (Conceptual — Identifying the Phase)
For each of the following scenarios, state whether it belongs to **Compile Time** or **Run Time**:
1. The Rust compiler flags a missing closing bracket `}` in your file.
2. A network connection drops while your server is handling a web request.
3. The compiler converts your Rust code into x86-64 machine instructions.
4. The program asks the user to type their username into the terminal.

---

### Exercise 2 (Spotting the Compile Error)
The following code snippet fails to compile. Identify the error and explain why the compiler rejects it:

```rust
fn main() {
    let application_name = "MetricsCollector";
    println!("Application: {}", application_name)
    let worker_threads = 4;
    println!("Workers: {}", worker_threads);
}
```

---

### Exercise 3 (Writing Your First Program)
Write a complete, runnable Rust `main` function that:
1. Declares a variable `database_host` containing the text `"localhost"`.
2. Declares a variable `max_connections` containing the number `100`.
3. Prints a startup message in the format:
   ```text
   Connecting to database at localhost with max connections: 100
   ```

---

## Solutions

### Solution to Exercise 1
1. **Compile Time**: Syntax checking happens before any binary is created.
2. **Run Time**: Network activity only happens while the program is actively executing.
3. **Compile Time**: Machine code translation is the primary job of the compiler.
4. **Run Time**: User interaction occurs during active execution.

---

### Solution to Exercise 2
**Explanation**: Line 3 (`println!("Application: {}", application_name)`) is missing a trailing semicolon (`;`). In Rust, statements must be terminated with a semicolon so the compiler can delineate where one instruction ends and the next begins.

**Corrected Code**:
```rust
fn main() {
    let application_name = "MetricsCollector";
    println!("Application: {}", application_name); // Added semicolon
    let worker_threads = 4;
    println!("Workers: {}", worker_threads);
}
```

---

### Solution to Exercise 3
**Approach**: Define the entry point `fn main()`, bind the two values to descriptive variable names using `let`, and use `println!` with two `{}` format placeholders.

```rust
fn main() {
    let database_host = "localhost";
    let max_connections = 100;

    println!(
        "Connecting to database at {} with max connections: {}",
        database_host, 
        max_connections
    );
}
```
