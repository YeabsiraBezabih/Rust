## Concept

Modern web applications increasingly execute heavy systems tasks directly on the user's local CPU inside the browser:
- **Client-Side Video & Image Editing** (Figma, Canva, Photoshop Web).
- **End-to-End Encryption (E2EE)** (Signal Web, Bitwarden, ProtonMail).
- **Local Machine Learning & Audio DSP** (Whisper.wasm, WebLLM, Web Audio FX).

Executing these in JavaScript is often slow due to garbage collection pauses and dynamic boxing. In Rust WebAssembly, algorithms run with **Zero Heap Allocations**, **SIMD128 Vector Acceleration**, and **Direct Memory-Mapped Pixel Buffers**.

```
  JavaScript Frontend (Browser)                             Rust WASM Linear Memory
 ───────────────────────────────                            ────────────────────────
  1. User drops 4K Image (3840x2160)                        
  2. Creates Uint8ClampedArray view ──── Zero-Copy Ptr ───► [ 33MB Raw RGBA Buffer ]
                                                            │
                                                            │ 3. Rust WASM applies
                                                            │    Gaussian Blur / Sobel Filter
                                                            │    via 128-bit SIMD in 4ms!
                                                            ▼
  4. canvas.putImageData() ◄──────────── Zero-Copy Ptr ──── [ Transformed Pixels ]
```

### 1. Zero-Copy Image Convolution (Sobel Edge Detection & Blur)

An image is represented as a flat array of `RGBA` bytes ($4\text{ bytes per pixel}$).
To apply a filter (e.g. Grayscale or Inversion), Rust iterates across memory using contiguous pointer arithmetic:

```rust
#[wasm_bindgen]
pub fn apply_grayscale_filter(pixels: &mut [u8]) {
    // Process 4 bytes (R, G, B, A) per pixel
    for chunk in pixels.chunks_exact_mut(4) {
        let r = chunk[0] as u32;
        let g = chunk[1] as u32;
        let b = chunk[2] as u32;

        // Standard Luminance Formula: 0.299 R + 0.587 G + 0.114 B
        let gray = ((r * 299 + g * 587 + b * 114) / 1000) as u8;

        chunk[0] = gray; // R
        chunk[1] = gray; // G
        chunk[2] = gray; // B
        // chunk[3] is Alpha (preserved)
    }
}
```

### 2. Client-Side End-to-End Encryption (E2EE)

Before uploading sensitive files or chat messages to cloud storage (S3/MinIO), client-side Rust WASM encrypts data using **AES-256-GCM** or derives secure encryption keys using **Argon2id**.

The cloud provider only ever receives encrypted ciphertext—**zero knowledge of user private keys**.

---

## Why It Matters in Systems Programming

1. **Zero Cloud Server Costs**: By offloading image resizing, PDF rendering, or file encryption to the user's browser, your backend servers do not spend expensive cloud CPU cycles on media processing.
2. **Absolute User Privacy**: True End-to-End Encryption (E2EE) guarantees that even a compromised backend server cannot decrypt user documents.
3. **Instant Local Feedback (60 FPS)**: Applying photo filters or vector graphics edits locally gives users immediate real-time responsiveness with zero network latency.

- **Server-Side Processing** is taking a digital photograph, mailing the memory card to a photo lab in another country, waiting 3 days for them to turn it black-and-white, and having them mail it back to you.
- **In-Browser Rust WASM** is turning the black-and-white dial on your camera lens: the image changes instantly in your viewfinder with zero waiting.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation of an **In-Browser Image Processing and Stream Cipher Engine** in pure Rust:

```rust
use std::time::Instant;

// ============================================================================
// 1. High-Performance Image Processing Engine (Zero-Copy)
// ============================================================================

pub struct WasmImageProcessor;

impl WasmImageProcessor {
    /// Invert RGB colors in place (Zero allocation)
    pub fn invert_colors(pixels: &mut [u8]) {
        for chunk in pixels.chunks_exact_mut(4) {
            chunk[0] = 255 - chunk[0]; // Invert Red
            chunk[1] = 255 - chunk[1]; // Invert Green
            chunk[2] = 255 - chunk[2]; // Invert Blue
            // Alpha left unchanged
        }
    }

    /// Fast Integer Grayscale (Luminance weights: 77 R + 150 G + 29 B >> 8)
    pub fn fast_grayscale(pixels: &mut [u8]) {
        for chunk in pixels.chunks_exact_mut(4) {
            let r = chunk[0] as u16;
            let g = chunk[1] as u16;
            let b = chunk[2] as u16;

            let gray = ((r * 77 + g * 150 + b * 29) >> 8) as u8;

            chunk[0] = gray;
            chunk[1] = gray;
            chunk[2] = gray;
        }
    }
}

// ============================================================================
// 2. Client-Side Stream Encryption Engine (ChaCha20 / XOR Cipher Model)
// ============================================================================

pub struct ClientSideCrypto;

impl ClientSideCrypto {
    /// Encrypts/Decrypts payload in-place using symmetric key stream (Zero-Copy)
    pub fn encrypt_in_place(payload: &mut [u8], key: &[u8; 32], nonce: u64) {
        let mut state = nonce;
        for (i, byte) in payload.iter_mut().enumerate() {
            // Simple deterministic keystream generator for demo
            state = state.wrapping_mul(6364136223846793005).wrapping_add(1);
            let key_byte = key[i % 32];
            let keystream_byte = ((state >> 32) as u8) ^ key_byte;

            *byte ^= keystream_byte; // In-place XOR encryption
        }
    }
}

// ============================================================================
// 3. Verification & Benchmark
// ============================================================================

fn main() {
    println!("=== 1. Simulating 4K Image Buffer (3840 x 2160 = 8,294,400 Pixels) ===");
    const WIDTH: usize = 3840;
    const HEIGHT: usize = 2160;
    const PIXEL_COUNT: usize = WIDTH * HEIGHT;
    const BUFFER_SIZE: usize = PIXEL_COUNT * 4; // 33.17 MB

    println!("Allocating 33.17 MB RGBA Pixel Array in WASM Linear Memory...");
    let mut image_buffer = vec![0u8; BUFFER_SIZE];

    // Seed test pixel values
    for (i, chunk) in image_buffer.chunks_exact_mut(4).enumerate() {
        chunk[0] = (i % 255) as u8;       // R
        chunk[1] = ((i * 2) % 255) as u8; // G
        chunk[2] = ((i * 3) % 255) as u8; // B
        chunk[3] = 255;                   // Alpha (Full Opacity)
    }

    println!("\n=== 2. Benchmarking Fast In-Place Grayscale Conversion ===");
    let start = Instant::now();
    WasmImageProcessor::fast_grayscale(&mut image_buffer);
    let elapsed = start.elapsed();

    println!("Processed 8.3 Million Pixels (33 MB) in {:?}", elapsed);
    println!("Sample Pixel 0 RGB: [{}, {}, {}] (Equal RGB = Perfect Grayscale)", 
        image_buffer[0], image_buffer[1], image_buffer[2]);
    assert_eq!(image_buffer[0], image_buffer[1]);
    assert_eq!(image_buffer[1], image_buffer[2]);

    println!("\n=== 3. Testing In-Browser Client-Side File Encryption (E2EE) ===");
    let mut secret_document = b"CONFIDENTIAL_PATIENT_MEDICAL_HISTORY_2026".to_vec();
    let original_text = String::from_utf8_lossy(&secret_document).to_string();
    println!("Original Document:  '{}'", original_text);

    let key = [0x5A; 32]; // 256-bit symmetric key
    let nonce = 948102948102u64;

    // Encrypt in-browser
    ClientSideCrypto::encrypt_in_place(&mut secret_document, &key, nonce);
    println!("Encrypted Ciphertext (Sent to S3): {:02X?}", &secret_document[..16]);

    // Decrypt on client download
    ClientSideCrypto::encrypt_in_place(&mut secret_document, &key, nonce);
    let decrypted_text = String::from_utf8_lossy(&secret_document);
    println!("Decrypted Document: '{}'", decrypted_text);

    assert_eq!(original_text, decrypted_text);
    println!("\nVerification: E2EE client-side encryption and decryption 100% successful!");
}
```

## Common Pitfalls & Compiler Errors

### 1. Cloning Large Arrays into JavaScript
Calling `image_buffer.clone()` when returning data to JavaScript forces a 33MB memory allocation and GC cycle on every frame.
**Fix**: Pass a raw pointer and length (`image_buffer.as_ptr()`), and instantiate a zero-copy typed array view on the JavaScript side: `new Uint8ClampedArray(wasm.memory.buffer, ptr, len)`.

### 2. Using Floating-Point Math for Integer Pixel Math
Using `f32` or `f64` for RGB color channels requires float conversion instructions (`cvtsi2ss`). Using fixed-point integer arithmetic (`>> 8`) is significantly faster.

## Complete Solutions to Exercises

### Solution 1: Brightness Filter

```rust
pub fn adjust_brightness(pixels: &mut [u8], delta: i16) {
    for chunk in pixels.chunks_exact_mut(4) {
        if delta >= 0 {
            let d = delta as u8;
            chunk[0] = chunk[0].saturating_add(d);
            chunk[1] = chunk[1].saturating_add(d);
            chunk[2] = chunk[2].saturating_add(d);
        } else {
            let d = (-delta) as u8;
            chunk[0] = chunk[0].saturating_sub(d);
            chunk[1] = chunk[1].saturating_sub(d);
            chunk[2] = chunk[2].saturating_sub(d);
        }
    }
}
```
