## Concept

Because WebAssembly only natively understands 32-bit and 64-bit numbers, passing a JavaScript string, object, or DOM element into Rust requires high-level interop glue code.

The **`wasm-bindgen`** toolchain automatically generates JavaScript wrappers and Rust FFI bindings to bridge this gap seamlessly.

```
┌──────────────────────────────────────┐                ┌──────────────────────────────────────┐
│  JavaScript Frontend (Browser)       │                │  Rust WASM Module                    │
│                                      │                │                                      │
│  import { greet, CanvasEngine }      │                │  #[wasm_bindgen]                     │
│    from "./pkg/my_app.js";           │ ─── Calls ───► │  pub fn greet(name: &str) -> String  │
│                                      │                │                                      │
│  const engine = new CanvasEngine();  │ ◄── Returns ── │  #[wasm_bindgen]                     │
│  engine.render_frame();              │                │  pub struct CanvasEngine { ... }     │
└──────────────────────────────────────┘                └──────────────────────────────────────┘
                   │                                                       ▲
                   └────────────────── [ wasm-bindgen ] ───────────────────┘
                                 Translates Strings, Structs,
                                   DOM Nodes & JS Closures
```

### 1. The `wasm-pack` Workflow

`wasm-pack` is the official CLI tool to build, optimize, and package Rust WebAssembly code for npm and web applications:

```bash
# Build optimized WebAssembly module for direct browser ES Module import:
wasm-pack build --target web --release
```

This command produces:
- `my_app_bg.wasm`: Optimized WebAssembly binary.
- `my_app.js`: JavaScript bridge module with TypeScript type definitions (`.d.ts`).

### 2. Browser Integration with `web-sys` and `js-sys`

- **`js-sys`**: Provides typed Rust bindings to JavaScript standard globals (`Promise`, `Uint8Array`, `ArrayBuffer`, `Date`, `JSON`).
- **`web-sys`**: Provides zero-cost Rust bindings to every single W3C browser API (`window`, `document`, `HTMLElement`, `CanvasRenderingContext2d`, `WebSocket`).

#### Manipulating the DOM in Pure Rust:
```rust
use wasm_bindgen::prelude::*;
use web_sys::{window, Document, HtmlElement};

#[wasm_bindgen]
pub fn append_status_badge(message: &str) -> Result<(), JsValue> {
    let window = window().ok_or("No global window found")?;
    let document = window.document().ok_or("No document on window")?;
    let body = document.body().ok_or("No body on document")?;

    // Create a new <div> element in pure Rust
    let div = document.create_element("div")?;
    div.set_class_name("p-4 bg-emerald-500 text-white rounded-lg");
    div.set_inner_html(message);

    body.append_child(&div)?;
    Ok(())
}
```

### 3. Passing Closures to JavaScript Event Listeners

To attach a Rust closure to a DOM click event, wrap the closure using **`Closure::wrap`**:

```rust
use wasm_bindgen::closure::Closure;
use web_sys::HtmlButtonElement;

#[wasm_bindgen]
pub fn attach_click_handler(button: HtmlButtonElement) -> Result<(), JsValue> {
    let closure = Closure::wrap(Box::new(move || {
        web_sys::console::log_1(&"Button clicked in Rust!".into());
    }) as Box<dyn FnMut()>);

    button.add_event_listener_with_callback("click", closure.as_ref().unchecked_ref())?;
    closure.forget(); // Keep closure alive in memory
    Ok(())
}
```

## Why It Matters in Systems Programming

1. **Direct Hardware Acceleration in Browser**: High-performance Rust engines (physics, GIS map renderers, audio synthesis) directly control HTML5 `<canvas>` and WebGL viewports.
2. **Type Safety Across Language Boundaries**: `wasm-bindgen` generates TypeScript `.d.ts` files automatically, guaranteeing compile-time type checking in React/Vue frontends.
3. **Zero-Copy Uint8Array Views**: Exposing Rust vectors to JavaScript via `js_sys::Uint8Array::view` avoids copying megabytes of image or audio data between JS and WASM.

---

## Real-World Analogy

- **Raw WASM** is like a diplomat who only speaks binary machine numbers.
- **`wasm-bindgen`** is a world-class simultaneous translator: when JavaScript speaks `String` or `Object`, it translates them into WASM memory pointer addresses; when WASM returns a byte slice, it formats it into a native JavaScript object for the browser.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation demonstrating **`wasm-bindgen` Structs, JS Interop Bindings, and Canvas Rendering**:

```rust
// ============================================================================
// 1. Simulating wasm-bindgen Interop Data Structures
// ============================================================================

#[derive(Debug, Clone)]
pub struct JsBridgeValue {
    pub raw_type: &'static str,
    pub string_val: Option<String>,
    pub number_val: Option<f64>,
}

impl JsBridgeValue {
    pub fn from_str(s: &str) -> Self {
        Self {
            raw_type: "string",
            string_val: Some(s.to_string()),
            number_val: None,
        }
    }

    pub fn from_f64(n: f64) -> Self {
        Self {
            raw_type: "number",
            string_val: None,
            number_val: Some(n),
        }
    }
}

// ============================================================================
// 2. Exported WASM Canvas Animation Engine
// ============================================================================

pub struct Particle {
    pub x: f64,
    pub y: f64,
    pub vx: f64,
    pub vy: f64,
    pub radius: f64,
}

pub struct WasmParticleEngine {
    particles: Vec<Particle>,
    width: f64,
    height: f64,
}

impl WasmParticleEngine {
    pub fn new(width: f64, height: f64, particle_count: usize) -> Self {
        let mut particles = Vec::with_capacity(particle_count);
        for i in 0..particle_count {
            let angle = (i as f64) * 0.1;
            particles.push(Particle {
                x: width / 2.0,
                y: height / 2.0,
                vx: angle.cos() * 2.5,
                vy: angle.sin() * 2.5,
                radius: 3.0,
            });
        }

        Self {
            particles,
            width,
            height,
        }
    }

    /// Advance simulation physics by 1 frame (60 FPS)
    pub fn step_physics(&mut self) {
        for p in &mut self.particles {
            p.x += p.vx;
            p.y += p.vy;

            // Bounce off boundaries
            if p.x <= 0.0 || p.x >= self.width {
                p.vx = -p.vx;
            }
            if p.y <= 0.0 || p.y >= self.height {
                p.vy = -p.vy;
            }
        }
    }

    /// Exposes raw memory pointer directly to JavaScript Canvas renderer
    pub fn get_particle_positions_ptr(&self) -> *const Particle {
        self.particles.as_ptr()
    }

    pub fn particle_count(&self) -> usize {
        self.particles.len()
    }
}

// ============================================================================
// 3. Verification & Execution
// ============================================================================

fn main() {
    println!("=== 1. Simulating wasm-pack & wasm-bindgen Module ===");
    println!("Initializing 1920x1080 Wasm Particle Physics Engine in Rust...");

    let mut engine = WasmParticleEngine::new(1920.0, 1080.0, 5);
    println!("Spawned {} particles in WASM linear memory.", engine.particle_count());

    println!("\n=== 2. Stepping Physics Animation Frames ===");
    for frame in 1..=3 {
        engine.step_physics();
        println!("Frame #{}:", frame);
        for (i, p) in engine.particles.iter().enumerate() {
            println!("  Particle {}: Pos({:>6.1}, {:>6.1}) | Vel({:>4.1}, {:>4.1})", i, p.x, p.y, p.vx, p.vy);
        }
    }

    println!("\n=== 3. Zero-Copy Pointer Export to JavaScript ===");
    let raw_ptr = engine.get_particle_positions_ptr();
    println!("Exported Raw Linear Memory Pointer: {:p}", raw_ptr);
    println!("JavaScript can instantiate `new Float64Array(wasm.memory.buffer, {:p}, 5 * 5)` with 0 memory copies!", raw_ptr);
}
```

## Common Pitfalls & Compiler Errors

### 1. Dropping Closures Before JavaScript Fires Events
If you wrap a Rust closure with `Closure::wrap` and assign it to an event listener, but allow the `Closure` struct to drop at the end of the function, the closure is deallocated. When the user clicks the button, the browser attempts to call freed memory (Panic).
**Fix**: Call `closure.forget()` to leak the closure handle permanently into the runtime.

### 2. Deep Struct Serializations Across the Boundary
Passing deeply nested `struct` trees by value across `wasm-bindgen` forces JSON serialization overhead.
**Fix**: Pass pointers to contiguous buffers or keep state inside Rust and export methods that return numbers or slices.

## Complete Solutions to Exercises

### Solution 2: Canvas Pixel Buffer

```rust
pub struct CanvasBuffer {
    pub width: usize,
    pub height: usize,
    pub pixels: Vec<u8>, // RGBA format (4 bytes per pixel)
}

impl CanvasBuffer {
    pub fn new(width: usize, height: usize) -> Self {
        Self {
            width,
            height,
            pixels: vec![255; width * height * 4],
        }
    }

    pub fn set_pixel(&mut self, x: usize, y: usize, r: u8, g: u8, b: u8, a: u8) {
        let idx = (y * self.width + x) * 4;
        self.pixels[idx] = r;
        self.pixels[idx + 1] = g;
        self.pixels[idx + 2] = b;
        self.pixels[idx + 3] = a;
    }
}
```
