## Concept

**WebAssembly (WASM)** is a low-level, binary instruction format (a **Virtual Instruction Set Architecture - Virtual ISA**) designed to execute at near-native speed across web browsers, edge workers, and standalone servers.

When you compile Rust to native machine code for Linux (e.g. `x86_64-unknown-linux-gnu`), the binary contains x86_64 CPU instructions that interact directly with the OS kernel via system calls.

When you compile Rust to WebAssembly (`wasm32-unknown-unknown` or `wasm32-wasi`):
1. The Rust compiler and LLVM produce a compact `.wasm` binary containing virtual stack-machine bytecode.
2. The runtime engine (V8 in Chrome, SpiderMonkey in Firefox, or Wasmtime on servers) executes this bytecode within a **strictly sandboxed, memory-safe virtual container**.

```
  Rust Source Code (.rs)
            │
            ▼ (rustc / LLVM)
  WebAssembly Module (.wasm)
            │
  ┌─────────┴────────────────────────────────────────────────────────────┐
  │  WASM Sandboxed Virtual Machine Runtime (V8 / Wasmtime)              │
  │                                                                      │
  │  ┌─────────────────────────────────┐ ┌─────────────────────────────┐ │
  │  │   Linear Memory (ArrayBuffer)   │ │  Stack Machine Bytecode     │ │
  │  │   [ 64KB Page 0 ]               │ │  i32.add, f64.mul, call ... │ │
  │  │   [ 64KB Page 1 ]               │ └──────────────┬──────────────┘ │
  │  │   [ 64KB Page N ... ]           │                │                │
  │  └─────────────────────────────────┘                ▼                │
  │   (Cannot touch host OS memory!)       [ JIT / AOT Compiler ]        │
  └─────────────────────────────────────────────────────┬────────────────┘
                                                        ▼
                                        Physical CPU Execution (x86 / ARM)
```

---

### 1. WebAssembly Linear Memory

WASM does not have direct access to physical host RAM. Instead, a WASM module is given a single contiguous, flat byte array called **Linear Memory**:
- Linear memory is allocated in fixed-size **Pages of 64 KB (65,536 bytes)**.
- The module can grow its memory dynamically using the `memory.grow` instruction.
- **Hardware-Level Sandboxing**: Memory addresses inside WASM are simply unsigned integer indices (`0` to `N - 1`) into this 64KB array buffer. The WASM module physically **cannot address or read any memory belonging to the host OS or other browser tabs**.

---

### 2. Compilation Targets: `wasm32-unknown-unknown` vs `wasm32-wasi`

| Target Triple | Environment | Capabilities |
| :--- | :--- | :--- |
| **`wasm32-unknown-unknown`** | Web Browsers, Cloudflare Workers | Pure compute; interacts with JavaScript via `wasm-bindgen`. No native OS filesystem. |
| **`wasm32-wasi`** | Standalone Servers, Docker, Fastly | Standard WASI interface (`std::fs::File`, `std::env`, standard I/O via host capability grants). |

---

### 3. Stack Machine Execution

WASM is a **Stack Machine**:
- Instructions push values onto an evaluation stack and pop operands to execute operations.
- Example: Adding two 32-bit integers:
  ```wat
  (func $add (param $a i32) (param $b i32) (result i32)
      local.get $a    ;; Push $a onto stack
      local.get $b    ;; Push $b onto stack
      i32.add         ;; Pop $a and $b, add them, push sum
  )
  ```

---

## Why It Matters in Systems Programming

1. **Near-Native Performance on the Web**: CPU-heavy algorithms (video transcoding, 3D gaming, CAD engines, physics engines, cryptography) run at $85 - 95\%$ of native C/Rust speed directly inside the browser.
2. **True Cross-Platform Portability**: Write systems code once in Rust and run it unchanged on Windows, Linux, macOS, iOS, Android, browsers, and edge CDN nodes.
3. **Security by Default (Zero Day Protection)**: Even if a buffer overflow occurs inside WASM code, the memory corruption is trapped inside its private 64KB array buffer—it cannot escape or inject shellcode into host OS memory.

---

## Real-World Analogy

- **Native Binary (`x86_64`)** is like a sports car driving on open public highways: it has full speed and direct access to any street, but a crash can take down the entire intersection.
- **WebAssembly** is like an ultra-high-speed electric go-kart inside a padded indoor racing arena: it drives at blazing speeds, but the rubber barriers physically prevent it from ever colliding with the rest of the city.

## Complete, Compilable Code Example

Below is a complete, self-contained implementation of a **WebAssembly Virtual Machine & Linear Memory Emulator** in pure Rust:

```rust
// ============================================================================
// 1. WASM Linear Memory (64KB Page Architecture)
// ============================================================================

pub const WASM_PAGE_SIZE: usize = 65536; // Exactly 64 KB per page

pub struct WasmLinearMemory {
    pages: Vec<[u8; WASM_PAGE_SIZE]>,
}

impl WasmLinearMemory {
    pub fn new(initial_pages: usize) -> Self {
        Self {
            pages: vec![[0u8; WASM_PAGE_SIZE]; initial_pages],
        }
    }

    pub fn grow(&mut self, additional_pages: usize) -> usize {
        let old_pages = self.pages.len();
        self.pages.resize(old_pages + additional_pages, [0u8; WASM_PAGE_SIZE]);
        old_pages
    }

    /// Read raw 32-bit integer at byte offset (Little-Endian)
    pub fn read_i32(&self, byte_offset: usize) -> Result<i32, &'static str> {
        let total_size = self.pages.len() * WASM_PAGE_SIZE;
        if byte_offset + 4 > total_size {
            return Err("WASM Memory Out-of-Bounds Trap!");
        }

        let page_idx = byte_offset / WASM_PAGE_SIZE;
        let page_offset = byte_offset % WASM_PAGE_SIZE;

        let bytes = &self.pages[page_idx][page_offset..page_offset + 4];
        Ok(i32::from_le_bytes([bytes[0], bytes[1], bytes[2], bytes[3]]))
    }

    /// Write raw 32-bit integer at byte offset
    pub fn write_i32(&mut self, byte_offset: usize, value: i32) -> Result<(), &'static str> {
        let total_size = self.pages.len() * WASM_PAGE_SIZE;
        if byte_offset + 4 > total_size {
            return Err("WASM Memory Out-of-Bounds Trap!");
        }

        let page_idx = byte_offset / WASM_PAGE_SIZE;
        let page_offset = byte_offset % WASM_PAGE_SIZE;

        let le_bytes = value.to_le_bytes();
        self.pages[page_idx][page_offset..page_offset + 4].copy_from_slice(&le_bytes);
        Ok(())
    }

    pub fn total_memory_bytes(&self) -> usize {
        self.pages.len() * WASM_PAGE_SIZE
    }
}

// ============================================================================
// 2. WASM Stack Machine Instruction Emulator
// ============================================================================

pub struct WasmStackMachine {
    eval_stack: Vec<i32>,
    memory: WasmLinearMemory,
}

impl WasmStackMachine {
    pub fn new(initial_pages: usize) -> Self {
        Self {
            eval_stack: Vec::new(),
            memory: WasmLinearMemory::new(initial_pages),
        }
    }

    pub fn push(&mut self, val: i32) {
        self.eval_stack.push(val);
    }

    pub fn pop(&mut self) -> Result<i32, &'static str> {
        self.eval_stack.pop().ok_or("WASM Stack Underflow")
    }

    /// i32.add instruction
    pub fn op_i32_add(&mut self) -> Result<(), &'static str> {
        let b = self.pop()?;
        let a = self.pop()?;
        self.push(a.wrapping_add(b));
        Ok(())
    }

    /// i32.mul instruction
    pub fn op_i32_mul(&mut self) -> Result<(), &'static str> {
        let b = self.pop()?;
        let a = self.pop()?;
        self.push(a.wrapping_mul(b));
        Ok(())
    }

    /// i32.store instruction: Pop value and memory address, write to linear memory
    pub fn op_i32_store(&mut self) -> Result<(), &'static str> {
        let value = self.pop()?;
        let address = self.pop()? as usize;
        self.memory.write_i32(address, value)
    }

    /// i32.load instruction: Pop memory address, read from linear memory, push value
    pub fn op_i32_load(&mut self) -> Result<(), &'static str> {
        let address = self.pop()? as usize;
        let val = self.memory.read_i32(address)?;
        self.push(val);
        Ok(())
    }
}

// ============================================================================
// 3. Execution & Verification
// ============================================================================

fn main() {
    println!("=== 1. Initializing WebAssembly VM with 2 Linear Memory Pages ===");
    let mut vm = WasmStackMachine::new(2);
    println!("Linear Memory Initialized: {} bytes ({} KB)", vm.memory.total_memory_bytes(), vm.memory.total_memory_bytes() / 1024);

    println!("\n=== 2. Simulating Bytecode: `(15 + 25) * 4` ===");
    // Bytecode sequence: i32.const 15, i32.const 25, i32.add, i32.const 4, i32.mul
    vm.push(15);
    vm.push(25);
    vm.op_i32_add().unwrap();
    vm.push(4);
    vm.op_i32_mul().unwrap();

    let computed_result = vm.pop().unwrap();
    println!("Evaluation Stack Result: {} (Expected: (15 + 25) * 4 = 160)", computed_result);
    assert_eq!(computed_result, 160);

    println!("\n=== 3. Writing and Reading from WASM Linear Memory ===");
    // Store result 160 at memory address 1024
    vm.push(1024); // Address
    vm.push(computed_result); // Value
    vm.op_i32_store().unwrap();
    println!("Wrote value {} to Linear Memory address 1024.", computed_result);

    // Load value back from address 1024
    vm.push(1024);
    vm.op_i32_load().unwrap();
    let loaded = vm.pop().unwrap();
    println!("Loaded value from Linear Memory: {}", loaded);
    assert_eq!(loaded, 160);

    println!("\n=== 4. Testing Out-of-Bounds Memory Sandboxing Trap ===");
    let trap_result = vm.memory.read_i32(999_999); // Exceeds allocated 128KB!
    println!("Attempted read at address 999,999: {:?}", trap_result);
    assert!(trap_result.is_err());
    println!("✅ Memory out-of-bounds access successfully trapped by sandbox!");
}
```

## Common Pitfalls & Compiler Errors

### 1. Assuming Standard C Library (libc) Exists in `wasm32-unknown-unknown`
Attempting to open files via `std::fs::File::open` or spawn OS threads with `std::thread::spawn` in `wasm32-unknown-unknown` panics at runtime because web browsers have no POSIX kernel. Use `wasm32-wasi` for server environments, or web APIs for browsers.

### 2. Passing Complex Types across the WASM Boundary
WASM only natively supports primitive numbers (`i32`, `i64`, `f32`, `f64`). Passing strings or structs requires writing bytes into WASM linear memory and passing the pointer offset and length to JavaScript.

## Complete Solutions to Exercises

### Solution 1: UTF-8 String Writer

```rust
impl WasmLinearMemory {
    pub fn write_utf8_string(&mut self, byte_offset: usize, text: &str) -> Result<usize, &'static str> {
        let bytes = text.as_bytes();
        let total_size = self.pages.len() * WASM_PAGE_SIZE;
        if byte_offset + bytes.len() > total_size {
            return Err("Out of bounds");
        }

        let page_idx = byte_offset / WASM_PAGE_SIZE;
        let page_offset = byte_offset % WASM_PAGE_SIZE;
        self.pages[page_idx][page_offset..page_offset + bytes.len()].copy_from_slice(bytes);

        Ok(bytes.len())
    }
}
```
