## Concept

Memory management is the central challenge in systems programming. 
- In languages like C, developers manually allocate and free heap memory, leading to crashes, memory leaks, and severe security exploits.
- In languages like Python, Java, or Go, a background **Garbage Collector (GC)** constantly scans memory at runtime, consuming extra CPU cycles and causing unpredictable latency pauses.

Rust solves this with **Ownership**—a set of compile-time rules that guarantees absolute memory safety with **zero runtime overhead** and **no garbage collector**.

---

### 1. The Three Inviolable Rules of Ownership

1. **Every value in Rust has an owner** (a variable).
2. **There can only be one owner at a time**.
3. **When the owner goes out of scope, the value is automatically dropped (freed from memory).**

```
Scope begins {
    let payload = String::from("HTTP/1.1 200 OK"); // `payload` is the owner of the heap buffer
    // ... payload is valid and usable here ...
} // Scope ends: `payload` goes out of scope -> Rust automatically calls `drop` to free the heap memory!
```

---

### 2. Move Semantics (Heap Types)

Consider a heap-allocated `String`:
```rust
let request_a = String::from("GET /index.html");
let request_b = request_a; // Ownership is MOVED to request_b
```

What actually happens in memory:
1. `request_a` is a stack descriptor (pointer to heap, length, capacity).
2. When assigned to `request_b`, Rust copies the 24-byte stack descriptor.
3. To prevent a **Double Free** bug (where both variables attempt to deallocate the same heap memory when they exit scope), Rust **invalidates `request_a`**.
4. `request_a` no longer owns the data. This transfer is called a **Move**.

```
STACK                                HEAP
┌───────────────┐                  ┌──────────────────────┐
│ request_a     │                  │                      │
│ (INVALIDATED) │ ───┐             │                      │
├───────────────┤    │             │  "GET /index.html"   │
│ request_b     │    └───────────> │  [0x7FFF00]          │
│ ptr: 0x7FFF00 │ ─────────────────┘                      │
└───────────────┘
```

If you try to use `request_a` after the move, the compiler stops you with an error.

---

### 3. Copy Semantics (Stack Primitives)

Simple scalar types (like `i32`, `u64`, `f64`, `bool`, `char`, and fixed arrays/tuples containing only these types) live entirely on the stack and have fixed sizes.

These types implement the **`Copy` trait**. When you assign or pass a `Copy` type, Rust creates an independent bitwise copy on the stack. **Both variables remain valid**:

```rust
let port_a: u16 = 8080;
let port_b = port_a; // Copied!

println!("Port A: {}, Port B: {}", port_a, port_b); // Valid: Both are alive
```

---

### 4. Deep Duplication with `.clone()`

If you explicitly want an independent, duplicated copy of heap data (allocating a brand-new heap buffer), you call the `.clone()` method:

```rust
let original_payload = String::from("JSON_BODY");
let copied_payload = original_payload.clone(); // Deep heap allocation

// Both original_payload and copied_payload are independent owners of separate heap buffers
```

---

### 5. Ownership and Functions

- **Passing a value to a function** moves ownership into that function's parameter.
- **Returning a value from a function** transfers ownership out to the caller.

```rust
fn handle_request(body: String) {
    // `body` is now the owner. When this function ends, `body` is dropped and freed.
}

fn main() {
    let request_body = String::from("{ \"user\": \"alice\" }");
    handle_request(request_body); // Ownership moved into `handle_request`
    // `request_body` is no longer valid here!
}
```

---

## Why it matters

In an HTTP web server, requests stream in continuously. When a worker thread finishes handling a request, all associated heap memory (headers, cookies, payload) must be freed instantly so the server does not run out of RAM. 

Rust's ownership guarantees deterministic, instant cleanup at the exact line of code where the owner goes out of scope, eliminating memory leaks without stopping the CPU for garbage collection.

---

## Analogy

Think of a physical **Car Title (Vehicle Registration)**:
- **Move**: You sell your car to a buyer and sign over the physical title. The buyer is now the sole legal owner. You cannot legally drive the car or sell it to someone else anymore. There is only one car and one title.
- **Copy**: A coin with the number "25" stamped on it. If you want a friend to have 25 cents, you pull another quarter out of your pocket. Both of you now have 25 cents.
- **Clone**: Building an exact physical replica of your car from scratch in a factory. It takes significant materials, labor, and time (heap allocation), but results in two separate cars.

## Code Example

```rust
// This function takes OWNERSHIP of the incoming String
fn inspect_and_consume(data: String) {
    println!("Consuming payload: '{}' (Length: {} bytes)", data, data.len());
    // At the end of this scope, `data` is dropped and its heap memory is freed!
}

// This function takes ownership and MOVES it back to the caller
fn sanitize_payload(mut raw_data: String) -> String {
    raw_data.push_str(" [SANITIZED]");
    raw_data // Implicit return transfers ownership back to the caller
}

fn main() {
    println!("--- 1. Copy Semantics (Stack Types) ---");
    let status_code: u16 = 200;
    let code_copy = status_code; // Stack copy
    println!("Original: {}, Copy: {}", status_code, code_copy); // Both valid!

    println!("\n--- 2. Move Semantics (Heap Types) ---");
    let initial_msg = String::from("CONNECT_TO_GATEWAY");
    
    // Ownership is moved into `inspect_and_consume`
    inspect_and_consume(initial_msg);

    // UNCOMMENTING THE LINE BELOW CAUSES A COMPILE-TIME ERROR:
    // println!("Trying to reuse initial_msg: {}", initial_msg);

    println!("\n--- 3. Transferring Ownership via Return ---");
    let raw_input = String::from("user_query_alpha");
    
    // Ownership moves into `sanitize_payload` and the returned String moves into `clean_input`
    let clean_input = sanitize_payload(raw_input);
    println!("Cleaned Input: {}", clean_input);

    println!("\n--- 4. Explicit Deep Copy (.clone()) ---");
    let broadcast_message = String::from("SYSTEM_ALERT");
    let duplicate_for_audit = broadcast_message.clone(); // Allocates new heap memory

    inspect_and_consume(broadcast_message);
    println!("Audit copy is still alive: {}", duplicate_for_audit);
}
```

## Common Mistakes

### 1. Using a Value After It Has Been Moved
Attempting to read or pass a variable after its ownership was transferred.

**Broken Code:**
```rust
fn main() {
    let config = String::from("timeout=30");
    let backup = config; // config is moved to backup
    println!("Config: {}", config); // Error!
}
```

**Compiler Output:**
```text
error[E0382]: borrow of moved value: `config`
 --> src/main.rs:4:28
  |
2 |     let config = String::from("timeout=30");
  |         ------ move occurs because `config` has type `String`, which does not implement the `Copy` trait
3 |     let backup = config;
  |                  ------ value moved here
4 |     println!("Config: {}", config);
  |                            ^^^^^^ value borrowed here after move
```

---

### 2. Excessive Cloning (`.clone()`) to Bypass the Compiler
Cloning every variable to avoid understanding ownership.

*Why it's a problem*: Calling `.clone()` duplicates heap buffers, allocating unnecessary memory and degrading system performance. The correct solution is usually to **borrow** (covered in Lesson 1.5).

---

### 3. Assuming Structs with Dynamic Fields are `Copy`
Assuming custom data types containing `String` or other heap objects can be copied automatically like integers.

## Exercises

### Exercise 1 (Move or Copy?)
For each variable assignment, state whether a **Move** or a **Copy** occurs:
1. `let a: i64 = 500; let b = a;`
2. `let s1: String = String::from("Rust"); let s2 = s1;`
3. `let flag: bool = true; let active = flag;`
4. `let packet: [u8; 4] = [10, 0, 0, 1]; let copy_packet = packet;`

---

### Exercise 2 (Fixing the Moved Value)
The following code fails to compile because `server_url` is moved into `ping_server`. Modify `ping_server` so it takes ownership, prints the URL, and **returns ownership back** to `main` so it can be printed again.

```rust
fn ping_server(url: String) {
    println!("Pinging: {}", url);
}

fn main() {
    let server_url = String::from("https://api.internal.net");
    ping_server(server_url);
    println!("Ping completed for: {}", server_url);
}
```

### Exercise 3 (Ownership Round-Trip with Metrics)
Write a complete Rust program with a function `process_transaction` that:
1. Takes ownership of a `String` representing a transaction description.
2. Calculates the length of the string in bytes (`.len()`).
3. Appends `" [PROCESSED]"` to the string.
4. Returns a tuple `(String, usize)` containing both the modified string and the byte length.
5. In `main()`, call the function and print both elements of the returned tuple.

---

## Solutions

### Solution to Exercise 1
1. **Copy**: `i64` is a primitive scalar type stored on the stack.
2. **Move**: `String` manages heap data and does not implement `Copy`.
3. **Copy**: `bool` is a 1-byte primitive stack type.
4. **Copy**: `[u8; 4]` is a fixed array of primitive `u8` bytes stored on the stack.

---

### Solution to Exercise 2
```rust
fn ping_server(url: String) -> String {
    println!("Pinging: {}", url);
    url // Return ownership back to the caller
}

fn main() {
    let server_url = String::from("https://api.internal.net");
    let server_url = ping_server(server_url); // Re-bind ownership via shadowing
    println!("Ping completed for: {}", server_url);
}
```

---

### Solution to Exercise 3
```rust
fn process_transaction(mut tx: String) -> (String, usize) {
    let original_length = tx.len();
    tx.push_str(" [PROCESSED]");
    (tx, original_length)
}

fn main() {
    let transaction_record = String::from("TX_9812_AUTH_CAPTURE");

    let (updated_record, byte_count) = process_transaction(transaction_record);

    println!("Updated Record: {}", updated_record);
    println!("Original Length: {} bytes", byte_count);
}
```
