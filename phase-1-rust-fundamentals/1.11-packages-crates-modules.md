## Concept

As systems codebases grow to thousands of lines across dozens of files, keeping all code in a single file becomes unmanageable. Rust provides a hierarchical module system to organize code, encapsulate logic, and strictly control access boundaries.

---

### 1. The Code Organization Hierarchy

```
┌────────────────────────────────────────────────────────┐
│                        PACKAGE                         │
│  Defined by Cargo.toml. Contains 1 or more Crates      │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │                   BINARY CRATE                   │  │
│  │  src/main.rs (Produces the executable binary)    │  │
│  │                                                  │  │
│  │  ┌────────────────────────────────────────────┐  │  │
│  │  │                  MODULES                   │  │  │
│  │  │  mod server { pub mod router; }            │  │  │
│  │  │  Encapsulates functions, structs, privacy  │  │  │
│  │  └────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

1. **Package**: A Cargo feature that bundles one or more crates. Managed by `Cargo.toml`.
2. **Crate**: A compilation unit that produces either:
   - A **Binary Crate**: Has a `src/main.rs` and compiles into a runnable executable.
   - A **Library Crate**: Has a `src/lib.rs` and provides reusable components for other programs.
3. **Module (`mod`)**: A named namespace within a crate that groups related definitions and controls privacy.

---

### 2. Privacy: Private by Default

In Rust, **all items (functions, structs, enums, fields, methods) are private to their parent module by default**.

To make an item accessible outside its module, you must prefix it with the **`pub`** keyword:

- `pub fn`: Public function.
- `pub struct`: Public struct (note: its **fields remain private** unless each field is also explicitly marked `pub`).
- `pub enum`: Public enum (making an enum `pub` automatically makes **all its variants public**).
- `pub(crate)`: Visible anywhere within the current crate, but hidden from external consumers.

---

### 3. Paths and the `use` Keyword

To refer to an item in the module tree:
- **Absolute Path**: Starts from the crate root using `crate::`:
  ```rust
  crate::network::http::parse_request();
  ```
- **Relative Path**: Starts from the current module using `self::` or parent module using `super::`:
  ```rust
  super::validate_port();
  ```
- **The `use` Shortcut**: Brings a path into scope so you can call it without typing the full path every time:
  ```rust
  use crate::network::http::parse_request;
  parse_request();
  ```
- **Re-exporting (`pub use`)**: Exposes an internal nested item at a higher level in your public API:
  ```rust
  pub use crate::network::http::HttpServer;
  ```

---

## Why it matters

In low-level systems (like an HTTP engine or an AI agent sandbox), internal memory buffers and raw sockets must be protected. If application code could directly manipulate a connection's internal byte cursor without going through the public `read()` method, state would quickly corrupt. 

Rust's strict `pub` privacy boundaries enforce safety at compile time: you expose only a safe public interface while keeping critical systems internals private.

---

## Analogy

Think of a **Commercial Bank**:
- **Package**: The entire bank branch property.
- **Crate**: The main banking hall (`main.rs`).
- **Module**: The Cashier Desk, the Loan Office, and the Security Vault.
- **Privacy (`pub`)**: The teller window and deposit slips are `pub` (open to the public). The security vault door and cash drawers are **private** (accessible only to authorized employees in that module).
- **`super::`**: A teller reaching behind them into the manager's office on the floor above.

## Code Example

Below is a complete, single-file demonstration of nested modules, privacy rules, struct field encapsulation, and path shortcuts.

```rust
// 1. Defining a top-level module named `telemetry`
mod telemetry {
    // A private constant: Only accessible inside `telemetry`
    const COLLECTOR_VERSION: &str = "2.4.0";

    // A public sub-module named `metrics`
    pub mod metrics {
        // A public struct with private fields (Encapsulation)
        #[derive(Debug)]
        pub struct SystemMetric {
            pub name: String,      // Public field: Read/Write from outside
            value: f64,            // Private field: Can only be modified by methods in this module!
        }

        impl SystemMetric {
            // Public constructor
            pub fn new(name: String, value: f64) -> SystemMetric {
                SystemMetric { name, value }
            }

            // Public getter method
            pub fn read_value(&self) -> f64 {
                self.value
            }

            // Internal helper using `super` to access the parent module's private constant
            pub fn format_with_version(&self) -> String {
                format!("[Collector v{}] {}: {}", super::COLLECTOR_VERSION, self.name, self.value)
            }
        }
    }
}

// 2. Bringing the public struct into scope with `use`
use telemetry::metrics::SystemMetric;

fn main() {
    // Constructing the metric using the public constructor
    let cpu_metric = SystemMetric::new(String::from("cpu_load_percent"), 45.8);

    println!("Metric Name : {}", cpu_metric.name);
    println!("Metric Value: {}", cpu_metric.read_value());
    println!("Full Report : {}", cpu_metric.format_with_version());

    // UNCOMMENTING THE LINE BELOW CAUSES A COMPILE ERROR (field `value` is private):
    // println!("Direct private access: {}", cpu_metric.value);
}
```

## Common Mistakes

### 1. Making a Struct Public but Forgetting Field Privacy
A beginner defines `pub struct Config { port: u16 }` and is surprised when external code cannot create it with `Config { port: 8080 }`.

*Why it happens*: Marking a struct `pub` makes the *type* visible, but its fields remain private by default. You must either mark the fields `pub port: u16` or provide a `pub fn new(...)` constructor.

---

### 2. Assuming Files on Disk Are Automatically Included in the Build
Creating `src/router.rs` and expecting Rust to compile it without declaring `mod router;` in `src/main.rs`.

*Why it happens*: Unlike other languages, Rust does not implicitly build every file in the directory. You must explicitly register modules in the root file (`main.rs` or `lib.rs`) using `mod filename;`.

---

### 3. Over-Exposing Internal Details
Marking every single function and field `pub` to avoid compiler privacy errors.

*Why it's dangerous*: Exposing internals makes refactoring impossible without breaking downstream code and allows callers to bypass safety invariants.

## Exercises

### Exercise 1 (Encapsulated Database Client)
Create a module `database` with:
1. A private constant `MAX_CONNECTIONS: u32 = 50`.
2. A public struct `Client` with a private field `connection_count: u32`.
3. A public constructor `Client::new() -> Client` initializing `connection_count` to `0`.
4. A public method `connect(&mut self) -> Result<(), String>` that increments `connection_count` up to `MAX_CONNECTIONS` or returns `Err("Pool full")`.

Test calling `Client::new()` and `connect()` from `main()`.

---

### Exercise 2 (Using `super::` in Nested Modules)
Define a module `network` containing:
- A private function `log_internal(msg: &str)`.
- A public sub-module `http` containing a public function `send_response()` that calls `log_internal` using `super::`.

---

### Exercise 3 (Refactoring Paths with `use`)
Given the path `crate::storage::engine::btree::BTreeIndex`, write a `use` statement that brings `BTreeIndex` into scope, and an aliased `use` statement that brings it in as `Index`.

---

## Solutions

### Solution to Exercise 1
```rust
mod database {
    const MAX_CONNECTIONS: u32 = 50;

    pub struct Client {
        connection_count: u32,
    }

    impl Client {
        pub fn new() -> Client {
            Client { connection_count: 0 }
        }

        pub fn connect(&mut self) -> Result<(), String> {
            if self.connection_count < MAX_CONNECTIONS {
                self.connection_count += 1;
                Ok(())
            } else {
                Err(String::from("Pool full"))
            }
        }

        pub fn active_count(&self) -> u32 {
            self.connection_count
        }
    }
}

use database::Client;

fn main() {
    let mut db = Client::new();
    db.connect().unwrap();
    println!("Active DB connections: {}", db.active_count());
}
```

---

### Solution to Exercise 2
```rust
mod network {
    fn log_internal(msg: &str) {
        println!("[NETWORK LOG] {}", msg);
    }

    pub mod http {
        pub fn send_response() {
            super::log_internal("HTTP/1.1 200 OK transmitted");
        }
    }
}

use network::http;

fn main() {
    http::send_response();
}
```

---

### Solution to Exercise 3
```rust
// Standard import:
use crate::storage::engine::btree::BTreeIndex;

// Aliased import with `as`:
use crate::storage::engine::btree::BTreeIndex as Index;
```
