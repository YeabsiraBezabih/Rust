# Lesson 1.10: Robust Error Propagation: The `?` Operator and Custom Errors

## Prerequisites
- Lesson 1.7: Enums and Algebraic Data Types (variants and rich payloads).

## Concept

In real systems, operations rarely consist of a single step. An HTTP request parser must:
1. Read bytes from a TCP stream.
2. Parse the HTTP method string.
3. Extract the URI path.
4. Parse the `Content-Length` header integer.
5. Decode the JSON body.

If any single step fails, the entire operation must abort and return the error to the caller. 

Handling this with nested `match` statements produces deeply indented, unreadable code (the "Pyramid of Doom"):

```rust
// The Tedious Way (Pyramid of Doom):
match read_stream() {
    Ok(raw) => match parse_method(raw) {
        Ok(method) => match parse_port(method) {
            Ok(port) => Ok(port),
            Err(e) => Err(e),
        },
        Err(e) => Err(e),
    },
    Err(e) => Err(e),
}
```

Rust eliminates this boilerplate with the **`?` (Question Mark) Operator** and **Custom Error Enums**.

---

### 1. The `?` Operator

When placed after an expression that returns a `Result`:
- If the expression evaluates to **`Ok(value)`**, the `?` operator unwraps it and produces the inner `value`, continuing execution on the same line.
- If the expression evaluates to **`Err(error)`**, the `?` operator **immediately returns early** from the current function with `Err(error)`.

```rust
// The Idiomatic Rust Way with `?`:
fn process_request() -> Result<u16, String> {
    let raw = read_stream()?;      // If Err, returns early!
    let method = parse_method(raw)?; // If Err, returns early!
    let port = parse_port(method)?;  // If Err, returns early!
    Ok(port)
}
```

> **Mandatory Rule**: You can only use the `?` operator inside a function whose return type is compatible with `Result` (or `Option`).

---

### 2. Domain-Specific Custom Errors with Enums

In professional systems code, you should avoid using raw text strings (`Result<T, String>`) for errors. Strings cannot be matched programmatically, waste heap memory, and are error-prone.

Instead, define a custom **Error Enum** representing every possible failure mode in your subsystem:

```rust
#[derive(Debug)]
enum HttpParseError {
    EmptyPayload,
    InvalidMethod(String),
    MalformedPort(String),
    MissingHeader(&'static str),
}
```

Now, the caller can inspect the exact variant and take appropriate action (e.g., responding with a `400 Bad Request` vs. a `500 Internal Server Error`).

---

## Why it matters

In an HTTP web framework or AI agent pipeline, errors are normal operating conditions (client disconnects, malformed headers, invalid JSON, rate limits). 

Using the `?` operator with custom error enums allows you to write clean, linear business logic that is 100% resilient. Every error is typed, captured, and propagated to the top-level error middleware with zero boilerplate and zero risk of uncaught exceptions.

---

## Analogy

Think of an **Automated Factory Assembly Line with Station E-Stops**:
- A car frame moves down the conveyor through Station 1 (Engine), Station 2 (Wheels), and Station 3 (Brakes).
- At each station, the robotic arm uses the **`?` sensor**.
- If Station 1 installs the engine successfully (`Ok`), the car moves instantly to Station 2.
- If the engine mount is defective (`Err`), the `?` sensor immediately diverts the entire chassis off the main line into the QA diagnostic bay (`early return`), tagging it with the exact fault code (`HttpParseError::EngineMountDefect`).

## Code Example

```rust
#[derive(Debug)]
enum HttpRequestError {
    EmptyRequest,
    UnsupportedMethod(String),
    InvalidPortNumber(String),
}

struct ParsedRequest {
    method: String,
    port: u16,
}

// Sub-step 1: Validating the HTTP Method
fn validate_method(raw_method: &str) -> Result<String, HttpRequestError> {
    match raw_method.to_uppercase().as_str() {
        "GET" | "POST" | "PUT" | "DELETE" => Ok(raw_method.to_uppercase()),
        _ => Err(HttpRequestError::UnsupportedMethod(raw_method.to_string())),
    }
}

// Sub-step 2: Parsing the Port Number
fn parse_port(raw_port: &str) -> Result<u16, HttpRequestError> {
    raw_port
        .parse::<u16>()
        .map_err(|_| HttpRequestError::InvalidPortNumber(raw_port.to_string()))
}

// Main Pipeline: Composing sub-steps seamlessly with `?`
fn parse_http_header_line(raw_line: &str) -> Result<ParsedRequest, HttpRequestError> {
    let mut tokens = raw_line.split_whitespace();

    // 1. Extract method token or return early if empty
    let method_token = tokens.next().ok_or(HttpRequestError::EmptyRequest)?;

    // 2. Validate method with `?`
    let method = validate_method(method_token)?;

    // 3. Extract port token or return early if missing
    let port_token = tokens.next().ok_or(HttpRequestError::EmptyRequest)?;

    // 4. Parse port with `?`
    let port = parse_port(port_token)?;

    // If all steps succeeded, construct and return the parsed struct
    Ok(ParsedRequest { method, port })
}

fn main() {
    let valid_input = "GET 8080";
    let invalid_method = "PATCH 8080";
    let invalid_port = "POST 99999";

    let test_inputs = [valid_input, invalid_method, invalid_port, ""];

    for input in test_inputs {
        println!("\nParsing: '{}'", input);
        match parse_http_header_line(input) {
            Ok(req) => println!("  Success -> Method: {}, Port: {}", req.method, req.port),
            Err(HttpRequestError::EmptyRequest) => println!("  Rejected: Request line was empty."),
            Err(HttpRequestError::UnsupportedMethod(m)) => println!("  Rejected: Method '{}' not allowed (405 Method Not Allowed).", m),
            Err(HttpRequestError::InvalidPortNumber(p)) => println!("  Rejected: '{}' is not a valid 16-bit port.", p),
        }
    }
}
```

## Common Mistakes

### 1. Using `?` in a Function Returning `()` (Void)
The `?` operator requires the enclosing function to return a `Result` or `Option`.

**Broken Code:**
```rust
fn main() {
    let port: Result<u16, _> = "8080".parse();
    let p = port?; // Error: `main` returns `()`, cannot return `Result`!
}
```

**Compiler Output:**
```text
error[E0277]: the `?` operator can only be used in a function that returns `Result` or `Option`
 --> src/main.rs:3:17
  |
1 | fn main() {
  | --------- this function should return `Result` or `Option` to accept `?`
2 |     let port: Result<u16, _> = "8080".parse();
3 |     let p = port?;
  |                 ^ cannot use the `?` operator in a function that returns `()`
```
*How to fix*: Either handle the error explicitly with `match`, or change `main` to `fn main() -> Result<(), Box<dyn std::error::Error>>`.

---

### 2. Mismatched Error Types
Using `?` on a function that returns `Result<T, ErrorA>` inside a function that returns `Result<T, ErrorB>` without converting the error.

---

### 3. Ignoring Error Payloads
Defining error enums without inner diagnostic data (e.g., `InvalidPort` instead of `InvalidPort(String)`), making it impossible to log what input caused the failure.

Refactor the following nested function to use the `?` operator:

```rust
fn calculate_density(mass_str: &str, volume_str: &str) -> Result<f64, String> {
    match mass_str.parse::<f64>() {
        Ok(mass) => match volume_str.parse::<f64>() {
            Ok(volume) => {
                if volume == 0.0 {
                    Err(String::from("Volume cannot be zero"))

                    Ok(mass / volume)
                }
            }
            Err(_) => Err(String::from("Failed to parse volume")),
        },
        Err(_) => Err(String::from("Failed to parse mass")),
    }
}
```

## Solutions

### Solution to Exercise 1
```rust
fn calculate_density(mass_str: &str, volume_str: &str) -> Result<f64, String> {
    let mass = mass_str.parse::<f64>().map_err(|_| String::from("Failed to parse mass"))?;
    let volume = volume_str.parse::<f64>().map_err(|_| String::from("Failed to parse volume"))?;

    if volume == 0.0 {
        return Err(String::from("Volume cannot be zero"));
    }

    Ok(mass / volume)
}

fn main() {
    println!("Density: {:?}", calculate_density("100.0", "20.0"));
    println!("Error: {:?}", calculate_density("invalid", "20.0"));
}
```

---

### Solution to Exercise 2
```rust
#[derive(Debug)]
enum DatabaseBootError {
    PortAlreadyInUse(u16),
    MissingConfigFile(String),
    AccessDenied,
}

fn validate_boot_config(port: u16, config_file: &str) -> Result<(), DatabaseBootError> {
    if port == 80 {
        return Err(DatabaseBootError::PortAlreadyInUse(port));
    }

    if config_file.is_empty() {
        return Err(DatabaseBootError::MissingConfigFile(String::from("Config path was empty")));
    }

    Ok(())
}

fn main() {
    match validate_boot_config(80, "db.conf") {
        Ok(_) => println!("Boot config valid!"),
        Err(e) => println!("Boot check failed: {:?}", e),
    }
}
```

### Solution to Exercise 3
```rust
fn parse_hex_byte(hex_str: &str) -> Result<u8, String> {
    let byte = u8::from_str_radix(hex_str, 16)
        .map_err(|_| format!("'{}' is not valid hexadecimal", hex_str))?;
    Ok(byte)
}

fn main() {
    let tests = ["FF", "1A", "ZZ"];
    for t in tests {
        match parse_hex_byte(t) {
            Ok(val) => println!("Hex '{}' -> Decimal {}", t, val),
            Err(e) => println!("Error: {}", e),
        }
    }
}
```
