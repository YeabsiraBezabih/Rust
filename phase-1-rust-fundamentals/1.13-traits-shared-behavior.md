# Lesson 1.13: Traits: Defining Shared Behavior

## Prerequisites
- Lesson 1.6: Structs: Custom Data Structures and Methods (`impl` blocks and methods).
- Lesson 1.8: Pattern Matching with `match` and `if let`.

---

## Concept

Many programming languages use classical Object-Oriented "Classes and Inheritance" (`class Dog extends Animal`) to share behavior. 

**Rust does not have classes or inheritance.** Instead, Rust uses **Traits** to define shared behavior across different types.

---

### 1. What is a Trait?

A **Trait** is an abstract contract: a collection of method signatures that define a specific capability. Any struct or enum can implement that trait by providing concrete code for those methods.

```
                  ┌────────────────────────────────────────┐
                  │            trait Loggable              │
                  │   fn format_log(&self) -> String;      │
                  └───────────────────┬────────────────────┘
                                      │
                 ┌────────────────────┴────────────────────┐
                 ▼                                         ▼
    ┌──────────────────────────┐              ┌──────────────────────────┐
    │   impl Loggable for      │              │   impl Loggable for      │
    │      HttpRequest         │              │      DatabaseQuery       │
    └──────────────────────────┘              └──────────────────────────┘
```

#### Defining a Trait:
```rust
trait Summary {
    fn summarize(&self) -> String;
}
```

#### Implementing a Trait for a Struct:
```rust
struct Article {
    headline: String,
    author: String,
}

impl Summary for Article {
    fn summarize(&self) -> String {
        format!("'{}' by {}", self.headline, self.author)
    }
}
```

---

### 2. Default Method Implementations

A trait can provide a default implementation. Types implementing the trait can either keep the default behavior or override it:

```rust
trait HealthCheck {
    // Default implementation
    fn is_healthy(&self) -> bool {
        true
    }
}
```

---

### 3. Traits as Function Parameters (`impl Trait`)

You can write functions that accept **any type that implements a specific trait**, without caring what the concrete struct is:

```rust
fn print_summary(item: &impl Summary) {
    println!("Summary: {}", item.summarize());
}
```

---

### 4. Essential Standard Library Traits

Rust provides several standard traits that give your types powerful capabilities:

| Trait | What it Enables | Common Usage |
| :--- | :--- | :--- |
| **`std::fmt::Debug`** | Formats data for developers using `{:?}`. | `#[derive(Debug)]` |
| **`std::fmt::Display`** | Formats data for end-users using `{}`. | Implemented manually via `impl Display for ...` |
| **`Clone` / `Copy`** | Explicit duplication (`.clone()`) and implicit stack copying. | `#[derive(Clone, Copy)]` |
| **`Default`** | Provides a standard default initialization (`Type::default()`). | `#[derive(Default)]` |
| **`PartialEq`** | Enables equality checks with `==` and `!=`. | `#[derive(PartialEq)]` |

---

## Why it matters

In backend architecture and networking systems, components must interact polymorphically. 

An HTTP response dispatcher does not need to know whether the response body is a `JsonPayload`, an `HtmlTemplate`, or a `RawStream`—as long as the type implements `ToHttpBytes`, the server can serialize and transmit it over a TCP socket. Traits give you clean decoupling with **zero runtime overhead** (resolved at compile time).

---

## Analogy

Think of a universal **USB-C Specification**:
- The **Trait** is the USB-C standard: "Any device connecting here must support 5-volt power delivery and high-speed data transfer."
- The **Structs** are a Flash Drive, a Mouse, and an External Monitor. They have completely different internal hardware, but all three implement the USB-C trait.
- Your Laptop (a function taking `&impl UsbDevice`) can talk to any of them through the unified port.

## Code Example

```rust
use std::fmt;

// 1. Defining a custom trait for payload serialization
trait SerializablePayload {
    // Required method: Every implementing struct must provide this
    fn to_wire_bytes(&self) -> Vec<u8>;

    // Default method: Can be used as-is or overridden
    fn byte_size(&self) -> usize {
        self.to_wire_bytes().len()
    }
}

// 2. Struct A: Plain Text Response
struct TextResponse {
    body: String,
}

impl SerializablePayload for TextResponse {
    fn to_wire_bytes(&self) -> Vec<u8> {
        self.body.as_bytes().to_vec()
    }
}

// 3. Struct B: JSON Response
struct JsonResponse {
    json_data: String,
}

impl SerializablePayload for JsonResponse {
    fn to_wire_bytes(&self) -> Vec<u8> {
        format!("{{\"data\": \"{}\"}}", self.json_data).into_bytes()
    }
}

// 4. Implementing `Display` so `TextResponse` can be printed with `{}`
impl fmt::Display for TextResponse {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "TextResponse: '{}'", self.body)
    }
}

// 5. Polymorphic function: Accepts ANY type that implements `SerializablePayload`
fn transmit_over_network(payload: &impl SerializablePayload) {
    let raw_bytes = payload.to_wire_bytes();
    println!("Transmitting {} bytes over TCP socket: {:?}", payload.byte_size(), raw_bytes);
}

fn main() {
    let text_res = TextResponse {
        body: String::from("Hello Server"),
    };

    let json_res = JsonResponse {
        json_data: String::from("user_id_42"),
    };

    // Printing using `Display` implementation ({})
    println!("{}", text_res);

    // Calling polymorphic function with two different types
    println!("\nTransmitting text response:");
    transmit_over_network(&text_res);

    println!("\nTransmitting JSON response:");
    transmit_over_network(&json_res);
}
```

## Common Mistakes

### 1. Forgetting to Import Traits Before Using Their Methods
If a trait is defined in another module or external crate, you **must bring the trait into scope** with `use TraitName;` before you can call its methods on a struct.

---

### 2. Attempting to Put Field Definitions in a Trait
Traits can only define method signatures, associated constants, and default method bodies—they **cannot declare fields**.

**Broken Code:**
```rust
trait NetworkDevice {
    mac_address: String, // Error: traits cannot have fields!
}
```
*How to fix*: Define a method `fn mac_address(&self) -> &str;` in the trait instead.

---

### 3. Confusing `Display` with `Debug`
Trying to print a struct with `{}` when only `#[derive(Debug)]` was added. `Display` is for end-user text formatting and must be implemented manually with `impl fmt::Display`.

## Exercises

### Exercise 1 (Custom Rendering Trait)
Define a trait named `RenderHtml` with a required method:
```rust
fn render(&self) -> String;
```
Create a struct `ArticleHeader { title: String, author: String }` and implement `RenderHtml` for it so that `render()` produces:
```html
<h1>Title</h1><p>By Author</p>
```

---

### Exercise 2 (Default Trait Methods)
Add a default method `fn is_empty(&self) -> bool` to `RenderHtml` that returns `true` if `self.render().is_empty()` and `false` otherwise. Demonstrate calling `is_empty()` in `main()`.

---

### Exercise 3 (Implementing `Display`)
Define a struct `SocketAddrV4 { ip: [u8; 4], port: u16 }`.
Implement the `std::fmt::Display` trait for `SocketAddrV4` so that `println!("{}", socket)` prints:
```text
127.0.0.1:8080
```

## Solutions

### Solution to Exercise 1 & 2
```rust
trait RenderHtml {
    fn render(&self) -> String;

    // Default method implementation
    fn is_empty(&self) -> bool {
        self.render().is_empty()
    }
}

struct ArticleHeader {
    title: String,
    author: String,
}

impl RenderHtml for ArticleHeader {
    fn render(&self) -> String {
        format!("<h1>{}</h1><p>By {}</p>", self.title, self.author)
    }
}

fn main() {
    let header = ArticleHeader {
        title: String::from("Systems Architecture in Rust"),
        author: String::from("Alice"),
    };

    println!("Rendered: {}", header.render());
    println!("Is Empty: {}", header.is_empty());
}
```

---

### Solution to Exercise 3
```rust
use std::fmt;

struct SocketAddrV4 {
    ip: [u8; 4],
    port: u16,
}

impl fmt::Display for SocketAddrV4 {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(
            f,
            "{}.{}.{}.{}:{}",
            self.ip[0], self.ip[1], self.ip[2], self.ip[3], self.port
        )
    }
}

fn main() {
    let socket = SocketAddrV4 {
        ip: [127, 0, 0, 1],
        port: 8080,
    };

    println!("Formatted Socket: {}", socket);
}
```
