# Lesson 1.14: Generics: Writing Type-Agnostic, Zero-Cost Abstractions

## Concept

When writing software, you often need to implement the exact same logic for multiple data types. For example, a queue data structure or an HTTP response wrapper should work whether it holds an integer, a string, or a custom user profile struct.

Instead of writing separate duplicate structs (`IntResponse`, `StringResponse`, `UserResponse`), Rust provides **Generics**—abstract placeholders for concrete types.

---

### 1. Generic Functions, Structs, and Enums

Generics are declared using angle brackets (`<T>`), where `T` is a conventional placeholder name for "Type".

#### A. Generic Functions:
```rust
fn get_first_element<T>(list: &[T]) -> Option<&T> {
    list.first()
}
```

#### B. Generic Structs:
```rust
struct ApiEnvelope<T> {
    request_id: u64,
    status_code: u16,
    payload: T, // Can be any type
}
```

#### C. Generic `impl` Blocks:
When defining methods on a generic struct, you must declare `<T>` right after `impl` so the compiler knows `T` is a generic parameter rather than a concrete type name:

```rust
impl<T> ApiEnvelope<T> {
    fn new(request_id: u64, status_code: u16, payload: T) -> ApiEnvelope<T> {
        ApiEnvelope { request_id, status_code, payload }
    }
}
```

---

### 2. Trait Bounds: Constraining Generics

By default, a generic parameter `T` can be *any* type in existence. Because the compiler does not know what `T` is, it will not allow you to print `T`, compare `T`, or perform arithmetic on `T`.

To use specific capabilities on a generic type, you apply a **Trait Bound** (`<T: TraitName>`):

```rust
// Only types that implement `std::fmt::Display` can be passed to this function:
fn print_response<T: std::fmt::Display>(res: &ApiEnvelope<T>) {
    println!("[ID: {}] Payload: {}", res.request_id, res.payload);
}
```

#### Multiple Trait Bounds and the `where` Clause:
When functions have multiple generic types with multiple bounds, you can use a `where` clause to keep the signature clean:

```rust
fn transmit_and_log<T, E>(data: T, error: E) 
where
    T: std::fmt::Display + Clone,
    E: std::fmt::Debug,
{
    // ...
}
```

---

### 3. Zero-Cost Abstraction: Monomorphization

In many languages (like Java), generics use "type erasure" and runtime reflection, adding CPU and memory overhead.

In Rust, generics have **zero runtime cost**. During compilation, Rust performs **Monomorphization**:
1. The compiler analyzes your code and identifies every concrete type used with the generic (e.g., `ApiEnvelope<String>` and `ApiEnvelope<u32>`).
2. It generates specialized, dedicated machine code for each concrete type.
3. The resulting binary runs at the exact same native speed as if you had written separate hand-crafted structs for each type.

```
Source Code: ApiEnvelope<T>
                   │ (Compile Time: Monomorphization)
       ┌───────────┴───────────┐
       ▼                       ▼
Machine Binary:         Machine Binary:
ApiEnvelope_String      ApiEnvelope_u32
(No runtime overhead)   (No runtime overhead)
```

---

## Why it matters

In web frameworks (like Axum or Actix) and AI agent execution runtimes, generic wrappers like `Json<T>`, `Query<T>`, and `State<T>` allow users to deserialize arbitrary data models with type safety. 

Because of monomorphization, your high-throughput HTTP server processes generic types with zero virtual table lookups, zero pointer boxing, and maximum CPU cache efficiency.

---

## Analogy

Think of a **Precision CNC Tooling Machine**:
- The generic blueprint (`<T>`) describes how to manufacture a protective equipment case for any item.
- When the factory sets the machine to make cases for smartphones (`T = Smartphone`), the CNC machine cuts solid aluminum to fit smartphones down to the millimeter.
- When set for laptops (`T = Laptop`), it cuts solid aluminum for laptops.
- In the end, there is no generic, loose, one-size-fits-all sack with extra padding; every finished product is custom-machined for its exact purpose with zero wasted space.

## Code Example

```rust
use std::fmt::{Debug, Display};

// 1. Generic Struct modeling a standardized API response container
#[derive(Debug)]
struct ApiResponse<T> {
    trace_id: u64,
    status: u16,
    data: T, // Generic data payload
}

// 2. Generic implementation block for all types T
impl<T> ApiResponse<T> {
    fn new(trace_id: u64, status: u16, data: T) -> ApiResponse<T> {
        ApiResponse { trace_id, status, data }
    }
}

// 3. Conditional Implementation: Methods available ONLY when T implements `Display`
impl<T: Display> ApiResponse<T> {
    fn display_summary(&self) {
        println!("[Trace: {}] Status {}: {}", self.trace_id, self.status, self.data);
    }
}

// 4. Generic function using a `where` clause
fn audit_and_compare<T>(expected: &T, actual: &T) -> bool
where
    T: PartialEq + Debug,
{
    if expected == actual {
        println!("Audit Passed: Values match ({:?})", expected);
        true
    } else {
        println!("Audit FAILED: Expected {:?}, found {:?}", expected, actual);
        false
    }
}

fn main() {
    println!("--- 1. Instantiating Generic Structs ---");

    // Case A: ApiResponse holding a String
    let string_res = ApiResponse::new(
        1001, 
        200, 
        String::from("Session successfully created")
    );
    string_res.display_summary();

    // Case B: ApiResponse holding an integer payload
    let metric_res = ApiResponse::new(1002, 200, 48500u32);
    metric_res.display_summary();

    // Case C: ApiResponse holding a vector (Vec does not implement Display, but implements Debug)
    let list_res = ApiResponse::new(1003, 200, vec!["us-east", "eu-central"]);
    println!("Vector response debug: {:?}", list_res);

    println!("\n--- 2. Generic Function with Trait Bounds ---");
    let target_status = 200;
    let current_status = 200;
    audit_and_compare(&target_status, &current_status);

    let expected_hash = "0xABC";
    let received_hash = "0xXYZ";
    audit_and_compare(&expected_hash, &received_hash);
}
```

## Common Mistakes

### 1. Forgetting `<T>` on the `impl` Header
Writing `impl ApiResponse<T>` instead of `impl<T> ApiResponse<T>`.

**Broken Code:**
```rust
struct Container<T> { value: T }

impl Container<T> { // Error: `T` is not in scope!
    fn get(&self) -> &T { &self.value }
}
```

**Compiler Output:**
```text
error[E0412]: cannot find type `T` in this scope
 --> src/main.rs:3:16
  |
3 | impl Container<T> {
  |      --------- ^ not found in this scope
  |      |
  |      help: add generic type parameter: `<T>`
```

---

### 2. Calling Methods Without the Required Trait Bound
Trying to compare `a == b` inside a generic function without `T: PartialEq`.

**Broken Code:**
```rust
fn is_same<T>(a: T, b: T) -> bool {
    a == b // Error: binary operation `==` cannot be applied to type `T`!
}
```
*How to fix*: Add the trait bound `fn is_same<T: PartialEq>(a: T, b: T) -> bool`.

## Solutions

### Solution to Exercise 1
```rust
struct Pair<T> {
    first: T,
    second: T,
}

impl<T> Pair<T> {
    fn new(first: T, second: T) -> Pair<T> {
        Pair { first, second }
    }

    fn swap(&mut self) {
        std::mem::swap(&mut self.first, &mut self.second);
    }
}

fn main() {
    let mut num_pair = Pair::new(10, 20);
    println!("Before: ({}, {})", num_pair.first, num_pair.second);
    num_pair.swap();
    println!("After:  ({}, {})", num_pair.first, num_pair.second);

    let mut str_pair = Pair::new("alpha", "omega");
    str_pair.swap();
    println!("Swapped strings: ({}, {})", str_pair.first, str_pair.second);
}
```

---

### Solution to Exercise 2
```rust
fn find_min<T: PartialOrd + Copy>(a: T, b: T) -> T {
    if a < b {
        a
    } else {
        b
    }
}

fn main() {
    println!("Min int: {}", find_min(10, 5));
    println!("Min float: {}", find_min(3.14, 1.59));
}
```

---

### Solution to Exercise 3
```rust
fn sync_state<T, E>(source: &T, target: &mut T, err: E) -> Result<(), E>
where
    T: std::fmt::Debug + Clone + PartialEq,
    E: std::fmt::Display + std::fmt::Debug,
{
    if source == target {
        Ok(())
    } else {
        *target = source.clone();
        println!("State updated: {:?}", target);
        Ok(())
    }
}

fn main() {
    let mut current = 10;
    let target = 20;
    sync_state(&target, &mut current, "SyncError").unwrap();
}
```
