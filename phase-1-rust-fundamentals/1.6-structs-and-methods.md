## Concept

While tuples allow you to group multiple types together, they become confusing when you have many fields because elements are accessed only by index (`tuple.0`, `tuple.1`).

A **Struct** (short for *structure*) is a custom data type that allows you to bundle and name multiple related values into a single meaningful unit.

---

### 1. Defining and Instantiating Structs

To define a struct, use the `struct` keyword, name the type in `PascalCase`, and list its **fields** with explicit types:

```rust
struct HttpRequest {
    method: String,
    path: String,
    port: u16,
    is_tls: bool,
}
```

To create an instance, provide concrete values for every field inside curly braces:

```rust
let request = HttpRequest {
    method: String::from("GET"),
    path: String::from("/api/v1/health"),
    port: 443,
    is_tls: true,
};
```

Access or modify fields using dot notation (`request.path`). If an instance is mutable (`let mut request = ...`), you can modify its fields directly.

---

### 2. Methods and the `impl` Block

In Rust, data and behavior are defined separately:
- The `struct` defines the **shape of the data**.
- An `impl` (implementation) block defines the **methods and functions associated with that struct**.

```
┌────────────────────────────────────────────────────────┐
│ struct HttpRequest                                     │
│   - method: String                                     │
│   - path: String                                       │
│   - port: u16                                          │
└───────────────────────────┬────────────────────────────┘
                            │
               ┌────────────┴────────────┐
               ▼                         ▼
    ┌──────────────────────┐  ┌──────────────────────┐
    │ Associated Functions │  │       Methods        │
    │ (Constructors)       │  │ (&self, &mut self)   │
    │ HttpRequest::new()   │  │ request.summary()    │
    └──────────────────────┘  └──────────────────────┘
```

#### The Three Flavors of `self`:
Methods are functions called on an instance using dot notation (`request.summary()`). The first parameter of a method is always some form of `self`:

1. **`&self` (Shared Borrow)**: Reads fields from the struct without modifying or consuming it. (Most common).
2. **`&mut self` (Mutable Borrow)**: Modifies fields inside the struct in-place.
3. **`self` (Value / Ownership Move)**: Consumes the struct, moving ownership into the method. The caller can never use the struct again. Useful for transforming one type into another (e.g., converting a `Request` into a `Response`).

#### Associated Functions (Constructors):
Functions defined inside an `impl` block that **do not take `self`** are called **associated functions**. They are typically used as constructors (often named `new`) and called using double-colons (`::`):

```rust
impl HttpRequest {
    // Associated function (constructor)
    fn new(method: String, path: String, port: u16) -> HttpRequest {
        HttpRequest {
            method,
            path,
            port,
            is_tls: port == 443,
        }
    }
}
```

---

### 3. Other Struct Flavors

1. **Tuple Structs**: Structs with named types but numbered fields (used for creating distinct types, known as the *Newtype Pattern*):
   ```rust
   struct Ipv4Address(u8, u8, u8, u8);
   let localhost = Ipv4Address(127, 0, 0, 1);
   ```
2. **Unit-Like Structs**: Structs with no fields at all (`struct DatabaseClosed;`), useful for state-machine tokens and markers.

---

## Why it matters

In backend architecture and networking systems, domain data must be rigorously structured. You cannot build a reliable HTTP engine by passing loose strings and port integers across dozens of functions. 

Structs encapsulate validation logic, guarantee that an `HttpRequest` is always structurally valid, and attach methods directly to the data, ensuring clean abstractions with zero runtime performance cost.

## Analogy

Think of a **Passport**:
- The **Struct Definition** is the blank template created by the government (Name field, Passport Number field, Expiration Date field).
- An **Instance** is your issued physical passport containing your actual information.
- Methods:
  - `&self` (Inspect): The airline gate agent looks at your photo to verify your identity.
  - `&mut self` (Modify): The customs officer stamps an entry visa onto page 4.
  - `self` (Consume/Surrender): The government shreds your expired passport and issues a replacement.

## Code Example

```rust
// Adding `#[derive(Debug)]` allows printing the struct with `{:?}`
#[derive(Debug)]
struct NetworkEndpoint {
    host: String,
    port: u16,
    active_connections: u32,
}

impl NetworkEndpoint {
    // 1. Associated Function / Constructor (called via NetworkEndpoint::new)
    fn new(host: String, port: u16) -> NetworkEndpoint {
        NetworkEndpoint {
            host,
            port,
            active_connections: 0,
        }
    }

    // 2. Method borrowing &self (Read-Only)
    fn connection_string(&self) -> String {
        format!("{}:{}", self.host, self.port)
    }

    // 3. Method borrowing &mut self (In-Place Mutation)
    fn register_connection(&mut self) {
        self.active_connections += 1;
        println!("Connection registered to {}. Total: {}", self.connection_string(), self.active_connections);
    }

    // 4. Method taking `self` by value (Consuming the struct)
    fn decommission(self) {
        println!("Decommissioning endpoint {} with {} active connections...", self.connection_string(), self.active_connections);
        // `self` is dropped here, freeing all associated memory!
    }
}

fn main() {
    // Using the constructor
    let mut gateway = NetworkEndpoint::new(String::from("api.gateway.internal"), 8080);

    // Calling a read-only method (&self)
    println!("Endpoint Target: {}", gateway.connection_string());

    // Calling a mutating method (&mut self)
    gateway.register_connection();
    gateway.register_connection();

    // Calling a consuming method (self)
    gateway.decommission();

    // UNCOMMENTING THE LINE BELOW CAUSES A COMPILE ERROR (use after move):
    // println!("Gateway info: {:?}", gateway);
}
```

---

## Common Mistakes

### 1. Calling an `&mut self` Method on an Immutable Struct Instance
If a struct variable was created with `let` instead of `let mut`, you cannot call mutating methods on it.

**Broken Code:**
```rust
let endpoint = NetworkEndpoint::new(String::from("localhost"), 80);
endpoint.register_connection(); // Error: cannot borrow `endpoint` as mutable!
```

---

### 2. Forgetting `&self` in Method Signatures
Omitting `&self` makes the function an associated function, meaning it cannot be called with dot syntax (`instance.method()`).

**Broken Code:**
```rust
impl NetworkEndpoint {
    fn get_port() -> u16 { // Missing `&self`!
        self.port           // Error: cannot use `self`
    }
}
```

---

### 3. Using an Instance After Calling a Consuming Method (`self`)
Calling a method that takes `self` transfers ownership. Attempting to use the struct afterward triggers a borrow-after-move error.

## Exercises

### Exercise 1 (Defining a Server Struct)
Define a struct named `HttpServerConfig` with the following fields:
- `host: String`
- `port: u16`
- `max_connections: u32`
- `enable_tls: bool`

Create an instance of this struct in `main()` representing a local TLS server on port `8443` with a limit of `5000` connections, and print its fields.

---

### Exercise 2 (Implementing Methods)
Add an `impl` block to `HttpServerConfig` with:
1. A constructor `new(host: String, port: u16) -> HttpServerConfig` that sets `max_connections` to `1000` and `enable_tls` to `true` if `port == 443` or `port == 8443`, and `false` otherwise.
2. A method `summary(&self) -> String` that returns a formatted string like `"https://0.0.0.0:8443 (Max: 1000)"`.

---

### Exercise 3 (A Consuming State Transition)
Create a struct `UnverifiedToken { raw_token: String }` and a struct `VerifiedToken { user_id: u64 }`.
Write a method `verify(self) -> VerifiedToken` on `UnverifiedToken` that consumes the unverified token and returns a `VerifiedToken` with `user_id = 42`. Demonstrate in `main()` that the unverified token cannot be used after verification.

## Solutions

### Solution to Exercise 1
```rust
struct HttpServerConfig {
    host: String,
    port: u16,
    max_connections: u32,
    enable_tls: bool,
}

fn main() {
    let config = HttpServerConfig {
        host: String::from("127.0.0.1"),
        port: 8443,
        max_connections: 5000,
        enable_tls: true,
    };

    println!("Host: {}, Port: {}, Max: {}, TLS: {}", config.host, config.port, config.max_connections, config.enable_tls);
}
```

---

### Solution to Exercise 2
```rust
struct HttpServerConfig {
    host: String,
    port: u16,
    max_connections: u32,
    enable_tls: bool,
}

impl HttpServerConfig {
    fn new(host: String, port: u16) -> HttpServerConfig {
        let enable_tls = port == 443 || port == 8443;
        HttpServerConfig {
            host,
            port,
            max_connections: 1000,
            enable_tls,
        }
    }

    fn summary(&self) -> String {
        let protocol = if self.enable_tls { "https" } else { "http" };
        format!("{}://{}:{} (Max: {})", protocol, self.host, self.port, self.max_connections)
    }
}

fn main() {
    let server = HttpServerConfig::new(String::from("0.0.0.0"), 8443);
    println!("Server Summary: {}", server.summary());
}
```

### Solution to Exercise 3
```rust
struct UnverifiedToken {
    raw_token: String,
}

struct VerifiedToken {
    user_id: u64,
}

impl UnverifiedToken {
    // Consumes `self` so the raw unverified token is permanently invalidated
    fn verify(self) -> VerifiedToken {
        println!("Verifying token '{}'...", self.raw_token);
        VerifiedToken { user_id: 42 }
    }
}

fn main() {
    let raw = UnverifiedToken { raw_token: String::from("bearer_abc123") };

    let session = raw.verify();
    println!("Verified User ID: {}", session.user_id);

    // `raw` cannot be accessed here because `verify` consumed it!
}
```
