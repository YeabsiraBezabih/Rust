## Concept

In Rust, managing how data changes over time is fundamental to program safety. Rust gives you three distinct tools for naming and modifying data: **Mutability (`mut`)**, **Constants (`const`)**, and **Variable Shadowing (`let`)**.

---

### 1. Mutability vs. Immutability

By default, all variables in Rust are immutable:
```rust
let active_connections = 5;
// active_connections = 6; // COMPILE ERROR: Cannot assign twice to immutable variable
```

To permit a variable's value to be modified in-place, you must explicitly declare it with `mut`:
```rust
let mut active_connections = 5;
active_connections = 6; // Valid
```

**Key Constraint**: Modifying a `mut` variable can change the **value**, but it **can never change the data type**:
```rust
let mut port = 8080;
// port = "8080"; // COMPILE ERROR: Expected integer, found &str
```

---

### 2. Constants (`const`)

A **constant** is a value bound to a name that can never change under any circumstance. 

Differences between `let` and `const`:
1. **Compile-Time Evaluation**: Constants are computed when the compiler builds the binary, not when the program runs.
2. **Mandatory Type Annotation**: You *must* explicitly state the type.
3. **Global Scope**: Constants can be declared outside of functions (in global/module scope).
4. **Naming Convention**: Always written in `SCREAMING_SNAKE_CASE`.

```rust
const MAX_BUFFER_SIZE_BYTES: usize = 4096;
```

---

### 3. Variable Shadowing

**Shadowing** occurs when you declare a *new* variable with the *same name* as a previous variable using the `let` keyword.

```rust
let request_limit = 100;
let request_limit = request_limit + 50; // Shadows the previous variable
```

```
┌────────────────────────────────────────────────────────┐
│ 1. let raw_port = "8080";     (&str)                   │
│ 2. let raw_port: u16 = 8080;  (u16 - Shadows line 1)   │
└────────────────────────────────────────────────────────┘
```

#### Shadowing vs. Mutability (`mut`):

| Feature | Mutability (`mut`) | Shadowing (`let`) |
| :--- | :--- | :--- |
| **How it works** | Reuses the *same* memory slot. | Creates a *brand-new* variable in memory. |
| **Can change type?** | ❌ No (type is permanently fixed). | ✅ Yes (new variable can have any type). |
| **Protection after edit** | Remains mutable. | Can lock the new variable as immutable. |

#### Shadowing in Nested Scopes:
When you shadow a variable inside an inner block `{ ... }`, the shadow only exists within that block. Once the block ends, the original outer variable re-emerges unchanged.

---

## Why it matters

In systems programming (such as HTTP request processing or packet deserialization), incoming data arrives in one format (e.g., raw ASCII text `"443"`) and must be converted through stages into a clean, typed representation (`u16`). 

Without shadowing, you would have to invent clunky, throwaway variable names (`port_str`, `port_trimmed`, `port_final`). With shadowing, you reuse the clean name `port` at each step, and once parsing is complete, the final variable is immutable—guaranteeing that downstream networking code cannot accidentally corrupt it.

---

## Analogy

- **Mutability (`mut`)**: An erasable whiteboard. You erase the number `5` and write `6` on the exact same surface. The whiteboard remains a whiteboard.
- **Shadowing (`let`)**: Placing a fresh sheet of paper on top of an existing one on a clipboard. The new sheet covers the old one completely and can contain completely different information (text instead of numbers). If you take off the temporary top sheet (exit an inner scope), the original sheet is still underneath.
- **Constant (`const`)**: A sign carved in granite before the building is even constructed.

## Code Example

```rust
// 1. Global Constant (computed at compile-time)
const DEFAULT_TIMEOUT_SECONDS: u32 = 30;
const SERVER_SIGNATURE: &str = "HyperRust/1.0";

fn main() {
    println!("Server Signature: {}", SERVER_SIGNATURE);
    println!("Default Timeout: {}s", DEFAULT_TIMEOUT_SECONDS);

    // 2. Data Transformation via Shadowing (changing types)
    // Step A: Raw string data received from a configuration file
    let port_setting = "  8080  ";

    // Step B: Shadowing with a trimmed string slice (same name, still &str)
    let port_setting = port_setting.trim();

    // Step C: Shadowing by converting the string to an unsigned integer (u16)
    // Note: `.parse::<u16>().unwrap()` converts text digits to a number
    let port_setting: u16 = port_setting.parse().unwrap();

    println!("Cleaned & Parsed Port: {}", port_setting);

    // 3. Scoped Shadowing
    let worker_threads = 4;
    println!("Outer worker threads: {}", worker_threads); // Prints 4

    {
        // Inner scope: Temporarily shadow `worker_threads`
        let worker_threads = worker_threads * 2;
        println!("Inner burst worker threads: {}", worker_threads); // Prints 8
    }

    // Outer scope re-emerges unchanged
    println!("Restored outer worker threads: {}", worker_threads); // Prints 4

    // 4. In-place Mutation with `mut` (same type only)
    let mut active_connections: u32 = 0;
    active_connections += 1;
    active_connections += 1;
    println!("Active connections: {}", active_connections);
}
```

## Common Mistakes

### 1. Attempting to Change Type via Mutation Instead of Shadowing
Beginners often forget the `let` keyword when trying to transform a variable into a new type.

**Broken Code:**
```rust
fn main() {
    let mut payload = "128";
    payload = 128; // Error: mismatched types!
}
```

**Compiler Output:**
```text
error[E0308]: mismatched types
 --> src/main.rs:3:15
  |
2 |     let mut payload = "128";
  |                       ----- expected due to this value
3 |     payload = 128;
  |               ^^^ expected `&str`, found integer
```
*How to fix*: Use `let payload: u32 = 128;` to declare a new shadowed variable.

---

### 2. Declaring `const` Without a Type Annotation
Unlike `let`, constants cannot rely on type inference.

**Broken Code:**
```rust
const MAX_RETRIES = 5; // Error!
```

**Compiler Output:**
```text
error: missing type for `const` item
 --> src/main.rs:1:18
  |
1 | const MAX_RETRIES = 5;
  |                  ^ help: provide a type for the item: `: i32`
```

---

### 3. Expecting Scoped Shadowing to Mutate the Outer Variable
Assuming an inner block's `let` permanently changes the outer variable.

**Broken Logic:**
```rust
fn main() {
    let timeout = 10;
    {
        let timeout = 60; // Only exists within this block!
    }
    println!("Timeout: {}", timeout); // Prints 10, NOT 60!
}
```

### Exercise 1 (Keyword Selection)
Choose whether each variable should be defined with `const`, `let`, `let mut`, or `let` (shadowing):
1. The mathematical constant $\pi$ ($3.14159$) used throughout an entire graphics engine.
2. A live counter tracking the number of active TCP connections as clients connect and disconnect.
3. An input string containing an IP address `"127.0.0.1"` that you trim and convert into a parsed network address.

What will this program print to the terminal? Trace the execution line by line:

```rust
fn main() {
    let buffer_size = 512;
    {
        let buffer_size = buffer_size * 2;
        println!("A: {}", buffer_size);
    }
    let buffer_size = buffer_size + 100;
    println!("B: {}", buffer_size);
}
```

---

### Exercise 3 (Writing a Metric Normalizer)
Write a complete Rust program that:
1. Declares a global constant `MAX_ALLOWED_CPU_PERCENT: f64 = 100.0`.
2. Inside `main()`, creates a variable `cpu_raw` containing `" 88.5% "`.
3. Uses shadowing with `let` to:
   - Trim whitespace and strip the `%` symbol (resulting in `"88.5"`).
   - Parse it into an `f64` number.
4. Prints the final parsed number and verifies it is less than `MAX_ALLOWED_CPU_PERCENT`.

---

## Solutions

### Solution to Exercise 1
1. `const` — Compile-time known, never changes, global.
2. `let mut` — The same memory slot is incremented and decremented at runtime.
3. `let` (shadowing) — Transforming representation and type while preserving immutability after parsing.

---

### Solution to Exercise 2
**Output:**
```text
A: 1024
B: 612
```
**Explanation**:
- Inside the inner block, `buffer_size` is shadowed to `512 * 2 = 1024` and printed.
- When the inner block ends, that shadow is destroyed. The outer `buffer_size` is still `512`.
- The next line shadows the outer `buffer_size` to `512 + 100 = 612` and prints it.

---

### Solution to Exercise 3
```rust
const MAX_ALLOWED_CPU_PERCENT: f64 = 100.0;

fn main() {
    let cpu_raw = " 88.5% ";

    // Shadowing step 1: Trim whitespace and remove '%'
    let cpu_raw = cpu_raw.trim().trim_end_matches('%');

    // Shadowing step 2: Convert to f64 float
    let cpu_raw: f64 = cpu_raw.parse().unwrap();

    println!("Parsed CPU Metric: {}%", cpu_raw);

    if cpu_raw <= MAX_ALLOWED_CPU_PERCENT {
        println!("CPU load within safe limits.");
    } else {
        println!("Warning: CPU load exceeds limit!");
    }
}
```
