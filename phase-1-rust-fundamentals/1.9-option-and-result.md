# Lesson 1.9: Handling Absence and Failure: `Option<T>` and `Result<T, E>`

## Concept

In most programming languages, variables can hold a special empty value called `null`, `nil`, or `None`. If you try to call a method on a `null` variable, the program crashes instantly (e.g., `NullPointerException` in Java, `Segmentation Fault` in C, `TypeError: cannot read property of undefined` in JavaScript). The inventor of `null`, Sir Tony Hoare, famously called it his "billion-dollar mistake."

**Rust has no `null`**. 

Instead, Rust models absence and failure using two built-in generic enums: **`Option<T>`** and **`Result<T, E>`**.

---

### 1. `Option<T>`: Presence vs. Absence

`Option<T>` represents a value that **may or may not exist**. It is defined in the standard library as:

```rust
enum Option<T> {
    Some(T), // A value of type T is present
    None,    // No value is present
}
```

Because `Option<T>` is in Rust's standard prelude, `Some` and `None` are available everywhere without importing them.

```
                  ┌──────────────────────────────┐
                  │       Option<String>         │
                  └──────────────┬───────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
      ┌─────────────────────┐         ┌─────────────────────┐
      │  Some("Bearer123")  │         │        None         │
      │   Value is present  │         │   Value is absent   │
      └─────────────────────┘         └─────────────────────┘
```

#### Why this is safe:
If a variable is of type `String`, it is **guaranteed to always contain a valid string**. It can never be null. 
If a value might be absent, its type *must* be `Option<String>`. You **cannot** use the string until you explicitly match and unpack the `Some` variant.

---

### 2. `Result<T, E>`: Success vs. Recoverable Error

`Result<T, E>` represents an operation that could either **succeed** with a value of type `T`, or **fail** with an error of type `E`.

```rust
enum Result<T, E> {
    Ok(T),  // Operation succeeded with value T
    Err(E), // Operation failed with error E
}
```

Like `Option`, `Ok` and `Err` are automatically available everywhere.

---

### 3. Unpacking and Handling `Option` and `Result`

#### A. Pattern Matching (`match` / `if let`):
The safest, most explicit way to handle both variants:

```rust
match parse_port("8080") {
    Ok(port) => println!("Listening on port {}", port),
    Err(err) => println!("Failed to parse port: {}", err),
}
```

#### B. Providing Defaults with `.unwrap_or()`:
If you want to use a fallback default when a value is absent or fails:

```rust
let timeout_setting: Option<u32> = None;
let timeout = timeout_setting.unwrap_or(30); // Evaluates to 30
```

#### C. The Dangerous Way: `.unwrap()` and `.expect()`:
- `.unwrap()`: Returns the inner value if `Some`/`Ok`. If `None`/`Err`, it **crashes the program immediately** (panics).
- `.expect("custom message")`: Same as `.unwrap()`, but prints your custom error message before crashing.

> **Rule for Systems Code**: Never use `.unwrap()` in production servers unless you can mathematically prove the value is guaranteed to be present. Always handle the error or provide a fallback.

## Why it matters

In web servers, HTTP request parsing constantly encounters missing or malformed data: optional headers, missing query parameters, invalid integer strings, or closed socket connections. 

In other languages, forgetting to check for null causes production outages. In Rust, if an HTTP header is optional, the function *must* return `Option<String>`. The compiler physically prevents your server from compiling until you write code to handle the `None` case.

---

## Analogy

- **`Option<T>`**: A wrapped mystery gift box. When you untie the ribbon, either it contains a watch (`Some(watch)`), or it is completely empty (`None`). You cannot wear the watch until you open the box and verify it exists.
- **`Result<T, E>`**: A certified mail envelope from a visa office. You open the seal to find either your approved travel visa (`Ok(visa)`) or a rejection notice explaining the reason (`Err("Insufficient funds")`).

## Code Example

```rust
// 1. Function returning an Option: Looking up an optional HTTP header
fn get_http_header<'a>(headers: &[(&'a str, &'a str)], target_key: &str) -> Option<&'a str> {
    for &(key, value) in headers {
        if key == target_key {
            return Some(value); // Found header
        }
    }
    None // Header was omitted by client
}

// 2. Function returning a Result: Parsing a raw port string into a u16
fn parse_network_port(raw_port: &str) -> Result<u16, String> {
    // `.parse::<u16>()` returns a Result
    match raw_port.trim().parse::<u16>() {
        Ok(port) if port > 0 => Ok(port),
        Ok(_) => Err(String::from("Port 0 is reserved and cannot be used.")),
        Err(_) => Err(format!("'{}' is not a valid 16-bit integer.", raw_port)),
    }
}

fn main() {
    println!("--- 1. Handling Option<T> ---");

    let request_headers = [
        ("Host", "api.internal.net"),
        ("Authorization", "Bearer token_xyz_99"),
    ];

    // Case A: Header is present
    let auth = get_http_header(&request_headers, "Authorization");
    match auth {
        Some(token) => println!("Authenticated with token: {}", token),
        None => println!("Anonymous request (No Authorization header)"),
    }

    // Case B: Header is absent, with default fallback
    let user_agent = get_http_header(&request_headers, "User-Agent").unwrap_or("GenericClient/1.0");
    println!("User Agent: {}", user_agent);

    println!("\n--- 2. Handling Result<T, E> ---");

    let valid_input = "8443";
    let invalid_input = "not_a_port";

    // Matching on a successful Result
    match parse_network_port(valid_input) {
        Ok(port) => println!("Successfully configured port: {}", port),
        Err(err_msg) => println!("Configuration Error: {}", err_msg),
    }

    // Matching on a failing Result
    match parse_network_port(invalid_input) {
        Ok(port) => println!("Successfully configured port: {}", port),
        Err(err_msg) => println!("Configuration Error: {}", err_msg),
    }
}
```

## Common Mistakes

### 1. Trying to Use `T` Directly on an `Option<T>`
Attempting to do math or string operations directly on an `Option` without unwrapping it first.

**Broken Code:**
```rust
let count: Option<u32> = Some(5);
let total = count + 1; // Error: cannot add integer to Option<u32>!
```

---

### 2. Overusing `.unwrap()` as a Shortcut
Using `.unwrap()` everywhere because dealing with `match` feels verbose.

**Broken Code:**
```rust
let port: Result<u16, _> = "invalid".parse();
let active_port = port.unwrap(); // PANIC: Thread crashes at runtime!
```
*How to fix*: Use `match`, `if let`, `.unwrap_or(default)`, or the `?` operator (Lesson 1.10).

---

### 3. Using `Option` When Error Context is Needed
Returning `Option<T>` (yielding only `None`) when the caller needs to know *why* the operation failed (file missing vs. permission denied vs. disk full). Use `Result<T, E>` whenever failure has a reason.

## Exercises

### Exercise 1 (User Role Lookup)
Write a function `find_user_role(username: &str) -> Option<&'static str>`:
- If `username == "admin"`, return `Some("Administrator")`.
- If `username == "guest"`, return `Some("GuestUser")`.
- For any other username, return `None`.

In `main()`, call `find_user_role` for `"admin"` and `"anonymous"`, printing the role or `"Role not found"`.

---

### Exercise 2 (Parsing Content Length)
Write a function `parse_content_length(header_value: &str) -> Result<usize, String>`:
- Uses `.parse::<usize>()` to convert the string.
- If successful, returns `Ok(size)`.
- If parsing fails, returns `Err(String::from("Invalid Content-Length header"))`.

Test both `"1024"` and `"abc"` in `main()`.

---

### Exercise 3 (Safe Configuration Extraction)
You are given an `Option<u32>` representing a custom connection timeout:
```rust
let configured_timeout: Option<u32> = None;
```
Use `.unwrap_or()` to assign a value to `effective_timeout`, using `30` as the fallback default if `configured_timeout` is `None`. Print `effective_timeout`.

## Solutions

### Solution to Exercise 1
```rust
fn find_user_role(username: &str) -> Option<&'static str> {
    match username {
        "admin" => Some("Administrator"),
        "guest" => Some("GuestUser"),
        _ => None,
    }
}

fn main() {
    let users = ["admin", "anonymous"];

    for user in users {
        match find_user_role(user) {
            Some(role) => println!("User '{}' has role: {}", user, role),
            None => println!("User '{}': Role not found", user),
        }
    }
}
```

---

### Solution to Exercise 2
```rust
fn parse_content_length(header_value: &str) -> Result<usize, String> {
    match header_value.parse::<usize>() {
        Ok(size) => Ok(size),
        Err(_) => Err(String::from("Invalid Content-Length header")),
    }
}

fn main() {
    let valid = "1024";
    let invalid = "abc";

    match parse_content_length(valid) {
        Ok(bytes) => println!("Payload size: {} bytes", bytes),
        Err(e) => println!("Error: {}", e),
    }

    match parse_content_length(invalid) {
        Ok(bytes) => println!("Payload size: {} bytes", bytes),
        Err(e) => println!("Error: {}", e),
    }
}
```

---

### Solution to Exercise 3
```rust
fn main() {
    let configured_timeout: Option<u32> = None;

    let effective_timeout = configured_timeout.unwrap_or(30);

    println!("Effective Connection Timeout: {} seconds", effective_timeout);
}
```
