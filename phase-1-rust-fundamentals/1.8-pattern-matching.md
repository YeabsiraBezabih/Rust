# Lesson 1.8: Pattern Matching with `match` and `if let`

## Prerequisites
- Lesson 1.6: Structs: Custom Data Structures and Methods.
- Lesson 1.7: Enums and Algebraic Data Types (variants and embedded payloads).

---

## Concept

In Lesson 1.7, we learned that Enums can store rich data inside their variants. How do we safely extract that data and execute specific logic for each variant?

Rust provides **Pattern Matching** through two powerful constructs: the exhaustive **`match`** expression and the concise **`if let`** syntax.

---

### 1. The `match` Expression

A `match` expression compares a target value against a series of **patterns** and executes the code associated with the first pattern that matches.

```rust
match value {
    Pattern1 => expression1,
    Pattern2 => expression2,
    _ => fallback_expression,
}
```

```
                        ┌────────────────────────┐
                        │   match incoming_cmd   │
                        └───────────┬────────────┘
                                    │
         ┌──────────────────────────┼──────────────────────────┐
         ▼                          ▼                          ▼
┌──────────────────┐       ┌──────────────────┐       ┌──────────────────┐
│ ServerCommand::  │       │ ServerCommand::  │       │ ServerCommand::  │
│ Start { port }   │       │ ReloadConfig     │       │ Stop             │
└────────┬─────────┘       └────────┬─────────┘       └────────┬─────────┘
         ▼                          ▼                          ▼
Bind `port` & Boot         Reload Config Files        Graceful Shutdown
```

#### Key Rules of `match`:
1. **Exhaustiveness**: Every single possible value or enum variant **must be covered**. If you omit even one variant, the compiler refuses to build your program.
2. **Data Extraction (Destructuring)**: You can bind and extract embedded data from inside variants directly in the pattern arm.
3. **The Catch-All Pattern (`_`)**: The underscore `_` matches any value not previously matched, acting as a default fallback.
4. **Multiple Choices (`|`)**: You can match multiple patterns with the pipe operator: `200 | 201 | 204 => "Success"`.
5. **Ranges (`..=`)**: You can match inclusive numeric ranges: `200..=299 => "2xx Success"`.
6. **Match Guards**: You can append an extra `if` condition to a pattern arm: `IpAddress::V4(a, ..) if a == 127 => "Loopback"`.
7. **Expression Returns**: `match` is an expression that produces a value. Every arm must return the **same data type**.

---

### 2. Concise Single-Variant Matching with `if let`

When you only care about handling **one specific variant** and want to ignore all other cases, writing a full `match` with a `_ => ()` fallback is unnecessarily verbose.

The **`if let`** syntax lets you handle a single matching pattern cleanly:

```rust
// Verbose with match:
match event {
    NetworkEvent::Connected { client_id, .. } => println!("Client {} connected", client_id),
    _ => (), // Ignore everything else
}

// Clean with if let:
if let NetworkEvent::Connected { client_id, .. } = event {
    println!("Client {} connected", client_id);
}
```

You can also attach an `else` block to `if let` to handle the non-matching case.

---

## Why it matters

In high-concurrency systems, unhandled edge cases cause catastrophic runtime crashes. 
- In other languages, adding a new enum state (e.g., adding `HttpVersion::Http3` to a web server) often results in silent runtime bugs when older switch statements forget to handle it.
- In Rust, because `match` is **mathematically exhaustive**, the instant you add a new variant to an enum, the compiler points to every single file and line in your entire codebase where that enum is matched and demands that you handle the new case.

---

## Analogy

- **`match`**: A high-speed sorting conveyor in an automated warehouse. Every package is scanned. Letters go to Chute 1; boxes under 5kg go to Chute 2; fragile packages go to Chute 3. If a package arrives that doesn't fit any chute, the conveyor automatically halts until a chute is added (compiler check).
- **`if let`**: A security guard standing at a gate looking *only* for vehicles carrying VIP passes. If a car has a VIP pass, the guard checks their credentials and opens the gate; every other vehicle is immediately waved past without extra questions.

## Code Example

```rust
#[derive(Debug)]
enum RouterAction {
    Route { path: String, handler_id: u32 },
    Redirect(String),
    RateLimited { retry_after_secs: u32 },
    NotFound,
}

// Function using an exhaustive match expression to generate a response status
fn process_router_action(action: &RouterAction) -> (u16, String) {
    // `match` evaluates to a tuple (u16, String)
    match action {
        RouterAction::Route { path, handler_id } => {
            (200, format!("Routing request to handler #{} at '{}'", handler_id, path))
        }
        RouterAction::Redirect(target_url) => {
            (301, format!("Redirecting permanently to {}", target_url))
        }
        // Match with a guard condition
        RouterAction::RateLimited { retry_after_secs } if *retry_after_secs > 60 => {
            (429, format!("Heavy rate limit: blocked for {} minutes", retry_after_secs / 60))
        }
        RouterAction::RateLimited { retry_after_secs } => {
            (429, format!("Rate limited: retry in {} seconds", retry_after_secs))
        }
        RouterAction::NotFound => {
            (404, String::from("404: Resource does not exist"))
        }
    }
}

fn main() {
    println!("--- 1. Exhaustive Pattern Matching with `match` ---");

    let action_a = RouterAction::Route {
        path: String::from("/api/v1/metrics"),
        handler_id: 104,
    };
    let action_b = RouterAction::RateLimited { retry_after_secs: 120 };
    let action_c = RouterAction::NotFound;

    let (status_a, msg_a) = process_router_action(&action_a);
    println!("Status {}: {}", status_a, msg_a);

    let (status_b, msg_b) = process_router_action(&action_b);
    println!("Status {}: {}", status_b, msg_b);

    let (status_c, msg_c) = process_router_action(&action_c);
    println!("Status {}: {}", status_c, msg_c);

    println!("\n--- 2. Concise Matching with `if let` ---");

    let incoming_event = RouterAction::Redirect(String::from("https://secure.internal/login"));

    // We only care if this is a Redirect; ignore all other variants
    if let RouterAction::Redirect(destination) = incoming_event {
        println!("Intercepted Redirect destination: {}", destination);
    } else {
        println!("Action was not a redirect.");
    }
}
```

## Common Mistakes

### 1. Non-Exhaustive Patterns
Forgetting to match all variants without providing a fallback `_`.

**Broken Code:**
```rust
enum Status { Active, Suspended, Deleted }

fn check_status(s: Status) {
    match s {
        Status::Active => println!("Online"),
        Status::Suspended => println!("Paused"),
        // Error: `Status::Deleted` is not covered!
    }
}
```

**Compiler Output:**
```text
error[E0004]: non-exhaustive patterns: `Status::Deleted` not covered
 --> src/main.rs:4:11
  |
4 |     match s {
  |           ^ pattern `Status::Deleted` not covered
```

---

### 2. Mismatched Return Types Across Match Arms
All match arms must evaluate to the exact same data type when assigning the match result to a variable.

**Broken Code:**
```rust
let code = 200;
let response = match code {
    200 => "OK",  // &str
    404 => 404,   // Error: integer instead of &str!
    _ => "Unknown",
};
```

---

### 3. Confusing `if let` Syntax
Writing `if event == Variant` instead of `if let Variant = event`. (Enums with data cannot be checked with `==` unless `PartialEq` is implemented, and `==` cannot extract inner data).

Write a function `http_category(status: u16) -> &'static str` using a `match` expression with range patterns:
- `100..=199` $\rightarrow$ `"Informational"`
- `200..=299` $\rightarrow$ `"Success"`

- `400..=499` $\rightarrow$ `"Client Error"`

## Solutions

### Solution to Exercise 1
```rust
fn http_category(status: u16) -> &'static str {
    match status {
        100..=199 => "Informational",
        200..=299 => "Success",
        300..=399 => "Redirection",
        400..=499 => "Client Error",
        500..=599 => "Server Error",
        _ => "Invalid Status Code",
    }
}

fn main() {
    println!("200: {}", http_category(200));
    println!("404: {}", http_category(404));
    println!("999: {}", http_category(999));
}
```

---

### Solution to Exercise 2
```rust
enum TaskPriority {
    Low,
    Medium,
    High { urgency_level: u8 },
    Critical(String),
}

fn estimate_sla_hours(task: &TaskPriority) -> u32 {
    match task {
        TaskPriority::Low => 72,
        TaskPriority::Medium => 24,
        TaskPriority::High { urgency_level } if *urgency_level > 5 => 2,
        TaskPriority::High { .. } => 6,
        TaskPriority::Critical(_) => 1,
    }
}

fn main() {
    let task1 = TaskPriority::High { urgency_level: 8 };
    let task2 = TaskPriority::Critical(String::from("Database unreachable"));

    println!("Task 1 SLA: {} hours", estimate_sla_hours(&task1));
    println!("Task 2 SLA: {} hours", estimate_sla_hours(&task2));
}
```

### Solution to Exercise 3
```rust
enum WebSocketFrame {
    Text(String),
    Binary(Vec<u8>),
    Ping,
    Close,
}

fn handle_frame(frame: WebSocketFrame) {
    if let WebSocketFrame::Text(message) = frame {
        println!("Received text message: {}", message);
    }
}

fn main() {
    let frame = WebSocketFrame::Text(String::from("Hello WebSocket!"));
    handle_frame(frame);
}
```
