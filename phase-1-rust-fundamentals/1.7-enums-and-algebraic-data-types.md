# Lesson 1.7: Enums and Algebraic Data Types

## Prerequisites
- Lesson 1.3: Scalar and Compound Data Types (tuples and primitive types).
- Lesson 1.6: Structs: Custom Data Structures and Methods (`impl` blocks and methods).

---

## Concept

In Lesson 1.6, we learned about **Structs**, which allow you to group related fields together. A struct is a **Product Type** ("AND" type): an `HttpRequest` has a `method` *and* a `path` *and* a `port`.

However, many concepts in software are mutually exclusive. A network connection is either `Connecting`, `Open`, or `Closed`—it can never be all three simultaneously.

An **Enum** (short for *Enumeration*) is a **Sum Type** ("OR" type): an enum variable holds **exactly one variant at a time**.

```
                       ┌─────────────────────────┐
                       │     enum IpAddress      │
                       └────────────┬────────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
       ┌────────────────────────┐      ┌────────────────────────┐
       │   V4(u8, u8, u8, u8)   │  OR  │       V6(String)       │
       │   Embedded Tuple Data  │      │   Embedded Heap String │
       └────────────────────────┘      └────────────────────────┘
```

---

### 1. Enums with Embedded Data (The Superpower)

In many languages (like C or Java), enums are simply named lists of numbers. In Rust, enums are **Algebraic Data Types**: **each variant can store its own unique payload of data**.

Variants can store:
- **No data** (Unit variant): `Disconnect`
- **Tuple-style data**: `V4(u8, u8, u8, u8)`
- **Anonymous Struct-style data**: `Connected { ip: String, port: u16 }`

```rust
enum NetworkEvent {
    Connected { client_id: u64, remote_addr: String },
    DataReceived(Vec<u8>),
    Ping,
    Disconnected,
}
```

---

### 2. Methods on Enums

Just like structs, you can attach methods and constructors to enums using an `impl` block:

```rust
impl NetworkEvent {
    fn is_critical(&self) -> bool {
        // Method logic inspecting self
        true
    }
}
```

---

### 3. Making Illegal States Unrepresentable

In traditional programming, developers often create a single struct with multiple optional flags:

```text
// BAD DESIGN (Fragile):
struct Connection {
    state: String,            // "connecting", "open", "closed"
    user_id: u64,             // Only valid if state == "open"
    error_message: String,    // Only valid if state == "closed"
}
```
*Problem*: A bug could cause `state` to be `"connecting"` while `error_message` is populated, creating an invalid state.

With Rust Enums:
```rust
// GOOD DESIGN (Type-Safe):
enum Connection {
    Connecting,
    Open { user_id: u64 },
    Closed { reason: String },
}
```
*Advantage*: You physically cannot access `user_id` unless the connection is in the `Open` state. The compiler makes invalid states impossible to represent.

---

### 4. Memory Layout (Tagged Unions)

In memory, a Rust enum is laid out as a **Tagged Union**:
1. **Discriminant (Tag)**: A small integer (usually 1 byte) identifying which variant is currently active.
2. **Payload Space**: A contiguous block of bytes sized to fit the **largest** variant.

---

## Why it matters

In low-level network protocol parsers and AI agent runners, systems transition through strict state machines. When building an HTTP/1.1 or WebSocket server, an incoming packet can be a `HandshakeRequest`, a `TextFrame`, a `BinaryFrame`, or a `CloseSignal`. Rust enums give you mathematical guarantees that incoming data is validated into exactly one type-safe state before processing.

---

## Analogy

Think of a **Specialized Delivery Container**:
- The outside of the container has a mechanical dial (the **Tag / Discriminant**) set to indicate the contents: `Documents`, `Fragile Electronics`, or `Empty`.
- If the dial says `Documents`, the container holds a sealed envelope (`String`).
- If the dial says `Fragile Electronics`, the container holds cushioned circuit boards (`(u32, u32)`).
- If the dial says `Empty`, it holds zero payload.
- You only handle one container, but its internal contents adapt perfectly to the category indicated by the dial.

## Code Example

```rust
#[derive(Debug)]
enum IpAddress {
    // Variant 1: Stores 4 bytes directly on the stack
    V4(u8, u8, u8, u8),
    // Variant 2: Stores a heap-allocated String
    V6(String),
}

impl IpAddress {
    // Method to format the IP address into a standard display string
    fn to_display_string(&self) -> String {
        match self {
            IpAddress::V4(a, b, c, d) => format!("{}.{}.{}.{}", a, b, c, d),
            IpAddress::V6(addr_str) => addr_str.clone(),
        }
    }

    // Method to check if the address is a local loopback
    fn is_loopback(&self) -> bool {
        match self {
            IpAddress::V4(127, 0, 0, 1) => true,
            IpAddress::V6(addr) if addr == "::1" => true,
            _ => false,
        }
    }
}

#[derive(Debug)]
enum WebhookPayload {
    Ping,
    UserCreated { user_id: u64, email: String },
    PaymentReceived(u64), // Amount in cents
}

fn main() {
    println!("--- 1. Modeling IP Addresses with Enums ---");
    let home_v4 = IpAddress::V4(127, 0, 0, 1);
    let gateway_v6 = IpAddress::V6(String::from("fe80::1ff:fe23:4567:890a"));

    println!("IPv4: {} (Is Loopback: {})", home_v4.to_display_string(), home_v4.is_loopback());
    println!("IPv6: {} (Is Loopback: {})", gateway_v6.to_display_string(), gateway_v6.is_loopback());

    println!("\n--- 2. Processing Multi-Payload Webhooks ---");
    let event_a = WebhookPayload::Ping;
    let event_b = WebhookPayload::UserCreated {
        user_id: 10482,
        email: String::from("dev@systems.internal"),
    };
    let event_c = WebhookPayload::PaymentReceived(4999);

    println!("Event A: {:?}", event_a);
    println!("Event B: {:?}", event_b);
    println!("Event C: {:?}", event_c);
}
```

## Common Mistakes

### 1. Treating an Enum Variant as an Independent Type
A beginner tries to write a function that takes only `IpAddress::V4` as a type.

**Broken Code:**
```rust
// Error: `IpAddress::V4` is a variant value constructor, NOT a type!
fn process_v4_only(ip: IpAddress::V4) { }
```
*How to fix*: The type is `IpAddress`. If you only want IPv4 data, you either pass `IpAddress` and match on it, or define a dedicated `struct Ipv4Addr(u8, u8, u8, u8);`.

---

### 2. Giant Memory Overhead from One Massive Variant
Because an enum's size in memory equals the size of its largest variant plus the tag, putting a massive 100KB buffer in one variant forces *every* variant of that enum to occupy 100KB of memory.

*How to fix*: Box large variant payloads (covered in Phase 3) to keep the enum compact.

---

### 3. Confusing Structs and Enums
Using a struct when values are mutually exclusive, leading to error-prone validation checks.

### Solution to Exercise 2
```rust
#[derive(Debug)]
enum NetworkProtocol {
    Http { port: u16 },
    Https { port: u16, cert_name: String },
    Tcp(u16),
    Disabled,
}

impl NetworkProtocol {
    fn get_port(&self) -> u16 {
        match self {
            NetworkProtocol::Http { port } => *port,
            NetworkProtocol::Https { port, .. } => *port,
            NetworkProtocol::Tcp(port) => *port,
            NetworkProtocol::Disabled => 0,
        }
    }
}

fn main() {
    let proto = NetworkProtocol::Https {
        port: 8443,
        cert_name: String::from("local.crt"),
    };

    println!("Port for protocol: {}", proto.get_port());
}
```

### Solution to Exercise 3
```rust
#[derive(Debug)]
enum AgentExecutionState {
    Idle,
    Prompting { model: String, temperature: f64 },
    ToolExecution { tool_name: String, step_index: u32 },
    Finished { total_tokens_used: u64 },
    Failed(String),
}

impl AgentExecutionState {
    fn is_active(&self) -> bool {
        match self {
            AgentExecutionState::Prompting { .. } => true,
            AgentExecutionState::ToolExecution { .. } => true,
            _ => false,
        }
    }
}

fn main() {
    let state = AgentExecutionState::ToolExecution {
        tool_name: String::from("run_sql_query"),
        step_index: 3,
    };

    println!("Agent is running: {}", state.is_active());
}
```
