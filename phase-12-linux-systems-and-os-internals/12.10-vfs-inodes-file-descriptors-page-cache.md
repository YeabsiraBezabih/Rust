## Concept

The Linux **Virtual Filesystem (VFS)** is an abstraction layer that allows user applications to interact with completely different storage backends (ext4, XFS, Btrfs, tmpfs, NFS, or `/proc`) using the exact same standard system calls (`openat`, `read`, `write`, `close`).

```

│                    Linux VFS 3-Tier Resolution & Data Structures             │
├──────────────────────────────────────────────────────────────────────────────┤
```

### 1. The 4 Core VFS Data Structures

1. **Superblock**: Represents an entire mounted filesystem (block size, total free blocks, filesystem magic number).
2. **Inode (Index Node)**: Represents a specific file or directory on disk. Contains metadata (size, timestamps, owner, permissions, pointers to physical disk blocks) but **does not contain the filename**.
3. **Dentry (Directory Entry)**: Caches pathname components in RAM (e.g. `/`, `var`, `log`) linking string filenames to Inode numbers.
4. **File Object**: Represents an open file instance created when a process calls `openat()`. Tracks the process's active byte offset and access mode.

---

### 2. High-Performance File Syscalls: `openat`, `pread`, & `getdents64`

- **`openat(dirfd, path, flags, mode)`**: Opens paths relative to a directory file descriptor. Prevents **Time-of-Check to Time-of-Use (TOCTOU)** race condition vulnerabilities.
- **`pread()` / `pwrite()`**: Reads or writes data at an explicit offset without modifying the file descriptor's shared offset pointer. Essential for multi-threaded databases accessing the same file concurrently!
- **`getdents64()`**: Fetches raw directory entries in bulk directly from the kernel into a user-space buffer, avoiding the per-file syscall overhead of `readdir()`.

---

### 3. Page Cache & Durability: `fsync` vs. `fdatasync` vs. `O_DIRECT`

When your Rust program calls `file.write()`, the data **is not written to disk immediately**. It is written to the **Linux Page Cache** in RAM and marked as "dirty".

To guarantee persistence against sudden power loss:

| Method | What It Flushes to Disk | Performance |
| :--- | :--- | :--- |
| **`fdatasync(fd)`** | File data pages + file size only (Omits non-essential metadata like `mtime`). | Fastest safe option for database WAL engines. |
| **`fsync(fd)`** | File data pages + all Inode metadata (timestamps, attributes). | Slower (requires two separate disk writes). |
| **`O_DIRECT`** | Completely bypasses the Linux Page Cache; transfers directly from user RAM to NVMe via DMA. | Requires memory page alignment; used by PostgreSQL & ScyllaDB. |

---

## Why It Matters in Systems & Backend Engineering

1. **Building ACID Write-Ahead Logs (WAL)**: Database systems (Postgres, SQLite, RocksDB) must invoke `fdatasync()` after every transaction commit to prevent data corruption.
2. **Thread-Safe Multi-Reader Engines**: Using `pread()` allows 64 worker threads to read different segments of an index file concurrently without acquiring mutex locks on file handles.
3. **High-Velocity Directory Traversals**: Writing fast find/grep tools requires parsing `getdents64` buffers rather than making thousands of individual `stat` syscalls.

---

## Real-World Analogy

- **The Inode** is a safety deposit box inside a vault with a unique serial number (**Inode Number**).
- **The Dentry** is the reception directory mapping customer names (**Filenames**) to their box serial numbers.
- **A Hard Link** is giving two different family members each a key that points to the exact same deposit box (**Two filenames pointing to the same Inode**).
- **`fdatasync`** is making sure the contents inside the deposit box are physically locked into the vault before leaving the bank.

## Complete, Compilable Code Example

The following Rust program simulates the **VFS Thread-Safe `pread`/`pwrite` Storage Engine** with simulated Inode and File Descriptor tables:

```rust
use std::collections::HashMap;
use std::sync::{Arc, RwLock};

/// Simulated Inode representing file metadata and storage blocks
#[derive(Debug)]
pub struct VfsInode {
    pub inode_number: u64,
    pub size: usize,
    pub blocks: Vec<u8>,
}

/// Simulated VFS Engine
pub struct VirtualFilesystem {
    inodes: Arc<RwLock<HashMap<u64, Arc<RwLock<VfsInode>>>>>,
    dentry_cache: Arc<RwLock<HashMap<String, u64>>>,
    next_inode: u64,
}

impl VirtualFilesystem {
    pub fn new() -> Self {
        Self {
            inodes: Arc::new(RwLock::new(HashMap::new())),
            dentry_cache: Arc::new(RwLock::new(HashMap::new())),
            next_inode: 1,
        }
    }

    /// Simulates `openat(O_CREAT)`
    pub fn create_file(&mut self, path: &str) -> u64 {
        let ino = self.next_inode;
        self.next_inode += 1;

        let inode = VfsInode {
            inode_number: ino,
            size: 0,
            blocks: Vec::new(),
        };

        self.inodes.write().unwrap().insert(ino, Arc::new(RwLock::new(inode)));
        self.dentry_cache.write().unwrap().insert(path.to_string(), ino);
        ino
    }

    /// Thread-safe `pwrite`: Writes at an explicit offset without locking other offsets
    pub fn pwrite(&self, inode_num: u64, offset: usize, data: &[u8]) -> Result<usize, &'static str> {
        let inodes = self.inodes.read().unwrap();
        let inode_lock = inodes.get(&inode_num).ok_or("EBADF: Inode not found")?;
        let mut inode = inode_lock.write().unwrap();

        if offset + data.len() > inode.blocks.len() {
            inode.blocks.resize(offset + data.len(), 0);
        }

        inode.blocks[offset..offset + data.len()].copy_from_slice(data);
        inode.size = inode.blocks.len();
        Ok(data.len())
    }

    /// Thread-safe `pread`: Reads at an explicit offset concurrently
    pub fn pread(&self, inode_num: u64, offset: usize, buf: &mut [u8]) -> Result<usize, &'static str> {
        let inodes = self.inodes.read().unwrap();
        let inode_lock = inodes.get(&inode_num).ok_or("EBADF: Inode not found")?;
        let inode = inode_lock.read().unwrap();

        if offset >= inode.blocks.len() {
            return Ok(0); // EOF
        }

        let available = inode.blocks.len() - offset;
        let bytes_to_read = buf.len().min(available);
        buf[..bytes_to_read].copy_from_slice(&inode.blocks[offset..offset + bytes_to_read]);
        Ok(bytes_to_read)
    }
}

fn main() {
    println!("=== Linux Virtual Filesystem (VFS) & pread/pwrite Engine ===\n");

    let mut vfs = VirtualFilesystem::new();
    let inode_id = vfs.create_file("/var/log/transactions.wal");
    println!("Created file '/var/log/transactions.wal' -> Inode #{}", inode_id);

    // 1. Concurrent writes at different offsets (simulating database WAL workers)
    vfs.pwrite(inode_id, 0, b"HEADER_BLOCK_V1").unwrap();
    vfs.pwrite(inode_id, 1024, b"TX_RECORD_#0001_COMMITTED").unwrap();

    // 2. Concurrent reads via pread without disturbing other offsets
    let mut header_buf = [0u8; 15];
    let mut tx_buf = [0u8; 25];

    vfs.pread(inode_id, 0, &mut header_buf).unwrap();
    vfs.pread(inode_id, 1024, &mut tx_buf).unwrap();

    println!("Read at offset 0:    {:?}", std::str::from_utf8(&header_buf).unwrap());
    println!("Read at offset 1024: {:?}", std::str::from_utf8(&tx_buf).unwrap());

    assert_eq!(&header_buf, b"HEADER_BLOCK_V1");
    assert_eq!(&tx_buf, b"TX_RECORD_#0001_COMMITTED");
}
```

## Common Pitfalls & Server Mistakes

### 1. Assuming `write()` Persists Data to Disk
- **Cause**: Writing transaction logs with standard `write()` and immediately responding `HTTP 200 OK`. If the server loses power 500ms later, un-flushed dirty pages in the Linux Page Cache evaporate!
- **Fix**: Call `file.sync_data()` (`fdatasync`) before confirming transaction commits.

### 2. Hard Link Limitations across Filesystems
- **Cause**: Attempting to create a hard link (`ln file1 /mnt/backup/file2`) across different storage mounts. Hard links reference raw Inode numbers, which are only unique within a single filesystem instance.
- **Fix**: Use soft/symbolic links (`ln -s`) for cross-mount references.

## Complete Solutions to Exercises

### Solution 1: Inode Hard Link Counter
```rust
pub struct InodeMetadata {
    pub inode_number: u64,
    pub hard_links_count: u32,
}

impl InodeMetadata {
    pub fn new(ino: u64) -> Self {
        Self { inode_number: ino, hard_links_count: 1 }
    }

    pub fn link(&mut self) {
        self.hard_links_count += 1;
    }

    pub fn unlink(&mut self) -> bool {
        self.hard_links_count = self.hard_links_count.saturating_sub(1);
        self.hard_links_count == 0 // True if inode should be deleted
    }
}

#[test]
fn test_hard_linking() {
    let mut meta = InodeMetadata::new(42);
    meta.link();
    assert_eq!(meta.hard_links_count, 2);
    assert!(!meta.unlink());
    assert!(meta.unlink()); // Deletion triggered
}
```

### Solution 2: Bulk Directory Scanner
```rust
pub fn parse_simulated_getdents(raw_bytes: &[u8]) -> Vec<(u64, String)> {
    let mut entries = Vec::new();
    let mut cursor = 0;

    while cursor + 8 <= raw_bytes.len() {
        let ino = u64::from_le_bytes(raw_bytes[cursor..cursor + 8].try_into().unwrap());
        cursor += 8;

        if let Some(null_pos) = raw_bytes[cursor..].iter().position(|&b| b == 0) {
            let name_bytes = &raw_bytes[cursor..cursor + null_pos];
            let name = String::from_utf8_lossy(name_bytes).to_string();
            entries.push((ino, name));
            cursor += null_pos + 1;
        } else {
            break;
        }
    }

    entries
}

#[test]
fn test_getdents_parser() {
    let mut buffer = Vec::new();
    buffer.extend_from_slice(&100u64.to_le_bytes());
    buffer.extend_from_slice(b"file_a.txt\0");
    buffer.extend_from_slice(&101u64.to_le_bytes());
    buffer.extend_from_slice(b"file_b.txt\0");

    let parsed = parse_simulated_getdents(&buffer);
    assert_eq!(parsed.len(), 2);
    assert_eq!(parsed[0], (100, "file_a.txt".to_string()));
    assert_eq!(parsed[1], (101, "file_b.txt".to_string()));
}
```
