## Concept

When building backend servers that handle **1,000,000 concurrent network connections** (the C10M problem), allocating 1 OS thread per socket crashes the kernel due to thread stack memory exhaustion and CPU scheduler overhead.

Linux solves this through **I/O Multiplexing**: a single thread can monitor thousands of file descriptors and only wake up when a socket is ready to read or write.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  Evolution of Linux High-Scale I/O Multiplexing              │
├──────────────────────────────────────────────────────────────────────────────┤
│  1. SELECT / POLL (O(N) Complexity)                                          │
│  User passes array of 10,000 FDs ──► Kernel iterates all 10,000 on each tick │
│                                                                              │
│  2. EPOLL (O(1) Readiness Notification - Red-Black Tree in Kernel)           │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ Epoll Instance (`epoll_create1`): Registered FDs stored in kernel RB-Tree│  │
│  │ Ready List: Linked list populated by NIC interrupt handlers            │  │
│  │ `epoll_wait()` returns only ACTIVE sockets!                            │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  3. IO_URING (True Asynchronous Completion - Lock-Free Shared Memory Rings)  │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ USER SPACE                           KERNEL SPACE                      │  │
│  │ [ Submission Queue (SQ) ] ────────► Kernel pulls SQEs (No syscalls!)   │  │
│  │                                      Executes NVMe/Network DMA         │  │
│  │ [ Completion Queue (CQ) ] ◄──────── Kernel posts CQEs (Zero copies!)   │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 1. `epoll`: Level-Triggered (LT) vs. Edge-Triggered (ET)

- **Level-Triggered (LT - Default)**: `epoll_wait()` will repeatedly return the file descriptor as long as there is unread data in the socket receive buffer. Safer, but triggers redundant wakeups.
- **Edge-Triggered (ET - `EPOLLET`)**: `epoll_wait()` returns the file descriptor **only once** when new data arrives. You **must read in a loop until `EWOULDBLOCK` / `EAGAIN`**; otherwise, your server will hang indefinitely waiting for new events!

### 2. Next-Gen Asynchronous I/O: `io_uring`

While `epoll` tells you when a socket is *ready* to be read (requiring a subsequent `read()` system call), **`io_uring`** performs the actual read or write operation asynchronously in kernel space:

1. **Shared Ring Buffers**: User space and Kernel space share two lock-free ring buffers mapped via `mmap`.
2. **Submission Queue (SQ)**: User space writes a Submission Queue Entry (`io_uring_sqe`) describing the operation (e.g. `IORING_OP_READV`).
3. **Completion Queue (CQ)**: When data arrives via DMA, the kernel posts a Completion Queue Entry (`io_uring_cqe`) containing the result and status code.
4. **SQPOLL Mode**: A dedicated kernel thread continuously polls the SQ ring, allowing your backend to perform millions of reads and writes with **ZERO system calls**!

---

## Why It Matters in Systems & Backend Engineering

1. **The Backbone of Tokio & Nginx**: Tokio (`mio` crate) is built directly on top of Linux `epoll`, allowing async Rust web services to handle tens of thousands of requests per second per core.
2. **Eliminating Kernel-User Context Switches**: `io_uring` is the new industry standard for high-performance storage engines, powering next-generation databases like ScyllaDB and PolarDB.
3. **Avoiding Starvation under Load**: Understanding `EPOLLEXCLUSIVE` and `EPOLLONESHOT` prevents the "Thundering Herd" problem when multi-threaded workers poll the same listening socket.

---

## Real-World Analogy

- **`select()` / `poll()`** is like a waiter walking to every single table in a 1,000-seat restaurant asking, "Are you ready to order yet?" (**O(N) Polling Overhead**).
- **`epoll`** is like giving each table a call button: when a customer presses the button, the waiter walks directly to that specific table (**O(1) Readiness Event**).
- **`io_uring`** is like a high-speed conveyor belt: the customer writes their order on a card and drops it onto the belt (**SQ Ring**); kitchen staff fulfills the order and sends the food back on the return belt (**CQ Ring**) without the waiter ever walking to the table!

## Complete, Compilable Code Example

The following program demonstrates an **Asynchronous Lock-Free Submission & Completion Queue Ring Buffer** modeling the architecture of `io_uring`:

```rust
use std::collections::VecDeque;
use std::sync::{Arc, Mutex};

/// Submission Queue Entry (SQE)
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SqEntry {
    pub user_data: u64, // Request tracking ID
    pub opcode: u8,     // 0 = READ, 1 = WRITE, 2 = ACCEPT
    pub fd: i32,
    pub buffer_len: usize,
}

/// Completion Queue Entry (CQE)
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CqEntry {
    pub user_data: u64,
    pub res: i32, // Bytes transferred or negative errno
}

/// User/Kernel Shared Memory Ring Buffer Simulation
pub struct MockIoUring {
    sq_ring: Arc<Mutex<VecDeque<SqEntry>>>,
    cq_ring: Arc<Mutex<VecDeque<CqEntry>>>,
}

impl MockIoUring {
    pub fn new() -> Self {
        Self {
            sq_ring: Arc::new(Mutex::new(VecDeque::new())),
            cq_ring: Arc::new(Mutex::new(VecDeque::new())),
        }
    }

    /// User Space: Submits an I/O request without issuing a syscall
    pub fn submit_sqe(&self, entry: SqEntry) {
        let mut sq = self.sq_ring.lock().unwrap();
        sq.push_back(entry);
    }

    /// Kernel Space Worker: Drains SQ, executes I/O, and posts to CQ
    pub fn kernel_process_batch(&self) -> usize {
        let mut sq = self.sq_ring.lock().unwrap();
        let mut cq = self.cq_ring.lock().unwrap();
        let mut processed = 0;

        while let Some(sqe) = sq.pop_front() {
            // Simulate instant zero-copy DMA I/O execution
            let bytes_transferred = sqe.buffer_len as i32;
            cq.push_back(CqEntry {
                user_data: sqe.user_data,
                res: bytes_transferred,
            });
            processed += 1;
        }

        processed
    }

    /// User Space: Harvests completed I/O results
    pub fn poll_cqe(&self) -> Option<CqEntry> {
        let mut cq = self.cq_ring.lock().unwrap();
        cq.pop_front()
    }
}

fn main() {
    println!("=== Linux I/O Multiplexing: epoll & io_uring Architecture ===\n");

    let ring = MockIoUring::new();

    // 1. User space queues 3 async socket reads without blocking
    println!("[USER SPACE] Queuing 3 async I/O read operations into SQ Ring...");
    ring.submit_sqe(SqEntry { user_data: 101, opcode: 0, fd: 4, buffer_len: 4096 });
    ring.submit_sqe(SqEntry { user_data: 102, opcode: 0, fd: 5, buffer_len: 1024 });
    ring.submit_sqe(SqEntry { user_data: 103, opcode: 1, fd: 6, buffer_len: 2048 });

    // 2. Kernel background thread processes queued requests
    let completed_count = ring.kernel_process_batch();
    println!("[KERNEL] Processed {} SQEs via DMA into CQ Ring.", completed_count);
    assert_eq!(completed_count, 3);

    // 3. User space harvests completions with zero context-switch overhead
    println!("\n[USER SPACE] Polling completions from CQ Ring:");
    while let Some(cqe) = ring.poll_cqe() {
        println!("  -> Request ID: {} | Bytes Completed: {}", cqe.user_data, cqe.res);
    }
}
```

## Common Pitfalls & Server Mistakes

### 1. Incomplete Draining in Edge-Triggered (`EPOLLET`) Mode
- **Cause**: Reading once from an Edge-Triggered socket and stopping when 1KB of data is received, while 5KB remains in the kernel buffer. `epoll_wait` will never fire again for that socket until *new* data arrives, causing a permanent client hang!
- **Fix**: Always loop `read()` until `WouldBlock` / `EAGAIN` is returned when using `EPOLLET`.

### 2. The Thundering Herd Problem
- **Cause**: 16 worker threads calling `epoll_wait()` on the same listening socket. When 1 client connects, all 16 threads wake up, but only 1 succeeds in `accept()`, wasting massive CPU cycles.
- **Fix**: Use `EPOLLEXCLUSIVE` or `SO_REUSEPORT` on the socket.

## Complete Solutions to Exercises

### Solution 1: Edge-Triggered Loop Emulator
```rust
use std::io::{self, ErrorKind};

pub fn drain_edge_triggered_socket<F>(mut read_chunk: F) -> Vec<u8>
where
    F: FnMut(&mut [u8]) -> io::Result<usize>,
{
    let mut aggregated = Vec::new();
    let mut temp_buf = [0u8; 1024];

    loop {
        match read_chunk(&mut temp_buf) {
            Ok(0) => break, // EOF
            Ok(n) => aggregated.extend_from_slice(&temp_buf[..n]),
            Err(ref e) if e.kind() == ErrorKind::WouldBlock => break, // Fully drained!
            Err(_) => break,
        }
    }

    aggregated
}

#[test]
fn test_et_drain() {
    let mut simulated_packets = vec![vec![1, 2, 3], vec![4, 5]];
    let result = drain_edge_triggered_socket(|buf| {
        if simulated_packets.is_empty() {
            Err(io::Error::new(ErrorKind::WouldBlock, "Drained"))
        } else {
            let chunk = simulated_packets.remove(0);
            buf[..chunk.len()].copy_from_slice(&chunk);
            Ok(chunk.len())
        }
    });

    assert_eq!(result, vec![1, 2, 3, 4, 5]);
}
```

### Solution 2: `epoll` Event Bitmask Decoder
```rust
pub fn decode_epoll_events(events: u32) -> Vec<&'static str> {
    let mut flags = Vec::new();
    if (events & 0x001) != 0 { flags.push("EPOLLIN"); }
    if (events & 0x004) != 0 { flags.push("EPOLLOUT"); }
    if (events & 0x008) != 0 { flags.push("EPOLLERR"); }
    if (events & 0x010) != 0 { flags.push("EPOLLHUP"); }
    if (events & 0x8000_0000) != 0 { flags.push("EPOLLET"); }
    flags
}

#[test]
fn test_epoll_flags() {
    let flags = decode_epoll_events(0x001 | 0x004);
    assert_eq!(flags, vec!["EPOLLIN", "EPOLLOUT"]);
}
```
