## Concept

While Linux Namespaces determine what a process can **SEE**, **Control Groups (cgroups v2)** determine what a process can **USE**.

Without resource enforcement, a single buggy container with a memory leak or an infinite CPU loop can consume 100% of host RAM and CPU cycles, crashing neighboring microservices and locking up the kernel.

In Linux, cgroups v2 provides a **Unified Virtual Filesystem Hierarchy** located at `/sys/fs/cgroup/`:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    Linux cgroups v2 Unified Hierarchy                        │
├──────────────────────────────────────────────────────────────────────────────┤
│  /sys/fs/cgroup/ (Root Cgroup)                                               │
│  ├── cgroup.subtree_control: "+cpu +memory +pids +io"                        │
│  │                                                                           │
│  ├── production_apps/                                                        │
│  │   ├── cgroup.procs: [PIDs of all production backend tasks]                │
│  │   ├── memory.max: 8589934592 (8 GB Hard RAM Cap ➔ Triggers OOM Killer)   │
│  │   ├── cpu.max: "200000 100000" (Max 2 CPU Cores CFS Bandwidth Quota)      │
│  │   ├── pids.max: 2048 (Fork bomb mitigation)                               │
│  │   └── memory.pressure: PSI Telemetry (Tracks hardware memory stalls)      │
│  │                                                                           │
│  └── background_workers/                                                     │
│      ├── cpu.weight: 100 (Lower CPU scheduling priority relative to prod)    │
│      └── io.max: "8:0 rbps=10485760 wbps=10485760" (10MB/s Disk I/O Throttle)│
└──────────────────────────────────────────────────────────────────────────────┘
```

---

### 1. The Core cgroups v2 Controllers

1. **Memory Controller (`memory.max`, `memory.high`)**:
   - `memory.max`: Hard ceiling. If process memory exceeds this threshold, the kernel invokes the **OOM (Out-of-Memory) Killer** to terminate processes *inside that specific cgroup*, leaving the host and other containers untouched!
   - `memory.high`: Throttling threshold. Slows down allocations to give the kernel time to reclaim page cache memory before hitting `memory.max`.
2. **CPU Controller (`cpu.max`, `cpu.weight`)**:
   - `cpu.max = "QUOTA PERIOD"`: Implements the **Completely Fair Scheduler (CFS) Bandwidth Quota**. For example, `"50000 100000"` allows the process to execute for 50ms every 100ms window (50% of 1 CPU core).
3. **PID Controller (`pids.max`)**:
   - Caps the maximum number of processes/threads. Neutralizes fork bomb attacks (`:(){ :|:& };:`) instantly.
4. **I/O Controller (`io.max`)**:
   - Enforces read/write IOPS and bandwidth caps per block device major/minor number.

---

### 2. Pressure Stall Information (PSI)

Historically, checking CPU/RAM saturation required guessing based on high load averages.

**PSI (Pressure Stall Information)** exposes exact hardware stall percentages at `/proc/pressure/`:
- **`some`**: Percentage of time at least *one* task was stalled waiting on CPU/Memory/IO.
- **`full`**: Percentage of time *all* tasks were completely blocked (e.g. system thrashing swap).

```bash
cat /proc/pressure/memory
# some avg10=0.00 avg60=0.02 avg300=0.00 total=14812
# full avg10=0.00 avg60=0.00 avg300=0.00 total=0
```

## Why It Matters in Systems & Backend Engineering

1. **Preventing Out-of-Memory Cascades**: Enforcing `memory.max` on microservices prevents memory leaks from crashing the host node or triggering cluster-wide Kubernetes node evictions.
2. **Predictable Latency in Multi-Tenant Clouds**: CFS quotas guarantee that CPU-intensive background batch jobs cannot starve real-time HTTP request handlers of CPU cycles.
3. **Proactive Auto-Scaling via PSI**: Reading PSI metrics in Rust allows services to shed load or spawn replica pods *before* the server runs completely out of memory.

## Real-World Analogy

- **Linux Namespaces** are the soundproof cubicle walls ensuring a worker cannot see other employees' desks.
- **cgroups v2** is the utility governor attached to the cubicle: it caps electricity consumption at 200 Watts (**`cpu.max`**), limits water flow to 1 gallon/hour (**`io.max`**), and trips the circuit breaker if the worker tries to plug in a space heater (**`memory.max` OOM Trigger**).

## Complete, Compilable Code Example

The following program provides a **cgroups v2 Resource Controller & PSI Monitor in Pure Rust**:

```rust
use std::collections::HashMap;

/// Represents Resource Quotas configured in cgroups v2
#[derive(Debug, Clone, Copy)]
pub struct ResourceLimits {
    pub max_memory_bytes: u64,
    pub max_pids: u32,
    pub cpu_quota_us: u64,
    pub cpu_period_us: u64,
}

/// Simulated cgroups v2 Controller
pub struct CgroupV2Manager {
    cgroups: HashMap<String, ResourceLimits>,
}

impl CgroupV2Manager {
    pub fn new() -> Self {
        Self { cgroups: HashMap::new() }
    }

    pub fn create_cgroup(&mut self, name: &str, limits: ResourceLimits) -> Result<(), &'static str> {
        println!("[CGROUP v2] Creating cgroup '/sys/fs/cgroup/{}/':", name);
        println!("  -> Writing memory.max = {} bytes ({:.2} MB)", 
            limits.max_memory_bytes, limits.max_memory_bytes as f64 / 1_048_576.0);
        println!("  -> Writing pids.max   = {} processes", limits.max_pids);
        println!("  -> Writing cpu.max    = \"{} {}\" ({:.1}% CPU Allocation)", 
            limits.cpu_quota_us, limits.cpu_period_us, 
            (limits.cpu_quota_us as f64 / limits.cpu_period_us as f64) * 100.0);

        self.cgroups.insert(name.to_string(), limits);
        Ok(())
    }

    /// Evaluates if an allocation triggers an in-group OOM Kill event
    pub fn simulate_memory_allocation(&self, name: &str, requested_bytes: u64) -> Result<(), &'static str> {
        let limits = self.cgroups.get(name).ok_or("Cgroup not found")?;
        if requested_bytes > limits.max_memory_bytes {
            Err("CRITICAL: Out of Memory (OOM Killer invoked for cgroup!)")
        } else {
            Ok(())
        }
    }
}

/// Pressure Stall Information (PSI) Parser
#[derive(Debug, PartialEq)]
pub struct PsiMetrics {
    pub avg10: f64,
    pub avg60: f64,
    pub avg300: f64,
}

impl PsiMetrics {
    pub fn parse_psi_line(line: &str) -> Option<Self> {
        let mut avg10 = 0.0;
        let mut avg60 = 0.0;
        let mut avg300 = 0.0;

        for token in line.split_whitespace() {
            if let Some(val_str) = token.strip_prefix("avg10=") {
                avg10 = val_str.parse().ok()?;
            } else if let Some(val_str) = token.strip_prefix("avg60=") {
                avg60 = val_str.parse().ok()?;
            } else if let Some(val_str) = token.strip_prefix("avg300=") {
                avg300 = val_str.parse().ok()?;
            }
        }

        Some(Self { avg10, avg60, avg300 })
    }
}

fn main() {
    println!("=== Linux cgroups v2 & Resource Sandboxing Engine ===\n");

    let mut cgroup_mgr = CgroupV2Manager::new();

    // 1. Provision cgroup with 256MB RAM cap and 50% CPU allocation
    let limits = ResourceLimits {
        max_memory_bytes: 256 * 1024 * 1024,
        max_pids: 64,
        cpu_quota_us: 50_000,
        cpu_period_us: 100_000,
    };

    cgroup_mgr.create_cgroup("sandboxed_api_01", limits).unwrap();

    // 2. Simulate Safe Memory Allocation (128 MB)
    let safe_alloc = cgroup_mgr.simulate_memory_allocation("sandboxed_api_01", 128 * 1024 * 1024);
    println!("\nAllocating 128MB RAM: {:?}", safe_alloc);
    assert!(safe_alloc.is_ok());

    // 3. Simulate Runaway Leak (512 MB) -> OOM Trigger
    let oom_alloc = cgroup_mgr.simulate_memory_allocation("sandboxed_api_01", 512 * 1024 * 1024);
    println!("Allocating 512MB RAM: {:?}", oom_alloc);
    assert!(oom_alloc.is_err());

    // 4. Parse Linux PSI Telemetry
    let sample_psi = "some avg10=2.45 avg60=1.12 avg300=0.50 total=89214";
    let parsed_psi = PsiMetrics::parse_psi_line(sample_psi).unwrap();
    println!("\nParsed PSI Memory Saturation: {:?}", parsed_psi);
    assert_eq!(parsed_psi.avg10, 2.45);
}
```

## Common Pitfalls & Server Mistakes

### 1. Attaching Processes to Domain (Non-Leaf) Cgroups
- **Cause**: In cgroups v2, a directory with child cgroups **cannot directly contain process PIDs** if controllers are enabled (the "No Internal Processes" rule).
- **Fix**: Always create dedicated leaf directories (e.g. `/sys/fs/cgroup/prod/service_a/`) for attaching processes.

### 2. Confusing `cpu.weight` with Hard Caps
- **Cause**: Setting `cpu.weight = 100` expecting it to prevent a process from using 100% of an idle CPU. `cpu.weight` is a *relative share*; if no other process wants CPU time, the task is allowed 100% usage!
- **Fix**: Use `cpu.max` if you need a strict, deterministic upper ceiling on CPU usage.

## Complete Solutions to Exercises

### Solution 1: CPU Quota String Formatter
```rust
pub fn format_cpu_max(cores_fraction: f64) -> String {
    let period_us: u64 = 100_000;
    let quota_us = (cores_fraction * period_us as f64).round() as u64;
    format!("{} {}", quota_us, period_us)
}

#[test]
fn test_cpu_max_formatting() {
    assert_eq!(format_cpu_max(0.5), "50000 100000");
    assert_eq!(format_cpu_max(2.0), "200000 100000");
}
```

### Solution 2: Fork Bomb Blocker Simulation
```rust
pub struct PidLimiter {
    pub max_pids: u32,
    pub current_pids: u32,
}

impl PidLimiter {
    pub fn new(max_pids: u32) -> Self {
        Self { max_pids, current_pids: 0 }
    }

    pub fn try_spawn(&mut self) -> Result<(), &'static str> {
        if self.current_pids >= self.max_pids {
            Err("EAGAIN: pids.max resource limit reached (Fork bomb blocked!)")
        } else {
            self.current_pids += 1;
            Ok(())
        }
    }
}

#[test]
fn test_fork_bomb_mitigation() {
    let mut limiter = PidLimiter::new(2);
    assert!(limiter.try_spawn().is_ok());
    assert!(limiter.try_spawn().is_ok());
    assert!(limiter.try_spawn().is_err());
}
```
