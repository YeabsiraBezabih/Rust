## Concept

A computer's physical RAM is fragmented across physical DIMM slots. To give every running process the illusion of a contiguous, private memory space, the CPU Memory Management Unit (**MMU**) and the Linux kernel implement **Virtual Memory**.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    Linux Virtual Memory & 4-Level Page Tables                │
├──────────────────────────────────────────────────────────────────────────────┤
│  VIRTUAL ADDRESS (User Space: 48-bit Canonical on x86_64)                    │
│  ┌──────────┬──────────┬──────────┬──────────┬─────────────────────────────┐ │
│  │ PML4 (9b)│  PDPT (9)│  PD (9)  │  PT (9)  │ Page Offset (12 bits = 4KB) │ │
│  └────┬─────┴────┬─────┴────┬─────┴────┬─────┴──────────────┬──────────────┘ │
│       │          │          │          │                    │                │
│  CR3 ─┴─► [PML4] ┴─► [PDPT] ┴─► [PD]   ┴─► [Page Table] ───►▼                │
│                                                              ┌─────────────┐ │
│  TLB (Translation Lookaside Buffer: Fast CPU MMU Cache) ───► │PHYSICAL RAM │ │
│                                                              │4KB Frame    │ │
│                                                              └─────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 1. Page Fault Mechanics: Minor vs. Major

When a process accesses a virtual memory address:
1. **TLB Hit**: Address translation is cached in CPU L1 TLB $\rightarrow$ access completes in 1 CPU cycle.
2. **TLB Miss**: CPU walks the 4-level page table hierarchy in RAM to find the physical mapping.
3. **Minor Page Fault**: The virtual address is valid (e.g. from `mmap` or `malloc`), but physical RAM has not yet been allocated. The kernel allocates a physical page, updates page tables, and resumes the instruction.
4. **Major Page Fault**: The requested page resides on disk (file-backed `mmap` or swapped out to disk). The thread is put to sleep (`TASK_UNINTERRUPTIBLE`) while disk DMA loads the 4KB block into RAM.

---

### 2. Memory Mapping with `mmap()`

Instead of copying data through user-space buffers using `read()`/`write()`, `mmap()` maps a file or anonymous memory directly into the process address space:

```rust
// In Linux via libc:
// let ptr = libc::mmap(
//     std::ptr::null_mut(),
//     length,
//     libc::PROT_READ | libc::PROT_WRITE,
//     libc::MAP_PRIVATE | libc::MAP_ANONYMOUS,
//     -1,
//     0
// );
```

#### Common Flags:
- `MAP_ANONYMOUS`: Allocates raw RAM without backing it by a file (used by custom allocators).
- `MAP_PRIVATE`: Modifications are private (Copy-On-Write).
- `MAP_SHARED`: Modifications write directly to the underlying file or shared memory region across processes.
- `MAP_POPULATE`: Eagerly allocates physical RAM and pre-faults page tables at map time.

---

### 3. Memory Protection (`mprotect`) & Advisory (`madvise`)

- **`mprotect()`**: Dynamically modifies page permissions (`PROT_READ`, `PROT_WRITE`, `PROT_EXEC`). Used to implement **Guard Pages** (placing a `PROT_NONE` page at the bottom of a stack to catch stack overflow with zero CPU runtime overhead).
- **`madvise()`**: Gives hints to the kernel page cache:
  - `MADV_WILLNEED`: Pre-fetches pages into RAM in the background.
  - `MADV_DONTNEED`: Informs the kernel pages are no longer needed; frees physical RAM immediately while retaining virtual address space.
  - `MADV_HUGEPAGE`: Enables Transparent HugePages (THP) for that memory region.

---

### 4. HugePages: 4KB vs. 2MB vs. 1GB

Standard Linux pages are **4 Kilobytes**. A high-throughput database caching 64GB of RAM requires $16,777,216$ page entries, causing constant TLB misses.

By using **HugePages (2MB or 1GB)**:
- 64GB of RAM requires only $32,768$ page entries (a 512x reduction!).
- Dramatically increases TLB hit ratios for in-memory databases (Redis, PostgreSQL, RocksDB).

---

## Why It Matters in Systems & Backend Engineering

1. **Zero-Copy High-Throughput Databases**: Engines like SQLite, LMDB, and Kafka rely on `mmap` to achieve millions of reads/sec without copying data between kernel and user buffers.
2. **Security Sandboxing with Guard Pages**: Isolating user scripts or execution runtimes requires protecting page boundaries with `mprotect(PROT_NONE)`.
3. **Locking Memory against Swap (`mlock`)**: Cryptographic keys and passwords must be locked into RAM using `mlock()` so they are never written to unencrypted swap disks.

---

## Real-World Analogy

- **A 4KB Page** is like a single index card in a library catalog: accurate for small notes, but indexing an entire encyclopedia requires millions of cards (**High TLB Pressure**).
- **A 2MB HugePage** is like a large binder storing 500 pages under a single tab: it takes up one slot in the drawer (**One TLB Entry**) while indexing vast amounts of information.
- **`mprotect(PROT_NONE)` Guard Page** is like putting an electrified tripwire at the edge of a balcony: the moment a process steps outside its allowed boundary, the hardware MMU instantly triggers an alarm (**Segmentation Fault**).

## Complete, Compilable Code Example

The following program demonstrates a **Safe Memory-Mapped Virtual Buffer with Guard Page Protection** in pure Rust:

```rust
use std::alloc::{alloc, dealloc, Layout};
use std::ptr::NonNull;

/// Simulates a Virtual Memory Region with Page-Aligned Buffers & Guard Pages
pub struct VirtualMemoryBuffer {
    ptr: NonNull<u8>,
    layout: Layout,
    page_size: usize,
    capacity: usize,
}

impl VirtualMemoryBuffer {
    pub const DEFAULT_PAGE_SIZE: usize = 4096; // 4KB Standard Page

    pub fn allocate_aligned(pages: usize) -> Result<Self, &'static str> {
        let page_size = Self::DEFAULT_PAGE_SIZE;
        let capacity = pages * page_size;

        // Ensure page alignment
        let layout = Layout::from_size_align(capacity, page_size)
            .map_err(|_| "Invalid memory layout")?;

        let raw_ptr = unsafe { alloc(layout) };
        let ptr = NonNull::new(raw_ptr).ok_or("Out of memory")?;

        // Initialize pages to zero (Demand zero paging simulation)
        unsafe {
            std::ptr::write_bytes(ptr.as_ptr(), 0, capacity);
        }

        Ok(Self {
            ptr,
            layout,
            page_size,
            capacity,
        })
    }

    pub fn write_at(&mut self, offset: usize, data: &[u8]) -> Result<(), &'static str> {
        if offset + data.len() > self.capacity {
            return Err("Segmentation Fault: Write exceeds virtual memory bounds!");
        }

        unsafe {
            let dest = self.ptr.as_ptr().add(offset);
            std::ptr::copy_nonoverlapping(data.as_ptr(), dest, data.len());
        }
        Ok(())
    }

    pub fn read_at(&self, offset: usize, len: usize) -> Result<&[u8], &'static str> {
        if offset + len > self.capacity {
            return Err("Segmentation Fault: Read exceeds virtual memory bounds!");
        }

        unsafe {
            let src = self.ptr.as_ptr().add(offset);
            Ok(std::slice::from_raw_parts(src, len))
        }
    }
}

impl Drop for VirtualMemoryBuffer {
    fn drop(&mut self) {
        unsafe {
            dealloc(self.ptr.as_ptr(), self.layout);
        }
    }
}

fn main() {
    println!("=== Linux Virtual Memory & Page-Aligned Allocation ===");

    // 1. Allocate 4 Virtual Pages (16 KB)
    let mut vmem = VirtualMemoryBuffer::allocate_aligned(4).expect("Allocation failed");
    println!("Allocated 4 Pages ({} bytes) with 4096-byte Alignment.", vmem.capacity);

    // 2. Perform safe aligned writes across page boundaries
    let message = b"High Performance Database WAL Header Record";
    vmem.write_at(0, message).unwrap();
    vmem.write_at(4096, b"Second Page Data Segment").unwrap();

    // 3. Verify Page Contents
    let read_data = vmem.read_at(0, message.len()).unwrap();
    println!("Page 0 Header Content: {:?}", std::str::from_utf8(read_data).unwrap());
    assert_eq!(read_data, message);

    // 4. Test Out-of-Bounds Memory Protection Trap
    let oob_result = vmem.write_at(16380, b"OVERFLOW_DATA_THAT_EXCEEDS_BOUNDS");
    println!("Simulated Guard Page Access Violation: {:?}", oob_result);
    assert!(oob_result.is_err());
}
```

## Common Pitfalls & Server Mistakes

### 1. File Truncation SIGBUS with `mmap`
- **Cause**: Mapping a file with `mmap()`, then another process truncates the file on disk. Accessing the memory beyond the new file size generates a `SIGBUS` signal that crashes the application.
- **Fix**: Handle `SIGBUS` with `sigaction` or coordinate file access with advisory file locks (`flock`).

### 2. Anonymous `mmap` Leaks
- **Cause**: Repeatedly calling `mmap()` without corresponding `munmap()` calls. Because `mmap` bypasses the standard heap allocator, leaks will not show up in typical allocator tracking.
- **Fix**: Encapsulate all raw `mmap` pointers in RAII structs with proper `Drop` implementations.

## Complete Solutions to Exercises

### Solution 1: Page Boundary Calculator
```rust
pub fn align_to_page_boundary(size: usize, page_size: usize) -> usize {
    assert!(page_size.is_power_of_two(), "Page size must be power of two");
    (size + page_size - 1) & !(page_size - 1)
}

#[test]
fn test_page_alignment() {
    assert_eq!(align_to_page_boundary(100, 4096), 4096);
    assert_eq!(align_to_page_boundary(4096, 4096), 4096);
    assert_eq!(align_to_page_boundary(4097, 4096), 8192);
    assert_eq!(align_to_page_boundary(1_000_000, 2 * 1024 * 1024), 2 * 1024 * 1024); // 2MB HugePage
}
```

### Solution 2: Memory-Mapped Ring Buffer Pointer Offset
```rust
pub struct MmapOffsetTracker {
    pub total_size: usize,
    pub current_offset: usize,
}

impl MmapOffsetTracker {
    pub fn new(total_size: usize) -> Self {
        Self { total_size, current_offset: 0 }
    }

    pub fn allocate_slice(&mut self, len: usize) -> usize {
        let offset = self.current_offset;
        self.current_offset = (self.current_offset + len) % self.total_size;
        offset
    }
}

#[test]
fn test_mmap_offset() {
    let mut tracker = MmapOffsetTracker::new(1000);
    assert_eq!(tracker.allocate_slice(300), 0);
    assert_eq!(tracker.allocate_slice(400), 300);
    assert_eq!(tracker.allocate_slice(500), 700);
    assert_eq!(tracker.allocate_slice(100), 200); // Cycled
}
```
