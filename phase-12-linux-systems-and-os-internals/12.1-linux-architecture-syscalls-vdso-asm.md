## Concept

Modern operating systems must enforce strict isolation: a buggy or malicious user application must never be allowed to directly corrupt physical RAM, write to raw storage sectors, or shut down CPU cores.

The Linux operating system accomplishes this using **Hardware Privilege Rings** enforced by the CPU:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    Linux CPU Privilege Rings & Syscall Boundary              │
├──────────────────────────────────────────────────────────────────────────────┤
│  RING 3: USER SPACE (Unprivileged)                                           │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ Rust Web Application / Backend Microservice (Axum, Tokio, Loco)        │  │
│  │   • Isolated virtual address space                                     │  │
│  │   • Cannot execute privileged CPU instructions (e.g. `cli`, `lgdt`)    │  │
│  │   • Cannot directly access physical peripherals or raw NICs            │  │
│  └───────────────────┬────────────────────────────────▲───────────────────┘  │
│                      │ Issues `syscall` instruction   │ Returns result/errno │
│ ─────────────────────┼────────────────────────────────┼───────────────────── │
│  VDSO ACCELERATION   │ (No context switch for time)   │                      │
│  ┌───────────────────┴────────────────────────────────┴───────────────────┐  │
│  │ Virtual Dynamic Shared Object (VDSO): Mapped directly into user space  │  │
│  │ Reads kernel data pages in user mode (`clock_gettime`, `getcpu`)       │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
│ ──────────────────────────────────────────────────────────────────────────── │
│  RING 0: KERNEL SPACE (Privileged Supervisor Mode)                           │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ Linux Kernel Syscall Dispatcher (`entry_SYSCALL_64`)                   │  │
│  │   • Syscall Table: Array of function pointers indexed by `%rax`        │  │
│  │   • VFS Layer, TCP/IP Stack, Device Drivers, Process Scheduler         │  │
│  │   • Direct access to CPU registers, MMU page tables, and physical RAM  │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 1. The Anatomy of a System Call (x86_64)

When your Rust program calls `std::fs::File::open()` or `std::net::TcpListener::bind()`, the CPU executes a hardware transition from **Ring 3** to **Ring 0**:

1. **Parameter Loading**: Arguments are placed into specific CPU registers following the Linux x86_64 ABI:
   - `%rax`: System call number (e.g. `1` for `sys_write`, `60` for `sys_exit`, `0` for `sys_read`).
   - `%rdi`: 1st argument (e.g. file descriptor `fd`).
   - `%rsi`: 2nd argument (e.g. buffer pointer `*const u8`).
   - `%rdx`: 3rd argument (e.g. buffer length `size_t`).
   - `%r10`: 4th argument (replaces `%rcx` in syscall ABI).
   - `%r8` : 5th argument.
   - `%r9` : 6th argument.
2. **`syscall` Instruction**: The CPU switches to Ring 0, saves the instruction pointer (`%rip`), and jumps to the kernel's `entry_SYSCALL_64` routine.
3. **Dispatch & Verification**: The kernel indexes into the `sys_call_table` and runs the kernel function.
4. **`sysretq` Instruction**: The kernel writes the return value into `%rax` and switches the CPU back to Ring 3.

---

### 2. The Cost of Context Switches vs. VDSO

A traditional system call incurs a **context switch penalty** (~100–300 CPU cycles) because:
- CPU privilege registers must be toggled.
- Kernel stacks are switched.
- CPU caches and branch predictors experience disruption.

To eliminate this overhead for high-frequency calls, Linux provides the **VDSO (Virtual Dynamic Shared Object)**:
- The kernel maps a read-only memory page containing kernel time variables directly into every user-space process.
- Functions like `clock_gettime(CLOCK_REALTIME)` read timestamps directly from user space without switching to Ring 0, achieving **sub-nanosecond execution speeds**!

---

### 3. Syscall Layers in Rust

```
Level 0: Raw Assembly (`std::arch::asm!`) ➔ Manual register loading, zero overhead.
Level 1: `libc` C FFI Crate              ➔ Thin wrappers over glibc/musl syscall wrappers.
Level 2: `nix` Crate                     ➔ Idiomatic, type-safe Rust representations of POSIX syscalls.
Level 3: `std` Standard Library          ➔ Cross-platform safe abstractions (`std::fs`, `std::net`).
```

## Why It Matters in Systems & Backend Engineering

1. **Sub-Microsecond Latency Engineering**: Understanding the syscall boundary allows you to eliminate redundant syscalls (e.g., using `writev` instead of 10 `write` calls, or utilizing `io_uring`).
2. **Zero-Dependency Statically Linked Binaries**: You can build micro-binaries that speak directly to the Linux kernel via raw syscalls with zero C runtime (`libc`) dependencies.
3. **Diagnosing Performance Cliffs**: When high CPU utilization occurs without high application throughput, tools like `strace` and `perf` track syscall frequency.

## Complete, Compilable Code Example

The following program demonstrates invoking raw Linux system calls directly using Rust inline assembly (`std::arch::asm!`), alongside `libc` and `nix` equivalents:

```rust
use std::arch::asm;
use std::time::Instant;

/// Raw Linux x86_64 Syscall: sys_write (Syscall #1)
/// Directly emits `syscall` CPU instruction with zero C runtime dependency!
pub unsafe fn raw_sys_write(fd: i32, buffer: &[u8]) -> isize {
    let ret: isize;
    asm!(
        "syscall",
        in("rax") 1,                  // sys_write syscall number
        in("rdi") fd,                 // File Descriptor (1 = stdout)
        in("rsi") buffer.as_ptr(),    // Pointer to byte buffer
        in("rdx") buffer.len(),        // Buffer length
        lateout("rax") ret,           // Syscall return value in %rax
        lateout("rcx") _,             // %rcx is clobbered by CPU syscall instruction
        lateout("r11") _,             // %r11 is clobbered by CPU syscall instruction
        options(nostack)
    );
    ret
}

/// Raw Linux x86_64 Syscall: sys_getpid (Syscall #39)
pub unsafe fn raw_sys_getpid() -> u32 {
    let pid: u32;
    asm!(
        "syscall",
        in("rax") 39,                 // sys_getpid syscall number
        lateout("rax") pid,
        lateout("rcx") _,
        lateout("r11") _,
        options(nostack, readonly)
    );
    pid
}

fn main() {
    println!("=== Linux Kernel Syscall Interface & VDSO Demonstration ===\n");

    // 1. Execute raw assembly syscall write
    let message = b"[RAW SYSCALL] Hello from Rust inline assembly (Ring 3 -> Ring 0 -> Ring 3)!\n";
    let bytes_written = unsafe { raw_sys_write(1, message) };
    println!("Raw sys_write returned: {} bytes written", bytes_written);

    // 2. Fetch Process ID via raw assembly vs std::process::id()
    let raw_pid = unsafe { raw_sys_getpid() };
    let std_pid = std::process::id();
    println!("Raw Syscall PID: {} | Stdlib PID: {}", raw_pid, std_pid);
    assert_eq!(raw_pid, std_pid);

    // 3. Measure VDSO acceleration (clock_gettime)
    println!("\nMeasuring VDSO timestamp retrieval speed across 1,000,000 iterations...");
    let start = Instant::now();
    for _ in 0..1_000_000 {
        let _ = Instant::now(); // Uses VDSO clock_gettime internally on Linux
    }
    let duration = start.elapsed();
    println!("1,000,000 VDSO time queries took: {:?}", duration);
    println!("Average time per timestamp: {:.2} ns (Zero Ring 0 context switch overhead!)", 
        duration.as_nanos() as f64 / 1_000_000.0);
}
```

## Common Pitfalls & Compiler Errors

### 1. Register Clobbering in Inline Assembly (`%rcx` and `%r11`)
- **Cause**: On x86_64, the CPU `syscall` instruction inherently overwrites `%rcx` (with `%rip`) and `%r11` (with `%rflags`).
- **Fix**: Always mark `lateout("rcx") _` and `lateout("r11") _` in `asm!` to prevent LLVM from assigning active variables to those registers.

### 2. Negative Return Codes vs `errno`
- **Cause**: In raw Linux syscalls, errors are returned as negative numbers between `-1` and `-4095` (e.g. `-2` for `ENOENT`). Glibc converts this into `errno = 2` and returns `-1`.
- **Fix**: When using raw assembly, check if `ret < 0` and treat `-ret` as the Linux error code.

## Complete Solutions to Exercises

### Solution 1: Raw Exit Syscall
```rust
use std::arch::asm;

pub unsafe fn raw_sys_exit(exit_code: i32) -> ! {
    asm!(
        "syscall",
        in("rax") 60, // sys_exit syscall number
        in("rdi") exit_code,
        options(noreturn)
    );
}
```

### Solution 2: Syscall Error Decoder
```rust
pub fn decode_syscall_error(ret: isize) -> Result<usize, &'static str> {
    if ret >= 0 {
        Ok(ret as usize)
    } else {
        match -ret {
            1 => Err("EPERM: Operation not permitted"),
            2 => Err("ENOENT: No such file or directory"),
            9 => Err("EBADF: Bad file descriptor"),
            12 => Err("ENOMEM: Out of memory"),
            13 => Err("EACCES: Permission denied"),
            22 => Err("EINVAL: Invalid argument"),
            _ => Err("Unknown Linux Kernel Error"),
        }
    }
}

#[test]
fn test_error_decoder() {
    assert_eq!(decode_syscall_error(42), Ok(42));
    assert_eq!(decode_syscall_error(-2), Err("ENOENT: No such file or directory"));
    assert_eq!(decode_syscall_error(-13), Err("EACCES: Permission denied"));
}
```
