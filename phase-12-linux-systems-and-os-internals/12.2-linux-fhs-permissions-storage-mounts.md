## Concept

In Linux, **everything is treated as a file** (or a stream of bytes accessible via a file descriptor). To manage thousands of system components, configuration files, device nodes, and application binaries without chaos, Linux follows the **Filesystem Hierarchy Standard (FHS)** and a strict **POSIX Permission Model**.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  Linux Filesystem Hierarchy Standard (FHS)                   │
├──────────────────────────────────────────────────────────────────────────────┤
│  / (Root Directory)                                                          │
│  ├── /etc/        ➔ System-wide configuration files (nginx.conf, sshd_config)│
│  ├── /var/        ➔ Variable data & logs (/var/log, /var/lib/docker)         │
│  ├── /tmp/        ➔ Ephemeral storage (Sticky-bit enabled: 1777)             │
│  ├── /opt/        ➔ Third-party self-contained software packages             │
│  ├── /proc/       ➔ Virtual kernel process information tree (In-memory)      │
│  ├── /sys/        ➔ Virtual kernel hardware & cgroups device tree (In-memory)│
│  ├── /dev/        ➔ Device nodes (Block devices, /dev/null, /dev/urandom)    │
│  └── /usr/bin/    ➔ Standard user executable binaries                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

---

### 1. The POSIX Permission Model & Octal Bitmasks

Every inode on a Linux filesystem records a 16-bit `st_mode` field representing:
1. **File Type** (Regular file, directory, symlink, socket, FIFO, character/block device).
2. **Special Bits** (SUID, SGID, Sticky Bit).
3. **Permission Triad** (Owner/User `u`, Group `g`, Others `o`).

```
┌────────┬────────────────┬────────────────┬────────────────┐
│ Special│  Owner (User)  │     Group      │     Others     │
│ SUID   │  Read/Write/Ex │  Read/Write/Ex │  Read/Write/Ex │
│  4 2 1 │   4   2   1    │   4   2   1    │   4   2   1    │
├────────┼────────────────┼────────────────┼────────────────┤
│  r w x │   r   w   x    │   r   -   x    │   r   -   -    │
│  (0)   │  (4 + 2 + 1=7) │  (4 + 0 + 1=5) │  (4 + 0 + 0=4) │
└────────┴────────────────┴────────────────┴────────────────┘
Octal Representation: 0754
```

- **Read (`r` = 4)**: View file content; list directory files (`ls`).
- **Write (`w` = 2)**: Modify file content; create/delete files in directory.
- **Execute (`x` = 1)**: Run binary/script; enter directory (`cd`).

---

### 2. Special Permission Bits: SUID, SGID, & Sticky Bit

| Bit | Octal Value | On Executable File | On Directory |
| :--- | :--- | :--- | :--- |
| **SUID (Set UID)** | `4000` | Process runs with privileges of file owner (e.g. `/usr/bin/passwd` runs as root). | No standard effect. |
| **SGID (Set GID)** | `2000` | Process runs with file's group ID. | New files created inherit parent directory group! |
| **Sticky Bit** | `1000` | Legacy swap flag. | Only file owner (or root) can delete files inside (`/tmp`). |

---

### 3. The `umask` Mechanism

When a process creates a file (default `0666`) or directory (default `0777`), the kernel filters out bits defined by the process's **`umask`**:
$$\text{Effective Mode} = \text{Default Mode} \ \& \ \sim(\text{umask})$$

- Standard server `umask` = `0022` $\rightarrow$ Files created with `0644` (`rw-r--r--`), Dirs with `0755` (`rwxr-xr-x`).
- Secure backend `umask` = `0027` $\rightarrow$ Files created with `0640` (`rw-r-----`), Dirs with `0750` (`rwxr-x---`).

---

### 4. Storage Mounts & `/etc/fstab`

Linux unifies physical partitions into a single directory hierarchy via **mount points**:
- `lsblk`: List block devices and NVMe drives.
- `df -h`: Check disk space usage across mounted filesystems.
- `du -sh /var/log`: Measure directory disk consumption.
- `/etc/fstab`: Defines persistent filesystem mounts loaded at boot.

---

## Why It Matters in Systems & Backend Engineering

1. **Production Security Auditing**: Misconfigured permissions on private keys (`chmod 644 ~/.ssh/id_ed25519` causes OpenSSH to abort) or sensitive files (`/etc/shadow`) expose systems to compromise.
2. **Container Storage Mounting**: Understanding volume mounts (`docker run -v /host/data:/app/data`) requires knowledge of mount points, UID mapping, and file permissions.
3. **Database Performance & Disk Starvation**: Monitoring disk usage and mounting database WAL directories on dedicated SSDs with specific mount options (`noatime`, `data=ordered`) maximizes throughput.

## Complete, Compilable Code Example

The following Rust program implements a **Linux Permission Validator & Security Auditor**:

```rust
use std::fs::Metadata;
use std::os::unix::fs::MetadataExt;

/// Represents Linux POSIX Permission Flags
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LinuxPermissions {
    pub mode: u32,
    pub is_suid: bool,
    pub is_sgid: bool,
    pub is_sticky: bool,
    pub user_read: bool,
    pub user_write: bool,
    pub user_exec: bool,
    pub group_read: bool,
    pub group_write: bool,
    pub group_exec: bool,
    pub other_read: bool,
    pub other_write: bool,
    pub other_exec: bool,
}

impl LinuxPermissions {
    pub fn from_mode(mode: u32) -> Self {
        Self {
            mode: mode & 0o7777,
            is_suid: (mode & 0o4000) != 0,
            is_sgid: (mode & 0o2000) != 0,
            is_sticky: (mode & 0o1000) != 0,
            user_read: (mode & 0o0400) != 0,
            user_write: (mode & 0o0200) != 0,
            user_exec: (mode & 0o0100) != 0,
            group_read: (mode & 0o0040) != 0,
            group_write: (mode & 0o0020) != 0,
            group_exec: (mode & 0o0010) != 0,
            other_read: (mode & 0o0004) != 0,
            other_write: (mode & 0o0002) != 0,
            other_exec: (mode & 0o0001) != 0,
        }
    }

    pub fn to_symbolic_string(&self) -> String {
        let mut s = String::with_capacity(10);
        // Owner
        s.push(if self.user_read { 'r' } else { '-' });
        s.push(if self.user_write { 'w' } else { '-' });
        s.push(if self.is_suid {
            if self.user_exec { 's' } else { 'S' }
        } else if self.user_exec { 'x' } else { '-' });

        // Group
        s.push(if self.group_read { 'r' } else { '-' });
        s.push(if self.group_write { 'w' } else { '-' });
        s.push(if self.is_sgid {
            if self.group_exec { 's' } else { 'S' }
        } else if self.group_exec { 'x' } else { '-' });

        // Others
        s.push(if self.other_read { 'r' } else { '-' });
        s.push(if self.other_write { 'w' } else { '-' });
        s.push(if self.is_sticky {
            if self.other_exec { 't' } else { 'T' }
        } else if self.other_exec { 'x' } else { '-' });

        s
    }

    /// Security Audit: Flags dangerous permissions (e.g. World-Writable)
    pub fn is_world_writable(&self) -> bool {
        self.other_write
    }

    /// Calculates effective permission given a process umask
    pub fn apply_umask(default_mode: u32, umask: u32) -> u32 {
        default_mode & (!umask)
    }
}

fn main() {
    println!("=== Linux Filesystem Hierarchy & Permission Auditor ===\n");

    // 1. Audit /tmp permissions (Expected: 1777 = rwxrwxrwt)
    let tmp_perms = LinuxPermissions::from_mode(0o1777);
    println!("0o1777 (/tmp) Symbolic: {}", tmp_perms.to_symbolic_string());
    assert_eq!(tmp_perms.to_symbolic_string(), "rwxrwxrwt");
    assert!(tmp_perms.is_sticky);

    // 2. Audit Private SSH Key permissions (Expected: 0600 = rw-------)
    let ssh_key_perms = LinuxPermissions::from_mode(0o600);
    println!("0o0600 (id_ed25519) Symbolic: {}", ssh_key_perms.to_symbolic_string());
    assert_eq!(ssh_key_perms.to_symbolic_string(), "rw-------");
    assert!(!ssh_key_perms.is_world_writable());

    // 3. Detect dangerous world-writable files
    let bad_perms = LinuxPermissions::from_mode(0o777);
    println!("0o0777 Security Alert: World Writable = {}", bad_perms.is_world_writable());
    assert!(bad_perms.is_world_writable());

    // 4. Demonstrate umask calculation
    let default_file = 0o666;
    let standard_umask = 0o022;
    let secure_umask = 0o027;

    let standard_effective = LinuxPermissions::apply_umask(default_file, standard_umask);
    let secure_effective = LinuxPermissions::apply_umask(default_file, secure_umask);

    println!("\nUmask Calculation for New Files (Default 0666):");
    println!("  Standard Umask (0022) -> Mode: 0{:o} ({})", 
        standard_effective, LinuxPermissions::from_mode(standard_effective).to_symbolic_string());
    println!("  Secure Umask   (0027) -> Mode: 0{:o} ({})", 
        secure_effective, LinuxPermissions::from_mode(secure_effective).to_symbolic_string());
}
```

## Common Pitfalls & Server Mistakes

### 1. Inability to Enter Directories (Missing `+x`)
- **Cause**: Setting `chmod 644` on a directory. In Linux, the read bit `r` allows listing filenames, but the execute bit `x` is required to traverse (`cd`) and access inodes inside the directory.
- **Fix**: Directories must have execute permissions (e.g. `chmod 755`).

### 2. World-Writable Files in Production
- **Cause**: Running `chmod -R 777` to fix permission errors during backend deployment.
- **Fix**: Never use `777`. Assign proper group ownership (`chown -R www-data:www-data /var/www`) and set `chmod 750` for dirs and `640` for files.

## Complete Solutions to Exercises

### Solution 1: Permission Mode Bitmask Calculator
```rust
pub fn calculate_octal_mode(symbolic: &str) -> Result<u32, &'static str> {
    if symbolic.len() != 9 {
        return Err("Symbolic string must be exactly 9 characters");
    }

    let bytes = symbolic.as_bytes();
    let mut mode = 0u32;

    // Owner (bytes 0, 1, 2)
    if bytes[0] == b'r' { mode |= 0o400; }
    if bytes[1] == b'w' { mode |= 0o200; }
    if bytes[2] == b'x' { mode |= 0o100; }

    // Group (bytes 3, 4, 5)
    if bytes[3] == b'r' { mode |= 0o040; }
    if bytes[4] == b'w' { mode |= 0o020; }
    if bytes[5] == b'x' { mode |= 0o010; }

    // Others (bytes 6, 7, 8)
    if bytes[6] == b'r' { mode |= 0o004; }
    if bytes[7] == b'w' { mode |= 0o002; }
    if bytes[8] == b'x' { mode |= 0o001; }

    Ok(mode)
}

#[test]
fn test_octal_conversion() {
    assert_eq!(calculate_octal_mode("rwxr-xr-x").unwrap(), 0o755);
    assert_eq!(calculate_octal_mode("rw-------").unwrap(), 0o600);
}
```

### Solution 2: SUID Binary Detector
```rust
pub fn is_dangerous_suid(mode: u32, uid: u32) -> bool {
    let has_suid = (mode & 0o4000) != 0;
    let is_root = uid == 0;
    has_suid && is_root
}

#[test]
fn test_suid_detector() {
    assert!(is_dangerous_suid(0o4755, 0)); // Root SUID binary
    assert!(!is_dangerous_suid(0o0755, 0)); // Normal binary
    assert!(!is_dangerous_suid(0o4755, 1000)); // Non-root SUID
}
```
