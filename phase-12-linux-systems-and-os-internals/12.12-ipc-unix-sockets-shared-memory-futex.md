## Concept

When building high-performance multi-process systems (such as container engines, Nginx master/worker architectures, or microservice sidecars), isolated processes must exchange data with minimal overhead.

Linux provides a spectrum of **Inter-Process Communication (IPC)** mechanisms ranging from byte streams to zero-copy shared memory and hardware-assisted locking:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    Linux Inter-Process Communication (IPC) Matrix            │
├──────────────────────────────────────────────────────────────────────────────┤
│  1. UNIX DOMAIN SOCKETS (UDS - AF_UNIX)                                      │
│  Process A ──► In-kernel memory buffer ──► Process B (Zero TCP/IP overhead!) │
│  • Supports `SCM_RIGHTS`: Transfer open file descriptors across processes!   │
│                                                                              │
│  2. POSIX SHARED MEMORY (shm_open + mmap)                                    │
│  Process A ──┐                                                               │
│              ├──► Physical RAM Page (Zero-Copy Instant Visibility!) ◄── Proc B│
│  3. LINUX FUTEX (Fast User-space Mutex: sys_futex)                           │
│  • Uncontended Lock: 1 atomic CAS instruction in user space (Zero syscalls!) │
│  • Contended Lock:   `FUTEX_WAIT` puts thread to sleep in kernel queue       │
│  • Unlock:           `FUTEX_WAKE` wakes waiting threads                      │
│                                                                              │
│  4. EVENTFD & TIMERFD                                                        │
│  Turns internal events and kernel timers into pollable File Descriptors!     │
└──────────────────────────────────────────────────────────────────────────────┘
```

---

### 1. Unix Domain Sockets & `SCM_RIGHTS` (Passing File Descriptors)

Unix Domain Sockets (`AF_UNIX`) bypass the entire TCP/IP network stack (no IP routing, no TCP checksums, no packet fragmentation).

#### The Superpower of `SCM_RIGHTS`:
A master process can bind to a privileged port (e.g. port `80` or `443`), `accept()` incoming TCP connections, and pass the active connection file descriptor directly to an unprivileged worker subprocess over a Unix socket via **Ancillary Data (`sendmsg` with `SCM_RIGHTS`)**!

---

### 2. POSIX Shared Memory (`shm_open`)

Shared memory provides the absolute fastest form of IPC:
1. Process A calls `shm_open("/my_shm", O_CREAT | O_RDWR)` and `mmap()`.
2. Process B opens the same `/my_shm` object and calls `mmap()`.
3. Both processes have pointers pointing to the **exact same physical RAM page**. Writes by Process A are instantly readable by Process B with **zero copy and zero syscall overhead**!

---

### 3. Linux Futexes: How Rust's `Mutex` Works Under the Hood

Before the **Futex (Fast User-space Mutex)**, acquiring a lock always required a `semop()` system call.

With Futexes:
1. **Uncontended Fast Path (99% of cases)**: An atomic `compare_exchange` in user space sets a 32-bit integer from `0` (unlocked) to `1` (locked). **Total cost: 1 CPU cycle, 0 system calls!**
2. **Contended Slow Path**: If another thread already holds the lock, the waiting thread issues `sys_futex(FUTEX_WAIT)`. The kernel puts the thread to sleep in the futex waitqueue until the holder calls `sys_futex(FUTEX_WAKE)`.

---

## Why It Matters in Systems & Backend Engineering

1. **Zero-Downtime Process Upgrades**: Master processes pass listening socket file descriptors to newly spawned binary versions over `SCM_RIGHTS`, allowing hot-restarts without dropping active connections.
2. **Sub-Microsecond Sidecar Communication**: Envoy sidecars and local proxies communicate with application containers over UDS at 10x the throughput of loopback TCP (`127.0.0.1`).
3. **High-Frequency In-Memory Caches**: Cross-process caches (like Dragonfly / local memory grids) share gigabytes of RAM across processes via `shm_open`.

## Real-World Analogy

- **Loopback TCP (`127.0.0.1`)** is like mailing a letter to your next-door neighbor through the postal service: it gets boxed, postmarked, and routed through the local sorting facility.
- **A Unix Domain Socket** is like handing the letter directly over the backyard fence.
- **Shared Memory (`shm_open`)** is like writing on a shared whiteboard located in the common hallway between two offices.
- **A Futex** is a "Do Not Disturb" sign on a conference room door: you only knock on the building manager's door (**Issue a Syscall**) if someone is already inside.

## Complete, Compilable Code Example

The following Rust program implements a **Zero-Copy Shared Memory Message Ring with Atomic Futex Coordination**:

```rust
use std::sync::atomic::{AtomicU32, Ordering};
use std::sync::Arc;
use std::thread;
use std::time::Duration;

/// Simplified Futex-Style Fast Mutex Lock
pub struct MiniFutexLock {
    state: AtomicU32, // 0 = Unlocked, 1 = Locked
}

impl MiniFutexLock {
    pub const fn new() -> Self {
        Self {
            state: AtomicU32::new(0),
        }
    }

    /// Fast-path acquisition: CAS instruction
    pub fn try_lock(&self) -> bool {
        self.state.compare_exchange(0, 1, Ordering::Acquire, Ordering::Relaxed).is_ok()
    }

    pub fn lock(&self) {
        while !self.try_lock() {
            // In real Linux: issues sys_futex(..., FUTEX_WAIT, ...) to sleep
            std::hint::spin_loop();
            thread::sleep(Duration::from_micros(50));
        }
    }

    pub fn unlock(&self) {
        self.state.store(0, Ordering::Release);
        // In real Linux: issues sys_futex(..., FUTEX_WAKE, 1) to wake sleeping threads
    }
}

/// Simulated Shared Memory IPC Buffer
pub struct SharedIpcBuffer {
    pub lock: MiniFutexLock,
    pub payload: [u8; 64],
    pub payload_len: usize,
}

fn main() {
    println!("=== Linux Inter-Process Communication & Futex Engine ===\n");

    let shared_mem = Arc::new(parking_lot::RwLock::new(SharedIpcBuffer {
        lock: MiniFutexLock::new(),
        payload: [0u8; 64],
        payload_len: 0,
    }));

    let writer_shared = Arc::clone(&shared_mem);
    let reader_shared = Arc::clone(&shared_mem);

    // 1. Spawning Writer Process/Thread
    let writer = thread::spawn(move || {
        println!("[WRITER] Preparing to write payload into shared memory region...");
        let mut buffer = writer_shared.write();
        buffer.lock.lock();

        let message = b"CRITICAL_SYSTEM_TELEMETRY_RECORD_#42";
        buffer.payload[..message.len()].copy_from_slice(message);
        buffer.payload_len = message.len();

        println!("[WRITER] Payload written. Releasing Futex lock.");
        buffer.lock.unlock();
    });

    // 2. Spawning Reader Process/Thread
    let reader = thread::spawn(move || {
        thread::sleep(Duration::from_millis(50));
        println!("[READER] Acquiring Futex lock to read shared memory...");
        let buffer = reader_shared.read();
        buffer.lock.lock();

        let data = &buffer.payload[..buffer.payload_len];
        println!("[READER] Read from Shared Memory: {:?}", std::str::from_utf8(data).unwrap());
        assert_eq!(data, b"CRITICAL_SYSTEM_TELEMETRY_RECORD_#42");

        buffer.lock.unlock();
    });

    writer.join().unwrap();
    reader.join().unwrap();
    println!("\nIPC Synchronization completed with zero memory copies.");
}
```

## Common Pitfalls & Server Mistakes

### 1. Orphaned POSIX Shared Memory Leaks in `/dev/shm`
- **Cause**: Creating shared memory segments via `shm_open()` and failing to call `shm_unlink()` upon process termination. The shared memory remains allocated in `/dev/shm` until system reboot!
- **Fix**: Always pair `shm_open` with `shm_unlink` in signal handlers or startup cleanup routines.

### 2. File Descriptor Leaks across `fork()` without `O_CLOEXEC`
- **Cause**: Opening pipes or sockets without `O_CLOEXEC` (`FD_CLOEXEC`). When `execve()` is called, child processes unintentionally inherit open file descriptors, keeping sockets open indefinitely.
- **Fix**: Always pass `O_CLOEXEC` (e.g. `pipe2(flags, O_CLOEXEC)`).

## Complete Solutions to Exercises

### Solution 1: Anonymous Pipe Pair Wrapper
```rust
use std::sync::mpsc::{channel, Receiver, Sender};

pub struct SafePipePair<T> {
    tx: Sender<T>,
    rx: Receiver<T>,
}

impl<T> SafePipePair<T> {
    pub fn new() -> Self {
        let (tx, rx) = channel();
        Self { tx, rx }
    }

    pub fn send(&self, item: T) -> Result<(), &'static str> {
        self.tx.send(item).map_err(|_| "EPIPE: Broken pipe")
    }

    pub fn receive(&self) -> Option<T> {
        self.rx.recv().ok()
    }
}

#[test]
fn test_pipe_pair() {
    let pipe = SafePipePair::<u32>::new();
    pipe.send(42).unwrap();
    assert_eq!(pipe.receive(), Some(42));
}
```

### Solution 2: `eventfd` Counter Simulation
```rust
use std::sync::atomic::{AtomicU64, Ordering};

pub struct EventFdEmulator {
    counter: AtomicU64,
}

impl EventFdEmulator {
    pub fn new(init_val: u64) -> Self {
        Self { counter: AtomicU64::new(init_val) }
    }

    pub fn write_increment(&self, value: u64) {
        self.counter.fetch_add(value, Ordering::SeqCst);
    }

    pub fn read_and_reset(&self) -> u64 {
        self.counter.swap(0, Ordering::SeqCst)
    }
}

#[test]
fn test_eventfd_emulator() {
    let efd = EventFdEmulator::new(0);
    efd.write_increment(5);
    efd.write_increment(10);
    assert_eq!(efd.read_and_reset(), 15);
    assert_eq!(efd.read_and_reset(), 0); // Reset to zero after read
}
```
