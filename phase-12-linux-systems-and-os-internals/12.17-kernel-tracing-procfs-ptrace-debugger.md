## Concept

To monitor server health, diagnose performance bottlenecks, and debug crashed production services, systems engineers inspect the Linux kernel's internal state through **`/proc`** and control running processes using the **`ptrace()`** system call.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    Linux Process Introspection & ptrace Architecture         │
├──────────────────────────────────────────────────────────────────────────────┤
│  DEBUGGER / TRACER PROCESS (GDB, LLDB, or Custom Rust Debugger)             │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ 1. Attaches to target PID via `ptrace(PTRACE_ATTACH, target_pid)`      │  │
│  │ 2. Replaces opcode at 0x401020 with `0xCC` (`INT 3` Breakpoint)       │  │
│  │ 3. Resumes execution via `ptrace(PTRACE_CONT)`                         │  │
│  └───────────────────▲────────────────────────────────┬───────────────────┘  │
│                      │ Waits for `SIGTRAP` via        │ Commands ptrace      │
│                      │ `waitpid(target_pid)`          │                      │
│                      ▼                                ▼                      │
│  TARGET APPLICATION PROCESS (Executing x86_64 Instructions)                  │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ 0x401018: mov %rax, %rdi                                               │  │
│  │ 0x401020: 0xCC (INT 3 Instruction Trapped by CPU!) ──► Emits `SIGTRAP` │  │
│  │                                                         (Process Paused)  │
│  └────────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  KERNEL /proc VIRTUAL FILESYSTEM (Live In-Memory State)                      │
│  • `/proc/[pid]/maps`    ➔ Active virtual memory segments                    │
│  • `/proc/[pid]/fd/`     ➔ Symlinks to all open sockets, pipes, and files    │
│  • `/proc/[pid]/stat`    ➔ CPU ticks, thread states, and memory RSS          │
└──────────────────────────────────────────────────────────────────────────────┘
```

---

### 1. The `/proc` Virtual Filesystem

The `/proc` directory is not stored on disk—it is a live virtual interface generated on the fly by the Linux kernel:

- **`/proc/[pid]/maps`**: Shows exact virtual address mappings, page permissions (`r-xp`), and loaded shared libraries.
- **`/proc/[pid]/fd/`**: Directory of symlinks representing every open file descriptor (vital for identifying socket leaks!).
- **`/proc/[pid]/stat`**: Space-delimited metrics containing PID, process name, state (`R`, `S`, `Z`), user CPU ticks (`utime`), system CPU ticks (`stime`), and RSS memory.
- **`/proc/meminfo`**: System-wide physical RAM metrics (`MemTotal`, `MemAvailable`, `Cached`, `Dirty`).

---

### 2. The `ptrace()` System Call

`ptrace` is the fundamental system call used by debuggers (like GDB and LLDB) and syscall tracers (like `strace`):

1. **`PTRACE_ATTACH`**: Pauses target process and makes the caller the parent tracer.
2. **`PTRACE_GETREGS` / `PTRACE_SETREGS`**: Reads or modifies CPU registers (`%rip`, `%rax`, `%rsp`, `%rflags`).
3. **`PTRACE_PEEKTEXT` / `PTRACE_POKETEXT`**: Reads or overwrites words of memory in the target's address space.
4. **`PTRACE_SINGLESTEP`**: Executes exactly one machine instruction and traps again.

---

### 3. How Software Breakpoints Work (`INT 3` / `0xCC`)

When you set a breakpoint on a function:
1. The debugger saves the **original byte** at that memory address (e.g. `0x55` for `push %rbp`).
2. Overwrites that byte with `0xCC` (the 1-byte x86_64 `INT 3` instruction).
3. When the CPU hits `0xCC`, it triggers a hardware interrupt. The kernel pauses the process and sends `SIGTRAP` to the debugger.
4. To resume: The debugger overwrites `0xCC` back with `0x55`, rewinds the instruction pointer (`%rip -= 1`), single-steps, re-inserts `0xCC`, and calls `PTRACE_CONT`.

---

## Why It Matters in Systems & Backend Engineering

1. **Live Production Diagnostics**: When a backend service deadlocks or spikes to 100% CPU, inspecting `/proc/[pid]/stack` or attaching a tracer pinpoints the exact line of execution without killing the node.
2. **Building Observability Tools**: Tools like `strace`, `lsof`, and custom APM profilers parse `/proc` and use `ptrace` to extract metrics.
3. **Security Analysis & Reverse Engineering**: Understanding `ptrace` and `/proc/maps` allows security engineers to detect unauthorized code injection and memory tampering.

---

## Real-World Analogy

- **`/proc`** is like the glass telemetry window on an industrial centrifuge: you can read temperature gauges, RPM meters, and fluid pressure without opening the machine.
- **`ptrace`** is the master diagnostic remote control: you can freeze the engine mid-rotation (**`SIGTRAP`**), inspect the position of every gear (**`PTRACE_GETREGS`**), manually rotate it forward by 1 notch (**`PTRACE_SINGLESTEP`**), and resume normal speed (**`PTRACE_CONT`**).

## Complete, Compilable Code Example

The following Rust program provides a **`/proc/[pid]/maps` Parser & Software Breakpoint State Machine Engine**:

```rust
use std::collections::HashMap;

/// Represents a Virtual Memory Mapping Segment from /proc/[pid]/maps
#[derive(Debug, PartialEq, Eq)]
pub struct MemoryMapping {
    pub start_addr: usize,
    pub end_addr: usize,
    pub permissions: String,
    pub pathname: String,
}

impl MemoryMapping {
    pub fn parse_maps_line(line: &str) -> Option<Self> {
        let parts: Vec<&str> = line.split_whitespace().collect();
        if parts.len() < 5 {
            return None;
        }

        let range: Vec<&str> = parts[0].split('-').collect();
        if range.len() != 2 {
            return None;
        }

        let start_addr = usize::from_str_radix(range[0], 16).ok()?;
        let end_addr = usize::from_str_radix(range[1], 16).ok()?;
        let permissions = parts[1].to_string();
        let pathname = if parts.len() >= 6 { parts[5].to_string() } else { "[anonymous]".to_string() };

        Some(Self {
            start_addr,
            end_addr,
            permissions,
            pathname,
        })
    }
}

/// Simulated Breakpoint State Machine for x86_64 Debugger
pub struct DebuggerBreakpointManager {
    original_bytes: HashMap<usize, u8>,
}

impl DebuggerBreakpointManager {
    pub fn new() -> Self {
        Self { original_bytes: HashMap::new() }
    }

    /// Set Breakpoint at memory address by replacing original byte with 0xCC (INT 3)
    pub fn set_breakpoint(&mut self, memory: &mut [u8], addr: usize) -> Result<(), &'static str> {
        if addr >= memory.len() {
            return Err("Address out of bounds");
        }

        let original = memory[addr];
        self.original_bytes.insert(addr, original);
        memory[addr] = 0xCC; // INT 3 Software Interrupt
        println!("[DEBUGGER] Placed INT 3 (0xCC) at 0x{:08x} (Saved original: 0x{:02x})", addr, original);
        Ok(())
    }

    /// Restore original opcode before resuming execution
    pub fn restore_breakpoint(&mut self, memory: &mut [u8], addr: usize) -> Result<(), &'static str> {
        if let Some(original) = self.original_bytes.remove(&addr) {
            memory[addr] = original;
            println!("[DEBUGGER] Restored original byte 0x{:02x} at 0x{:08x}", original, addr);
            Ok(())
        } else {
            Err("No active breakpoint at address")
        }
    }
}

fn main() {
    println!("=== Linux Kernel Introspection & Debugger Engine ===\n");

    // 1. Parse sample /proc/[pid]/maps output
    let sample_maps = "55a8e3400000-55a8e3412000 r-xp 00000000 08:01 131075 /usr/local/bin/rust-api";
    let mapping = MemoryMapping::parse_maps_line(sample_maps).unwrap();
    println!("Parsed /proc/maps Entry:");
    println!("  Address Range: 0x{:x} - 0x{:x}", mapping.start_addr, mapping.end_addr);
    println!("  Permissions:   {}", mapping.permissions);
    println!("  Binary Path:   {}", mapping.pathname);
    assert_eq!(mapping.permissions, "r-xp");

    // 2. Simulate setting and restoring an INT 3 software breakpoint
    let mut code_segment = vec![0x48, 0x89, 0xe5, 0x55, 0xc3]; // Sample x86_64 instructions
    let mut dbg = DebuggerBreakpointManager::new();

    println!("\nOriginal Code Segment: {:02x?}", code_segment);
    dbg.set_breakpoint(&mut code_segment, 3).unwrap();
    println!("Patched with Breakpoint: {:02x?}", code_segment);
    assert_eq!(code_segment[3], 0xCC);

    // Simulate hitting breakpoint and resuming
    dbg.restore_breakpoint(&mut code_segment, 3).unwrap();
    println!("Restored Code Segment:   {:02x?}", code_segment);
    assert_eq!(code_segment[3], 0x55);
}
```

## Common Pitfalls & Server Mistakes

### 1. `Operation not permitted` (`EPERM`) on `PTRACE_ATTACH`
- **Cause**: Linux kernel security modules (`Yama`) blocking unprivileged processes from attaching to non-child processes (`/proc/sys/kernel/yama/ptrace_scope`).
- **Fix**: Run with `sudo` or set `ptrace_scope = 0` during debugging sessions.

### 2. Instruction Pointer Overrun After `INT 3`
- **Cause**: When the CPU executes `0xCC`, the instruction pointer `%rip` advances by 1 byte. Resuming execution without decrementing `%rip` skips the original instruction!
- **Fix**: The debugger must subtract 1 from `%rip` before calling `PTRACE_CONT`.

## Complete Solutions to Exercises

### Solution 1: `/proc/meminfo` Free Memory Parser
```rust
pub fn parse_meminfo_available_mb(content: &str) -> Option<u64> {
    for line in content.lines() {
        if line.starts_with("MemAvailable:") {
            let parts: Vec<&str> = line.split_whitespace().collect();
            if parts.len() >= 2 {
                let kb = parts[1].parse::<u64>().ok()?;
                return Some(kb / 1024); // Convert KB to MB
            }
        }
    }
    None
}

#[test]
fn test_meminfo_parser() {
    let mock_meminfo = "MemTotal:       16384000 kB\nMemFree:         4096000 kB\nMemAvailable:    8192000 kB\n";
    assert_eq!(parse_meminfo_available_mb(mock_meminfo), Some(8000));
}
```

### Solution 2: CPU Register State Formatter
```rust
pub struct CpuRegisters {
    pub rip: u64,
    pub rsp: u64,
    pub rax: u64,
    pub rbx: u64,
}

impl CpuRegisters {
    pub fn format_registers(&self) -> String {
        format!(
            "RIP: 0x{:016x} | RSP: 0x{:016x}\nRAX: 0x{:016x} | RBX: 0x{:016x}",
            self.rip, self.rsp, self.rax, self.rbx
        )
    }
}

#[test]
fn test_register_formatting() {
    let regs = CpuRegisters {
        rip: 0x00401020,
        rsp: 0x7fffffffe000,
        rax: 42,
        rbx: 0,
    };
    assert!(regs.format_registers().contains("RIP: 0x0000000000401020"));
}
```
